# Loading-push path diagnostics

No model parameters or optimizer states are updated. The tar archive is read in
memory; the original input bundle and previous raw arrays remain unmodified.

Run in the experiment checkout with the project's Python environment:

```bash
python analysis/chargpt_loadsign_1023/measure.py gate
python analysis/chargpt_loadsign_1023/measure.py run
python analysis/chargpt_loadsign_1023/report.py
```

The gate verifies the bundle SHA256 and eight states against both the previous
loading push and autograd. All 700 states are subsequently compared against the
previous per-unit arrays (including exact sign fractions and alive masks).
Source, probe, dtype, and readout definitions are reused from the previous run.

For final pre-LN residual t, q=(t-mean(t))/sigma and b=gamma*(e@vL), the
transpose LN Jacobian is

    J_LN^T(e@vL) = [b-mean(b)-q*mean(q*b)]/sigma.

The `direct` diagnostic retains the first two terms. It keeps the original
forward LN, sigma, and logits. This is a change to the local derivative, not an
experiment that removes LN from the network. `exact` retains all terms.
`loaderror` changes only e to softmax(h@vL.T)-uniform; it does not change the
forward representation or tied token embeddings. `absK` changes only the sign
of the token weight K=y_uniform@ybar_task.

The observed own-weight push is obtained by multiplying the pullback by the
FFN down columns, activation derivative, and K, then averaging all tokens.
No derivative of the upstream representation with respect to its own parameters
is included. Saved representations may differ across tasks and enter the fixed
coefficient K; this is distinct from movement caused by upstream updates.

All main s values use the same alive set defined on the current-task probe.
Units alive there but inactive on the uniform gradient probe may have exactly
zero push. These remain in the main denominator and are recorded separately.
The cancellation ratio excludes 0/0 and reports its missing count.

ReLUcap is a training-time weight constraint in the original implementation;
its fixed-state activation and derivative are ordinary ReLU. No activation
clipping is introduced by this diagnostic.

Results are descriptive over 10 saved seeds. A local diagnostic intervention
cannot establish the historical learning process that created the state.

Two exploratory follow-ups are distinct:

- `components.py`: freezes an exact positive-semidefinite softmax secant matrix
  and splits the prediction into self output, other outputs, and fixed residual.
  This attribution is exact but is not a unique attribution of a nonlinear map.
- `loading_sources.py`: instead splits the construction of F into FFN units and
  the fixed residual, using F=B T^T+F_r and the Gram matrix G=T^T T.
  The diagonal loading source is not identical to the lemma's self form.

The lemma additionally averages old labels with features, derivatives, K and
kappa fixed, removes the old-label-correlated readout remainder, and takes the
confident-correct limit. A positive globally projected kappa alone does not
establish these conditions. Input-index off-diagonal terms in that proof must
not be identified with unit-index cross terms in these diagnostics.

Follow-up gates use `gate`, then full runs use `run`. The corresponding reports
are `report_components.py`, `combine.py`, and `report_loading.py`. The third
stage reads the verified first-stage raw arrays from the archive named in
backup_manifest.json. Retain that archive for reproduction. `plot.py` draws
only the prediction-side decomposition, not the theoretical self form.

`probe_control.py` (`gate`, then `run`) is a fourth exploratory control. It uses
current-task inputs for both F and the switch-expectation gradient, compares
the original-task CE gradient, and measures predictive confidence. Box M
samples stochastic next tokens from second-order Markov transition tables;
it is not a deterministic input-label memorization task. `report_probe.py`
summarizes that control. No per-unit files are generated by the fourth stage.

Section 10 adds saved-state alignment and consecutive task-end rotation:

```bash
python analysis/chargpt_loadsign_1023/rotation_measure.py gate
python analysis/chargpt_loadsign_1023/rotation_measure.py elr
python analysis/chargpt_loadsign_1023/rotation_measure.py run
python analysis/chargpt_loadsign_1023/rotation_report.py
python analysis/chargpt_loadsign_1023/rotation_archive.py
```

`rotation/` contains separate states, windows, correlations, judgments and
provenance; the earlier judgments are unchanged. The alignment cosine contracts
the class axis with the original probe's weighted error, so its sign equals the
existing other-unit direct push. This is not an independent geometric outcome.
Rotation uses adjacent integer task ends only, preserving unit indices. The main
correlation is across unit medians with at least three valid observations per
unit; both-endpoint-alive and task-wise/pooled sensitivities are also reported.

The ELR reconstruction restores the unsaved L0 activation multiplier from the
control C3 row norms. It validates chain-probe statistics against the original
CSV and checks the L1 total against autograd before reporting any decomposition.
Available ELR endpoints are seed5–9, task50/100. Source files in the original
`chargpt_cl_1019` worktree are only read. `rotation/backup_manifest.json` records
verified copies of these borrowed inputs as well as the new per-unit arrays;
the original backup manifest is retained. To restore an absent original ELR
source tree, use the manifest's `input_restore_root` as the `SOURCE` root in
`rotation_measure.py` (the recorded file hierarchy is identical).

The report can be regenerated directly from archived arrays after cleanup.
The recorded measurement commit/hash identifies the exact code used. No
endpoint correlation alone establishes historical freezing or its causality.
