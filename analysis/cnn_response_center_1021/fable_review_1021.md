## 結論: B を先に回し、A は 4 腕のまま「媒介率を測る走」に格下げして続ける

**優先順は B → A。** B は V13 の §5「成長上限の救済と不救済」に CNN の登録介入が一つも無い穴を直接埋め、checkpoint と natural 腕の bit 一致再生が既にあるので最も安い。A は部品 5 の「CNN の応答交換は未実施」を埋めるが、leaky の c1 では場の差が小さく（p⁺ .01 対 .10、平均 φ′ はおよそ 0.11 対 0.19）、Adam が勾配の大きさを正規化するため、結果は「媒介率 x 割」という境界の記述になる可能性が高い。両方向支持で BIDIRECTIONAL を取りに行く走ではなく、媒介率と CI を主の数として登録する。

## 案 A の修正勧告

- **最大の欠陥は検出力の未宣言。** 媒介する差の大きさが未確認のまま sign test を主にしている。最初の 3,000 更新の natural 差は self 腕 2 本で初めて出る。登録に「LRc self − LR self が 10 seed で 9/10 以上正かつ平均 2 pt 未満なら UNDERPOWERED とし、移植腕を媒介として読まない」という門を入れる。
- **主の数は媒介率にする。** (LR←LRc − LR self)/(LRc self − LR self) とその逆方向を bootstrap CI つきで出し、< 0.3 を NOT_CARRIED、> 0.7 を CARRIED と事前に切る。sign test は補助。
- **Adam 下では場は「大きさ」でなく「向きと前向きの利得」で効く。** 移植で変わるのは c1 勾配の分担パターンと、同じ Δz が特徴をどれだけ動かすかの係数。この読みを spec に書いておくと、null の解釈が「c1 の傾き場は担い手でない、差は前向きの特徴内容（rank 5.9）と c2 の位置が運ぶ」に自然に落ちる。
- **チャネル対応の弱さを明記。** 対応は index だけで、30 課題 × 3 万更新後の c1 の第 j チャネルは両腕で別物。swap_ee と同じ限界だが、c1 は 16 チャネルで rank 5.9 なので MLP より効く。
- **省けるもの。** receiver-winner 上と全空間の両方の φ′ 統計は安いので残す。Adam 状態の保持は self-sham が natural と bit 一致するので良い。固定場でよく、動く場は要らない。

**(3) 倍率対照は最初の走に入れない。** 理由は二つ。backward の channel 別定数 c_j は Adam で約 1/(1−β₂) 更新の過渡を除いて吸収される一方、forward では特徴の変化を c_j 倍にするので「平均傾きだけ同じ」という名前と中身が合わない。実質は RM で既にある LR 対照の CNN 版で、LR←LRc が動いたときの追試として置く方が安い。5 腕目を入れるなら、donor のチャネルを置換した移植腕の方が「開いた割合が増えただけか、配置が合っているからか」を分けられる。

## 案 B の修正勧告

- **最大の欠陥は bias を残した cap。** W だけ q 倍すると m′ = q(m−b)+b なので r′ = (m−b)/s + b/(qs) となり、b < 0 の層では縮めるほど相対位置が深くなる。文字 GPT は bias 無しの箱だったから W だけで済んだ。5+1 CNN は全層 bias で、LRc では c1 の沈降が全部 b 経路だった前例がある。**W 行と b を同じ q で縮める**と m′ = qm、r 不変で、恒等式 m = rs の「幅だけ」を操作する介入になる。これが本論の部品 3 の文に一番まっすぐ乗る。
- **s_ref は実行時と同じ推定量で。** probe SD を参照、batch EMA を実行時に使うと、2 つの推定量の系統差だけで q が常時当たる／当たらないが決まる。課題 1 の末尾 1,000 更新を EMA 追跡だけで再生し、その EMA を s_ref² にする。
- **簡素化の下限（問 4）。** 残すのは 4 点。unit 別の課題 1 末幅を閾値、batch 分散の EMA 0.99、Adam 直後に W 行と b を q 倍して V を q² 倍、全 4 site に当てて site 別の発火頻度と超過量を記録。上流→下流の逐次再計算は要らず、1 回の forward で全 site を測って同時に当てる。ずれは次の更新で EMA が吸う。within/between の分解、probe 幅の超過監視は診断として残してよいが判定には使わない。
- **natural 再生の bit 一致検査を必須に。** 予算延長走との S-reuse 照合。
- **ELU の主判定は小さな効果を前提に書く。** 戻せる上限は F1 の −1.17 pt で、継続は fresh に 4.9 pt 勝ったまま。「NO_CHANGE でも幅はこの箱の担い手でない」と事前に書く。応答の回復（φ′ .27 → 約 .5〜.6、r 不変）は副指標として登録し、成績と応答が分かれたら「応答を保っても成績は上がらない」と読む。

## 第2回答（訂正と最終確認）

鮮度確認を完了しました。vault は HEAD 6699161、COLLABORATION_NOTICE は無く、先生側の未公開差分も 0 で、親の確認と一致します。

**最終案に賛成します。採用 1〜3 と不採用 4〜6 のいずれにも異議はありません。**

- 4 の比率について。LR と LRc は初期特徴も入力も Adam も別物なので、receiver 内の対応差を群間の自然差で割っても自然間接効果にはなりません。主を二方向の対応差と 95% CI、sign＋Holm 2 に置き、比率は分母の CI が 0 を跨がないときだけ参考値として併記する扱いが正しいです。私が出した 0.3 と 0.7 の閾値は撤回します。
- 5 の読み方について。非有意は「この層・この場・この窓で効果を確認できず、CI の上限は x pt」までに留めるべきで、「担い手でない」は言い過ぎでした。cap は予算間比較と別の軌道なので、−1.17 pt を改善幅の上限と呼ぶのも誤りです。
- 6 について。Adam の相殺は定数倍率の定常状態の話で、位置と入力で変わるゲート場には当てはまりません。rank 5.9 対 13 は記述であり、場の交換の原因と決めない方針に同意します。

残る点は致命ではなく、起動前に固める 3 点です。

1. **A の対照腕は self-sham に固定する。** 分岐時は delta が 0 で natural と一致しても、1 歩後は a_R0 ＋ [φ(z_R0＋Δ) − φ(z_R0)] と φ(z_R0＋Δ) の丸めが違い、bit では合いません。対応差は同じ kernel を通る self-sham 対 移植で取り、natural との比較は許容誤差つきの再現検査に置きます。
2. **A の検定の実質を spec に一行。** 10 seed の両側 sign test は 9/10 で p = .021、Holm の第 1 段 .025 を通ります。8/10 では届かないので、判定は「9/10 以上」と同じ意味になります。CI を主の数として並べる方針はこの点でも妥当です。
3. **B の s_ref 参照は課題 1 のデータの幅である。** 5+1 は hard と easy が交互なので、後期 hard 課題では batch の幅が課題 1 と系統的に違い得ます。cap はそれを承知で課題 1 の幅へ戻す設計だと明記し、site 別の発火頻度と超過量に「課題の型」の列を足して、ELU で cap が当たり続けるのが沈降の成長か課題のデータ差かを後で分けられるようにします。

W と b を同率で縮める方式は、射影の瞬間に r が保たれる点で部品 3 の恒等式に乗ります。上流が動くので網全体の幅媒介とは言わない、という但し書きも同意です。
