# Fable エージェントへの依頼 4: R0 の未導出 2 点（A 共通成分の形成則・B 後期の持続崩れ）

依頼者: Claude Fable（親）、2026-10-28。Issa「解析してください」「Fable をエージェントにして」。箱は vit_long_1024 追補 D（2 ブロック ViT、rlfix、seed 10252010、LN なしの腕 R0 と S）。前の依頼 3 の答え `results/vit_long_1024_2blk_rlfix/posthoc_r0_collapse_codex.md` の「検証と残る問い」のうち、本稿で R0 を対照として使うときに根拠が弱い 2 点を埋める。A と B は別のエージェントが同時に担当する。

## 0. 2 つの問い

- **A 形成則**: R0 では課題 20〜40 の間に patch 側の尺度が 100 倍になる（埋め込み 13→37、注意 0 後 28→274、FFN0 出力 100→11,193、注意 1 出力 258→8,119。重みのノルムは FFN0 fc2 42→51、value1 19→21 で 1.2〜1.5 倍）。増幅は重みの大きさでなく向きの配置で作られている（注意 1 の増加 log 4.0 のうち入力 Z が 5.4、重みノルム積 0.56）。head を毎課題 0 に戻す条件で、何がこの配置を課題をまたいで一貫した向きに回すのか。S（共有 head）では同じ区間で 7 倍（173→1,189）に留まるのはなぜか。
- **B 後期の持続崩れ**: R0 の 60→61 は head の lr を 1/100 にすると T90 に 2,675 で届くが、末の暗記率 0.81、最後 1,000 更新の平均 0.65 に戻る。30→31 の同じ介入は 0.999 が持続する。戻る主因が (i) 体の表現の制約か (ii) head と体の結合した更新の不安定さか。

物語で埋めず、導けるところは導き、導けないところは「測った事実」と書く。親の仮説（§3）は検証の対象で、合わなければ外れと書く。

## 2. やること

### A 形成則（担当: エージェント A、出力は `posthoc_r0_form/`、script は `fable_r0form_*.py`）

A-1. **課題の中の時系列**。R0 と S を t10 と t30（Adam あり）から 1 課題 5,000 更新回し直し、25 更新ごとに固定 probe で記録する: 埋め込み・注意 0 後・FFN0 出力・注意 1 出力の patch rms、FFN0 の平均出力ベクトル（向きの保存用に 50 更新ごと）、m2 のノルム、CLS の rms、head のノルム、暗記率、損失。課題を 3 相に割る: 切替相（暗記率が上がり始めるまで、目安 0〜200 更新）、当てはめ相（T90 まで）、当てはめ後。相ごとの log 尺度の増分を腕 × 課題で表にする。
A-2. **S の切替相の縮み**。S の切替相で patch 側と CLS の尺度が縮むか（半径成分）。縮むなら、その大きさを装填の押しの半径成分（ln_loading_1026 の分解: 直通＝半径）と突き合わせる。R0 の切替相は head=0 で体の勾配が厳密に 0 なので、head が育つまでの更新数と、その間の体の動き（Adam のモーメントの残りだけ）を分けて記録する。
A-3. **Adam の残りの寄与**。R0 t30→31 で体の Adam のモーメントを 0 にして始めた回し直しと base を比べ、課題内の log 尺度の増分の差を出す。
A-4. **課題をまたぐ一貫性**。保存状態 t1..t10 と t10,20,30,40,(60,100) で、FFN0 の平均 patch 出力ベクトル・注意 0 の平均出力・m2 の増分の一貫性 C と隣接 cos を R0 と S で出す。t10→40 の増分が一方向に積むのか乱歩なのか。
A-5. **力の符号**。FFN0 の patch 出力に仮想の倍率 α を入れ、∂L/∂α を訓練画像で autograd で測る（R0・S の回し直しの 50 更新ごと）。−∂L/∂α の符号と大きさが、A-1 の窓ごとの log 尺度の増分と相関するか（Spearman）。当たっている画像では ∂L/∂α < 0（尺度を上げると損失が下がる）が導けている（依頼 3 の「CE が尺度の成長を促す限定した条件」）。外れている画像の分と、切替相の S（旧 head × 新ラベル）での符号も出す。
A-6. **止まる条件**。R0 t60→61 base（T90 未到達）の課題内の log 尺度の増分を t30→31 と比べ、当てはめが失敗すると成長が止まるか。
A-7. **導出**。A-1〜A-6 の結果で、「1 課題の正味の成長 = 当てはめ相の成長 − 切替相の縮み」「R0 は縮みが無いぶん速い」「当てはめが失敗すると成長が止まるので自己制限」がどこまで式で言えるか。言えない段は測った事実と書く。

### B 後期の持続崩れ（担当: エージェント B、出力は `posthoc_r0_late/`、script は `fable_r0late_*.py`）

すべて R0 t60（model_t60 + adam_t60、head reset）からの 1 課題 ≤ 5,000 更新の回し直し。対照に t30 を同じ条件で回す。暗記率は 25 更新ごと。
B-1. **再現**。head lr 1/100 の base を回し、暗記率の時系列の形（急落が ≥ 0.1/25 更新で何回あるか、漸減か）を出す。
B-2. **届いた時点で凍結**。暗記率が初めて 0.9 に届いた更新で (a) 体を全部凍結して head だけ続ける、(b) 最終 FFN だけ凍結、(c) 注意 1 だけ凍結、(d) ブロック 0（埋め込み含む）だけ凍結、(e) 凍結なし（= B-1）。残りの更新での暗記率の最後 1,000 更新の平均を表にする。
B-3. **両方 1/100**。head と体の両方の lr を 1/100 にして持続するか。
B-4. **届いた時点の表現**。届いた時点の体を凍結し head を 0 に戻して head だけ 5,000 更新で学び直す。届くなら「その時点の体は表せる」で、課題末の体で 18 条件すべて未到達だった凍結 probe と区別する。
B-5. **一歩の logit 変化の分解**。届いた前後 200 更新で、Δℓ = (ΔW)h + W(Δh) + ΔWΔh の各項の rms（画像 × クラス）を更新ごとに出す。体の項を param group（埋め込み+ブロック 0 / 注意 1 / 最終 FFN）に分ける。t30→31 の同じ量と比べる。
B-6. **判定量**。sign 歩幅の上界 η‖∂ℓ/∂θ_group‖₁ を届いた時点の状態で group ごとに出し、logit の余裕（正解と次点の差の中央値）と比べる。「η‖∂ℓ/∂θ_体‖₁ が余裕を超えると当てはめが持たない」が t30 と t60 を分けるか。
B-7. **判定**。(i) 表現の制約と (ii) 更新の不安定さのどちらが主因か、B-2〜B-6 のどれが決め手かを書く。両方が混ざるなら割合でなく、どの測定がどちらを支持するかを書く。

## 4. 制約（破らない）

- 既存ファイルの変更・削除・移動をしない。新しい script は `analysis/vit_long_1024/posthoc_2blk/fable_r0form_*.py` / `fable_r0late_*.py`、生の出力は `~/Projects/obsidian-research-data/vit_long_1024_2blk_rlfix/posthoc_r0_form/` / `posthoc_r0_late/` にだけ書く。担当外のディレクトリに書かない。
- git の操作（add・commit・checkout・stash・branch）をしない。commit は親がする。vault に書かない。
- 新しい訓練走をしない。保存状態からの回し直しは 1 条件 ≤ 5,000 更新。
- もう一方のエージェントが同じ GPU を同時に使う。GPU は 1 エージェント ≤ 5 GB（`torch.cuda.set_per_process_memory_fraction` か max_split を使う）、RSS ≤ 2.5 GB、GPU の仕事は同時に 1 本、`nice -n 10`、`torch.set_num_threads(4)`。走る前に `nvidia-smi` と `free -g` を見て、空きが GPU 3 GB・RAM 3 GB を切るなら待つ。
- プロセスを殺さない（自分が起動したものを除く）。`pkill -f` を使わない。
- 既存の入力の SHA256 を記録し、終わりに変わっていないことを確かめる（依頼 3 の codex_input_hashes.json と同じ形）。
- `PROGRESS.md` を担当ディレクトリに置き、節目ごとに時刻つきで 1〜3 行追記する（親はこれだけを見張る）。
- 1 時間ごとに RSS と GPU の最大値を PROGRESS.md に書く。
