# spec_gate_rearrangement_0912 — 侵食の飽和はゲート零交差の密度で決まるか

## 0. 位置づけ

[[perm_overlap_0912]] で、侵食 $c$ の「活性化不変」は **k=1 でしか測っていなかったことの産物**と分かった。境界で入れ替える画素の割合 $k$ を下げると:

| k | 切替 CE (LR/SN06) | c (leaky .1) | c (Snake .6) |
|---:|---|---:|---:|
| 0 | 0.015 / 0.053 | **−0.0285** | +0.0036 |
| 0.1 | 0.198 / 0.228 | −0.0099 | **+0.0423** |
| 1 | 3.949 / 4.597 | +0.0421 | +0.0445 |

leaky は切替ショックに完全追従（Spearman +1.000）して符号反転するのに、**Snake は CE 0.23（1/20 のショック）で満額の侵食が立つ**（飽和比 $S=c(0.1)/c(1)=0.95$、leaky は −0.24）。

**事後の読み（未検定）**: Snake のゲート $1+\sin(2\alpha z)$ は $z$ 上で周期 $\pi/\alpha$ ごとに 0 に触れるので、画素を 1 割入れ替えるだけで**応答するユニットの集合が大きく入れ替わる**。leaky のゲートは $\mathrm{sign}(z)$ しか見ないので 1 割では反転しにくい。

これは [[gradient_factors_0910]] の「ゲートは Adam に消される」と矛盾しない。消えるのはユニットごとの**定数倍** $g2$ であって、**どのユニットが応答するかという配置**は消えない。

本 spec はこの読みを潰す。**私は活性化の形の汎関数で 4 連敗している**（φ″・gcorr・RMS φ′・h）。今回は φ′ の汎関数ではなく「境界で φ′ のパターンがどれだけ組み変わるか」を**直接測る**。

## 1. 測る量 — 境界でのゲート組み換え

タスク $t$ の開始時、**1 回も更新する前に**、固定プローブ 512 標本で

$$p_{\text{old}}=\varphi'\!\left(x[\pi_{t-1}]W_1^{\mathsf T}+b_1\right),\qquad p_{\text{new}}=\varphi'\!\left(x[\pi_t]W_1^{\mathsf T}+b_1\right)$$

- **`gate_corr`** = Pearson 相関 $\mathrm{corr}(p_{\text{old}},p_{\text{new}})$（全 (標本, ユニット) 上）。1 なら組み換えなし。
- **`gate_l1`** = $\mathbb E|p_{\text{new}}-p_{\text{old}}|/\mathbb E\,p_{\text{old}}$（相対組み換え量）
- **`nz`** = 前活性分布の $\pm\sigma$ 内に入るゲート零点の個数。Snake は $\sigma\alpha/\pi$（周期 $\pi/\alpha$）、leaky・ELU は 1（$z=0$ の 1 本）。解析値を記録。

$W_1,b_1$ は同一なので、動くのは入力の置換だけ。**同じネットワークが 2 つの置換をどう違って見るか**を測っている。

## 2. 腕・水準・走

活性化 7 種 × $k\in\{0,\,0.1,\,1.0\}$ × 3 seed = **63 走 × 120 タスク**（約 28 分）。

| 群 | 活性化 | 零交差 | 狙い |
|---|---|---|---|
| 傾き族 | `LR001`(a=.01)・`LR`(.1)・`LR03`(.3) | **1 本（固定）** | ゲートの**コントラスト**を 100 倍振っても交差数は不変 |
| 平滑 1 交差 | `ELU1` | 1 本（平滑） | 折れ目でなくても 1 本なら leaky 側か |
| 周期族 | `SN02`(α=.2)・`SN06`(.6)・`SN15`(1.5) | $\sigma\alpha/\pi$ ≈ 0.16 / 0.41 / 1.16 | **交差密度**を 7 倍振る |

`LIN` は $\varphi'\equiv1$ で `gate_corr` が定義できない（分散 0）ため除外。$k$ は 3 水準に絞る（飽和比 $S=c(0.1)/c(1)$ が主変数、$k=0$ は「ショックゼロ」の錨）。

ストリーム設計は [[perm_overlap_0912]] と同一（全腕で `randperm` を必ず 1 回引き、$k=1$ は宿主経路、$k<1$ は別生成器）。`LR` の $k=1$ が G1 と外部整合を担う。

## 3. 事前登録の予測と判定

判定は t = 100, 120 × 3 seed。飽和比 $S_{\text{act}} = c(k{=}0.1)\,/\,c(k{=}1)$（活性化ごとに 1 値、7 個）。

### V1 `GATE_REARRANGEMENT` — 組み換え量が飽和を説明するか（**本体**）
7 活性化の $S$ と、$k=0.1$ での `gate_corr` の Spearman。
- `EXPLAINS` … ≤ −0.8（組み換えが大きい＝ gate_corr が低いほど飽和する）
- `FAILS` … |Spearman| < 0.5
- `PARTIAL` … その他

**予測: `EXPLAINS`。**

### V2 `CROSSING_DENSITY` — Snake 族で α に単調か
`SN02` < `SN06` < `SN15` の順に $S$ が上がるか（n=3）。
- `MONOTONE` … 厳密に単調増
- `NOT` … その他

**予測: `MONOTONE`。** ただし **n=3 なので偶然一致の確率は 1/6**。V1 が主で、これは補強。

### V3 `CONTRAST_IRRELEVANT` — 傾き族は飽和しないか
`LR001`・`LR`・`LR03` の $S$。
- `NO_SATURATION` … 3 本とも ≤ 0.5
- `SATURATES` … いずれかが ≥ 0.8
- `PARTIAL` … その他

**予測: `NO_SATURATION`。** ゲートのコントラストを 100 倍振っても交差は 1 本のままなので、読みが正しければ 3 本とも leaky（−0.24）付近に並ぶ。**ここが崩れると読みは死ぬ**（コントラスト説になる）。

### V4 `ELU_SIDE` — 平滑な 1 交差はどちら側か
- `LIKE_LEAKY` … $S(\texttt{ELU1})\le0.5$
- `LIKE_SNAKE` … ≥ 0.8
- `BETWEEN` … その他

**予測: `LIKE_LEAKY`。**

### V5 `GATE_VS_SHOCK` — c を並べるのはどちらか
全 21 セルで Spearman(`gate_corr`, c) と Spearman(切替 CE, c) を比較。
- `GATE_WINS` … |前者| ≥ |後者| + 0.15
- `SHOCK_WINS` … |後者| ≥ |前者| + 0.15
- `TIE` … その他

**予測: `GATE_WINS`。** 根拠: 切替 CE は [[perm_overlap_0912]] で leaky 単独なら +1.000、2 活性化まとめると +0.60 に落ちた。ゲート組み換えが真の変数なら 2 活性化をまたいでも並ぶはず。

## 5. 限界（事前に宣言）

- **これは 5 回目の活性化形状の検定である。** 前 4 回（φ″・gcorr・RMS φ′・h）は全て外れた。今回が違うのは、φ′ の汎関数ではなく**境界での組み換えを直接測る**点だが、それでも φ′ から作った量である。
- `gate_corr` は $W_1,b_1$ に依存する。腕ごとに $W_1$ が違うので、**「活性化の形の効果」と「その活性化が育てた $W_1$ の効果」を分離していない**。
- Snake の `nz` は $\sigma$ に依存し、$\sigma$ は成長の結果（ループ）。V2 が `MONOTONE` でも因果の向きは出ない。
- $S=c(0.1)/c(1)$ は比なので、$c(1)$ が小さい腕で不安定。$c(1)$ は全腕 0.03–0.05 の見込みだが、外れたら生値も併記する。
- n=3（V2）、7 活性化（V1）。
- $k<1$ は Permuted MNIST の外側。LoP の設計指針としては読まない。
- SGD 対照なし。120 タスクは天井の手前。

## 追補 1（2026-09-12・**本走の前**・判定タスク t=100,120 の値は未読）

スモーク（NTASK=61・TRACK={60}・seed 0）で、検査 2 件を直す。**判定・帯・予測はいずれも変更していない。**

**P4 の変異対照の設計ミス。** 「対を壊した相関 `corr(a, shuffle(c))` が `gate_corr` から 0.2 以上離れること」としていたが、`gate_corr` 自体が既に 0 に近いセル（`K100_SN06` で 0.0225）では差が 0.024 しか出ず、**検出力が量そのものに依存してしまう**。絶対値の言明に改める:
- `p4` = 手計算の Pearson と `torch.corrcoef` の差 ≤ 1e−12（実測 ≤3.3e−13）
- `p4_self` = `corr(a,a) − 1` ≤ 1e−12（推定量が正しく規格化されている）
- `p4_shuf` = |corr(a, shuffle(c))| ≤ 0.05（対を壊せば 0 を返す）

**P5 を判定から外し、報告のみにする。** 「k=1 の `gate_corr` が無関係な 2 置換の帰無と ±0.02 で一致する」は前提が誤り。境界の 2 置換のうち**片方は直前に 625 歩学習した置換**なのでゲートのパターンが構造化されており、両方新規に引いた帰無とは体系的にずれる。実測は `K100_LR` 0.252 対 帰無 0.361、`K100_SN06` 0.023 対 0.052。飽和比の分母の定義には影響しない。

**開示（V1 に不利）**: t=60・k=0.1 の `gate_corr` は **LR 0.796 / SN06 0.825 / SN15 0.447**。**SN06 は LR より組み換えが小さい**のに飽和する側である。V1 `EXPLAINS` が求める順序（飽和する腕ほど gate_corr が低い）は、Snake 族の内部（SN06 > SN15）では成り立つが、**leaky と Snake をまたぐと逆**になっている。判定タスクではないが、V1 は苦しい。`gate_l1`（LR 0.212 / SN06 0.384 / SN15 0.602）は逆に Snake 側が大きく、**2 つの組み換え指標が食い違う**。判定は事前登録どおり `gate_corr` で行う。

なお `K010_LR` は `perm_overlap_0912` を t=60 で完全再現（cos +0.020261・D2 0.293469 が一致）。
