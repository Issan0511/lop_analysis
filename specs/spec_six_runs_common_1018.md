### 0.4 指標・標本・判定の字義

- `online` はその課題の全学習ミニバッチにおける **更新前** argmax 正解率の平均。終端精度 `memo` と別列にする。
- F51 の後期窓は **t∈{21,23,25,27,29}**。これは「第 21〜29 hard 課題」という意味ではない。早期窓は t∈{1,3,5,7,9}。
- 先に seed 内で窓平均・対応差を作り、その後 seed を集約する。反復単位は seed。画像・更新・課題を独立 seed として水増ししない。
- 各数値判定に使う差ベクトルは本文に列挙する。n=10、df=9、float64 で `mean(d) ± t[9,1−0.05/(2m)]·sd(d)/sqrt(10)`。m はその spec の判定用区間数で、各走内の Bonferroni 同時区間。t 区間は seed 差に対する近似推論であり、正規性を保証しない。平均・95%の通常区間・中央値・全10差・符号数も併記する。SD=0 は一点区間とし `DEGENERATE_SD`。
- **論文にない「2pt以上」を成功の条件に足さない。** 効果の方向の基準は0とする。既存の同等性幅 **ε_eq=0.005（0.5pt）** は論文§6/A.4にある「並ぶ/同等」を数量化する場合にのみ継承する。新しい非劣性の読みもこの幅を用いた比較であることを明記し、無条件の同一性とは呼ばない。
- `POS(d)` ⇔ 区間下端>0。`EQ(d)` ⇔ 区間全体⊆[−ε_eq,+ε_eq]。`NI(A,B)` ⇔ A−B の区間下端>−ε_eq。差を検出できないだけの区間は EQ/NI としない。境界の等号は EQ のみ含め、POS/NI は含めない。「≫」という記号自体を判定には使わず、正の対応差の確認と実際の効果量で記す。
- 表の複合ラベルは全条件の AND。別記の優先順がない場合、候補ラベルが一つだけ成立したときに採用し、どれも成立しない/複数成立するときは `MIXED` として `NO_UNIQUE_PATTERN`/`OVERLAPPING_EVIDENCE` を記録する。同等性幅内の小差で二つの読みが両立しても、都合のよい方だけ選ばない。事後に閾値を替えず、全連続量を出す。6 走全体の familywise 有意差を保証する設計ではない。

**何を支持/限定するかは論文の文に対応させる。** ラベルを得ること自体を独立の研究目標にはしない。

### 0.5 完全性・S 検査・保存

**S 検査は実装・配管を検査する。仮説が外れたことを CHECK_FAILED にして捨てない。**

- 評価 seed は原則 0–9、走 3・6 は 10–19。較正・実装検査は 100–109（指定した probe は 100–102）。研究全体で未使用の seed とは称さない。
- 10 seed と登録全腕・全課題の一意な行を要求する。欠測は `INCOMPLETE`、検査違反は `CHECK_FAILED`、数値発散は `DIVERGED`。そのまま記録し、失敗 seed を落として n を縮めない。発散を黙って精度0にもしない。正しい checkpoint から同一条件で再開は可。
- 診断は学習 RNG・P・Adam・EMA を進めない。各分岐は独立 clone、ラベル・バッチ列・画像 id を hash で対応させる。介入による正当な moment 変更は各 spec に列挙する。
- 同一演算経路の無介入は bit/byte 一致を要求する。ノルム・集約・異なる演算形状の比較の許容は、算術誤差と独立参照から本走前に導出する。**観測残差を見て許容を広げない。** 許容内の本物と許容外の指定変異の両方を示す。感度を失った上界は PASS にしない。
- 各 run の `checks.json` は検査値・許容の根拠・各変異の検出を収録。`all_pass` は必須検査と必須変異検出の AND。仮説の性能閾値と数値誤差の許容を混同しない。
- 保存: `spec.md`、`provenance.json`、`checks.json`、`per_task.csv`/分岐結果、単位別診断、`verdict.json`、`summary.md`。spec・起動ソース・全 import・設定・データ/subset・クラス/ラベル/バッチ列・初期状態・checkpoint・解析コードの hash、環境、R/slot 順、再利用元、発散/再開履歴を含める。
- 診断の m=E_x z、s=SD_x z、r=m/s は**unit ごとに**作ってから集約する。`median(m)/median(s)` と `median(m/s)` は別名にする。s=0 は個数と符号を記録し、0除算を小定数で隠さない。既存列の定義は変えない。新設の Var_x は correction=0、旧 s は宿主の correction を維持し、メタデータに記載する。
- repo へ移す実装作業では既存 `CLAUDE.md` の worktree/commit/main 統合・生データ退避の規則を継承する。この文書の作成は本走や GPU 使用の開始を意味しない。
