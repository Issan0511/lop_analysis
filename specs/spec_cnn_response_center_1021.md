# CNN の中心化が保った c1 応答場を双方向に交換する

実験 ID: `cnn_response_center_1021`。2026-10-21。

登録状態: REGISTERED

## 問いと比較の範囲

RL-CIFAR の LeakyReLU(0.1) CNN で、入力中心化を続けた LRc と非中心化 LR の課題 30 末を比較する。両履歴の成績差を、最初の畳み込み層 c1 における応答場への介入が両方向に動かすかを調べる。これは中心化が長期に保った状態と、その局所応答の因果効果を同じ seed・同じ次課題でつなぐ介入である。c1 の全 Jacobian の交換、中心化の効果の完全な媒介、実ラベルへの一般化はこの走の判定対象にしない。

既存の LR/LRc の履歴と成績は既知である。新規に生成する介入結果を見る前に、spec と実行コードを commit/push する。登録前には synthetic check と静的検査だけを行う。

## 固定する箱

- 元走: `cnn_drive_verify_1009/LR` と `cnn_center_1010/LRc`。seed 10–19、課題 30 末。
- 1200 枚の固定 CIFAR-10 訓練画像、課題ごとに独立な一様乱数ラベル。課題 31 の 400 epoch × 75 更新 = 30,000 更新。batch 16、Adam lr 0.001、beta=(0.9,0.999)、eps=1e-8、weight decay なし。
- c1: conv5×5(3→16,pad2) → LeakyReLU → maxpool2。続いて同じ形の c2、FC100、FC100、head10。全層 bias あり。入力の LR は /255、LRc は CIFAR-10 訓練 50,000 枚の固定チャネル平均を引く。追加の増強・尺度変更なし。
- 受け手の全重み、Adam の m/v/step、activation の記録状態を保つ。課題 31 のラベル・batch 順列は元走の保存 generator から再開し、同 seed の全腕で一致させる。
- 各腕は seed 10–19 を同じ順序の 10-run bundle として計算する。束の変更は数値条件の変更として扱う。主走の対照には自己場を用いる。自然網は同じ精度・GPU・束の preflight で開始時、1 step、75 更新窓を比較する。

## 腕と介入

主比較は次の 4 腕。

| 腕 | 受け手 | c1 の応答場 | 入力・後段・Adam |
|---|---|---|---|
| LR_self | LR t30 | 自己場（LR t30） | LR |
| LR_swap | LR t30 | LRc t30 | LR |
| LRc_self | LRc t30 | 自己場（LRc t30） | LRc |
| LRc_swap | LRc t30 | LR t30 | LRc |

同じ画像の global ID、チャネル、空間座標を対応させる。供与者は自身の入力処理で c1 の前活性を作る。受け手の固定された課題 30 末を R0、供与者を D0 とし、更新中の受け手を Rθ とする。

チャネル対応は初期化を共有する同じ index に固定する。30 課題の学習後に同じ index が同じ特徴意味を表すとは保証しない。意味で整列した場の交換という主張はしない。介入結果を見てからチャネルを並べ替えない。

\[
\tilde a(x;\theta)=\phi(z_{R0}(x))+
\{\phi[z_{D0}(x)+(z_{R\theta}(x)-z_{R0}(x))]-\phi(z_{D0}(x))\}.
\]

`zRθ-zR0` を先に計算する。固定項には勾配を流さない。差が 0 の場合は frozen 値をそのまま返す AnchorAdd を使い、開始時の c1 特徴、pool winner、全後段特徴、logits、CE を保存する。開始時の c1 への微分は `φ′(zD0)` だが、入力 Jacobian・c1 重み Jacobian 自体は受け手のものを使う。更新後はこの明示された人工関数として訓練する。元の活性化関数と同一であるとは主張しない。

自己場では D0=R0 とし、移植腕と同じ anchor 演算をそのまま行う。自然 forward への分岐で代用しない。実数演算では自然な活性化と同じでも、浮動小数点では開始後の差の再構成・引き算の丸めが異なりうる。その差を主比較に混ぜないため、主比較は自己場と他方の場の交換に固定する。

gain 対照は今回の主走には採用しない。実装の任意 flag は後の独立した検討用であり、今回走らせる腕は上記 4 腕に固定する。

## 判定と統計

主指標は課題 31 の更新 1–3000 の online accuracy（更新前の batch 予測）。seed を反復単位とし、次の対応差を取る。

1. 救済: `LR_swap − LR_self`。
2. 逆移植: `LRc_self − LRc_swap`。

各差に両側 exact sign test（厳密な 0 の tie を除く）、2 検定に Holm 補正、family alpha 0.05。平均対応差と seed bootstrap percentile 95% CI（20,000 回、乱数 seed 1021）を併記し、10 seed の値を省略しない。予測方向の支持には、符号の多数派と平均差の両方が正であることを要求する。2 方向ともこの条件で有意なら `BIDIRECTIONAL`、一方のみなら `ONE_DIRECTION`、どちらも支持されなければ `NONE`。有意な差について多数派と平均差がともに逆方向なら `OPPOSITE`、多数派と平均差の方向が食い違えば `HETEROGENEOUS` とする。全体表示は `HETEROGENEOUS`、`OPPOSITE` の順に優先し、方向ごとの符号数・平均・判定も必ず残す。9 seed の小悪化と 1 seed の大改善を改善の再現とは数えない。

tie がない 10 seed では 8/10 同方向の両側符号検定 p=0.109375 は不足し、支持には少なくとも 9/10 が同方向である必要がある（9/10 の p=0.021484375）。tie があれば有効 n で exact test を行うため、「常に 9/10 必須」とは扱わない。

副指標: 全 30,000 更新・最後 3,000 更新の online accuracy/CE、固定 1200 枚での memo accuracy/CE、応答・位置・幅・rank。副指標による主判定の救済はしない。非有限損失の seed を除外しない。発生時はその腕の非有限以後を失敗として記録し、online accuracy 0 と CE +∞ を適用して全 seed の主判定を残す。

自己場対照群の `LRc_self − LR_self` は各窓の平均差・seed 表・bootstrap CI を副の参考として報告する。この対照群差で介入効果を割った値を「媒介率」として同定しない。

## 測定

更新 0,100,750,3000,15000,30000 に、固定 1200 枚の各層の前活性位置・幅・相対位置・p(z>0)・平均微分・微分分散、活動の effective rank を測る。raw c1 前活性と人工場の effective z を別の列に置く。

この走の幅と微分分散は固定評価集合に対する母分散（分母 N）とする。既存 engine の過去表は不偏分散（分母 N−1）を使っていたため、過去表の再現検査には元 engine の評価関数をそのまま使う。

c1 の応答は (a) 全空間位置、(b) 実際の受け手特徴の MaxPool winner 上を別に集約する。開始時は自然受け手の winner と一致することを確かめる。LeakyReLU は厳密なゼロ勾配死を持たない。`p<0.005` を記録してもゼロ勾配死と呼ばない。平均微分を実際の勾配ノルムと呼ばない。集約値に加え unit/channel 別の量を保存する。

## 実行前検査と再現性

- ソースの完全状態と各 seed checkpoint の P/m/v/step/activation 状態が一致し、課題番号 30、両履歴の label/batch generator が一致すること。
- 画像 global ID とチャネル・空間座標対応。画像順・供与者・対象層を誤らせた変異を検出すること。
- 全画像で anchor 開始時の各層特徴・pool winner・logits・CE が受け手自然と一致すること。数値差がある場合は最大差を残し、本走前に解決する。
- synthetic finite difference と autograd で供与者の φ′、受け手入力による c1 勾配、対象外層の開始時勾配を確認すること。
- 自己場と自然の開始時 forward/gradient/1-step Adam を照合する。同じ課題 31 の最初の 75 更新でパラメータ・Adam 状態・online accuracy/CE の差も記録する。2 step 以後の一致は要求せず、ここでの成績差を主走の支持・不支持には使わない。
- graph/eager、完全状態復元後の 1 step、同じ実行の再現、診断で P/m/v/step/activation/generator を変えないことを検査する。
- 元の engine と自然 forward/gradient/Adam を同じ束・同じ入力で比較する。元 GPU の保存値との一致/不一致と torch/CUDA/cuDNN/TF32 の設定を記録する。

保存された課題 30 の自然網の評価は、元 engine の chunk=20 評価で照合する。工学的な許容誤差は memo accuracy で 1/1200 以下、その他の既存指標（CE、c1 平均・幅・全位置/Pool 上の平均微分）は `abs(new-old)/max(1,abs(old)) < 1e-4` とし、bit 一致したかと実際の最大差も必ず記録する。許容を超えれば実装・数値条件を調べ、本走を止める。成績の良し悪しでこの許容値は変えない。

run の中断・再開は epoch 境界の完全状態を用いる。出力ディレクトリを排他 lock し、元 checkpoint を上書きしない。source/data/code の hash、commit、ホスト・GPU・数値設定、bundle 順序を provenance に残す。ログは epoch 単位。生データは最後に標準の archive へ移し manifest を commit する。

real checks と本走はともに、`src/`・`specs/` の未commit変更（未追跡ファイルを含む）を拒否する。親が凍結時に `登録状態: REGISTERED` を記した spec の commit を `--release` に渡し、実行中の spec とその commit の spec が同じことを要求する。合格した preflight の登録 commit・実装 commit・依存コード hash・数値環境・データ/束 identity は本走開始時に照合する。検査後にコードや数値条件が変わった場合、その合格は無効にして検査をやり直す。結果ファイルだけの commit は実装 commit を変えない。

## 読める結論と残る範囲

双方向の成績変化が確認されれば、中心化による長期予防と c1 の応答場の因果効果を同じ比較内で結べる。開始時予測を一致させても、供与者の場は微分の平均・分布・配置を同時に変えるため、単なる平均 gain と配置/非線形性の寄与は追加対照なしでは区別しない。片方向・不成立の場合も c1 という介入箇所と 1 課題窓に限って結論を出す。

非有意というだけで「c1 は原因でない」「rank が原因である」とは結論しない。10 seed の精度、固定されたチャネル対応、人工場の運転中の変化、受け手の入力処理・後段・Adam 状態が残ることを含めて解釈する。
