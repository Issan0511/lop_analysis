## 1. 問い

**入力と中間層を中心化した ReLU に bias への操作も加えると、200 課題目付近の再学習成績がどれだけ改善するか。**

旧 `ch_chb_200_0919` では、CH の t181–200 online の seed 平均は 0.52818144、CHB は 0.99042762 だった。一方、性能と深さを組み合わせた分類が同じ seed 対の9/10以上で成立することを要求し、主ラベルは `INCONCLUSIVE` となった。旧仕様・結果・判定は変更しない。今回の主結果は性能差そのもので、深さや分類の一致本数を性能差の成立条件に加えない。

既知結果の正本: `results/ch_chb_200_0919/summary.md` と `verdict.json`。元の介入・学習過程は `specs/spec_relu_doors_0919.md`、`specs/spec_ch_chb_200_0919.md`、`src/relu_doors_0919.py`。

## 2. 二つの条件と学習過程

| 条件 | 操作 |
|---|---|
| CH | 入力平均画像を引く C ＋ 両隠れ層の ReLU 出力からユニット別 EMA を引く H。bias は自由 |
| CHB | CH と同じ中心化に、元実装の B 操作（各 Adam 更新後に b1 をゼロにし、b2 に decoupled WD）を追加 |

- 元の `src/relu_doors_0919.py` を変更せず使用する。B の係数は既存値 `lambda=0.1713`、出力層 bias は自由。**元実装は b1 をランダム初期化し、最初の更新後からゼロにする**。この初回の挙動も再現し、「初期化から bias を持たない」別条件へ変更しない。
- CIFAR-10、seed ごとに固定した1200枚、課題ごとに独立一様乱数ラベル。raw画像から平均画像を引き、尺度では割らない。
- 3072–100–100–10、ReLU、float32、Adam lr=1e-3、betas=(0.9,0.999)、eps=1e-8、重みへの WD なし。H の EMA 係数は元実装の0.01、勾配を通さない。
- 200課題、各400 epoch ×75 step =30,000更新、batch16。全過程を課題1から新規実行する。
- **seed 10–19の10本**。旧追試のseed 0–9と重ならない。研究全体で未使用とは主張しない。この条件・予算でのseed 10–19の結果は設計に用いていない。
- 同じseedの初期重み、画像集合、ラベル乱数、標本順を両条件で対応させる。各条件10 seedを元実装と同じ方法で束ね、CH→CHBの順に逐次実行する。
- n=10は元の実験との反復数・計算予算の一致を優先した選択であり、事後に必要な支持本数へ達するまでseedを追加しない。精度・検出力が事前に保証された標本数とはしない。
- 実行中の別実験へ競合するGPU負荷を追加しない。利用可能になってから検査・本走を開始する。GPU空き確認は5分以上の間隔とする。

## 3. 主結果: 最後の20課題の性能差

`online_acc` は、各課題30,000更新について、その更新前のミニバッチargmax正解率を平均した量である。乱数ラベルへの学習過程の成績を測り、自然なCIFAR分類の汎化精度や課題終端の正解率とは区別する。

各seed s、条件 aについて、`W[a,s] = mean(online_acc[a,s,t], t=181..200)` を計算し、対応差 `d[s] = W[CHB,s] - W[CH,s]` を作る。

**主推定値は10本の対応差の平均。95%信頼区間は `mean(d) ± t(9,0.975) * sample_sd(d)/sqrt(10)`。** float64で集計し、正解率とpercentage pointsの両方で報告する。標本SDが厳密にゼロなら一点区間とする。独立反復の単位はseedであり、200課題を200個の独立標本に数えない。t区間はseed間の差についての近似推論で、正規性を保証しない。

結果本文は最初に「CHは何%、CHBは何%、差は何pt［95%区間］」と書く。対応差全10本、正負・ゼロの本数、両条件の平均・中央値・最小・最大も併記する。

- 区間下端が0より大きい: 「CHBの後期成績がCHより高いことを支持する」。
- 区間上端が0より小さい: 「CHBの後期成績がCHより低いことを支持する」。
- それ以外: 「この反復数では差の方向を確定できない」と区間付きで記す。効果が無い・同等とは書かない。

この推論上の文は数値の代わりに置かず、結果全体を単一の `INCONCLUSIVE` ラベルで表さない。実用上の最小効果量・同等性幅は今回指定されていないため、後から閾値を足して「十分な改善」「同等」「治癒」を判定しない。
