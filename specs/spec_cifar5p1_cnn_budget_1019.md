# cifar5p1_cnn_budget_1019 — 実ラベル 5+1 CIFAR の CNN で課題あたりの学習予算を延長する

依頼: Issa の意向「実ラベル CNN で幅が成長する条件を調べ、沈降・応答低下・可塑性喪失の関係を追う」を受けた、12 腕比較のセッションへの続きの依頼（Issa 経由）。
前段: `specs/spec_neokunekune_methods_cifar5p1_cnn_1018.md`（登録 `170beea5`）、結果 `results/neokunekune_methods_cifar5p1_cnn_1018/main/`（main `1928e4a1`）、vault の結果ノート `測定/Neokunekune_手法比較12腕_5p1CNN_結果_1018.md`。

## 1. 問い

前段では、課題 2 → 30 で FC2（f2）の幅が伸びていた。固定 probe での unit 幅の中央値は、ELU 1.09 → 6.69、KKT1 1.94 → 5.17、SNAfrz1 1.65 → 4.40 だった。本走は、課題あたりの更新数を延ばしたとき次の 4 点がどうなるかを測る。

1. 幅は伸び続けるか。
2. 位置 r = m/s は負側へ動くか。応答（入力平均の φ′）は下がるか。
3. 新品の網（fresh）との差はどうなるか。
4. 活性化でどう違うか。

- 予算延長は幅だけを操作する介入ではない。更新数・当てはめ・Adam の状態も同時に変わる。この走だけで幅の因果効果が確立したとは扱わない。
- 既に見た seed 2000〜2009 の延長である。独立した新規 seed での追試とは呼ばない。
- 今回の実行範囲は、この予算比較までとする。cap や応答の交換は行わない。

## 2. 箱

前段 §2 の箱をそのまま使う。CIFAR-100 fine label・チャネル標準化・30 課題（奇数 hard 5 クラス × 500 枚、偶数 easy 1 クラス × 500 枚、90 クラス再訪なし）・出力 100・RC CNN（c1 c2 f1 f2 の 4 site、全層 bias）・Adam（β1 .9、β2 .999、ε 1e−8、bias correction あり、課題間で状態を継続）・batch 32・float32・AMP なし・TF32 なし・決定的アルゴリズム。初期化（`init`、CPU）・クラス列（`c51_classes`）・probe（`neo_c51_probe`、20 枚 × 100 クラス）は前段の関数をそのまま使う。

実装は前段のモジュール（`src/neokunekune_methods_cifar5p1_cnn_1018.py`、`src/neokunekune_cifar5p1_cnn_1018.py`）を import して継承し、改変しない。

## 3. 腕と予算

| 腕 | 中身（前段の定義） | lr |
|---|---|---|
| R | ReLU | 3e−4 |
| ELU | ELU(α = 3.6) | 3e−4 |
| KKT1 | 従来の kunekune（適応 α、c 0.6） | 3e−4 |
| SNAfrz1 | 適応 Snake。各条件の課題 1 末で α と V を unit・channel ごとに固定 | 3e−4 |

- lr は全腕 3e−4。前段の較正（seed 100〜102）で 4 腕それぞれに選ばれた値である。予算ごとの再較正はしない。
- 予算は 780・2340・7800 更新／課題の 3 条件。hard・easy の両方を延ばし、30 課題、seed 2000〜2009 で回す。
- SNAfrz1 は元の定義どおり、各条件の課題 1 の最後の更新の後で固定する。予算で固定時の α が変わるので、その値（site ごと・unit ごと）を条件ごとに保存する。
- 1 条件 = 4 腕 × 10 seed = 40 run を、R = 40 の束 1 つで回す。束の並びは腕優先・seed 昇順。

## 4. 課題列と batch 列

- 同じ seed では、全腕・全予算でクラス列と初期値を共有する。
- 課題 t の batch 列は 2 つの部分からなる。
  - 最初の 780 batch は、前段と同じ `c51_batch` stream を課題 1 から順に消費して作る（`cifar5p1_mlp_0920.batch_indices`、1 課題あたりの消費量は予算によらない）。
  - 781 番目以降は、課題ごとに独立な stream `H.stream("c51_budget_ext|t<t>", seed)` から同じ関数で作る。
- このため、短い予算の batch 列は長い予算の batch 列の prefix になる。予算を変えても、後続の課題の乱数列はずれない。780 予算の batch 列は前段とビットで一致する。
- 全予算・全課題の batch 列は訓練前に確定し、各 (seed, 予算, 課題) の sha256 を保存する。

## 5. 測るもの

### 5.1 固定 probe での幅・位置・応答

固定 probe（前段と同じ 2,000 枚）で、4 site の各 unit・channel について次を求める。主に見る層は FC2（f2）で、他の 3 層は補助とする。

| 量 | 定義 |
|---|---|
| 平均 m | 前活性 z の平均。conv は画像 × 位置で平均 |
| 幅 s | z の母 SD。conv は画像 × 位置での SD。conv は位置内の SD・位置間の SD も併記 |
| 相対位置 r | m / s（s = 0 は未定義として数える） |
| 入力平均の局所微分 φ′ | φ′(z) の平均。前段の dmean |
| 正側占有率 p⁺ | z > 0 である標本の割合。conv は画像 × 位置で数える |
| 死 | φ′(z) の probe 上の最大が 1e−6 未満（前段の宿主の DEAD_TOL）。4 腕とも φ′ ≥ 0 |
| 低応答 | 入力平均の φ′ が 0.1 未満。本 spec で定める |
| 出力 0 | 活性 a の probe 上の最大 |a| が厳密に 0（前段の zeroout） |
| 実効ランク | site の活性の Gram 行列から求める前段の eff_rank（conv はチャネルを列にする） |

- 測る時刻は、初期状態と、各課題の最後の更新の後（境界 b = 0, 1, …, 30）。probe は課題によらないので、課題 t の開始前の状態は境界 t − 1 の状態と同じである。SNAfrz1 の固定は α の値を変えないので、境界 1 の値は固定の前後で同じになる。
- 課題 t の開始前と終了後には、その課題の訓練画像でも同じ量を求める（新しいクラスが既存の unit のどこに落ちるかを見る）。
- unit ごとの値をすべての境界で保存する。層の集約は unit の中央値と四分位で、統計は float64 で集める。中央値どうしの積から m を復元しない。
- 診断は重み・Adam・適応 α の状態を変えない（検査 S-pure）。

### 5.2 online・test・fresh

- 各課題で、更新前 online 精度を 3 通りに集計する。最初の 100 更新、最初の 780 更新、課題全体。780 予算では最初の 780 更新と課題全体が同じになる。
- 課題末の train 精度と、その課題のクラスの test 精度を残す。予測は 100 出力の argmax のまま。
- 課題 9・19・29 に fresh 対照を置く。fresh は同じ課題・同じ batch 列・同じ予算で、初期値・Adam 0・更新番号 0・V = 1・未固定の状態から学習する。SNAfrz1 の fresh は、その課題が最初の課題なので、課題の間ずっと通常の適応 Snake として動く。固定は課題の終わりにしか起きないので、fresh の学習には入らない。
- fresh − 継続の差を、課題全体・最初の 780 更新・最初の 100 更新の online と、test 精度で求める。

### 5.3 保存する checkpoint

次の介入（cap・応答の交換）に使えるよう、各条件で次の完全な状態を保存する。完全な状態とは、重み・Adam の m と v・更新番号・活性化の状態（V・α・固定の有無）・設定である。

- 初期状態（境界 0）。
- 課題 1 末（SNAfrz1 の固定の後）。
- 課題 9・19・29 の開始前（境界 8・18・28）と終了後（境界 9・19・29）。
- 課題 30 末（最終状態）。

## 6. 登録する比較と読み

主量はすべて後期 hard 課題 t = 21, 23, 25, 27, 29 の seed ごとの平均で、比較は同じ seed の予算間の対応差である。

| 族 | 量 | 比較 |
|---|---|---|
| F1 学び直し能力 | 最初の 780 更新の online | 予算 B − 780、B ∈ {2340, 7800}、4 腕 |
| F2 長く学習した分 | 課題全体の online | 同上 |
| F3 fresh との差 | 課題 29 の fresh − 継続（課題全体の online） | 同上 |
| F4 FC2 幅 | 境界 30 の FC2 幅（unit の s の中央値）の log | 同上 |

- 各族 8 比較で、seed の percentile bootstrap（20,000 回、NumPy の `default_rng(1019)` から `integers(0, 10, size=(20000, 10))` で作った 1 つの添字行列を全比較で共有）を使う。族ごとに Bonferroni で両側 1 − 0.05/8、分位点 0.003125 と 0.996875。
- ラベルは、下端 > 0 で `HIGHER`、上端 < 0 で `LOWER`、それ以外は `INCONCLUSIVE`。端が 0 と等しいときは満たさない。
- 記述（判定ではない、95% 区間）: 最初の 100 更新の online、test 精度、課題 9・19 の fresh − 継続、FC2 と他 3 層の幅の課題内の伸び（log s(境界 30) − log s(境界 2)）、r・φ′・p⁺・死・低応答・出力 0・実効ランクの境界ごとの軌道、SNAfrz1 の固定時の α。
- 読みの規則（実行前に固定）:
  - ①「幅の継続成長」: F4 の 7800 − 780 が `HIGHER` で、7800 の課題内の伸びの 95% 区間が 0 より上。
  - ②「負側への位置変化と応答低下」: 境界 30 の FC2 の r の中央値と φ′ の中央値について、7800 − 780 の 95% 区間がともに 0 より下。記述の読みで、確認的判定ではない。
  - ③ fresh との差: F3 のラベル。
  - ④ 活性化の違い: 腕の間の記述。
  - ELU が ① を満たし、F1 が `LOWER` でなく、課題 29 の fresh − 継続（7800）の 95% 区間が 0 より下、FC2 の死が 0 なら、「ELU は幅の成長後も健全」と結論に残す。
  - 次の介入の候補: ① を満たし、かつ F1 `LOWER`・F3 `HIGHER`・② のいずれかを満たす (腕, 予算) を「幅の成長と可塑性・応答の低下が同居する条件」として記録する。
- 全 run の完走が前提。欠けのある (腕, 予算) を含む比較は `INCOMPLETE`。
- 780 予算は前段の 12 腕本走と同じ計算になるはずである。本走で再計算し、前段の `per_task.csv` の 4 腕の共通列（online・train / test・switch CE 等）とビットで一致することを **S-reuse-780** として確かめる。一致すれば前段と同一の軌道として扱い、本走はそこに欠けていた測定（課題 9・19 の fresh、p⁺・死・低応答・出力 0・実効ランク、課題開始前の訓練画像の統計、境界ごとの unit 値、checkpoint）を足したものになる。一致しなければ FAIL と記録し、本走の値で集計する。

## 7. 実装と検査

新しいモジュール `src/cifar5p1_cnn_budget_1019.py` が前段の `MethodsEngine` を継承し、batch・記録のバッファを予算の長さにする。診断は前段の `unit_stats` に p⁺・φ′ の最大・|a| の最大・Gram を足した関数で行う。

検査（各検査に、わざと壊した変異を付けて検出を確かめる）:
- **S-prefix**: 780 予算の batch 列が前段とビットで一致する。2340 の列は 7800 の列の、780 の列は 2340 の列の prefix である。予算を変えても全課題の最初の 780 batch が同じである。行が課題のクラスに属し、延長部分も permutation の連結である。
- **S-engine-780**: 予算 780 の新しいエンジンが前段のエンジンと、同じ slot・同じ batch でビット一致する。
- **S-stats**: 新しい統計（p⁺・死・出力 0・実効ランク）を独立に書いた float64 の参照と照合する。
- **S-pure**: 診断が重み・Adam・α・V・記録を変えない。
- **S-freeze**: SNAfrz1 の α と V が課題 1 の後に変わらず、保存した固定時の α と一致する。
- **S-graph**・**S-resume**・**S-fresh**: CUDA graph と eager の一致、途中で止めて再開した場合の一致、fresh が初期状態から同じ batch 列で学習すること。
- smoke は seed 9000・9001、最初の 2 課題、3 予算で行い、計時に使う。性能の根拠にはしない。
