# 幅 × 正規化の 2×2 — 2 つの箱の食い違いの残り 2 候補を切る

状態: 事前登録（2026-09-20、本走前・判定値は未観測）。
親: [spec_randlabel_joudaki_vit_0919.md](spec_randlabel_joudaki_vit_0919.md)。設定はすべて継承する。

## 1. ここまでに潰れたもの

`relu_doors_0919`（3072-100-100-10 MLP・正規化なし・ランダムラベル CIFAR）では ReLU が窓 .113 まで崩壊する。
`joudaki_vit_battle_0919` では崩壊しない。違いは 4 つあり、うち 1 つが決着した。

| 候補 | 状態 |
|---|---|
| **ラベル** | **棄却**。ランダムラベルにしても窓 .940・fresh gap −.261・早期−後期 −.062。3 つとも喪失の逆向き |
| **幅** | 残存 ← 本 spec の因子 1 |
| **正規化** | 残存 ← 本 spec の因子 2 |
| データ（CIFAR / Tiny ImageNet） | 未検証 |

## 2. 設計

ランダムラベルセルから**2 因子だけ**動かす。他はすべて同一（腕 `R`・seed0–9・40 タスク × 500 更新・
1 タスク 250 枚・iid uniform ラベルを毎タスク引き直し・同じ画像集合・バッチ順・拡張・
Adam 1e−4・float32・TF32 無効・compile + fused Adam・head リセット）。

| | hidden 1536 | hidden 96 |
|---|---|---|
| **LN あり** | **実施済み**（窓 .940・gap −.261） | **W** |
| **LN なし** | **N** | **WN**（`relu_doors_0919` の組み合わせ） |

- 幅は `mlp_ratio` 4.0 → 0.25（FFN hidden 1536 → 96、MLP 箱の 100 に対応）
- 正規化は `normalization` `'layer'` → `'none'`（上流の `get_normalization` が norm1・norm2・最終 norm の
  3 か所すべてを `nn.Identity()` にする）
- **発散は記録し、例外で走を落とさない**。LN なしは発散しうる。発散は「崩壊」ではないので別ラベルにする

## 3. 判定（値を見る前に固定）

各セルについて、ランダムラベルセルと同一の 3 つを取る:

- **G（主判定）**: `fresh_gap = fresh(t40) − continual(t40)` の 10 seed 中央値が **> 0**
- **C**: 窓（t21–40）の中央値が **< .5**（崩壊）
- **D**: 早期（t1–10）− 後期（t31–40）の中央値が **> 0**（単調劣化）

読み替え:

- **W だけで G > 0** → **幅が lever**。`transport_holes_0910`（「ReLU でも lever は幅」）と整合
- **N だけで G > 0** → **正規化が盾**
- **WN でだけ G > 0** → **両方が同時に要る**（交互作用。どちらの主効果でもない）
- **どれも G ≤ 0** → 幅でも正規化でもない。残るのはデータか、まだ挙げていない因子

## 4. 却下した設計と、その理由（記録）

**「250 枚 / 384 次元 = 0.65 なので head だけで解けてしまい、body が適応しなくてよいのでは」**
という懸念を立て、本走前に検証した。body を初期値のまま凍結し head だけ学習させた結果:

| 枚数 | 枚数/384 | body 凍結・head のみの暗記率 |
|---|---|---|
| 250 | 0.65 | **.308** |
| 2500 | 6.51 | .231 |

点数が次元より少なくても解けない。**未学習 ViT の CLS 特徴は一般の位置に無く**（token がほぼ同じ表現に潰れ
実効ランクが 384 より遥かに低い）、点を数える議論は成り立たない。
よって 250 枚でも **body は実際に働く必要があり**、親 spec §2.1 の較正は難しさを消していない。
`mlp_ratio` が head の読む次元（384）を変えないことは事実だが、上記より本 spec の設計は維持する。

## 6. 結果（2026-09-20）

| セル | 窓(t21–40) | C 崩壊 | 早期−後期 | **G fresh gap** | G>0 | 発散 |
|---|---|---|---|---|---|---|
| 1536 / LN あり（親） | .9402 | 0/10 | −.0615 | **−.2609** | 0/10 | 0 |
| **W** 96 / LN あり | .9298 | 0/10 | −.0809 | **−.2783** | 0/10 | 0 |
| **N** 1536 / LN なし | .2481 | 6/10 | +.3432 | **+.3004** | 6/10 | 0 |
| **WN** 96 / LN なし | .3199 | 8/10 | +.4973 | **+.2280** | 9/10 | 0 |

登録した読み替えに従えば **「N だけで G > 0 → 正規化が盾」**（W は出ず、N と WN で出た）。

### 機構（副次読み出し・記述）

task40 の 6 層平均:

| セル | `z<0` 質量 | **完全死 channel** |
|---|---|---|
| 1536 / LN あり | .736 | **.0005** |
| W 96 / LN あり | .589 | **.0000** |
| N 1536 / LN なし | .739 | **.2764** |
| WN 96 / LN なし | .569 | .1007 |

**疎化の量は同じ（.736 対 .739）なのに死は 550 倍違う。**
LN は疎化を減らしていない。疎化が **channel ごとの恒久的な死**に変わるのを防いでいる。
原典 §4 の "keep activations operating in their more dynamic, non-linear range" が、
独立に組んだ箱で再現された。

**幅は死を作らない**（16 分の 1 にして死 0）。ただし **死をどれだけ許容できるかは決める** —
WN は死 .101 と N の .276 より少ないのに崩壊は 8/10 対 6/10 と多い。

### 登録後に得た情報（予測は動かしていない）

予測を書いた**後**に原典 Appendix B を読み、以下が判明した:

- **プロトコルは完全一致**。"a sequence of 40 tasks, each containing a disjoint subset of 5 classes.
  **Each task is trained for 500 steps** ... resulting in 20,000 total training steps"（B.1.1）。
  ViT 既定も patch8/dim384/depth6/heads6/**mlp_ratio 4.0**/**LayerNorm**/**dropout 10%**、
  **lr は ViT だけ 1e−4**（B.1.3）。**露出量は交絡ではなかった**
  （姉妹 MLP 箱の 30,000 更新/タスクは原典ではなく `spec_rlcifar_mlp_battle_0918` の設計判断）
- **原典自身が「正規化が LoP を防ぐ」と主張している**（§4 Preventing LoP with Normalization、
  Fig B.3「Normalization reduces the number of dead/saturated units」、
  Fig B.5「without normalization and no dropout」）。
  よって **LN 付き ViT で LoP が出ないことは原典と矛盾しない**

Claude はこれを読む前に「原典の LoP を再現しなかった」と述べたが、**これは誤り**だった。
Fig 3.1 の "depending on the architecture" と Fig B.5 の "without normalization" を読み落としていた。
原典を再現しなかったのではなく、**原典が予測するとおりの結果が出ていた**。

残る差: 原典の LoP 図は "no normalization **and no dropout**" だが、本 spec の N/WN は dropout .1 を残している。
