## 1. 問い

`boundary_dense_0907` で、1 タスクの沈下 −0.0116 のうち **バイアス b が運ぶのは 17% だけ**で、残りは「w_flip の整列 A」だと分かった。Random Label MNIST の事後解析（[[RandomLabelMNIST前活性_事後_0907]]）でも、実効バイアス b_eff = b + w·x̄ が沈む一方、等方的な w の成長で説明できるのは沈下の **14% が上限**だった。

そこで Issa の指摘: **w·µ は b と同じ役割をしている**。ならば「w がシフトしている」は機構の名前ではなく、**どの向きにシフトしているか**を測らないと中身が無い。

> **蓄積した Δw_flip は「入力の一定成分の向き」に乗っているのか（＝実効的に 15 本の余分なバイアス）、それとも「そのタスクのパターン固有の向き」に乗っているのか。**

## 2. この箱で厳密に成り立つ幾何（仮定ではなく実装から導かれる事実）

`target_mu_norm = 3.041` の腕では、中心化は EMA ではなく**解析的な一様オフセット**である（`dose_const_5m._refresh_fixed_offset`）:

  x_centered = x − 0.5·γ(k)·**1**,  k = Σ flip_state,  γ = ((k+2.5) − √((k+2.5)² − 20(k+1.25) + 20·3.041²)) / 10

γ は k にしか依存しないので、**タスク内で厳密に定数**。したがって:

**(G1) タスク k の flip 側の実効入力は定ベクトル** u_k ≡ x̃_k − 0.5γ_k·**1**₁₅ （x̃_k ∈ {0,1}¹⁵）

**(G2) タスク内の Δw_flip は u_k に厳密に平行**（rank-1）。
  ∂L/∂w_flip = g·u_k で u_k はタスク内定数なので Δw_flip = (−lr Σ_t g_t)·u_k ≡ Δc_k·u_k。
  → `boundary_dense` が残した confound「A は Δw か running-mean の追随か」は、**この箱では追随項が恒等的に 0**。本走で実測して確定させる（§4 の S 検査）。

**(G3) z̄ の厳密な 3 分解**（z̄ は 32 点厳密支持上の平均）:
  **z̄ = b + w_flip·u_k + m_k·Σ_j w_free,j**,  m_k ≡ 0.5(1 − γ_k)
  第 3 項は自由 5 ビットの平均が 0 でないことから来る。`layer1_w_free` は既に記録済みなので、3 項すべてが実測から出る。

**(G4)** u_k = 0.5(1−γ_k)·**1** + f_k,  f_k ≡ x̃_k − 0.5·**1** ∈ {±0.5}¹⁵。
  第 1 項は**タスクが変わっても向きが変わらない**（全 1 方向）。第 2 項だけがパターン固有。
  各タスク境界で反転するのは 15 ビット中 **ちょうど 1 本**なので、f_k の相関時間は τ ≈ 7.5 タスク。

**(G4) が問いの答えの形を決める**: Δw_flip = (Σ_k Δc_k)·0.5(1−γ)·**1** + Σ_k Δc_k f_k。
第 1 項は Δc_k がすべて同符号（沈下）なので **タスク数に比例して伸びる**。第 2 項は f_k が脱相関するので **√タスク数**。したがって十分先では全 1 方向が勝つ——**それが「w のシフト＝実効バイアス」の定量版**である。本走はその比を測る。

## 4. 判定

CI は **seed ブートストラップ 2000・`rng(20260907)`**。統計は「ユニット×seed の中央値」を seed 方向にブートストラップする。

### 主判定 `WFLIP_ALIGN` — 蓄積した重み変化はどの向きか

Δw_flip(k) ≡ w_flip(k) − w_flip(0) について、**全 1 方向の分散寄与率**

  **s_k ≡ (Δw_flip(k)·1̂)² / ‖Δw_flip(k)‖²**,  1̂ = **1**₁₅/√15

を タスク k=199 で取る（`WSref_1216`）。

- **`BIAS_LIKE`**: s の CI が全部 **0.7 より上** → シフトは実効バイアスそのもの（15 本の余分な bias）
- **`PATTERN_LIKE`**: CI が全部 **0.3 より下** → パターン固有の向きに貯まっている
- **`MIXED`**: CI が 0.3〜0.7 に収まる
- **`NOT_DETERMINED`**: CI が上の 3 つのどれにも収まらない、**または効果量の床**を割る:
  **床** = ‖Δw_flip(199)‖ の中央値が ‖w_flip(0)‖ の中央値の **0.5 倍未満**（＝そもそも動いていない）

> ランダムな 15 次元ベクトルなら s ≈ 1/15 = 0.067。`PATTERN_LIKE` はそれに近い側。

### 第 2 判定 `J_SOURCE` — タスク境界の戻り J は何が運ぶか

J（境界での z̄−b の跳び・`boundary_dense` で E[J] = +0.00778 と実測）は、§2 から**厳密に 3 項**に分かれる:

  J = **[ビット項] ±w_flip,i** + **[γ-flip 項] −0.5Δγ·Σw_flip** + **[γ-free 項] −0.5Δγ·Σw_free**

（i は反転したビット。符号は 0→1 で +、1→0 で −。）3 項の窓内平均の**符号付きシェア**を出し、E[J] の何割を運ぶかで:

- **`BIT_CARRIED`**: ビット項が E[J] の **70% 以上**
- **`GAMMA_CARRIED`**: γ 2 項の和が **70% 以上**
- **`MIXED`**: それ以外
- **`NOT_DETERMINED`**: |E[J]| の CI が **0.003/タスク**（床・実測 0.0078 の 38%）を跨ぐ、または 3 項の和が実測 J と 1% を超えてずれる

> `GAMMA_CARRIED` なら、45% の戻りは物理ではなく**用量固定の設計が作った一様シフトの副作用**であり、他の箱に持ち出せない。これは判定を分ける実質的な違いなので主判定と別に立てる。過去に一様シフトで 4 回刺されている（`b+2`・`edge_law` の ±5/±4・`smooth_kink` の s=3・`act_offset` の c=±2）。

### S 検査（**すべて変異対照つき**——空虚な S 検査は通算 6 回目を出さない）

| 名前 | 内容 | 変異対照（これが**落ちる**ことを実測する） |
|---|---|---|
| **S-null** | `WSref_1216` の `state_hash` が `offset_grid_0906/logs` の `LRoff0_1216` と一致 | 1 ユニットの `w_flip` を +1e−6 ずらした記録を作ると hash が**外れる** |
| **S-rank1** | タスク内 Δw_flip の u_k 直交成分の割合 `r = ‖Δw_⊥‖/‖Δw‖` が **< 1e−5**（float32 の丸め） | 同じ比を **u_k の 1 ビットをずらした u′** で測ると **> 0.1** |
| **S-zbar** | §2 (G3) の 3 分解の残差 \|z̄ − (b + w_flip·u + m·Σw_free)\| が \|z̄\| の **1e−5** 未満 | m を 0 にすると残差が **1e−2 を超える** |
| **S-J** | 3 項の和が `boundary_dense` の J と一致（相対 1e−4） | γ 2 項を落とすと **1% を超えてずれる** |

S-rank1 が落ちたら (G2) が壊れているので、**主判定を出さずに止める**（`boundary_dense` の A の解釈もそこでやり直し）。

## 5. 予測（結果を見る前に記入）

- **Claude・主判定**: `BIAS_LIKE` **65%** / `MIXED` **25%** / `PATTERN_LIKE` **5%** / `NOT_DETERMINED` **5%**。
  **数値予測 s ≈ 0.93**。根拠: §2 の帳簿で Δc_k = A_k/‖u‖²_flip = −0.0174/7.87 = −0.00221/タスク、190 タスクで全 1 成分の長さ = 190·0.00221·0.524·√15 = **0.85**、パターン成分は τ≈7.5 の乱歩で 0.5·√15·0.00221·√(190·2·7.5/15)… ≈ **0.23**。s = 0.85²/(0.85²+0.23²) = 0.93。床（‖Δw_flip‖ ≈ 0.88 対 ‖w_flip(0)‖ ≈ 1.22 の半分 = 0.61）も通る見込み。
- **Claude・第 2 判定**: `BIT_CARRIED` **45%** / `MIXED` **35%** / `GAMMA_CARRIED` **15%** / `NOT_DETERMINED` **5%**。
  根拠: ON のビットは u_k,i = 1.02、OFF は 0.024 で **42 倍**の速さで整列するので、「今 ON のビット」の w は「今 OFF のビット」より負に深い。1→0 の反転は深い負を外す（J>0 大）、0→1 は浅い負を入れる（J<0 小）——この非対称だけで E[J] ≈ +0.008 のオーダーが出る（実測 +0.0078）。γ 2 項は 1 回あたり ±0.16 と**桁で大きいが符号が半々**なので平均には残りにくい（ただし分散は支配するはず）。
- **Claude・S-rank1**: `< 1e−5` **90%**（残り 10% は float32 の累積誤差が閾値を超える場合。落ちたら閾値でなく (G2) を疑う前に dtype を確認する）。

## 8. 追補 1（実装中・**結果を見る前**に登録）

検査 `src/test_wflip_split_0907.py` が §4 の S 検査の**数値**の欠陥を 3 つ捕まえたので、走らせる前に直す。判定のラベル定義・効果量の床・予測は**一切変えない**。

### 8-1. S-rank1 の推定量を「差の平方根」から「直交射影の直接計算」へ

登録時は r = √(‖Δw‖² − (Δw·û)²)/‖Δw‖ のつもりだったが、これは Δw が u に平行なとき桁落ちする。**直交射影を直接引いた** r = ‖Δw − (Δw·û)û‖/‖Δw‖ に変える（同じ量の、条件数の良い計算）。

検査で実測した差（ユニットごとに Δc が違う現実的な形・float64）: 直接射影 **< 1e−12**、差の平方根 **> 1e−9**。行が全部同じなら差の平方根は厳密に 0 になるので「常に悪い」は偽——**悪化するのは係数が混ざる実データの形のときだけ**、と実測した上で記録する。

### 8-2. `rank1_max` を 1e−5 → **1e−4**

**登録した閾値は、正しい実装でも数値的な理由で落ちる。** 重みは float32 で記録され、1 タスクの ‖Δw_flip‖ ≈ 0.006 に対し ‖w_flip‖ ≈ 1.2 で**比が約 190** なので、差を取った時点で相対誤差が入る。実走の規模で厳密に平行な増分を float32 に丸めて読み戻すと

  r の中央値 **6.8e−6** / 最大 **1.7e−5**

で、登録した 1e−5 を最大値が超える。閾値を **1e−4** にする（床の 6 倍・変異対照 0.1 の 1000 分の 1 なので、検査の切れ味は変わらない）。検査 `test_rank1_float32_floor_is_below_the_registered_tolerance` が、床が 0 でないこと（1e−7 超）と閾値を下回ることの両方を実測する。

### 8-3. S-zbar の分母を |z̄| → **max(|z̄|, 1)**

z̄ ≈ 0 のユニットで相対残差が発散し、中央値でしか意味を持たない量になっていた。スケールで割る形に変える。閾値 1e−5 と変異対照 1e−2 は据え置き（float32 の床は 3e−7 程度）。

### 8-4. `j_rel` を 1e−4 → **1e−2**

実測 J = [z̄−b](t0+1) − [z̄−b](t0) は境界の**後の 1 step の学習を含む**。一方 §4 の 3 項分解はタスク終端に記録した w から作る純粋な幾何なので、両者の差の下限は 1 step 分の整列 ≈ A/10,000 = 1.7e−6/タスク ＝ E[J] = 0.0078 の **2.2e−4**。1e−4 では**設計上必ず落ちる**。1e−2 にする（下限の 45 倍・γ 項を落とす変異対照は 10% 規模で外れる見込みなので分離は保たれる。実際の分離は結果に数値で書く）。

> **この 4 点はすべて「量の定義と数値の床」であって、ラベルの境界（0.7 / 0.3 / 0.7）と効果量の床（0.5 / 0.003）と §5 の予測は変えていない。**

## 9. 追補 2（preflight 後・**判定値を見る前**に登録）— S-rank1 を相対値でやめる

preflight（30,000 step・seed 0/1・本走の腕と同じ設定）で S-rank1 の**最大値が 0.019** に出た。切り分けたところ、**(G2) の破れではなく、これは検査の形が間違っている**と分かった。

**診断**（`results/_preflight_wflip_split_0907/`）:

| ‖Δw‖ の五分位（seed 0） | 2.9e−3 | 1.1e−2 | 3.7e−2 | 9.8e−2 | 2.0e−1 |
|---|---|---|---|---|---|
| r = ‖Δw_⊥‖/‖Δw‖ | 7.7e−4 | 1.8e−4 | 7.5e−5 | 2.3e−5 | 1.0e−5 |
| **‖Δw_⊥‖（絶対値）** | **2.0e−6** | **1.9e−6** | **2.8e−6** | **2.4e−6** | **2.2e−6** |

- **log r 対 log‖Δw‖ の傾き = −0.981（seed 0）/ −1.022（seed 1）。** 記録精度なら −1、本当の破れなら 0。
- 歩幅 ‖Δw‖ が **69 倍**動く間、直交残差の**絶対値は 2.3e−6 で一定**。

つまり r は「平行かどうか」ではなく「そのユニットがどれだけ動いたか」を測っている。**登録した相対値の閾値は、量として ill-posed だった。**

**訂正した S-rank1**: 直交残差を**丸めの雑音で規格化**した

  **ρ ≡ ‖Δw_⊥‖ / (eps₃₂ · ‖w_flip‖)**

を使う（eps₃₂ = 1.19e−7）。判定は**中央値**で:

- **PASS**: median(ρ) < **100** かつ 変異対照（u を 1 ビットずらす）の median(ρ) > **1000**
- preflight 実測: ρ = **15.9 / 16.5**（最大 63.4 / 44.9）、変異対照 **86,518 / 147,556** → **分離 5,400 倍**で PASS

床が 16 であって 1 でないのは、記録の丸めだけでなく **1 タスク 10,000 step ぶんの float32 演算の丸めが乗る**ため（合成データで記録の丸めだけを与えると ρ ≈ 0.3 に下がることを検査で実測）。

**追補 1 の 8-2（`rank1_max` = 1e−4）はこの追補 2 が置き換える**。8-1・8-3・8-4 はそのまま。ラベルの境界・効果量の床・§5 の予測は**やはり変えない**。

> 教訓: **比を検査に使うときは、分母が判定と無関係に動かないことを先に確かめる。** 今回は分母（歩幅）が 69 倍動いていた。`drift_law` の「符号が変わる量に log–log」と同じ型の設計ミスで、**preflight が捕まえたので結果を見る前に直せた**。
