## 0. 一行

RL-CIFAR × MLP（raw）で第1層 × 第2層 = {leaky .1, ELU, GELU} × {leaky .1, ELU} の **6 セル（＋参照 GG）× 10 seed × 50 タスク**を回し、

### 1.2 なぜこの腕・この箱（起案文の理由をそのまま）

3 型（順当な沈下・第1層の死・学んでから崩れる）が同じ箱・同じ入力条件で同時に見えるのは raw だけ。層ごとに活性化を替えるのは、どちらの層が何を決めるかを**介入で**分ける最小の操作。バトルのエンジンをそのまま使え、腕の数はバトルの半分以下。

### 1.3 起案文から直す 5 点

1. **leaky 層の Q は恒真 0 なので、起案文 H1 の前半は外れようがない。** leaky .1 の |φ′| は 0.1 か 1 で、閾値 1e−6 を下回らない。A6 の実測でも `LR`/raw は両層・t0–t10 すべて 0.0000（§1.1 の表）。起案文の「X→leaky は第2層が低応答過半に達しない」は**データが何であっても真**で、空虚な検査の 7 回目になる。→ **層の沈下は活性化を跨いで比べられる量で測り直す**（§4.2 の p⁺ と d）。A6 の規則そのままのラベルは副として残し、構成上決まるセルには `BY_CONSTRUCTION` を付ける（§5.3）。
2. **床の閾値はこの箱では死活を分けない。** ラベル引きの最良定数予測器から導いた床（§5.1 の F + 3s/√20、seed 別に 0.11535–0.12070）に対し、明らかに死んでいる `SILU`/raw の窓は **10/10 seed で床の上**（0.1187–0.1270）、`GELU`/raw も 1 seed（seed 6・0.1183）が上に出る。→ 死活の主ラベルは**親バトルの登録規則「窓 < 0.5」を継承**し、床は 3 段の下端として併用する（§5.1）。MNIST のキメラが使った「床 + 3s/√n」だけでは、この箱の死を取りこぼす。
3. **raw の「第2層の死」は名前を変える。** A6 では raw の ELU→ELU は `L1_FIRST`（T\*=1・10/10）で、第2層の Q が過半を越えるのは t2。t1 の online は 0.826 で学べている。raw で EE を「第2層の死」と呼ばない。第3の型は**時間の形**で定義する（**t1 は学べて後で崩れる** = `LEARNS_THEN_DIES`）。「第2層が先に低応答化する」列は std にある（A6: `L2_FIRST` 10/10）が、**std はこの走に載せない（Issa の決定・0922）**。raw の 3 型は時間の形だけで定義する。
4. **‖µ₂‖ は act1 を跨いで水準を比べない。** µ₂ = mean_x a₁ の尺度は第1層の活性化で変わる。登録するのは **EE 対 EL**（act1 が同じ ELU）と、**GL・GE の自分の t00 との比**だけ（§5.4）。
5. **raw のみ・R=10 で回すので、親バトルの保存結果（R=20・raw+std）とは bit で並ばない。** S2 の教訓「同じエンジンでも束ねる模型数 R が違うと bit 一致しない」（relu_doors の R=10 対 R=20 で 460 項目中 193 不一致）。したがって **親 3 セル（LL・EE・GG）はバトルから借りず、この走の R=10 で作り直す**（§3）。
   複製エンジンの健全性は、**親エンジンを無改変のまま本走と同じ配置（`--arm LR/ELU/GELU --seeds 0-9 --conds raw --tasks 3`、R=10）で回した参照走**との bit 一致で示す（§7 S1）。バトルの保存結果と突き合わせる必要は無く、**std は検査にも要らない**（Issa・0922）。この形の利点は、検査が**実際に走らせる配置そのもの**を見ること（R=20 の検査は、この走が一度も使わない配置の保証にしかならなかった）。
   壁時計はスロットを半分にしてもほとんど縮まない（この網は 1 step がカーネル起動の回数で決まり、バトルの実測は R=1 で 4.5 ms/step・R=20 で 9.5–11.8 ms/step（7 並列時））。

### 1.4 この走が埋める穴

V11 の「活性化 → 応答」の枝（作業リスト §2 の S 群の隣）。背骨の箱で「どちらの層の活性化が何を決めるか」を、登録した介入で言えるようにする。MNIST の `FLOOR_IN_DEEP_LAYER` が箱を跨ぐか（跨がないなら、V11 の当該段落は MNIST 限定に戻す）。

### 2.1 手順（バトル §2.1 と同一・宿主 `pmnist_rlcifar_0907` / `pmnist_0905` は無改変）

網 3072-100-100-10、init は `H.init_params(seed, device, DIMS)`（`init` stream）。CIFAR-10 訓練 50,000 枚から seed ごとに 1200 枚（`rlc_subset`）。タスクごとに一様乱数ラベル（`rlc_labels`）、バッチ順は epoch ごとに randperm（`rlc_batch`）。画像はタスクをまたいで固定。
50 タスク × 400 epoch × 75 step（batch 16）= 30,000 step/タスク、cross-entropy、Adam（lr 1e−3・β 0.9/0.999・ε 1e−8・moment はタスクをまたいで保持）、WD なし、正規化層なし、float32。
読み出しはバトルの `evaluate`（`evaluate_rl` と列が同じ）と `preact_hist`、online_acc は更新前 argmax の平均。発散は宿主どおり打ち切り、救わない。

### 2.2 エンジン（バトルの複製）

`src/layer_chimera_cifar_0921.py` = `src/rlcifar_mlp_battle_0918.py` の複製に、

```python
class Chimera(Act):
    def __init__(self, a1: Act, a2: Act): ...
    def phi(self, z, layer=0, train=False):  return (self.a1 if layer == 0 else self.a2).phi(z, layer, train)
    def dphi(self, z, layer=0):              return (self.a1 if layer == 0 else self.a2).dphi(z, layer)
```

だけを足す。`forward` は既に `act.phi(z1, 0, train)` / `act.phi(z2, 1, train)` と層番号を渡しているので、**前向きの式・演算順・カーネルは変わらない**。逆伝播は autograd（`Act.dphi` は診断列であって訓練の差し込み口ではない — A6 §1.3 の訂正 1 を継承）。
`make_act` はセル名（§3）を受けて `Chimera` を返す。**走が書く列はバトルと 1 列も変えない**（新しい量は §4.2 の解析段で snapshot から作る）。宿主・バトル本体は 1 行も書き換えない。

- 新しい `EXPERIMENT = "layer_chimera_cifar_0921"`、出力は `results/layer_chimera_cifar_0921/<CELL>/`。
- CUDA graph・checkpoint/resume・`perturb`/`nan_slot` の検査 hook・`replay_stack` はそのまま引き継ぐ。`replay_stack` はセル名から `Chimera` を作る。
- 検査は `src/layer_chimera_cifar_0921_checks.py`（バトルの checks の複製 + §7 の新しい 3 本）。

### 2.3 入力条件（raw のみ）

1 プロセス = 1 セル × raw × seed 0–9 = **R 10**、スロット順は `[(s, "raw") for s in 0..9]`。

- `raw`: x = u8/255（バトルの `raw` と同じ）。std は載せない（Issa・0922）。
- R がバトル（20）と違うので、同じセルでもバトルの**保存結果**とは軌道が bit で並ばない（§1.3-5）。7 セルはすべて同じ R=10・同じスロット順で回すので、セルどうしは seed 対応で比べられる。
- 検査 S-off（§7 S1）の参照も同じ R=10・raw で取る。この spec のどの走にも std は無い。

### 2.4 seed

seed 0–9（バトル・A6 と同じ。腕どうしの対応をとるため新 seed は使わない）。**この 10 seed の親（LL・EE・GG）の水準はバトルで既知**（R=20 の実現値）なので、R=10 で作り直しても親の水準は新しい標本とは言えない（§9）。

### 4.2 解析段が snapshot から作る列（`analysis/layer_chimera_cifar_0921/measure.py`）

A6 と同じやり方で、保存状態を**走自身のスロット順・同じ device** で `replay_stack` して z1,a1,z2 を組み直す（A6 はこれで保存 z(float16) と完全一致を確認している）。t00–t50 の全状態、全 7 セル × 10 スロット × 51 = 3,570 状態。層 l の入力を h₁=X, h₂=a₁、画像 N=1200、ユニット H=100 として

- **p⁺**（活性化に依らない沈下）: `p_pos_l(t) = (1/N) Σ_x (1/H) #{i : z_{l,i}(x) > 0}`。1 枚あたりの正側ユニット数は 100·p⁺（起案文の副 endpoint）。
- **d**（深さ）: 符号つき `d_l(t) = mean_i m_i/sd_i`、A6 と同じ `D_l(t) = mean_i |m_i/sd_i|`（m_i, sd_i は画像間の平均と母標準偏差 ddof=0）。sd=0 かつ m≠0 は符号つき無限大、m=sd=0 は未定義として個数を残す（勝手な ε を分母に足さない）。
- **Q**（A6 の低応答率・活性化依存）: `Q_l(t) = #{(x,i) : |g_train| < 1e−6}/(N·H)`。`g_train` は保存状態の z を leaf にした autograd（そのセルの層 l の活性化に対する）。診断値 `dphi` との差・厳密零の不一致数も別列で残す（A6 §4.1 の型）。閾値 1e−6 は `H.DEAD_TOL` の操作的定義の継承であって機構の臨界ではない。**この閾値は活性化ごとに z の条件へ翻訳される**: ELU は z < −13.8155（ln 1e−6）、GELU は z < −5.394（および φ′ の零点 z = −0.7518 のごく近傍。幅 ~1e−5 で無視できる大きさだが、**絶対値で数える**ので混ざりうることを記す）、**leaky は空集合（|φ′| ∈ {0.1, 1}）**。
- **担い手**: `mu2_norm(t) = ‖mean_x a₁(x)‖₂`、`mu1_norm(t) = ‖mean_x X‖₂`（入力固定なので seed ごとにタスク不変。raw の既知値は中央値 26.195・seed 範囲 25.93–26.51。照合用）、`a1_rms(t) = sqrt(mean_{x,i} a₁²)`（MNIST キメラの操作確認 `a1_rms` の相似形）、`cos(w₂ᵢ, µ₂)` の unit 中央値、`w2_row_norm` の unit 中央値。
- **参照**: 各セル・各 seed の t00 値（p⁺, d, Q, ‖µ₂‖）。§5 の閾値はすべてこの t00 か、親セルの seed 散らばりから作る。

### 4.3 窓と集約（バトルの登録をそのまま）

窓 = **t31–50 の online_acc 平均**（走ごと）。早期 = t1–10、後期 = t41–50、低下 = 早期 − 後期。
腕の集約は **seed 中央値**、対比較は **seed 対応の符号検定**（両側・正確・0 は落とす。`analysis/rlcifar_mlp_battle_0918/report.py` の `sign`）。「勝ち」= 負けが 1 seed 以下かつ p<0.05（バトル §5 の規則）。
発散した走は対から外し、数を報告する。セル単位のラベルは **6/10 以上の多数**（A6 §5.1 の多数規則）。欠測・検査失敗のセルは `INAPPLICABLE` とし、9 seed の多数決に縮めない。

## 5. 登録する判定（閾値はすべて算術から導く。導出を書く）

### 5.1 死活の 3 段と型ラベル（seed ごと → 6/10 多数）

**段**:

1. `ALIVE` ⇔ 窓 ≥ 0.5。**親バトル §5 の登録規則の継承**（崩壊 = 窓 < 0.5）。0.5 は「対の過半」型の操作規則であって機構の臨界ではない。
2. `AT_FLOOR` ⇔ 窓 ≤ thr_s。**床の導出**: そのseedのタスク t のラベル引き `y_t` に対する最良定数予測器 `F_t = max_c n_c(t)/1200`（`H.stream("rlc_labels", s)` から再生。1200 枚・10 クラス）、`F_s = mean_{t=31..50} F_t`、`s_s = sd_{t=31..50} F_t`（ddof=1）、`thr_s = F_s + 3 s_s/√20`。実測値は seed 別に 0.11535–0.12070（起案時に計算済み・§9 に開示）。
3. `PARTIAL` ⇔ thr_s < 窓 < 0.5。この箱には既存例がある（`LK001`/raw 0.3881）。

**型**（段 × t1 の online。`LOW_FROM_TASK1` ⇔ t1 の online < 0.5 は A6 §4.1 の名前と規則の継承）:

| 段 | t1 online | 型ラベル |
|---|---|---|
| `ALIVE` | ≥ 0.5 | **`SLOW_SINK`**（順当な沈下。低下 = 早期−後期 を併記） |
| `ALIVE` | < 0.5 | `LATE_START` |
| `PARTIAL` | ≥ 0.5 | `LEARNS_THEN_PARTIAL` |
| `PARTIAL` | < 0.5 | `LOW_FROM_T1_PARTIAL` |
| `AT_FLOOR` | ≥ 0.5 | **`LEARNS_THEN_DIES`** |
| `AT_FLOOR` | < 0.5 | **`DEAD_FROM_T1`** |

窓 − thr_s の余白と、窓の seed 散らばりを必ず併記する。**床の近く（窓 < 0.15）の `PARTIAL` は「床の上」であって「学習している」ではない**と明記し、memo_acc と §5.3 の層の量で裏を取る（§1.3-2 の SiLU の例）。

### 5.2 Q1（主）: 型が分かれるか

raw の 6 セルの型ラベル（§5.1）で、次の順に当てはめる。

0. **6 セルすべて同型** → **`NO_SPLIT`**（型が分かれない。3 型の主張はこの箱では立たない）。
1. **3 対とも act2 に依らず同型**（型(L,leaky)=型(L,ELU)、型(E,leaky)=型(E,ELU)、型(G,leaky)=型(G,ELU)。0 に当たらない場合）→ **`L1_DECIDES`**。
2. **act2 の列の中で 3 セルが同型で、2 列が別の型** → **`L2_DECIDES`**（MNIST の `FLOOR_IN_DEEP_LAYER` と同型）。
3. **LL・EL が `ALIVE`、LE・EE が `AT_FLOOR`/`PARTIAL` で `LEARNS_THEN_DIES` 系、GL・GE が `DEAD_FROM_T1`** → **`BOTH_LAYERS_THREE_TYPES`**（起案文の期待。3 型が 1 つの箱に揃う）。
4. それ以外 → **`MIXED`**（6 セルの型を表で書く。どの規則にも寄せない）。

**反証（起案文のまま）**: `EL` が `AT_FLOOR` に落ちたら「順当な沈下」型は CIFAR に無く、MNIST 限定の主張に戻す。`GL` が `ALIVE` なら「第1層の死は第1層だけで決まる」が崩れる。

**下位の対比較**（上の主ラベルと独立に、論文が引くのはこちら。すべて §4.3 の符号検定）:

- **C1 第2層の床**: 窓の対応差 `EL − EE`、`GL − GE`、`LL − LE`。各々 `L2_FLOOR_HELPS` / `TIE` / `L2_FLOOR_HURTS`。
- **C2 第1層**: 窓の対応差 `GL − LL`、`GE − LE`、`EL − LL`、`EE − LE`。各々 `L1_HURTS` / `TIE` / `L1_HELPS`。
- **C3 順序（起案文 H1 の後半）**: `LL − EL`、`EL − GL`。`ORDER_AS_PREDICTED` / `TIE` / `ORDER_REVERSED`。**両方が `AT_FLOOR` の対は `ORDER_AT_FLOOR` として順序を読まない**（床どうしの大小に意味を持たせない）。

### 5.3 Q2（副）: 層の先後

**(a) 機能喪失時刻の深さ比較（主に使う。閾値なし・活性化を跨いで比べられる）**: A6 §5.1-4 の fallback をそのまま主規則に上げる。
`T_A = min{t ∈ 1..50 : online(t) < 0.5}`（0.5 は §5.1 と同じ親の登録規則）。T_A があるセルの seed について、その時点の保存状態で `D_l = mean_i |m_i/sd_i|` を両層で作り、大きい層を `DEEPER_L1_AT_LOSS` / `DEEPER_L2_AT_LOSS` とする。D の丸め区間が重なる・未定義ユニットがある・∞ 対 ∞ なら `DEEPER_TIE`。T_A が無ければ `NO_LOSS`（生きているセルに死んだ層は無い）。セルのラベルは 6/10 多数、なければ `SPLIT`。
これは「どの層が先に閾値を越えたか」ではなく「**機能を失った瞬間にどちらの層がより深く沈んでいたか**」の登録で、閾値をひとつも置かない代わりに時間の先後は言わない。先後は (b) と (c) の時間経過から読む。
（起案時の案「p⁺ が t00 の半分を切る時刻」は、1/2 の出どころが弱いので登録から外し、p⁺ は (c) の報告列に残す。Issa・0922。）

**(b) A6 §5.1 の規則そのまま（起案文の副 endpoint）**: Q の閾値通過で `L1_FIRST` / `L2_FIRST` / `SIMULTANEOUS` / `INITIAL_LOW` / `FALLBACK_*` / `NO_EVENT_BY_T10` を出す。**leaky を含む層は Q ≡ 0 で構成上到達しない**ので、`LL`・`EL`・`GL`（第2層 leaky）と `LL`・`LE`（第1層 leaky）のラベルには **`BY_CONSTRUCTION`** を付け、**新しい閾値通過としての支持・予測的中に数えない**（A6 §5.1-3 が ReLU の `INITIAL_LOW` に課したのと同じ扱い）。
(a) と (b) が食い違ったら両方を残し、どちらかを他方の定義にしない。

**(c) 時間経過（報告・閾値なし）**: 各層の `Q_l(t)`・`p_pos_l(t)`・`d_l(t)`・`D_l(t)`・`dead_frac_l(t)` の t00–t50 の列を全セル・全 seed で出す（起案文の副 endpoint「各層の低応答率の時間経過」）。層の先後を言葉で書くときはこの列を引き、(a) の深さラベルと (b) の閾値ラベルのどちらかを他方の定義にしない。

### 5.4 Q3（副）: 担い手 ‖µ₂‖（起案文 H3）

- **P3a**: `‖µ₂‖(t10)` の対応差 `EE − EL`（act1 が同じ ELU なので水準を比べてよい）。符号検定で `MU2_EE_GT_EL` / `TIE` / `MU2_EL_GT_EE`。起案文の「≫」は、これに加えて **10 seed の範囲が重ならない**（max_s EL < min_s EE）ときだけ `NON_OVERLAPPING` を付けて書く。
- **P3b**: `GL`・`GE` の各 seed で `‖µ₂‖(t10) ≤ ‖µ₂‖(t00)`。9/10 以上なら `MU2_BELOW_INIT`（参照: `GG` は既知で 0.132 対 1.529）。
- **報告**: `LL`・`LE` の ‖µ₂‖ と、全セルの `a1_rms`・`w2_row_norm`・`cos(w₂,µ₂)` の時間経過。T_A（§5.3a）での ‖µ₂‖ も併記する（起案文の「T\* での ‖µ₂‖」の置き換え。T\* の定義は leaky 層で恒真なので使わない）。
- **禁止**: act1 が違うセル間の ‖µ₂‖ の水準比較（§1.3-4）。比べるのは自分の t00 との比だけ。

### 5.5 Q4（副）: 第1層の運命は下流に依らないか（起案文 H2 の本体）

第1層の量 x ∈ {`p_pos_1`, `d_1`, `Q_1`} について、t ∈ {1, 2, 10} で

- 帯: `band_x(t) = max_s x_GG(t) − min_s x_GG(t)`（**この走の参照セル GG（R=10）の 10 seed の範囲**。固定値でも固定倍率でもない）。
- `|median_s (x_GL(t) − x_GE(t))| ≤ band_x(t)` かつ `|median_s (x_GL(t) − x_GG(t))| ≤ band_x(t)` が 3 量すべてで成り立てば **`L1_INDEPENDENT_OF_L2`**、1 つでも外れたら **`L1_DEPENDS_ON_L2`**（外れた量と t を書く）。
- **同じ検査を ELU の列でも行う**（`EL` 対 `EE`、帯は `EE` の seed 範囲）。**これが変異対照**: 第2層の活性化が第1層に効くなら ELU 列で `L1_DEPENDS_ON_L2` が出るはずで、両列とも「独立」なら帯が広すぎたと読む。
- `Q_1` は GELU 列で 1 に飽和しうる（既知 0.9994）。飽和した量での「一致」を独立の証拠として単独で使わない。主は `p_pos_1` と `d_1`。

### 5.6 Q5（副）: 低応答と機能の分離（A6 の注意の再確認）

各セルで「Q または p⁺ が先に通過した時刻」と「online が初めて 0.5 を割る時刻 `T_A`」を別の列で出し、一致しないことを確認する。**低応答先行層を機能的 LoP そのものと呼ばない**（A6 の限定の継承）。`EL` が `ALIVE` のまま `Q_1 → 0.95` になるなら、それがこの走で一番わかりやすい例になる。

### 5.7 結論の限界（先に書く）

- 6 セル＋参照・10 seed・1 箱・raw のみ。std（第2層が先に沈む列）は扱わないので、「型が入力の大きさで変わる」はこの走では言わない。**前向きと逆向きを層内で分けていない**ので、「効いているのはゲートか前向きの値か」はこの走では決まらない。
- 層のラベルは**機能喪失時の深さ**（§5.3a）と**操作的な閾値通過**（§5.3b）で、どちらも因果的なボトルネック層の確定ではない（A6 の限定の継承）。
- `LL`・`EE`・`GG` は**バトルの腕の R=10 での作り直し**で、水準は既知。新しい情報は 4 つのキメラセルにある。
- 型ラベルは窓と t1 の 2 点で決める粗い分類で、タスク内の経路は見ていない。
- ‖µ₂‖ の比較は介入の媒介率ではない（S5 `cap_cifar_ee_0920` が上限で介入した量の、ここでは観測値）。

## 8. 実行計画

- **ジョブ**: 7 本（`LL`・`EL`・`GL`・`LE`・`EE`・`GE`・`GG`）。1 本 = 1 プロセス = 1 セル × raw × seed 0–9（R=10）。S-off の参照走（**親エンジン**の `LR`・`ELU`・`GELU` × R=10 × 3 タスク、3 本並列で ~20 分）は本走の前に回し、`_soff/` に置く。`--threads 2`（`eff_rank` はスレッド数で桁が変わるのでバトルと同じ 2 に固定し provenance に書く）。
- **launcher**: `analysis/layer_chimera_cifar_0921/{plan.py,launch.py}`（バトルの複製、`RUNNER` を差し替え）。`plan.json` は `own_max` を S7 の実測で決める（初期値 4、RAM に余裕があれば 6）、`rss_gb 2.0`・`reserve_gb 2.5`・`min_gpu_mb 500`・`retries 3`、起動間隔 25 s。**STOP ファイル** `results/layer_chimera_cifar_0921/_launch/STOP` で新規起動を止める。
- **起動**: `setsid nohup python3 analysis/layer_chimera_cifar_0921/launch.py --plan PLAN.json > results/layer_chimera_cifar_0921/_launch/launch_0921.log 2>&1 &`。**ログ名に `/` を入れない**（0910 の無言失敗）。
- **費用**: バトルの実測で 1 腕（R=20・50 タスク）が 7 並列時に 4.9–5.8 h。R=10 でも 1 step の時間はほとんど変わらない（カーネル起動律速）ので 1 本 4–6 h と見込み、7 本を 4–7 並列で **6–10 h**（一晩 1 回）。S7 で実測してから確定する。
- **ディスク**: snapshot は 1 状態 1.75 MB（W 1.23 MB + z1,z2 float16 0.48 MB）。51 状態 × 10 スロット × 7 セル ≈ **6.3 GB**、S-off の参照走が +0.2 GB（4 状態 × 10 スロット × 3 腕）。`/` は 472 GB 空き。解析段の派生列は CSV で数 MB。
- **解析**: 本走後に `measure.py`（6,120 状態の再生・数分）→ `report.py`（`verdict.json` と `summary.md`）。解析を直したときは**本走の `provenance.json` を書き直さず**、解析側に別の provenance（コード SHA・入力の SHA・時刻）を書く（0910 の「解析を直すとハッシュ不一致」の教訓）。

- **止め時**: 6 本が `provenance.json` を書いたら終わり。途中で止めた場合も ckpt から再開でき、再開点は provenance の `resumed_at_task` に残る。
