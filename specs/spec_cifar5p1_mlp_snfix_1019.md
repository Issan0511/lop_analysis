# cifar5p1_mlp_snfix_1019 — 5+1 CIFAR の MLP に固定 Snake の腕を足す

登録: 2026-10-19、Claude（Opus 5.5）。依頼は Issa の「CIFAR 5+1 MLP に固定 Snake の腕を追加してください」（2026-10-19）。

## 0. 一行

5+1 CIFAR の MLP 箱（`cifar5p1_mlp_0920`、16 腕）に、α を定数にした Snake 2 本と、課題 1 の末で α を固定する SNAfrz1 を足す。19 腕を同じ環境・同じ条件で回し、0920 と同じ検定で比べる。

## 1. 経緯

- 0920 の 16 腕にある Snake 族は、α を前活性の幅に合わせて動かす腕だけだった。SNA・KKA・KKA23・KKT1 の 4 本である。
- 実ラベル 5+1 の CNN の 12 腕比較（`neokunekune_methods_cifar5p1_cnn_1018`）には、α を固定した SN06・SN3 と、課題 1 の末で固定する SNAfrz1 が入っていた。CNN では SNAfrz1 が ELU 以外の 7 腕に勝った。
- 依頼の「固定 Snake」は、CNN の 12 腕と同じく α を定数にした腕と読む。課題 1 の末で固定する SNAfrz1 も固定の一つなので、同じ走に入れる。腕の定義は CNN の 12 腕に揃える。

## 2. 箱

- 0920 の spec §2 のままである。CIFAR-100 で、hard（5 クラス）と easy（1 クラス）が交代する 30 課題を、課題あたり 780 更新、batch 32 で学ぶ。
- 網は 3072-100-100-100 の MLP、入力は std、最適化は Adam（lr 1e−4、WD なし）、seed は 0〜9。
- エンジン・データ・課題列・batch 列・初期値は `src/cifar5p1_mlp_0920.py` をそのまま呼び、書き換えない。新しい腕の活性化だけを新しいモジュール `src/cifar5p1_mlp_snfix_1019.py` に書く。
- 0920 の規則どおり、どの腕も lr と形をこの実験のために調整しない。
- CPU のスレッド数は 2 に固定する。eff_rank が LAPACK のスレッド数で最終桁を変えるためである（0920 の S-nochange で確かめた罠）。

## 3. 腕

| 腕 | 定義 |
|---|---|
| SN06 | φ(z) = z + sin²(αz)/α、α = 0.6 を 2 つの隠れ層の全 unit で固定する |
| SN3 | 同じ式で α = 3 |
| SNAfrz1 | 課題 1 の最後の更新までは SNA と同じに動かし、その後は α を unit ごとに固定する |

- SNA の α は clip(0.6 / W, 0.005, 3) である。W は、batch 内の前活性の分散を指数移動平均（β = 0.01）した値の平方根である。
- 固定 α の 2 本は、SNA と同じ演算順（`a.reciprocal()` を掛ける）で φ を計算する。φ′ は 1 + sin(2αz) である。
- SN06・SN3 も W の移動平均を記録する。ただし φ には使わない。課題末に 2αW の中央値を報告し、ゲートの鋭さを記述する。
- SNAfrz1 は、課題 2 の最初の更新から、α を決める移動平均を止める。実際の幅は別の変数で記録し続け、2αW の中央値はそちらで報告する。固定した α は unit ごとに `frozen_alpha.json` に保存する。
- SNAfrz1 の fresh 対照は、初期状態から最後の hard 課題（課題 29）を 780 更新学ぶ。固定は課題の末にしか起きないので、fresh の学習の間 α は SNA と同じく動く。したがって SNAfrz1 の fresh は SNA の fresh とビットで一致するはずである。

比べる相手は 0920 の 16 腕である。SNA・KKA・KKA23・KKT1・R・LR・LK001・LK03・SL・RSL・ELU・SILU・GELU・LK07・CR・DF を、0920 と同じ設定のまま同じ環境で回し直す。19 腕すべてを、この走の中の値で比べる。

## 4. 測るもの

0920 と同じである。

- 主指標は後期窓で、hard 課題 21・23・25・27・29 の更新前 online 精度の平均である。
- ほかに、早期窓（hard 課題 1〜9）、低下（早期 − 後期）、fresh gap（課題 29 の fresh − 継続）を測る。
- 第 2 層の死・出力 0・mob（φ′ の平均）・実効ランク、重みの行ノルム、課題末の train と test 精度も残す。

## 5. 登録する比較と読み

- 検定は 0920 と同じ対応符号検定である。厳密な両側検定で、差が 0 の seed は除く。
- 族ごとに Holm で補正する。p_holm < 0.05 で中央値の差が正なら `A_WINS`、負なら `B_WINS`、それ以外は `TIE` とする。
- 発散した run を含む比較は、その seed を除いて行う（0920 の規則）。

**族 N**（新しい腕、10 比較）:

| a | b | 問い |
|---|---|---|
| SN06 | SNA | α を幅に合わせて動かすことが要るか |
| SN3 | SNA | 同上 |
| SNAfrz1 | SNA | 課題 1 の後に α を止めると変わるか |
| SN06 | KKT1 | 0920 の代表腕との比較 |
| SN3 | KKT1 | 同上 |
| SNAfrz1 | KKT1 | 同上 |
| SN06 | ELU | Snake 族以外の最上位との比較 |
| SN3 | ELU | 同上 |
| SNAfrz1 | ELU | 同上 |
| SN06 | SN3 | 固定する α の大きさ |

**族 vs_best**（0920 と同じ形）: 19 腕を後期窓の中央値で並べ、首位と残り 18 腕を比べる。Holm は 18 本で補正する。

**新しい 3 腕の読み**（0920 §3.3 のまま、seed の中央値で読む）:
- Q1: 低下 > 0。
- Q2: fresh gap > 0。
- Q3: 後期窓 < 0.20（崩壊）。

**読みの文**（実行前に固定）:
- SN06 − SNA と SNAfrz1 − SNA がともに `TIE` なら、「この箱では α を幅に合わせて動かしても止めても、後期窓は変わらない」と書く。
- 新しい腕が SNA に `A_WINS` なら、その腕を Snake 族の代表の候補として記録する。
- SN06 − SN3 は α の大きさの効果として記述する。この走で α の最適値は探さない。
- 2αW の中央値の推移は記述であり、判定には使わない。

**S-reuse-0920**: 回し直した 16 腕の `per_task.csv` と `fresh_control.csv` を、main にある 0920 の同名ファイルとバイト単位で比べる。一致すれば、16 腕は 0920 と同じ軌道であり、新しい seed での追試ではない。一致しなければ FAIL と記録し、比較はこの走の値で行う。

## 6. 検査

本走の前に all_pass を commit する。各検査に、わざと壊した版を付けて検出を確かめる。

- **S-fixed**: SN06・SN3 の φ と φ′ を、float64 の autograd と照合する。学習の後でも α が定数のままであることを確かめる。変異: α を SNA と同じく動かすと検出される。
- **S-frz**: SNAfrz1 は課題 1 の末まで SNA とビットで一致する（課題 1 の per_task の行）。課題 1 の後の α は SNA の課題 1 末の α と一致し、課題 2 以降は変わらない。fresh 対照は SNA の fresh とビットで一致する。変異: 固定を 1 課題遅らせると検出される。
- **S-graph**: 新しい 3 腕で、CUDA graph と eager がビットで一致する（2 課題）。
- **S-nochange-early**: 0920 の R と SNA を 2 課題だけ回し、課題 1・2 の行が committed の `per_task.csv` の行と同じ文字列になる。変異: lr をわずかに変えると一致しなくなる。
- **smoke**: 新しい 3 腕 × seed 0〜9 × 2 課題で計時する。性能の根拠にはしない。

## 9. 追補 1: 検査の直し（2026-10-19、本走の前、性能の値は未観測）

実装 `2329ae09` で回した最初の検査は `all_pass = False` だった。不合格は 3 つで、原因と直しは次のとおりである。実装（活性化と走らせ方）は変えていない。

| 検査 | 不合格の中身 | 原因 | 直し |
|---|---|---|---|
| S-fixed | SN06 の α が per_task の行で 0.6 と一致しない | CSV は数を 10 桁で書く（`.10g`）。float32 の 0.6 は 0.6000000238418579 で、行の文字列 "0.6000000238" を数に戻すと一致しない。SN3 の α = 3 は丸めの影響を受けない | 行の文字列を、float32 の α を同じ書式で書いた文字列と比べる |
| S-frz | SNAfrz1 の fresh の行が SNA と一致しない | fresh の行には継続側の online と fresh gap も入る。継続側は課題 1 の後で SNAfrz1 と SNA が違うのが正しい | fresh 側の online 精度だけを比べる |
| S-nochange-early | R の課題 1・2 の行が 0920 の行と一致しない | 違うのは `eff_rank_l2` だけで、20 行のうち 5 行の 9〜10 桁目である。ほかの列はすべて一致し、SNA は全列が一致した。0920 は torch 2.13.0+cu126、今は 2.13.0+cu130 である。実効ランクは更新の後に、GPU 上の float64 の Gram と CPU の LAPACK の固有値から計算する記述量で、学習には入らない | 実効ランク以外の全列が同じ文字列であることを合格の条件にする。実効ランクは相対差の最大を記録する |

- 追加で LR と ELU も 2 課題回し、全列が 0920 の行と一致することを確かめた。
- **S-reuse-0920** は登録どおりバイト単位の照合（`label`）を残す。これに加えて、実効ランクを除く全列と fresh の行を文字列で比べる軌道の照合（`trajectory_label`）を報告する。16 腕が 0920 と同じ軌道を通ったかは、軌道の照合で読む。腕の比較は登録どおりこの走の値で行うので、どちらの照合も比較の結果を変えない。
- 予測 P6 は登録どおりバイト単位の照合で採点する。
