# perm_dial_rl_0915 —— ラベルは RL のまま、画素の一部だけを毎タスク置換する（蹴りのダイヤル）

親: `spec_relu_gelu_silu_rl_ext150_0914.md`（結果 `fca473d`）
動機（Issa・0915）: RL と PM の一番の違いは平均入力 μ が固定かどうか。PM はタスク切替で入力がばらばらになり、死んだユニットにもリセットが起きる。
事後の確認（登録外）: 150 タスク走の per-unit 列で、ReLU 第 1 層の復活は RL で 0/44,019、PM で 12–16%/タスク。タスク境界の蹴り
sd(Δz̄ᵢ) は PM で ‖w̃ᵢ‖·sd(μ) の算術と q3 以上の分位で 1 割以内。GELU は RL で第 2 層が水面に留まり生存、PM で t10 に谷の向こうへ入り t66–117 に崩壊。

## 0. 問い

ラベル（毎タスク新しい一様乱数）と画像（1200 枚固定）はそのままに、**入力の蹴りだけ**を連続的に入れる。
蹴りは死んだ単調ゲートのユニットを蘇らせるのか。谷型（GELU・SiLU）を谷の向こうへ突き落とすのか。

## 1. 箱と腕

`relu_gelu_silu_rl_ext150_0914` と同一（1200 枚・784-100-100-10・Adam・6000 更新/タスク・**150 タスク**・seed 0–2・両層同一活性化）。
環境は RL のみ。活性化 5（LR・ELU1・R・GELU・SILU）× 置換画素数 k 5 水準 × seed 3 = **75 モデル**。

**ダイヤル**: 各タスク・各 seed で、新しいストリーム `partial_perm_0915` から画素の並べ `o = randperm(784)` と鍵 `r = rand(784)` を引き、
K = o[:k] の画素だけを K 内で `argsort(r[:k])` の順に置換する（残りの画素は元の位置）。置換は毎タスク元の画像に対して作る。
k の水準は、タスク境界の蹴り sd(Δ w̃·μ) が k=784 の **0 / 25 / 50 / 75 / 100 %** になるよう算術で選んだ（ランダム w̃・3 つの 1200 枚部分集合で数値計算）:

| k | 0 | 25 | 107 | 270 | 784 |
|---|---|---|---|---|---|
| f = k/784 | 0 | 0.032 | 0.137 | 0.344 | 1 |
| 蹴り sd の比（算術） | 0 | 0.25 | 0.50 | 0.75 | 1 |

蹴りは √f ではなく頭打ちで伸びる（f = 0.25 で既に 65%）ので、f を等間隔にするとダイヤルが上に偏る。そのため蹴りで等間隔にした。
k = 0 は既存の乱数を 1 つも余計に消費しないように別ストリームにしてあり、`relu_gelu_silu_rl_ext150_0914` の RL と同一の走になるはず。

## 2. 判定

**床**: モデルごとに late 窓 **t141–150** の online 精度平均が F + 3s/√10 以下なら `AT_FLOOR`（F・s は同じ窓の各タスクの多数派ラベル割合。ラベルは全セルで乱数なので縮退しない）。
**生存数** S(a, k) = その (活性化, k) で `ABOVE_FLOOR` の seed 数（0–3）。

**腕ごとのラベル**（端点で決める・中間水準は報告）: S(a,784) > S(a,0) → `KICK_RESCUES` ／ S(a,784) < S(a,0) → `KICK_KILLS` ／ 等しい → `KICK_NEUTRAL`。

**Q1（全体）**
- LR が全 k で S = 3、かつ LR 以外の k > 0 の全 16 セルで S = 0 → **`LEAK_ONLY_SURVIVES`**
- (R または ELU1 が `KICK_RESCUES`) かつ GELU が `KICK_KILLS` → **`KICK_CROSSING`**
- どちらでもない → **`OTHER`**（腕ごとのラベルを列挙）

k = 0 の列は親の走の再生で、GELU 3/3・SiLU s2 が t141–150 で床の上だったことが既知。`LEAK_ONLY_SURVIVES` は k > 0 のセルで判定する。

## 3. ゲート

- **G0（再現）**: k = 0 で LR が S = 3、ELU1 が S = 0。
- **G1（錨・診断）**: k = 0 の 15 モデルの online_acc・train_ce を親 `fca473d:results/relu_gelu_silu_rl_ext150_0914/rows.csv` の RL 行と 150 タスク全部で照合し max|Δ| を報告。
- **G2（操作チェック）**: LR の第 1 層で、タスク境界の正規化した蹴り Δz̄ᵢ / ‖w̃ᵢ‖ の分散が k とともに**単調に増える**（5 水準・3 seed プール）。単調でなければ Q1 は `NOT_TESTABLE`。k = 0 に対する超過分の sd の比を算術の 0.25/0.5/0.75/1 と並べて報告する。

## 4. 報告のみ

- 全 25 セルの生存数と late 精度・最初に床を割ったタスク
- ReLU の復活率（第 1 層・第 2 層）を k ごとに
- GELU・SiLU の第 2 層の φ′<0 の占有と |φ′|<1e−8 の割合（t50/t100/t150）を k ごとに
