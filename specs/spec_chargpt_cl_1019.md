**経緯。** Issa は LN 付き Transformer で沈降が確実に出る設定を探していた。自前の Joudaki ViT（affine LN・Adam 1e−4）は沈まなかった。1019 のチャットで Li ら 2022 と Shvetsov ら 2026 の Transformer の設定を原典と公開コードで照合し（§1.1）、GPT-nano の再現は重い（H100 で 3 時間前後、RTX 5060 Ti で 1〜2 日の概算）ので、クラウド CPU で文字単位の小さな GPT の 1 課題パイロットを回した（§1.2）。学習率 1e−3 なら LN があっても沈み、1e−4 では沈まなかった。これを継続学習に落とす 2 案について、Issa「両方やって」「RLっぽくしたくはあるけど言語モデルでは厳しいよねー」。

## 0. 一行

LN 付き 4 層の文字 GPT を、**箱 M：課題ごとに作り直す乱数の 2 次マルコフ言語**と、**箱 W：Shakespeare の固定窓 1200 個への乱数ラベル**の二つで継続学習させる。問いは三つ。課題を切り替えるたびに FFN の前活性が沈むか。それと一緒に学ぶ力が落ちるか。Adam 1e−4 では沈まないか（ViT との対応）。

## 1. 背景（このチャットで確かめた事実）

### 1.1 先行研究の Transformer

- **Li ら 2022（Lazy Neuron）**：T5（RMSNorm）、ViT-B/16 と BERT（LN）で、FFN の ReLU 後の非ゼロ率が初期の約 50% から数%へ下がる。T5 以外は学習の終点の値だけ。
- **Shvetsov ら 2026 の公開ログ**（github.com/On-Point-RND/BugOrFeature の `GPT_LOGS_AND_PER_LAYER_VALUES/`）：GPT-nano 124M・FineWeb・7,168 反復。既定の正規化は **RMSNorm**（論文表 1 の負の割合 89.0% はこれ）。LN 版（`LayerNorm.json`）は γ のみで β なし（RMSNorm を置き換える関数が bias を消す作り）、全線形層 bias なし、活性化は down_proj 入力の最大値 10〜39 から ReLU と推定。up_proj 出力（活性化の直前）の負の割合は層平均 89.3%（層 0 で 76.8%、中間 85〜96%、最終 77.4%）。FFN 入力の負の割合は約 50%、重みの平均は約 1e−5（標準偏差 0.16）。ログは終点 1 点だけで、行列は Muon で更新している。
- 両論文とも、継続学習・可塑性・bias と入力平均の経路は扱っていない。

### 1.2 1 課題パイロット（事後・未登録・seed 0 のみ・クラウド CPU）

Tiny Shakespeare の文字単位の言語モデル。4 層、d 128、4 head、FFN 512、文脈 128、RoPE、tied embedding、pre-LN、約 80 万パラメータ。1 反復 32×128 トークン、warmup 300・一定・warmdown 350 の計 1,200 反復。測定は検証側から固定した 64×128 トークン、eval モード、50 反復ごと。

| 走 | 正規化と bias | dropout | 活性化 | 最適化と lr | 検証損失 | 負の前活性の割合（層 0〜3） | 平均が負の unit |
| -- | ------------- | ------- | ------ | ---------- | ------- | -------------------------- | --------------- |
| A | LN γ のみ・bias なし | なし | ReLU | Muon 5e−4 ＋ AdamW 5e−3（β₂ 0.95） | 1.56 | 0.72 0.73 0.72 0.65 | 91〜99% |
| C | LN γ のみ・bias なし | なし | ReLU | AdamW 1e−3（β₂ 0.95） | 1.59 | 0.75 0.73 0.70 0.67 | 92〜99% |
| B | LN γ・β・bias あり | 0.1 | ReLU | Adam 1e−4 | 2.08 | 0.59 0.55 0.51 0.50 | 46〜61% |
| D | LN γ・β・bias あり | 0.1 | ReLU | Adam 1e−3 | 1.70 | 0.81 0.75 0.71 0.69 | 96〜99% |
| E | LN γ・β・bias あり | 0.1 | GELU | Adam 1e−3 | 1.69 | 0.81 0.77 0.75 0.73 | 98〜100% |

読み（すべて 1 seed・1 データ・1 つの大きさ）：

- **沈むかを決めたのは学習率。** B と D は学習率だけが違う。沈み始めは A・C・D・E とも 200〜300 反復（warmup の終わり）で、warmdown に入る 850 反復ごろに頭打ち。
- **形を保ったまま平均がずれる。** A の unit の平均÷標準偏差の中央値 −0.59・−0.62・−0.57・−0.37 から正規分布で計算した負の割合 0.72・0.73・0.72・0.64 は、実測 0.72・0.73・0.72・0.65 と一致する。
- **担い手は入力平均の経路。** A・C は bias も β もない。D・E では FFN の up の bias が +0.004 → −0.02 へ動いたが、Σ|bᵢ| と Σ|μᵢ| の比は 0.08〜0.10（unit ごとの比の中央値ではなく和の比）。残りは重みと LN 出力のトークン平均の内積（β を通る分を含む。分けていない）。
- **死んだ unit はどの走でもゼロ。** GELU でも ReLU と同じかそれ以上に沈む。Muon は必須ではない（C）。
- 損失は nanoGPT の README の目安（同じ 4 層・d 128 の CPU 設定で約 1.88、6 層・d 384 で約 1.47）と比べて妥当。

## 2. 箱

### 2.1 共通のモデル

| 項目  | 固定内容                                                                    |
| --- | ----------------------------------------------------------------------- |
| 構造  | 因果 Transformer、4 層、d 128、4 head、FFN 512（4 倍）、文脈 128、RoPE、注意の残差に 1/√(2L) |
| 正規化 | pre-LN（各ブロックの注意と FFN の前、最終出力の前）。腕で γ のみ・γ と β・なしを切り替える（§3）              |
| FFN | up（128→512）→ ReLU → down（512→128）。dropout なし                            |
| 初期化 | PyTorch の既定。腕の間で初期値を共有できる部分は seed ごとに同じにする                              |
| 精度  | float32                                                                 |

### 2.2 箱 M：乱数の 2 次マルコフ言語を次々に学ぶ

- **記号**：65 個の抽象記号（Shakespeare の文字とは対応させない）。出力層は埋め込みと共有。
- **規則**：課題 t ごとに、65² = 4,225 個の文脈 (a, b) それぞれについて次記号の分布 p_t(·|a, b) ~ Dirichlet(α·**1**) を独立に引く。α は段 0 で {0.01, 0.03, 0.1} から選ぶ。
- **系列**：最初の 2 記号を連鎖の定常分布 π_t から引き、p_t で長さ 129 を生成する。batch 32。毎回新しく生成し、同じ系列は使わない（データは無限）。
- **物差し**：エントロピー率 H_t = Σ π_t(a, b)·H(p_t(·|a, b)) を正確に計算する（4,225 状態の定常分布をべき乗法で）。成績は**超過損失 = 交差エントロピー − H_t**。最初の 2 位置は文脈が足りないので損失と成績から除く。

  | α    | 1 文脈の期待エントロピー | 引いた連鎖 1 本のエントロピー率 |
  | ---- | ------------- | ----------------- |
  | 0.01 | 0.729 nat     | 0.704 nat         |
  | 0.03 | 1.432 nat     | 1.436 nat         |
  | 0.1  | 2.371 nat     | 2.363 nat         |

  一様分布なら 4.174 nat。期待値はディガンマ関数による厳密値、右列は乱数で 1 本引いた値（seed は固定していない。1019 に計算）。
- **課題**：50 課題。1 課題 N_M 更新（段 0 で {1000, 3000, 10000} から選ぶ）。
- **RL らしさ**：文脈の集合 4,225 個は全課題で同じで、正解の分布だけが入れ替わる。網は 4,225×65 の表を重みに覚え直す必要があり、容量を要求する点で乱数ラベルの記憶に近い。違いは、入力の系列も新しい連鎖から来るので**入力の分布も課題ごとに変わる**こと。

### 2.3 箱 W：Shakespeare の固定窓に乱数ラベル

- **データ**：Tiny Shakespeare（karpathy/char-rnn、1,115,394 文字、65 文字、sha256 `86c4e6aa9db7c042ec79f339dcb96d42b0075e16b8fc2e86bf0ca57e2dc565ed`）の先頭 90% から、重ならない 128 文字の窓を 1,200 個、seed ごとに 1 度だけ無作為に選ぶ。全課題で同じ窓。
- **ラベル**：各窓に {0, …, 9} の一様乱数ラベルを課題ごとに独立に付け直す。50 課題。
- **読み出し**：最終 LN の出力を 128 位置で平均し、線形 128→10。読み出しも課題をまたいで持ち越し、リセットしない（乱数ラベル MNIST の箱と同じ）。
- **訓練**：batch 16、epoch ごとに順序を引き直す。1 課題 N_W 更新（段 0 で {3000, 7500, 30000} から選ぶ。30,000 は乱数ラベル MNIST と同じ 400 epoch）。
- **位置づけ**：乱数ラベルの直訳で、MLP の乱数ラベル MNIST と一番直接に比べられる。ただし言語モデルではなく分類器。

### 2.4 中間案 M′（v1 では回さない・記録のみ）

Issa の「RL っぽくしたいが言語モデルでは厳しい」への答え。生成型の言語モデルでは正解が次の入力そのものなので、入力を固定したまま正解だけを替えることはできない。M はそのうち「同じ文脈・新しい正解」の部分だけを保っている。

M′ は Shakespeare の本文を入力に固定し、各位置の正解を「直前 2 文字 → 乱数表」で課題ごとに付け替える。入力が固定で正解だけが替わるので乱数ラベルに一番近く、因果 Transformer と位置ごとの交差エントロピーも保てる。正解を決定的にすれば到達できる最小の損失は 0、雑音を混ぜればその量で決まる。ただし正解が次の入力ではないので、生成型の言語モデルではなく系列への付票になる。M と W の結果が食い違ったときの切り分けに使う。

## 3. 腕

| 腕    | 正規化      | 線形層の bias | 最適化と lr   | 役割                                   |
| ---- | -------- | --------- | --------- | ------------------------------------ |
| `C3` | LN γ のみ  | なし        | Adam 1e−3 | 主腕。パイロット C の継続版                      |
| `C4` | LN γ のみ  | なし        | Adam 1e−4 | 学習率の対照。ViT の学習率                      |
| `B3` | LN γ と β | あり        | Adam 1e−3 | bias と β の経路を測る。ViT の構成に近い           |
| `N4` | なし       | なし        | Adam 1e−4 | LN と低い学習率の組み合わせの切り分け（ViT の 2×2 への接続） |

- **最適化**：Adam(0.9, 0.999, 1e−8)、weight decay 0、学習率は一定。warmup は課題 1 の最初の 300 更新だけ。Adam の状態・重み・読み出しは課題をまたいで持ち越し、リセットしない。パイロットの AdamW β₂ 0.95 と warmdown は使わない（乱数ラベル MNIST の箱にそろえる）。
- **seed**：本走は 0〜9。seed は初期値・規則（M の遷移表、W の窓とラベル）・batch の順・probe を決める。乱数は役割ごとに別の stream（`init` / `rule` / `data` / `probe`）に分け、同じ seed の腕の間で規則・ラベル・batch の列をビット一致させる。
- 活性化の比較（GELU、KKT1・SNA など）と救済の介入は v1 に入れない。箱が成立してから v2 で足す。

## 4. 測るもの

### 4.1 沈降

- **probe**：M は (i) 現在の課題の連鎖から引いた 64×128 と、(ii) 一様乱数の記号列 64×128（全課題で固定）の二つ。W は 1,200 窓のうち固定した 256 窓。no-grad・eval モードで測り、optimizer にも学習の乱数にも触れない。
- **unit ごとの量**（FFN の up 出力 z、層ごと）：平均 μᵢ、標準偏差 σᵢ、qᵢ = probe のトークンのうち z < 0（ReLU で φ′ = 0）の割合。**沈んだ unit は qᵢ ≥ 0.95**（既存ノートの定義にそろえる）。死んだ unit は probe の全トークンで z ≤ 0。層の集計は、負の割合、平均が負の unit の割合、μᵢ/σᵢ の四分位、沈んだ unit と死んだ unit の割合。
- **平均の分解**：μᵢ = wᵢ·(γ ⊙ m̂) ＋ wᵢ·β ＋ bᵢ。m̂ は LN の正規化後（affine の前）の出力のトークン平均。三つの項を別々に保存し、cos(wᵢ, γ ⊙ m̂) も取る。β・bias がない腕では該当の項は 0。
- **時点**：全課題の課題末。加えて課題 1・2・10・11・25・26・49・50 の中で、更新 0・10・25・50・100・200・400、以後 500 ごと。
- **切替の押し**：各切替の最初の 100 更新での Δμᵢ/σᵢ（課題末の σ で割る）の層中央値。切替のたびに一段ずつ深くなる「ラチェット」かを見る。
- **重み**：up の行ノルムと行平均を課題末ごとに保存。checkpoint は初期値と課題 1・10・25・50 の末（1 個約 3MB）。

### 4.2 成績

- **箱 M**：オンライン超過損失（更新前のバッチの交差エントロピー − H_t）を、課題の最初 500 更新と課題全体で平均する。課題末の超過損失は、現在の連鎖から新しく引いた 256×128 で測る。
- **箱 W**：`online_acc`（更新前のバッチ精度）を、課題の最初 1,000 更新と課題全体で平均する。`memo_acc` は課題末の 1,200 窓に対する精度。
- **fresh**：課題 10・25・50 で、継続走と同じ初期値・Adam の状態ゼロから、同じ規則（ラベル）・同じ batch 列・同じ更新数で学ばせる。fresh gap は M では継続 − fresh（超過損失）、W では fresh − 継続（精度）。どちらも**正なら継続の網が劣る**。課題 1 は継続走そのものが fresh なので別に走らせない。
- **窓**：早期は課題 1〜10、後期は課題 41〜50。

## 5. 判定（Issa の承認 1019 で凍結。段 0 の結果を見て変えない）

各腕・各箱ごとに seed で対応させ、n = 10 の両側符号検定と、対応差の平均 ± SE を報告する。非有意を同等の証明とはしない。

- **Q1 沈降**：課題 10 の末で、負の割合の層平均 ≥ 0.65 かつ平均が負の unit の割合 ≥ 0.8 が 8/10 seed 以上なら `SINKS`。負の割合 < 0.58 が 8/10 以上なら `NO_SINK`。それ以外は `MIXED`。
- **Q2 ラチェット**：μᵢ/σᵢ の層中央値の課題末の値を後期窓と早期窓で比べ、後期が 0.1 以上深い seed が 8/10 以上なら `RATCHET`。差の絶対値 < 0.1 が 8/10 以上なら `SATURATED`。後期が 0.1 以上浅いのが 8/10 以上なら `RECOVER`。それ以外は `MIXED`。切替の押しの符号（課題 2〜50 の平均）は報告のみ。
- **Q3 喪失**：オンライン成績が後期窓で早期窓より悪く、かつ課題 50 の fresh gap > 0 の seed が 8/10 以上なら `LOSS`。課題 50 の fresh gap ≤ 0 が 8/10 以上なら `NO_LOSS`。それ以外は `MIXED`。
- **Q4 学習率**：`C3` が `SINKS` で `C4` が `NO_SINK` なら `LR_GATES_SINKING`。
- **Q5 LN と低い学習率**：`N4` が `SINKS` で `C4` が `NO_SINK` なら `LN_SLOWS_AT_LOW_LR`。両方 `NO_SINK` なら `LR_ALONE`。両方 `SINKS` ならパイロット B と食い違うので、そのまま記録する。
- **Q6 bias の担う割合**（`B3`）：課題 50 の末の |bᵢ|/|μᵢ| の unit 中央値と、wᵢ·β の割合。報告のみ（パイロットでは bias の分 0.08〜0.10）。
- 箱 M と箱 W の判定の一致・不一致は報告のみ。

## 6. 予測（Claude・1019・走る前の記名）

1. **Q1**：`C3` は両方の箱で `SINKS`。確信は M で高、W で中（分類の交差エントロピーで押しの大きさが違い得る）。
2. **Q2**：W は読み出しが毎課題作り直されるので `RATCHET`。確信 低〜中。M は 1 課題目で頭打ちの `SATURATED`。確信 低。
3. **Q3**：W は `LOSS`、M は `MIXED`。確信 低。LN が喪失を和らげるという報告（Lyle ら 2024）があり、沈んでも学べる結果は十分あり得る。その場合は「LN 付きでは沈むが学べる」として、鎖のどこを LN が切るかの問いに移る。
4. **Q4**：`LR_GATES_SINKING`。確信 中。
5. **Q5**：`LN_SLOWS_AT_LOW_LR`。確信 低〜中。
6. **外れたときに第一に疑うもの**：予算（N_M・N_W）が短すぎて課題の中で沈む前に切り替わること。次に、箱 M の規則が易しすぎて網が表を覚え直す必要がないこと。

## 7. 段 0（較正。判定には使わない）

`C3` だけ、seed 100〜102、5 課題。

- **箱 M**：α ∈ {0.01, 0.03, 0.1} × N_M ∈ {1000, 3000, 10000}。新品の網が課題 1 の末で超過損失 ≤ 0.1 nat に届く最小の N_M を各 α で求め、更新 100 の時点の超過損失が 0.5 nat 以上ある（易しすぎない）α のうち、費用が本走の予算に収まるものを選ぶ。
- **箱 W**：N_W ∈ {3000, 7500, 30000}。課題 1 の末で `memo_acc` ≥ 0.95 に届く最小の N_W を選ぶ。
- 段 0 は 5 課題しか回さないので、後期窓の量（Q2・Q3）は見えない。選ぶ規則はこの二つに限り、ほかの量で選び直さない。選んだ値と理由を本 spec の追補として本走の前に commit する。

## 8. 検査（本走の前）

- **S-entropy**：計算した H_t と、真の連鎖そのものの予測を生成した系列で評価した交差エントロピーの差 < 0.01 nat。
- **S-rule**：遷移表の各行の和が 1、課題間で規則が独立、腕の間でビット一致。W のラベルが各課題で一様（χ² p > 0.01）、課題間で独立、腕の間でビット一致。
- **S-online**：オンライン成績が更新前の予測で計算されていること（1 バッチを手計算で照合）。
- **S-probe**：probe が全課題・全腕で同じで、測定が optimizer と学習の乱数に触れないこと。
- **S-decomp**：μᵢ と分解の三項の和の差 < 1e−5。
- **S-repro**：1 腕 seed 0 の 2 課題（短い予算）を 2 回走らせて記録がバイト一致。
- **S-cost**：1 腕 1 seed 2 課題の壁時計から本走全体を見積もり、§9 に追記する。

## 追補 0（2026-10-19・Claude（Opus 5.5）・段 0 と本走の前）

実装で決めた解釈と、段 0 の選び方の細目である。段 0 の数値も本走の数値も見る前に書いた。§5 の判定と閾値は変えていない。実装は `src/chargpt_cl_1019.py`、検査は `src/chargpt_cl_1019_checks.py`。

### A. 実行と精度

- 手元の RTX 5060 Ti で回す。学習の 1 更新（順伝播・逆伝播・Adam）を eager のまま CUDA グラフに取り込み、毎回それを再生する。
- 精度は float32 のままにする。TF32 は切り、`torch.use_deterministic_algorithms(True)` で回す。
- 注意は SDPA ではなく、行列積と softmax で書く。数式はパイロットと同じである。
- 測定はグラフの外の eager で行う。学習の記憶にも乱数にも触れない。
- **torch.compile は使わない。** 試したところ 1 更新が 4.7 → 3.4 ms（箱 M）に縮んだが、勾配が float64 の参照から相対 3e−5〜3e−4 ずれた（eager は 2e−7 前後）。ずれは RoPE を外すと消える。RoPE だけ、FFN だけ、LN と残差の 1 ブロックだけを compile した場合は eager と同じ精度で、原因の箇所は突き止めていない。計算が eager の fp32 と同じであることを優先した。
- 速さ：1 更新が箱 M（batch 32）で 4.7 ms、箱 W（batch 16）で 2.7 ms。時間の半分強は fp32 の行列積（約 16 TFLOPS）である。複数プロセスを同時に走らせても合計の速さは増えなかった（GPU の上では交代で動く）。

### B. 初期値

- パラメータ名ごとに別の stream から、PyTorch 既定の分布で引く。Linear は U(±1/√fan_in)、LN は γ = 1・β = 0。
- 埋め込みは出力の頭（Linear 128→65）と共有し、その初期化を使う。
- これで、腕にない bias・β・LN を除けば、同じ seed の全腕で初期値が同じになる。

### C. 箱 M

- **除く「最初の 2 位置」**：系列の s₀ と s₁ を指す。損失と成績の目標は s₂〜s₁₂₈ の 127 個である。s₁ は π から引いたので p の予測ではない。こうすると、真の連鎖の期待損失がちょうど H_t になる。
- **定常分布**：遅延連鎖 ½(I + P) のべき乗法で求め、L1 差が 1e−14 を下回ったら止める。定常分布は P と同じで、周期をもつ連鎖でも収束する。
- **Q1・Q2 の主 probe**：(i) 現在の課題の連鎖から引いた 64×128 を使う。(ii) 一様乱数の記号列は副として報告だけする。理由は、網が実際に学ぶ入力の分布で測るためである（パイロットが検証データで測ったのと同じ考え）。
- **課題末の超過損失**：課題ごとに固定した 256 本で測る。段 0 の「更新 100 の時点の超過損失」も、課題 1 のこの 256 本で測る。
- 系列は GPU の Philox 乱数（stream `data`、課題ごと）で、課題の頭から 250 更新分ずつ作る。

### D. 箱 W

- **窓**：先頭 90% を、seed ごとの乱数のずれ（0〜127 文字）から 128 文字の区画に切り、1,200 区画を無作為に選ぶ。
- **読み出しの bias**：腕の「線形層の bias」に従う。C3・C4・N4 はなし、B3 はありである。
- 因果注意のまま、最終 LN の出力を 128 位置で平均する。言語モデルの頭は使わない（埋め込みとしては使う）。

### E. fresh

- 課題 1 と同じ条件で、課題 t の規則と batch 列を学ぶ。同じ条件とは、同じ初期値、Adam の状態ゼロ、最初の 300 更新の warmup である。
- fresh gap は、オンライン成績の課題全体の平均で取る（0920 の 5+1 CIFAR と同じ）。M は継続 − fresh（超過損失）、W は fresh − 継続（`online_acc`）。どちらも正なら継続の網が劣る。

### F. 判定の量（§5 の閾値はそのまま）

- **Q1**：「負の割合の層平均」は、4 層の `neg_frac` の平均である。「平均が負の unit の割合」は、4 層の `units_mean_neg` の平均である。どちらも課題 10 の末に主 probe で測る。
- **Q2**：「μᵢ/σᵢ の層中央値」は、層ごとの unit 中央値を 4 層で平均した値である。早期窓・後期窓の値は、窓の中の課題末の値の平均である。
- **Q3**：「オンライン成績」は課題全体の平均である（M は超過損失、W は `online_acc`）。窓の値は課題の平均である。
- **切替の押し**：課題 t の更新 0 と更新 100 の μᵢ の差を、課題 t の更新 0 の σᵢ（同じ probe）で割る。その層ごとの unit 中央値を報告する。

### G. 検査の帯（§8 の文言の解釈）

- **S-entropy**：8,192 本（約 104 万目標）で測る。標本の標準誤差が 0.0025 nat 以下であることも確かめる。すると帯 0.01 nat は 4 SE 以上あり、偶然では落ちない。
- **S-rule**：
  - 遷移表の各行の和は、|和 − 1| < 1e−13 とする（65 項の float64 の丸めは約 1.4e−14）。
  - 課題間の独立は、連続する課題の遷移表の相関を |r| ≤ 4/√274,625 で確かめる。
  - W のラベルの一様性は、50 課題の多重性を Bonferroni で補正し、各課題で χ² の p > 0.01/50 とする。§8 の p > 0.01 をそのまま 50 課題に当てると、正しい乱数でも 1 seed あたり 4 割（1 − 0.99⁵⁰）、10 seed なら 99% の確率でどこかが落ちるためである。
  - W の課題間の独立は、同じ窓のラベルが一致する割合を 0.1 ± 4·√(0.09/1,200) で確かめる。
  - 腕の間のビット一致は、各課題の batch 列と規則の sha256 で照合する。
- **S-decomp**：μᵢ と分解の三項を float64 で計算し、差を < 1e−5 とする。
- **追加 S-engine**：グラフの 1 更新が eager と同じ計算であることを確かめる。勾配の float64 参照からの相対誤差が、eager の 4 倍以内であることとする。
- **追加 S-inert**：測定を入れた走と入れない走で、最終の重みがビット一致することを確かめる（S-probe の後半）。

### H. 段 0 の選び方の細目

- 「課題 1 の末で届く」と「更新 100 で易しすぎない」は、3 seed のすべてで満たすことを条件にする。
- 候補の α が複数あれば、本走全体の ETA を 10 時間以内に収められるものの中で最小の α を選ぶ。小さい α ほど文脈ごとに覚える情報が多く、乱数ラベルに近いからである。
- どの候補でも 10 時間を超えるなら、§9 に従って本走に入らず、候補ごとの見積もりを Issa に報告する。

### 0. 一行

FFN の入力からトークン間の平均（担い手の向き）を EMA で引く腕と、up の bias も外す腕を足す。担い手を塞ぐと、学び直す力が保たれるか（C3 対 C3H）と、塞いだあとに bias の経路が沈みを運ぶか（B3H 対 B3HB）を決める。MLP の扉 H・CH・CHB の Transformer 版である。

### 1. 経緯

- 事後解析 1（seed 0）で、FFN の担い手 K_n = ȳ·y_n はほぼ全トークンで正だった。最終層では、切替の期待の押しが生きた unit の 58〜81% で沈める側を向いた。
- LN が消すのはトークンの中の平均で、トークンをまたいだ平均は残る。なので LN では担い手は消えない（Neokunekune のセッションの見立て）。
- 消せるのは、トークン間の中心化と、β・bias の経路の抑制である。MLP ではこれが扉 H と扉 B に当たる（[[ReLUが沈む道を1本ずつ塞ぐ_relu_doors_結果_0919]]）。

### 2. 腕

| 腕 | 土台 | 変える所 | MLP の対応 |
| -- | -- | -- | -- |
| C3H | C3（LN γ のみ・bias なし・lr 1e−3） | 各 FFN の入力 y から EMA 平均 m を引く | CHB（bias がもともと無い） |
| B3H | B3（LN γ・β・bias あり・lr 1e−3） | 同じ中心化。up の bias は学習する | CH（bias の経路が開いている） |
| B3HB | B3 | 同じ中心化。up の bias を外す（恒等的に 0） | CHB |

- **中心化**：y は LN の affine の後、up の直前。m は特徴ごとの EMA で、勾配を通さず、訓練と評価で同じ値を使う。偏りの補正（Adam と同じ m/(1 − (1 − β)^t)）を入れる。
- **β = 0.1**（MLP の扉 H は 0.01）。箱 M は課題ごとに入力の分布が変わるので、0.01（時定数 100 更新）だと、押しが集まる切替直後の約 200 更新で m が遅れる（Neokunekune のセッションの反論 1）。
- **因果**：EMA は、その forward で中心化に使ったあとで更新する。同じ系列の未来のトークンは混ざらない（検査 S-causal）。
- **β の扱い**：β はトークンで共通なので、中心化が EMA 平均と一緒に引き去る。B3H に残る経路は up の bias だけである。
- **そのほか**：本走と同じ箱 M（α 0.01・N_M 10,000・50 課題・fresh は課題 10・25・50）、seed 0〜9。本走の C3・B3 と seed で対応させる。課題 1・10・25・50 の末の checkpoint には Adam の状態も保存する（切替直後の更新を後から再生できるように）。

### 3. 何を主な量にするか

**恒等式に近い量は主にしない。** C3H と B3HB では、probe の平均と m の差は EMA の遅れと標本の差だけなので、次の 3 つはほぼ構成から出る（Neokunekune のセッションの反論 2）。
- Q1 の負の割合
- 深い層の死亡率（トークン平均が 0 近くに固定されれば、全トークンで 0 以下にはなれない）
- B3H の |bᵢ|/|μᵢ|（β と m̂ の項を消した残りは bᵢ と遅れだけ）

**学ぶ力の族**（主比較 C3 対 C3H。現代の作りで、担い手を塞ぐと学び直しが保たれるか）
- L1：終盤（課題 41〜50）のオンライン超過損失。
- L2：悪化の大きさ Δ = 終盤 − 序盤（課題 1〜10）。
- L3：課題 50 の fresh gap。

**機構の族**（主比較 B3H 対 B3HB。中心化のあとに bias の経路が沈みを運ぶか。副比較 B3 対 B3H）
- M1：沈む速さ。負の割合の層平均の、課題 1〜10 の末での傾き。
- M2：課題 10・50 の末の負の割合。
- M3：深い層（第 2・3 層）の課題 50 の末の死亡率（B3H 対 B3HB の差を見る）。

**記録だけ**
- 切替直後 100 更新の Δμ/σ（層中央値）
- 中心化の遅れ ‖ȳ − m‖/‖ȳ‖
- up のノルム
- 課題 1・10・25・50 の末で事後に測る量：FFN 隠れ層の実効階数、unit ごとの開く割合のトークン間のばらつき、最終層の κ と切替の期待の押し、注意側の入力の共有成分

**検定**：本 spec §5 と同じく、seed で対応させた両側符号検定（n = 10）と対応差の平均 ± SE。「8/10 seed 以上」の規則で判定し、族ごとに Holm で補正する。

#### 0. 問い

#### 2. 操作の共通の形（受け手の L0 の ReLU に入る活動を置き換える。固定項は detach）
r_t(x) = 受け手の今の L0 前活性、r_0(x) = 受け手の出発点の凍結写しの L0 前活性、d_0(x) = 供与者の出発点の凍結写しの L0 前活性。凍結写しは各自の埋め込み・LN1₀・注意 0（残差加算込み）・LN2₀・W_up,0 を通す（受け手の LN 入力を共有しない）。各バッチ・各評価集合でその x について毎回計算する。
- 自己（対照）: ã = φ(r_0) + {φ(r_0 + (r_t − r_0)) − φ(r_0)}（実数では φ(r_t)。同じ演算経路を通すための対照）。
- β-FA（① しきい値の持ち上げ・開始時の活動を保つ形）: ã = φ(r_0) + {φ(r_0 + β + (r_t − r_0)) − φ(r_0 + β)}。開始時の W_down への入力は自然網と同じで、受け手の z に対する微分だけが持ち上げ後のゲートに変わる。β は固定。
- β-F（任意・報告のみ）: 自然な固定 bias z ← r_t + β（開始時に古い W_down の列からの書き込みが戻る）。
- F-swap（② 応答場の交換・CNN の c1 の交換と同じ補償つき）: ã = φ(r_0) + {φ(d_0 + (r_t − r_0)) − φ(d_0)}。移るのはゲート／局所微分の場で、供与者の全 Jacobian ではない。ã は負になりうるが、再び ReLU をかけない。
- F-swap-scale（尺度対照）: g_0 = c ⊙ d_0、c_i = s_R0,i / s_D0,i（較正集合で unit ごとに固定、正の倍率だけ）、ã = φ(r_0) + {φ(g_0 + (r_t − r_0)) − φ(g_0)}。課題 90 末の L0 の幅は C3-2 で 11.8〜22.2、cap で 0.30〜0.50（Astra の再集計）で数十倍違うため。c の上限・ゼロ幅の扱いは事前に決める。
- 実装の条件（批評 §4）: 凍結写しは deep copy、全パラメータ・buffer を不変、勾配を流さない、optimizer のパラメータ列から外す（Engine の graph 暖機・Adam 状態の復元が列の全パラメータを前提にしている点に注意）。参照の forward は no_grad（MLPKune は grad 有効時に V を更新する）。課題切替で R0・D0 を更新しない。埋め込みと head は共有なので、head の総勾配が開始時に不変とは仮定しない。

#### 8. 言わないこと（批評 §10 をそのまま採る）
- 回復比が 0.5 を超えても、cap による長期予防の半分以上を L0 の応答が自然に媒介したとは言わない（cap の履歴を保ったまま媒介変数だけを入れ替える自然な反実仮想ではない）。
- 救済はこの受け手・対象集合・開始点・期間での操作の効果。逆向きの悪化があっても、L0 の応答の喪失だけが喪失の十分条件・必要条件とは言わない。無作為に閉じた unit と自然に閉じた unit を同一視しない。
- 学びが変わっても、平均応答の「量」だけの効果とは言わない（ゲートの配置・入力依存性・境界からの距離・勾配の向き・後段と上流の適応を含む）。補償は開始時の予測差を消すが、その後の特徴・rank・予測の一致は保証しない。
- 同じ seed・同じ unit 番号は初期の対応であり、90 課題後の特徴の意味が揃っている保証はない。供与者の W_down・入力 Jacobian・Adam は移していない。交換が失敗しても、他の対応付けや別の層の応答の因果を否定しない。
- 固定するのは参照網で、z_eff と局所微分は入力と受け手の変位で動く。「静的な場だから応答を一定に保った」とは言わない。
- p < 0.005 は probe 依存の近死。ReLU では同じ集合上の微分の分散は p(1 − p) なので、開く割合と独立の証拠ではない。
- 操作が短期間しか成立しない場合の不救済と、成立・持続しても救済されない場合を区別する。初期改善と末尾の悪化を一つの「救済」に丸めない。
- 修復（課題 90）と早期の介入（課題 50）から、発症前の予防や 10 課題を超える保持を結論しない。2 ブロック・合成 2 次マルコフ・この lr/Adam・この seed 範囲を超えて一般化しない。
- 追補 7・下見・MLP/CNN の結果を知った上で設計した。登録が先行するのは新しい介入の成績に対してだけ。

### 9.B 確定した数（走る前、既存の数から）
- **p* = 0.3321**。課題 10 末の C3-2（追補 7、seed 0〜9）の unit_stats の鎖の probe で、L0 の unit ごとの開く割合 1 − mean(z < 0) の中央値を seed ごとに取り、その 10 値の中央値。seed 別は 0.308・0.331〜0.343・0.363。保存値は z = 0 を開く側に数える定義だが、float32 の ReLU 前活性がちょうど 0 になる割合は無視できるとみなす。複数の p* は試さない。
- **較正集合と検証集合**：課題 t₀+1 の鎖（主は t₀ = 90、副は t₀ = 50）から、`ChainM.sample(64, cpu_gen(seed, "row5", t₀+1, "calib"))[:, :128]` と `cpu_gen(seed, "row5", t₀+1, "valid")` で作る。それぞれ 64 系列 × 128 位置 = 8,192 トークンで、全位置を使う（既存の応答の計測と同じ。損失は最初の位置を除くので、これと違う点を明記する）。訓練データの列には触れない。
- **開く割合と D**：p_i = mean(z_i > 0)（厳密な不等号）。D = {i : p_i < 0.005}（較正集合、受け手の出発点の凍結写し）。
- **β**：i ∈ D は β_i = −quantile(r_0,i, 1 − p*)（torch.quantile の線形補間、8,192 トークン）。D の外は β_i = 0。r_0,i の分散が 0 の unit は β_i = 0 とし、数を報告する（課題 90・50 の保存値では 0 個）。
- **F-swap-scale の倍率**：c_i = s_R0,i / s_D0,i（較正集合での unit ごとの前活性の標準偏差、正の倍率だけ）。安全規則として、s_D0,i < 10⁻³ または c_i > 1,000 の unit は c_i をその seed の c の中央値に置き換えて数を報告する。保存値では s_D0 の最小は 0.10、c は 7〜194 で、この規則に当たる unit は 0 個の見込み。幅の一致の誤差（較正集合で std(c_i d_0,i) / s_R0,i − 1）を記録する。
- **D の大きさ（参考、較正集合）**：課題 90 末の C3-2 で 0〜490 unit（seed 4・8 は 0 = 無介入 seed）、課題 50 末で 3〜338。
- **主の課題数**：課題 91〜100（10 課題）、副は課題 51〜60。β-F は報告のみで族に入れない。§9 の保留の腕は入れない。

### 9.C 実効学習率だけを保つ腕 ELR（Issa の承認、V13 セッション経由、走る前に追記。9.A §5 の 4 比較の族には入れない別の確認的比較）
- 文字どおりの形（cap なしで L0 の lr を unit ごとに ‖w‖/‖w₁‖ 倍）は ‖w‖ を指数で発散させる（V13 セッションの見積もり：約 6.8 課題ごとに e 倍、課題 20 で 10〜30 倍）。主の腕には使わず、短い診断だけを回す。
- **ELR**：受け手 C3-2、seed 0〜9、課題 1 末（重み＋Adam）から課題 2〜100。L0 だけに当てる（L1 は素のまま。cap は両層なのでこの違いを記録）。
  - 各 Adam の更新のあと、L0 の W_up の各行を課題 1 末のノルム ‖w_i,1‖ に射影し直す（NaP と同じ。lr/‖w‖ が課題 1 の値に保たれる）。射影は更新の半径方向の成分も消す。
  - L0 の前活性に、学習しない正の倍率 k_i(t) を掛ける（φ(k_i z_i)）。k_i(t) = ‖w_i^{C3-2}(t)‖/‖w_i^{C3-2}(1)‖ で、同じ seed の C3-2 の unit_stats の rownorm（各課題末、全課題）を、課題の中で更新ごとに線形補間する（√t 則の当てはめは使わない）。
- 操作の成立：L0 の課題ごとの回転 1 − cos の中央値が、C3-2 の中央値の 10 倍以上（課題 40〜50・90〜100）。L0 の出力の RMS（課題 t の鎖の probe）が C3-2 の ±20% 以内。C3-2 の参照値は保存済みの checkpoint（課題 39〜50・89〜100）から同じ probe で計算する。
- 判定：追補 7 と同じ対称の規則。課題 91〜100 の 3 相（T015・E1000・ELast）すべてで C3-2（追補 7 の走）より良い seed が 8/10 以上で `ELR_RESCUES`、すべて悪い seed が 8/10 以上で `ELR_HARMS`、それ以外は `MIXED`。符号検定の p と対の差の中央値を併記。ELR − ReLUcap-2 の差は記述のみ。
