| 箱 | ホスト | 網 | データ | 1 タスク |
|---|---|---|---|---|

## 2. 活性化

- **Swish** φ_α(z) = z·σ(αz)。`SW1`（α=1 = SiLU）、`SW3`（α=3）。
- **適応αSwish** `SWA1`・`SWA3`: α_j = clip(c/W_j, 1e−3, 1e3)、W_j = √EMA_β[var z_j]、β=0.01、c = 1・3。
  統計・粒度（fc はユニット、conv はチャネル、位置で共有）・β は SNA と同じ。α は detach。
  - Swish は尺度共変: φ_{α/s}(sz) = s·φ_α(z)。α=c/W ならゲート φ′ は u = z/W だけの関数 g(cu)。
  - g(x) = σ(x)(1 + x(1−σ(x)))。g=0 は x = −1.278（φ の最小点）、g の最小 −0.0999 は x ≈ −2.40、x→−∞ で 0⁻。
    適応では、反転域（φ′<0）は u < −1.278/c、ゲート最小は u ≈ −2.40/c に固定される。
  - clip を広く取るのは、Snake の hi=3 が周期を入力の尺度より細かくしないためのもので、周期のない Swish には要らないから。当たった割合は `alpha_clip_frac_*` に残す。
- **`SNAc3`**: ホストの SNA を c=3 で（2αW=6。clip はホストの既定: MLP [0.05, 3]・CNN [0.005, 3]）。
  CNN の c1 は W≈0.2 なので α=15 が hi=3 に当たり、SN3 と同じ α=3 になる。c2・f1・f2 だけが SN3 と違い、2αW=6（SN3 は 4.6 / 40 / 77、t41–50）。

## 3. 腕と装置

| 箱 | 装置 | 新しく走らせる腕（×10 seed） | 再利用する参照 |
|---|---|---|---|
| `cnn` | GPU（参照と同じ RTX 5060 Ti・torch 2.13.0+cu130） | `SNAc3` `SWA1` `SW1` `SWA3` `SW3`（この優先順） | `rlcifar_cnn_0908` の `SNA` `SN06` `SN3` `LR` `R` |
| `mlp` | CPU 1 スレッド | `LR` `SNA` `SN06` `SN3` `SNAc3` `SW1` `SW3` `SWA1` `SWA3` | `pmnist_rlmnist_0906` の `R`（GPU）。`LR`・`SNA` の GPU 版は装置の照合に使う |

- CNN を GPU に置くのは、参照 5 腕が同じ GPU で bit 一致で再現する（§4 S-reuse）から。CNN の CPU は 1 スレッドで GPU の数分の一の速さ。
- MLP を CPU に置くのは、GPU を CNN に回すため（MLP はカーネル起動律速で CPU 1 スレッドが GPU 1 プロセスより速い: 19 s 対 30 s / タスク）。MLP の比較は `R` を除き CPU の中で閉じる。
  `R` は GPU の参照を使う（t3 で崩壊済みで、CPU では死んだユニットの subnormal 演算で数倍遅くなる）。
- 装置の照合: MLP の `LR`・`SNA` を CPU と GPU で比べ、装置の違いが雑音（偏りなし）に収まるかを見る（§5 の D）。

## 4. 検査（`src/swish_battle_0917_checks.py`、本走の前に all_pass）

- **S-act**: φ′ の解析式 = autograd（float64、固定・適応の両クラス、1e−12）。変異: ゲートから a z s(1−s) の項を落とすと検出される。
- **S-scale**: φ_{α/s}(sz) = s·φ_α(z)、φ′_{α/s}(sz) = φ′_α(z)。変異: σ(αz) → σ(αz + 0.1z) で検出（定数ずらしは αz が尺度不変なので検出されない）。
- **S-ema-off**: β=0 の `SWA<c>` はホストの run_one を通して `SW<c>` と全列一致（両箱・c=1,3）。変異: β=0.01 なら学習列がずれる。
- **S-fresh**: 同じプロセスで `SWA1` を 2 回走らせて一致（状態の持ち越しなし）。
- **S-wiring**: 短い適応走のあと V が動き、α·W = c、捕捉した最終重みの logits が「層 l に α_l を当てる独立 forward」と一致し、記録された memo_acc と再計算が一致する（宿主の評価関数の取り違え対策）。変異: 2 層の α を入れ替えると logits が変わる。
- **S-reuse**（GPU）: 無改変のホストが保存済みの参照行（CNN の SNA・LR、MLP の SNA、seed 0・task 1）を csv の 10 桁で全列再現する。検出力: 同じ行が seed 1 の行とは食い違う。
  予備実行（01:44–01:48 の手動実行）で CNN SNA 63 列・CNN LR 43 列・MLP SNA 35 列が全一致した。

## 5. 読み出し

窓はホストの判定と同じ **タスク 31–50 の online_acc**（1 タスク内の更新前正解率の平均）。
副: タスク 1–10 → 41–50 の低下、memo_acc、崩壊タスク（online<0.5 の最初のタスク、seed の中央値）、サイト別の mob（φ′ の平均）、α と α·W、標準化深さ c·z̄/W（`zbar`/`zsd`）。

同じ装置の対は seed 対応の符号検定（ホストの `sign`、「勝ち」は負けが 1 seed 以下かつ p<0.05）。装置をまたぐ対（MLP の `R`）は対応なしの平均差だけを示す。

**判定は 3 つ。**

- **A. CNN の SNAc3**（前のターンの診断の判別）。q = mean(SNAc3−SNA) / mean(SN3−SNA)（同じ GPU・seed 対応）。
  - `C_VALUE`: SNAc3−SNA が勝ち、かつ q ≥ 0.5 → SNA の負けは c の値（谷の位置）で説明できる
  - `PARTIAL`: 勝ちだが q < 0.5
  - `ADAPTATION_COST`: 勝ちでない（q は併記）→ 負けは適応そのものの代償
  - `WORSE`: 負け
  0.5 は二つの仮説の予言（SNA 並み・SN3 並み）の中点。
- **B. 適応の効果**（両箱、c=1・3）: SWA_c − SW_c → `ADAPT_WINS` / `ADAPT_LOSES` / `TIE`。
- **C. バトル**（両箱）: 窓の平均で全腕を順位付けし、SWA の良い方と SNA・LR を対で比べる → `SWA_ABOVE` / `SWA_BELOW` / `TIE`。
- **D.（装置の照合・報告のみ）** MLP の LR・SNA について CPU と GPU の窓の平均の差と、seed 間の散らばり。

## 6. 事前予測

### Claude（Opus 5、本走の前）

根拠: CNN の診断（SNA は全サイトで φ′ の谷に座る）、`relu_gelu_silu_rl_0914` の固定 SiLU（80 epoch/タスクの RL-MNIST で 3 seed 中 2 本が t47–50 に床、第 2 層 z̄₂ −34・反転域 55%）、V10 の標準化深さの有界性（崩壊層は d≈−3）。
