## 1. 問い

中心化（CH′）と bias 抑制（B）の損益は、活性化と課題あたりの予算で符号が変わるか。

- 入力が固定の乱数ラベルの MLP・CNN では、中心化が大きく助けた。
- 入力分布が課題で変わる箱では逆が出た。文字 GPT（10,000 更新/課題）では、中心化した腕は沈まないのに学ぶ力が土台より悪かった。5+1 CIFAR MLP でも、CH − R は標準予算の +0.116 から 10 倍予算の −0.086 へ反転した（V12 付録 G.2）。
- 読みの候補は次のとおり。沈降が死まで進む箱では、経路を塞ぐ利益が勝つ。浅く止まる箱では、閾値を置き直せない害が勝ち、害は幅とともに育つ。

この箱の土台は、活性化で沈降の深さが違う（`results/cifar5p1_cnn_budget_1019/summary.md`）。

| 土台 | 予算 780 | 予算 7800 |
|---|---|---|
| ReLU の FC2 の死の割合 | 0.85 | 0.94 |
| ELU α3.6 の FC2 の r | −0.19 | −0.73 |
| ELU α3.6 の FC2 の局所応答 φ′ | 0.65 | 0.27 |

ELU は 7800 で学び直し（最初の 780 更新の online）が 780 より 1.17 pt 低い。死は 0 のままである。
したがって、ReLU は塞ぐ利益が勝つ側、ELU は長い予算で塞ぐ害が出る側と予測できる。本走はこの 2×2（活性化 × 予算）を試す。

- 中心化と B は 1 つの腕にまとめて入れる。どちらが効いたかはこの走では分けない。
- seed 2000〜2009 は前段で見た seed である。独立した新規 seed での追試とは呼ばない。
- 予算 2340 は回さない。

## 3. 腕・予算・束

| 腕 | 活性化 | CH′＋B | lr |
|---|---|---|---|
| RCB | ReLU | あり | 3e−4 |
| ECB | ELU（α = 3.6） | あり | 3e−4 |
| R | ReLU | なし（前段の R と同じ） | 3e−4 |
| ELU | ELU（α = 3.6） | なし（前段の ELU と同じ） | 3e−4 |

- lr は前段と同じ 3e−4 で、再較正しない。
- 予算は 780 と 7800 更新／課題。seed は 2000〜2009。
- 1 予算 = 4 腕 × 10 seed = 40 run を、R = 40 の束 1 つで回す。束の並びは RCB、ECB、R、ELU の順で、腕の中は seed 昇順。

### 3.1 土台を束に同居させる理由

依頼は「土台の R・ELU は既存走を再利用し、数 seed で一致を確かめる」である。本走では、土台の 20 run を同じ束で計算し直し、全 seed・両予算で前段とのビット一致を確かめる（S-reuse、§8）。理由は 2 つある。

1. 束の大きさ R が変わると、group conv のアルゴリズムの選び方が変わりうる。R = 20 の束で数 seed を回して一致しなくても、原因が実装か束の大きさかを分けられない。前段では R = 40 の束どうしで、腕の組み合わせを変えてもビットで一致した（前段 S-reuse-780、1200 行 × 41 列、不一致 0）。
2. 一致しなかった場合も、同じ実行形の土台が手元に残る。

増えるのは GPU の計算だけである。

S-reuse が `PASS` なら、束の中の土台は前段の軌道と同一として扱う。`FAIL` なら列ごとの最大の差を記録し、主の比較には束の中の土台（同じ実行形）を使う。この扱いは本走の前に決めておく。

## 4. CH′＋B の移植

### 4.1 入力の C は入れない

Codex の C は「CIFAR-10 の train 5 万枚の色のチャネル平均を引く」である。この箱の入力は、すでに CIFAR-100 の train の色のチャネル平均（4 桁に丸めた定数）を引いて標準偏差で割ってある。

- 標準化した train 5 万枚のチャネル平均は (−9.3e−5, 1.9e−4, 6.5e−5) で、チャネルの SD は 1.000 である（2026-10-20 に計算）。
- クラスごとのチャネル平均のばらつき（SD）は 0.23〜0.30 である。これが課題で入力平均が変わる分で、Codex の spec でも C は引かない（subset 別の平均は引かない）。

したがって C は、この箱ではほぼ恒等である。残りの 2e−4 を引くと入力のビットが土台と変わり、S-reuse が使えなくなる。C は入れず、「中心化」は H′ と B の 2 つを指す。

### 4.2 H′（全特徴の中心化）

`src/cnn_center_feat_1011.py` の `feat` 型と同じ規則にする。

- c1・c2 の後: pool 後の各チャネル × 位置の EMA 平均 m を引いてから次の層へ渡す。c1 は 16 × 16 × 16、c2 は 16 × 8 × 8。平均は画像の軸だけでとる。並びは (channel, y, x)。
- f1・f2 の後: unit ごとの EMA 平均を引く。f2 の後の値は読み出し f3 へ入る。
- EMA: m ← (1 − β) m + β · bm、β = 0.01、初期 0、勾配なし、課題の境で保持する。bm はその更新の訓練 forward（更新前の重み）の、中心化前の出力のミニバッチ平均である。
- 順番: 訓練 forward → 勾配 → Adam → EMA。forward は更新前の m を使う。
- online・test・切替 CE・probe の診断は、その時点の m で行う。
- 活性化は ReLU・ELU の各腕の φ をそのまま使う（ReLU は前段の `torch.relu`）。

### 4.3 B_width（現在の幅に合わせた bias の射影）

Codex の spec §6.3 と実装 `project_bias` の規則にする。

1. 毎更新、Adam と EMA の後に、同じミニバッチの画像をもう一度 no_grad で前へ通す。EMA も乱数も更新しない。
2. c1 → c2 → f1 → f2 の順に、その層までの補正を反映した入力で、bias を加える前の q = W ∗ h_in を計算する。
3. 幅 s を q から求める。conv はチャネル c・位置 p ごとにミニバッチの画像の軸の母分散 v_{c,p} をとり、s_c = √(mean_p v_{c,p}) とする。fc は unit ごとの画像の軸の母 SD。統計は float64 で計算する。
4. b_c ← clip(b_c, −κ s_c, +κ s_c)、κ = 0.2。上限の内側の bias はビットを書き換えない。s = 0 なら b = 0。
5. 補正後の bias で z = q + b を作り、活性化・pool・現在の m を通して次の層へ進む。f3 の bias には掛けない。

- 最初の訓練 forward は初期化の bias を使う。B は最初の Adam 更新の後から入る。
- B は勾配を作らず、W・Adam の m と v・更新番号を変えない。
- **Codex の実装との違い（2 点）**。
  - 丸め: Codex は float64 の clip を float32 へ最近接で丸めるので、上限を半 ulp まで越えうる。本走は、丸めた値が上限を越えたときだけ 0 の方向へ 1 ulp 戻す。これで |b_c| ≤ κ s_c が許容幅なしに成り立ち、S-proj を許容幅なしで判定できる。
  - 発散: Codex は非有限の q・幅・bias で走全体を止める。本走は前段のエンジンの run ごとの発散の記録に従い、その run を発散と記録して他の run は続ける。
- この操作が抑えるのは、ミニバッチ上のチャネル幅に対する bias の比である。全入力・全位置で同じ上界が成り立つとは主張しない。固定 probe での比を別に測る（§6.2）。
- bias の変更は unit の幅を変えず、平均 m を同じ量だけ動かす。r = (a + b)/s の a/s や s そのものは保たない。bias 支配を抑えたことと、r・応答を保ったことを同一視しない。

### 4.4 実行形

EMA と射影を、捕捉する 1 更新の CUDA graph の中に入れる。演算はすべて形が固定で、ホストとの同期を含まないので捕捉できる。束の中で中心化のない run は m を 0 のまま保ち、射影も掛けない。m = 0 を引く演算はビットを変えない（x − 0 = x）。

束の全 run が中心化なしのときは、前段のエンジンと同じ演算列を通す（検査 S-off）。graph と eager の一致は S-graph で確かめる。

## 6. 測る量

### 6.1 前段と同じ量

前段 §5 の量を同じ定義で測る。

- 固定 probe（2,000 枚）での 4 site の unit ごとの m・s・r・φ′ の平均・p⁺・死・低応答・出力 0・実効ランク。測る時刻は初期状態と各課題の末（境界 0〜30）。
- 各課題の開始前と終了後の、その課題の訓練画像での同じ量。
- online（最初の 100 更新・最初の 780 更新・課題全体）、課題末の train・test 精度、切替 CE。
- 課題 9・19・29 の fresh 対照。fresh は初期値・Adam 0・更新番号 0・m = 0 から、同じ課題・同じ batch 列・同じ予算で学ぶ。中心化の腕の fresh も CH′＋B を入れて学ぶ。
- 境界 0・1・8・9・18・19・28・29・30 の完全な状態（重み・Adam・m の EMA・活性化の状態）。

### 6.2 新しく測る量

- **p⁺ の全配列**: unit ごとの p⁺ を、正の標本の数（整数）と標本数で全境界に保存する。
- **開く割合の区分**: 6 つの区分に分ける。p⁺ = 0、(0, 0.05)、**まばらな検出器 [0.05, 0.3)**、[0.3, 0.7]、(0.7, 0.95)、[0.95, 1]。境目は整数の比較で判定する（例: p⁺ < 0.05 ⇔ 20 × 正の数 < 標本数）。区分は `mlp_center_x10_1020` の spec と同じである。
- **射影の発火**: 毎更新・site ごとに、上限に当たった unit の割合（run ごと）。課題ごとに unit ごとの発火回数と、射影前の |b|/s の最大。
- **bias / 幅の比（probe）**: 各境界で、固定 probe 上の bias なしの q から幅 s_q（§4.3 と同じ定義を probe 全体で）、q の平均 a、bias b を求める。b/s_q、a/s_q、(a + b)/s_q を unit ごとに保存する。
- **EMA の遅れ**: 各課題の更新 0・1・3・10・30・100・300・780・2340・7800（予算以下）の時点で、その課題の訓練画像全部での中心化前の出力の平均 x̄ と、その時点の m から、‖x̄ − m‖ / ‖x̄‖ を site ごとに求める。更新 0 は切替の直後、学習の前である。毎更新のミニバッチ版 ‖bm − m‖ / ‖bm‖ も記録する（バッチの雑音を含む記述量）。
- 統計は float64 で集める。中央値どうしの積から m を復元しない。

## 7. 登録する判定

主量は後期 hard 課題（21, 23, 25, 27, 29）の seed ごとの平均である。比較は同じ seed・同じ予算の対応差で、精度は pt（百分率の点）で表す。

### 7.1 主の判定

**D = 中心化の腕 − 土台の腕** の、後期 hard 課題の最初の 780 更新の online。4 セルで判定する。

| セル | 中心化の腕 | 土台 | 予算 |
|---|---|---|---|
| ReLU・780 | RCB | R | 780 |
| ReLU・7800 | RCB | R | 7800 |
| ELU・780 | ECB | ELU | 780 |
| ELU・7800 | ECB | ELU | 7800 |

- 検定は seed の対応符号検定である。厳密な両側の二項検定で、D = 0 の seed は除く。
- 4 比較に Holm をかけ、p_holm < 0.05 なら判定を出す。向きは正の seed 数と負の seed 数の多い方で決める。正が多ければ `CENTER_HIGHER`、負が多ければ `CENTER_LOWER`、それ以外は `TIE`。
- seed 10 本の厳密な符号検定の p は、10/10 で 0.00195、9/10 で 0.0215、8/10 で 0.109 である。したがって Holm の最初の棄却には 10/10 が要る。
- 発散した run の seed はそのセルから除き、残りの seed 数を記す。全 run の完走が前提で、欠けのあるセルは `INCOMPLETE` とする。
- 記述として、D の平均・中央値・seed ごとの値と、seed の percentile bootstrap の 95% 区間（`default_rng(1020).integers(0, 10, size=(20000, 10))` の添字行列を全量で共有）を出す。

### 7.2 副の比較

符号検定（厳密・両側・D = 0 の seed を除く）で記述する。Holm はかけない。

1. **交互作用**: seed ごとの I = (D_ELU,7800 − D_ELU,780) − (D_ReLU,7800 − D_ReLU,780) の符号。あわせて、ELU の D_7800 − D_780 と ReLU の D_7800 − D_780 のそれぞれの符号。
2. **FC2 の幅**: 境界 21〜29 の末の平均での、FC2 の unit の s の中央値の log の差（中心化 − 土台）。4 セル。
3. **まばらな検出器**: 同じ窓での、FC2 の p⁺ ∈ [0.05, 0.3) の unit の割合の差（中心化 − 土台）。4 セル。

### 7.3 記述（判定ではない）

最初の 100 更新と課題全体の online、test 精度、課題 9・19・29 の fresh − 継続、4 site の r・φ′・p⁺・死・低応答・実効ランクの境界ごとの軌道、開く割合の 6 区分、射影の発火率と bias / 幅の比、EMA の遅れの切替後の推移。

## 8. 実装と検査

新しいモジュール `src/cnn_center_budget_1020.py` が前段の `BudgetEngine` を継承し、H′ と B_width を run ごとに足す。検査は `src/cnn_center_budget_1020_checks.py` で、各検査にわざと壊した変異を付けて検出を確かめる。許容幅は演算の丸めから導き、固定の倍率を置かない。ビットの一致を求める検査には許容幅を置かない。

| 検査 | 本物で要求すること | 必ず検出する変異 |
|---|---|---|
| S-prefix | batch 列の sha256 が前段の `batch_hashes.json`（780・7800、seed 2000〜2009）と一致 | 延長部分を共有 stream から引く |
| S-off | 束の全 run が中心化なしのとき、前段の `BudgetEngine` と状態がビット一致（予算 780、1 課題） | batch を 2 つ入れ替える |
| S-reuse-smoke | 本走と同じ束（R = 40）で課題 1 を回し、R・ELU の 20 run の毎更新の CE と正誤が前段の生データ `b780/steps/t01.npz` とビット一致 | 土台の run に m の EMA を掛ける |
| S-center | m の EMA の形（並び・画像の軸だけの平均）・β・更新順・課題の境での保持が `cnn_center_feat_1011.FeatDoors` とビット一致。訓練の 1 更新を独立に書いた eager の参照（forward は更新前の m、EMA は更新前の z）と一致 | 位置も平均する／課題の境で m を 0 に戻す／更新後の z で EMA |
| S-proj | 射影後の \|b_c\| ≤ κ s_c が全更新・全 unit で成り立つ（許容幅なし）。Codex の `project_bias`（ReLU の run）と、丸めを 0 方向へ戻した unit を除いてビット一致。上限内の bias・W・f3 の bias・Adam の m と v は射影で変わらない。幅の計算を独立の float64 の参照と照合し、幅が 100 倍違う 2 チャネルと位置の平均だけが違う fixture で確かめる | 層の中央値の幅を全チャネルへ／画像 × 位置の全分散を幅に使う／全層の幅を補正前に一括で測る／固定の絶対上限 |
| S-graph | 中心化の束で CUDA graph と eager の状態がビット一致（課題 1 全部と課題 2 の 100 更新） | — |
| S-pure | 診断（probe・訓練画像の統計、bias / 幅の比、EMA の遅れ、CE・精度）が重み・Adam・m・記録を変えない | 診断で EMA を進める |
| S-resume | 課題 1 の後で止めて再開した結果が、止めない結果とファイル・状態ともに一致 | 再開で m を落とす |
| S-fresh | fresh が初期状態（m = 0 を含む）から課題の batch 列で学び、2 課題の走で継続の課題 1 を再現する | — |
| S-stats | p⁺ の正の数・6 区分・bias / 幅の比の集計を、同じ z・q からの独立の float64 の参照と照合。整数の数は完全一致、float64 の和は和の丸めの上界の内側 | 最初の chunk だけで数える |

- 本走の中でも S-proj を毎更新で数え、1 回でも越えたら走を `CHECK_FAILED` で止める。
- 本走の後、verdict で **S-reuse** を判定する。R・ELU の 600 行 × 2 予算の `per_task.csv`、`probe_stats.csv`（前段と共通の列）、`fresh_control.csv` を、前段の `b780`・`b7800` とビットで照合する。
- **smoke** は seed 100、課題 3、両予算で 1 腕ずつ（780 は RCB、7800 は ECB）。計時と出力の形の確認に使い、性能の根拠にはしない。束の大きさ 40 の計時は S-reuse-smoke で取る。
