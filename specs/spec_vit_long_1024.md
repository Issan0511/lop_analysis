## 0. 一行

原典の ViT から LN を外した N セル（ReLU・乱数ラベル 250 枚）を 60 課題 × 500 更新に延ばし、head の扱いだけを変えた 2 腕を、同じ seed 0〜4 で対にして回す。腕 R0 は原典どおり課題ごとに head を 0 に戻す。腕 S は課題 1 の後は戻さず、課題 1 の 5 行を全課題で使う。原典の手順では、課題の最初の一歩で体への勾配がちょうど 0 になる。前課題の読み出しが新課題の誤差を体へ運ぶ道（段①の切替の押し）が無い。S はその道を開く。喪失は暗記率が 0.9 に届くまでの更新数 T90 で測る。課題末の重みを全 60 課題で残し、走った後で S の切替の押しの向きを当てる。

## 1. 問い

- **Issa の判断（1024）。** LN なしの箱（factorial の N セル）は喪失を出したが、40 課題 × 500 更新では 10 seed 中 4 seed が崩れ切らなかった。そこで課題数を 60 に延ばし、指標を到達時間 T90 に替え、課題末の重みを残す。時間を縮めるため、課題あたりの更新数は 500 のままにし、腕は LN なしの 2 つに絞った（案 B）。LN ありの腕と実ラベルの腕は回さない（§4.4）。
- **背景（1024 に分かったこと）。**
  - 原典の手順は、課題の始めに head の 200 行を 0 にし、損失を新課題の 5 行に限る。最初の更新では logit がすべて 0 で、体への誤差 ∂L/∂h = Wᵀ(p − y) はちょうど 0 になる（§4.6）。
  - だから、前課題の読み出しが新しいラベルの誤差を体へ運ぶ道が無い。N セルの喪失は、段①（切替の押し）の相 1 が無いまま起きた喪失である。
  - Dohare et al.（Nature 2024）の Continual ImageNet も、head を課題ごとに 0 へ戻す。Methods はこれを標準の慣行とし、可塑性の研究には理想的でないとも書いている（1024 の Fable の読み）。
  - 共有と戻すを同じ箱で並べた先行例は、1024 の検索では見つからなかった。
- **この走の問い。**
  1. head を共有して段①の道を開くと、後期の課題を学ぶ力は R0 より落ちるか（J0、主）。
  2. 60 課題で、各腕は到達時間で見て喪失するか（J1）。
  3. 課題 60 の末に、FFN の unit は死んでいるか（J3）。
  4. S では、最終ブロックの FFN の CLS 位置への切替の押しが、unit を沈める向きに揃うか（J5。走った後に保存状態で計算する）。
- **Issa の向き（1024 の発言）。** 「head を戻さないとすぐ壊れるのでは」。
- **記録に下げた問い。** 課題の中で幅が伸びるか（草案の J2・J2b）は、判定にせず記録だけにする（§7.5）。U = 500 では、当てはめた後の期間が短いからである。

用語（初出で言葉を添える）:

- **online 正解率**: 各更新の前のミニバッチ正解率を、課題の中で平均した量（battle と同じ）。訓練の状態で測るので、拡張と dropout が入る。正解は損失の行（下）の 5 つの argmax で数える。
- **損失の行**: head の 200 行のうち、損失と正解率に使う 5 行。R0 は課題 t の 5 クラス classes_t の行、S は全課題で課題 1 の 5 クラス classes_1 の行である。乱数ラベル y ∈ {0, …, 4} を、その 5 行の y 番目へ写す。
- **暗記率**: 課題の訓練画像 250 枚を評価の状態（dropout なし・拡張なし）で通し、損失の行の argmax が乱数のラベルと一致する割合。
- **T90**: 課題の中で暗記率が初めて 0.9 以上になる更新数。25 更新ごと（u = 25, 50, …, 500）に測る。250 枚では 225 枚以上が当たることに当たる。500 更新までに届かなければ「未到達」とし、数値は 525（= U + 25）として扱う。
- **T・U**: 課題数（60）と、課題あたりの更新数（500）。
- **up 行**: FFN の最初の線形層 fc1 の行 w_j。unit j への 384 次元の入力重みである。
- **probe**: seed ごとに固定した検証画像 64 枚。1 枚は 65 token（CLS と 64 patch）なので、4,160 位置になる。
- **死（J3 の量）**: probe の全 4,160 位置で z > 0 になる割合 p が 0.005 未満の channel。4,160 位置のうち 20 位置以下でしか開かない channel である（依頼文では「完全死」と呼んだ）。p = 0 の channel は「厳密な死」として別に記録する。
- **頭と胴**: 課題の最初の 100 更新（頭）と、残りの 400 更新（胴）。
- **CLS 位置**: token 0。head は最終の正規化（この箱では恒等）の後の CLS 位置だけを読む。

## 4. 腕と箱

### 4.1 箱（N セルから変えないもの）

- **模型**: `analysis/joudaki_vit_battle_0919/model.py` の `make_model('R', seed, device, config)` を、factorial の `cell_config(4.0, 'none')`（N セル）で呼ぶ。上流の vit.py を無改変で使い、6 つの FFN の活性化だけを `R`（ReLU。`src/rlcifar_mlp_battle_0918.make_act('R')`）に替える。patch 8、埋め込み 384、6 ブロック、6 head、FFN 1536（mlp_ratio 4）、CLS、qkv の bias、dropout と attention dropout 0.1。
- **正規化**: `normalization='none'` で、上流の `get_normalization` が norm1・norm2・最終 norm の 13 か所を `nn.Identity` にする。パラメータは 10,814,024 個（1024 に GPU の模型で数えた）。
- **初期値**: `torch.manual_seed(seed)` の後に上流の `_init_weights`（trunc normal 0.02、bias 0）。同じ seed の R0 と S は初期値が一致する。
- **学習**: Adam（lr 1e−4、β 0.9 / 0.999、ε 1e−8、weight decay なし、fused）。Adam の moment は head も含めて課題をまたいで持ち越す（原典どおり）。battle の `train_forward` で `torch.compile(fullgraph=True)` にし、`fallback_random=True` で dropout の ATen 乱数列を保つ。float32、TF32 無効、`torch.use_deterministic_algorithms(True)`、`CUBLAS_WORKSPACE_CONFIG=:4096:8`。batch 128、warmup なし。勾配の clip はせず、非有限の検出だけを行う。
- **compile の形と再開**: 250 枚を batch 128 で回すので、batch の大きさは 128 と 122 が交互に来る。compile は最初の 128 で大きさを固定した graph を、最初の 122 で batch の次元を動かせる graph を作り、以後はすべて後者を使う。この 2 つの graph の勾配は、丸めの分だけ違う（1024 に測った。最大の差 1.4e−9）。だから途中の課題から再開するプロセスは、学習の前に 128 と 122 の batch で forward と backward を 1 回ずつ通す（乱数の状態は戻し、勾配は捨て、Adam は進めない）。こうして、続けて回したプロセスと同じ graph を持たせる（§8 の S-resume で確かめる）。
- **拡張**: 8 の pad と 64 の crop、反転 0.5、明るさ・コントラスト・彩度の jitter 0.1 をランダムな順で掛ける（Pillow の `transform`）。評価は拡張なし。標準化は ImageNet の mean と std。
- **乱数の stream**（どれも `stream_seed(...)`、sha256 の先頭 8 byte）: batch の順は `('batch', seed, task)`、拡張は `('augment', seed, task, step, idx)`、loader は `('loader', seed, task)`、乱数ラベルは `('randlabel', seed, task)`。どれも学習の履歴によらず、(seed, task) だけで決まる。dropout だけは大域の CUDA 乱数から順に引く。
- **乱数ラベル**: 各課題で 250 枚に {0, …, 4} の一様な iid のラベルを引き直す（randlabel の `random_labels`）。250 枚を batch 128 で回すので、1 epoch は 128 枚と 122 枚の 2 batch になり、500 更新は 250 epoch である。

### 4.2 40 課題を超える課題列

- Tiny ImageNet は 200 クラスなので、重複しない 5 クラスの課題は 40 個しか作れない。
- 課題 t の巡回の番号を c = ⌊(t − 1)/40⌋、巡回の中の位置を i = (t − 1) mod 40 とする。
- **クラスの組**: c = 0 は `task_classes(seed)`（battle と同じ）。c ≥ 1 は、200 クラスを `random.Random(stream_seed('cycle', seed, c))` で混ぜて 5 個ずつに切った 40 組を使う。
- **画像**: 各クラスの訓練画像（path の順に並べた 500 枚）の 50c + 1 番目から 50c + 50 番目を使う。1 課題は 5 クラス × 50 枚 = 250 枚になる。
- この並べ方では、どの訓練画像も 2 つの課題に出ない。T = 60 は巡回 0（課題 1〜40）と巡回 1（課題 41〜60）を使う。
- 課題 61（巡回 1 の位置 20）は学習に使わない。J5 の課題 60 の末の probe にだけ使う（§7.4）。
- 巡回 0 の画像とラベルは、randlabel・N セルの `make_task_dataset` とビットで一致する（§8 の S-stream）。
- 巡回ごとにクラスの組を混ぜ直すのは、40 課題ごとに同じ 5 クラスの画像分布が戻る周期を作らないためである。
- 乱数ラベルでは、クラスの名前はラベルの情報を持たない。クラスが別の巡回で再び出ても、画像とラベルは新しい。

### 4.3 腕

| 腕 | head を 0 にする時 | 損失と正解率の行 | 乱数ラベル y の写し先 | 役割 |
| --- | --- | --- | --- | --- |
| **R0**（戻す） | 各課題の始め（課題 1 を含む）に、200 行の重みと bias | classes_t | classes_t[y] | 原典の手順。N セルを 60 課題に延ばしたもの |
| **S**（共有） | 課題 1 の始めだけ | 全課題で classes_1 | classes_1[y] | 前課題の読み出しを新課題の損失に残し、段①の道を開く |

共通: T = 60、U = 500、seed 0〜4、LN なし、ReLU、FFN 1536、乱数ラベル 250 枚（§4.2）、Adam 1e−4（moment は持ち越す）、batch 128、dropout 0.1、float32・TF32 無効、compile と fused Adam。

- 同じ seed の R0 と S は、初期値・画像・ラベル・batch の順・拡張・dropout の乱数が一致する。dropout の乱数は大域の CUDA 乱数から順に引かれ、1 更新に引く数は腕によらない。
- 課題 1 では 2 腕の計算が同じなので、課題 1 はビットで一致するはずである（§8 の S-arm1）。違いは課題 2 の始めからで、S では head が課題 1 の末の値のまま残る。
- S の残りの 195 行は勾配を受けないので、0 のまま動かない。R0 では前課題の行が 0 に戻された後も Adam の 1 次 moment で少し動くが、損失の外にあるので学習に入らない（原典と同じ）。
- S では、同じ 5 行が 60 課題の間ずっと学び続ける。乱数ラベルではクラスの名前は情報を持たないので、どの 5 行を使うかは学習に関わらない。
- 課題 1 の最初の 500 更新は、R0 でも S でも、N セルの課題 1 と同じ初期値・画像・ラベル・batch の順・拡張を通る。参照値は別のマシンで出たので、ビットの一致は期待しない（§8 の S-smoke-b で差を記録する）。
- **fresh**: 課題 25・50・60 で、初期化したての網にその課題だけを 500 更新学ばせる。初期値は継続の網と同じ `make_model('R', seed)` で、Adam は新しく作る。画像・ラベル・batch の順・拡張は、継続の網のその課題と同じにする。
  - R0 と S で課題のデータは同じで、初期化したての網はどちらの手順でも head が 0 から始まる。だから 2 腕の fresh は、厳密な算術では同じ計算になる。違うのは、損失の行の位置による和の順序の丸めだけである。
  - そこで fresh は seed ごとに 1 回だけ、R0 の手順（head を 0、損失の行は classes_t）で回し、両腕の比較に使う。
  - 課題 1 の fresh は継続の網の課題 1 と同じ計算になるので、回さない（§8 の S-fresh1 で一度だけ確かめる）。

### 4.4 回さない腕

- **腕 B（LN あり）と腕 C（実ラベル）は回さない（1024 の Issa の決定、時間の短縮）。** 草案での役割は、B が「LN が盾として予算を延ばしても保つか」の対照、C が「実ラベルでは幅が伸び続けるか」の記録だった。
- だからこの走は、LN の盾についても実ラベルについても何も言わない（§9）。

### 4.5 予算

- 1 走（1 腕・1 seed）は 60 課題 × 500 更新 = 30,000 更新である。N セル（20,000 更新）の 1.5 倍になる。
- 2 腕 × 5 seed で 300,000 更新、fresh は 15 課題 × 500 = 7,500 更新を足す。
- white-san の実測 65 ms/更新（親の依頼の値）で、学習だけで 1 走 32.5 分、10 走で 5.4 時間、fresh で 0.14 時間になる。評価・記録・保存・compile を足して、合計は約 6.1 時間である（§10.4）。§8 の S-speed で測り直す。
- U を 500 のまま延ばさない代わりに、T を 1.5 倍にした。N セルの後期の窓（課題 21〜40）の先の 20 課題（41〜60）を、この走の後期の窓にする。
- 腕ごとに 5 seed で、J1・J3・J5 の過半は 3/5、J0 は 4/5 とする。

### 4.6 段①がこの箱で働く形

- **R0（原典）**: 課題の始めに head の 200 行がすべて 0 になる。新課題の最初の更新では logit がすべて 0 で、予測は一様になる。体への誤差 ∂L/∂h = Wᵀ(p − y) は厳密に 0 である。前課題の読み出しは、新課題の損失に一度も入らない。切替で実際に働くのは次の 2 つである。
  1. **Adam の慣性**: 体の勾配が 0 でも、持ち越した 1 次 moment m で、体は前課題の最後の向きに動き続ける。m は 1 更新に 0.9 倍ずつ減るので、効くのは約 10 更新である。
  2. **head の学び直し**: 新しい head W′ は、新課題のラベルと特徴の相関の向きに育つ。一次の近似では、新ラベルの一様な期待のもとで、体への誤差は E_y[∂L/∂h_n] ∝ −h_n になる（§7.4 の J5r で導く）。
- **S（共有）**: 課題 t の末の head の 5 行が、課題 t + 1 の最初の更新の読み出しになる。新しいラベルは一様な iid なので、最初の一歩の誤差の期待は E_y[p_n − e_{y_n}] = p_n − 1/5 である。体への誤差は Wᵀ(p_n − 1/5) で、0 ではない。前課題の読み出しが新課題の誤差を体へ運ぶので、段①の押しが学習の中で働く。これは MLP・CNN・GPT の箱（読み出しを共有する）と同じ形である。
- J5 は S の課題末の状態で、この押しが沈める向きに揃っているかを測る（§7.4）。R0 の同じ量は「head を戻さなかったら」の反実仮想になるので、記録だけにする。
- S の head は戻さないので、60 課題分の学習を持ち越す。R0 と S の違いには、段①の道の有無のほかに、head の大きさの蓄積と、損失の行の Adam moment の続き方も入る（§9）。

## 5. 却下した代案

### (a) 腕 B（LN あり）と C（実ラベル）も回す

- 1024 の Issa の決定で回さない（時間の短縮、§4.4）。

### (b) 草案の推奨（100 課題 × 1,500 更新、A と B で 28 GPU 時間）

- 時間を縮めた案 B を採った。U = 500 のままなので、T90 の上限は 500 で、J1 の「早期の 2 倍」は早期の T90 の中央値が 262.5 以下の seed でしか満たせない（§7.2）。

### (c) S でも課題ごとに classes_t の行を使い、前の行は戻さない

- 課題 1〜40 では、新課題の行は一度も学ばれていない 0 の行である。最初の一歩の体への勾配は R0 と同じく 0 になり、段①の道は開かない。
- だから S は、全課題で同じ classes_1 の 5 行を使う。

### (d) S の損失を 200 行すべてにかける（mask をやめる）

- 損失の形が R0 と変わり、比べるものが head の扱いだけでなくなる。5 行の mask は両腕で同じにした。

### (e) 40 課題を超えた後、同じ 250 枚を使い回す（40 課題の列を繰り返す）

- 同じ画像が新しい乱数ラベルで戻ってくる。前に覚えた対応が新しい対応とぶつかる課題になり、「新しい課題を覚える」の型から外れる。
- §4.2 の並べ方なら、どの画像も一度しか出ない。

### (f) 1 課題の画像を 2,500 枚にする（乱数ラベル）

- randlabel の較正（§2.2）で、2,500 枚は 500 更新で暗記率 .229 だった。床に張り付いて、喪失ではなく「学べない」を測ってしまう。

### (g) U を延ばす代わりに lr を上げる

- 原典の ViT の lr（1e−4）を外れる。randlabel の較正では、lr 3e−4 は暗記を良くしなかった（2,500 枚で .229 から .220）。lr は後の lever として §9 に残す。

### (h) 1 枚の GPU に 2 本以上を並べる

- 0919 の測定で、総処理量は 2 本で 0.92 倍、4 本で 0.97 倍だった（§2.4）。速くならないので 1 本ずつ回す。

### (i) 10 seed にする

- 時間が 2 倍になる。5 seed で、過半を 3/5（J0 は 4/5）とする。

### (j) dropout を外した腕（原典の Fig. B.5 の「正規化なし・dropout なし」）

- 喪失の大きさを変える別の lever なので、今回は回さない（§9）。

### 6.2 課題の中の記録（`intask.npz`）

- 25 更新ごと（u = 0, 25, …, 500。u = 0 は head の扱いを決めた後、最初の更新の前）に、次を取る。
  - 暗記率と暗記の損失（課題の訓練画像 250 枚、評価の状態）。T90 はこの記録から出す。
  - 6 ブロックの up 行のノルムの中央値（全 1536 unit）。
  - 損失の行の 5 行のノルムと bias。
- 更新ごとに、batch の正解数・batch の大きさ・損失を取る。online の元の値である。
- 評価は、網を `eval()` にし、compile していない元の module を `no_grad` で通してから `train()` に戻す（randlabel の `train_accuracy` と同じ）。250 枚を 128 枚と 122 枚の 2 回で通す。評価は dropout を使わないので、大域の乱数を消費しない。この記録が学習の軌道を変えないことは、§8 の S-recorder で確かめる。
- 1 課題に 21 回の評価が入り、学習の約 3% の時間と見込む（§8 の S-speed で測る）。

### 6.3 単位の統計（`layer_stats.csv` と、保存した重みからの事後の計算）

- **走の中では、初期値と各課題末だけ**に probe の層の要約を取る。1 課題に 64 枚の forward が 1 回なので、学習の 0.5% に満たない。
- **重い量は、保存した重みから後で計算する**。課題末の重みは全 60 課題で残すので、どの課題末でも計算できる。走を遅くしないために、この分け方にした。後で計算する量は、unit ごとの配列（μ_j・σ_j・p_j・‖w_j‖・b_j）、更新 100 の状態の層の要約、r の分け方（chargpt_l0carrier_1023 §3）、残差への書き込みの比（chargpt_handover_1023 §3.2）、生き返り、J5 である。
- 走の中の値と事後の値は、同じ GPU の float32 の eager の forward で、同じ画像の組なら一致するはずである。事後の解析の最初に、課題 60 の末の死で確かめる。
- **probe**: 検証画像 10,000 枚を file 名の順に並べ、`torch.Generator().manual_seed(stream_seed('probe', seed))` の `randperm` の先頭 64 枚を取る。同じ seed のどの腕・どの課題でも同じ 64 枚を使う。評価の状態・拡張なしで通す。
- **forward の取り方**: 上流の forward と同じ順で、ブロックごとに module を呼んで途中の値を取る（hook を使わない。compile の guard を変えないため）。この forward の logit が `model(x)`（評価の状態）とビットで一致することを、§8 の S-model で確かめる。
- 層の要約（ブロック l = 1〜6 の FFN ごと。全 4,160 位置と、CLS の 64 位置を別々に）:

| 量 | 定義 |
| --- | --- |
| μ・σ・r の中央値 | unit j の前活性 z の平均 μ_j と sd σ_j（ddof 1）、r_j = μ_j / (σ_j + 1e−12) の、unit の中央値 |
| p_j | z > 0 になる位置の割合 |
| 死・厳密な死 | p_j < 0.005 の unit の割合と、p_j = 0 の unit の割合。CLS だけでは 64 標本なので、厳密な死だけを出す |
| 正側の片側化（記録） | p_j ≥ 0.99 の unit の割合 |
| 負側の質量 | すべての（位置、unit）の z のうち、z < 0 の割合（factorial の `negative_mass` と同じ式） |
| up 行のノルム | ‖w_j‖ の中央値。全 unit と、生きた unit（p_j > 0）の別に出す。fc1 の bias の中央値と、負の bias の割合も出す |
| FFN の入力の要約 | FFN の入力 x̃（LN が無いので残差そのもの）の位置の平均 m について、‖m‖、‖m‖/√384、平均の割合 ‖m‖² / mean_n ‖x̃_n‖²。位置の共分散 C（ddof 1）の participation ratio tr(C)² / tr(C²) |

- **ブロック 6 の読み方**: ブロック 6 の FFN は、CLS 以外の位置では損失に効かない（§7.4）。ブロック 6 の死と位置は、CLS の値と並べて読む。

### 6.4 保存（checkpoint）

| fresh | 課題末と更新 100 の重み | 25・50・60 | 43.3 MB |

- 大きさは「パラメータ数 10,814,024 × 4 byte（float32）」で、Adam 込みはその 3 倍（重み・m・v）になる。
- 置き場は `~/Projects/obsidian-research-data/vit_long_1024/runs/<腕>/seed<k>/ckpt/`（fresh は `runs/fresh/seed<k>/task<t>/ckpt/`）。書き込みは一時ファイルからの原子的な置き換えにする（battle の `atomic_save`）。
- 合計は 55.0 GB（51.2 GiB）で、2026-10-24 の空き 437.95 GB の半分（219.0 GB）を超えない（§10.4）。

### 6.5 fresh

- 課題 25・50・60 で回す（§4.3）。1 つの fresh の課題が 1 つのプロセスで、Adam・compile・乱数は課題ごとに新しく作る。
- 記録は §6.1〜§6.3 と同じ量である。
- fresh と継続の網の違いには、初期の特徴を一から作る費用、Adam の moment が 0 から始まること、dropout の乱数の履歴の 3 つが入る（§9）。

## 7. 判定（走る前に固定）

### 7.0 集約の共通規則

- 窓は、早期 = 課題 2〜11、後期 = 課題 41〜60 とする。課題 1 は初期値から始まり、2 腕で同じ計算なので、窓に入れない。
- seed ごとに 1 つの値を作り、条件を満たす seed を数える。腕ごとの判定（J1・J3・J5）は 5 seed のうち 3 seed 以上、J0 は 4 seed 以上で決める。
- 発散した走は、発散した課題までの記録を残す。判定には、その判定の窓を終えた seed だけを使う。使える seed が 4 未満なら、その判定のラベルは `INSUFFICIENT` とする。使える seed が 4 のときも、閾値の seed の数（3 または 4）は変えない。発散した seed の数は、ラベルと別に書く。
- T90 は打ち切りのある量なので、平均を取らず、中央値と数で扱う。未到達は 525 として並べ、表には未到達の数を添える。
- 同じ seed の R0 と S の差は、符号を数えるだけにする。5 対では全勝でも両側の exact 符号検定が p = 0.0625 なので、検定の言い方をしない。

### 7.1 J0 SHARED_VS_RESET（主）

- seed k の値は Δ_k = mean_{t=41..60} online_S(k, t) − mean_{t=41..60} online_R0(k, t) とする。online は課題平均（500 更新の平均）である。

| ラベル | 条件 |
| --- | --- |
| `SHARED_WORSE` | Δ_k < 0 の seed が 4 以上 |
| `SHARED_BETTER` | Δ_k > 0 の seed が 4 以上 |
| `MIXED` | それ以外 |
| `INSUFFICIENT` | 両腕が後期の窓を終えた seed が 4 未満 |

- **併記: 喪失の始まりの課題**（S と R0 の対）。m_t を、online の課題 t − 4〜t の 5 課題の平均とする（t = 6〜60。課題 1 は入れない）。始まりは、m_t < 0.5 となる最初の t である。来なければ「なし」と書く。
- 併記: seed ごとの Δ_k、早期（課題 2〜11）の同じ差、online の最初の 100 更新で取った同じ差。
- 読み方の注意: 後期に両腕が床（偶然水準 0.2 の近く）に張り付いた seed では、Δ_k の符号は雑音で決まる。その seed は始まりの対で読む。

### 7.2 J1 喪失（各腕）

seed k の到達時間 T90_{k,t}（未到達は 525）から、次を出す。

- **E_k と L_k**: 早期（課題 2〜11）の T90 の中央値と、後期（課題 41〜60）の T90 の中央値。
- **N_k**: 後期の 20 課題のうち、未到達の課題の数。
- **seed の条件**: L_k ≥ 2 E_k、かつ N_k ≥ 11（後期の課題の過半で未到達）。
- **学習の成立**: 早期の 10 課題のうち 6 課題以上で到達した seed。

| ラベル | 条件 |
| --- | --- |
| `LOSS` | seed の条件を満たす seed が 3 以上 |
| `NO_LOSS` | 満たす seed が 3 未満で、学習が成立した seed が 3 以上 |
| `NOT_JUDGEABLE` | 学習が成立した seed が 3 未満 |
| `INSUFFICIENT` | 後期の窓を終えた seed が 4 未満 |

- 2 倍と過半（11/20）は依頼の値である。評価の間隔 25 更新は、早期の T90 の目安（100〜300 更新）より十分小さい。
- N_k ≥ 11 なら L_k = 525 になる。だから 2 倍の条件は、未到達が過半の seed では E_k ≤ 262.5 と同じである。
- 記録: seed ごとの E_k・L_k・N_k・L_k / E_k、10 課題ごとの T90 の中央値と未到達の数、online の早期 − 後期、課題末の暗記率、T50・T75。
- **fresh との比較（記録）**: t = 25・50・60 で、online の差 Δ_fresh(t) = online_fresh(t) − online_継続(t)（課題平均と最初の 100 更新）と、T90 の対（継続、fresh）を、両腕について出す。Δ_fresh > 0 は継続の網が劣ることを指す。

### 7.3 J3 死（各腕）

- D_k = 課題 60 の末の、6 ブロックの死（probe の 4,160 位置で p < 0.005）の割合の平均。

| ラベル | 条件 |
| --- | --- |
| `DEATH` | D_k ≥ 0.2 の seed が 3 以上 |
| `NO_DEATH` | それ以外 |
| `INSUFFICIENT` | 課題 60 を終えた seed が 4 未満 |

- 0.2 は依頼の値である。参考に、N セルの課題 40 は .2764、LN ありは .0005 だった（16 枚の読み出しで z の最大が 0 以下、§2.1）。量の定義が違うので、並べて書くだけにする。
- 記録: 厳密な死、ブロックごとの値、CLS だけの値、factorial と同じ読み出し（課題 40 と 60）、死が初めて 0.2 以上になる課題、負側の質量、課題 40 の末の D の値。

### 7.4 J5 最終ブロックの FFN の CLS 位置への切替の押し（事後、保存状態。主は S）

J5 は走った後に、保存した課題末の重みだけで計算する。学習も optimizer の更新もしない。計算は CPU の float64 で行う。定義は走る前のここで固定する。

最終ブロックの FFN の出力は、CLS 位置の分しか logit に届かない。その後に注意の層が無いからである。だから最終ブロックの FFN の重みへの勾配は CLS 位置からだけ来て、J5 は CLS 位置で定義する。

記号（ブロック 6、CLS 位置、画像 n、状態は課題 t の末）:

| 記号 | 意味 |
| --- | --- |
| r_n | ブロック 6 の注意の後の残差。LN が無いので、これが FFN の入力である |
| z_n、a_n | z_n = W1 r_n + b1、a_n = φ(z_n) |
| U_j | fc2 の列 j。unit j が残差へ書く向き（384 次元） |
| h_n | head が読む特徴。最終の norm も恒等なので h_n = r_n + W2 a_n + b2 |
| W、b | 課題 t の末の損失の行の 5 行と bias。S は classes_1 の行で、課題 t + 1 の損失がそのまま使う。R0 は classes_t の行で、課題 t + 1 の始めに 0 へ戻される |

- **装填**（kappa_cnn5p1_1022 §3 の定義を移す）: F_t = Σ_{m∈課題 t} (e_{y_m} − 1/5) ⊗ h_m（5 × 384）。y_m は課題 t の乱数ラベルで、画像は課題 t の 250 枚を評価の状態で通す。クラスで中心化した head を W^c = W − mean_c W とし、κ_t = ⟨W^c, F_t⟩ / ‖F_t‖²、cos²、Q = κ_t‖F_t‖ を出す。装填成分は vL = κ_t F_t である。
- **勾配の probe**: 次の課題（t + 1）の訓練画像 250 枚の CLS 位置を、評価の状態で通す。課題 60 の末では、§4.2 の規則で作った課題 61 の画像を使う（学習には使わない）。ȳ は probe の r_n の平均、担い手は K_n = r_n · ȳ + 1 とする（bias の経路を含む V13 の K_n = x̄ · x_n + 1）。loadsign と同じ K⁰_n = r_n · ȳ も記録する。
- **誤差**: e_n = softmax(W h_n + b) − 1/5。S では、これが課題 t + 1 の最初の一歩の、新ラベルについての期待の誤差そのものである（E_y[p − e_y] = p − 1/5）。R0 では「head を戻さなかったら」の反実仮想になる。
- **装填成分を通す逆伝播**: g_n = vLᵀ e_n。
- **押し**: S_j = mean_n K_n φ′(z_nj) (g_n · U_j)。S_j > 0 なら、勾配降下は w_j · ȳ + b_j を下げる。これを「沈める側」と呼ぶ。
- **生きた unit**: probe の CLS 位置で、z_nj > 0 の画像が 1 枚以上ある unit。
- **状態ごとの値**: s_load = 生きた unit のうち S_j > 0 の割合（0 は正に数えない）。
- **窓**: 早期 = 課題末 1〜9（probe は課題 2〜10）。後期 = 課題末 41〜60（probe は課題 42〜61）。

| ラベル | 条件 |
| --- | --- |
| `LOADING_SINKS` | S の早期の s_load の、seed の中の中央値（9 状態）が 0.75 以上の seed が 3 以上 |
| `NOT_SINKING` | そうでない |
| `INSUFFICIENT` | 課題 10 を終えた S の seed が 4 未満 |

- 同じ規則を後期の窓（20 状態）に当てたラベル（`LOADING_SINKS_LATE` / `NOT_SINKING_LATE`）も出す。記録である。
- 早期を主にした理由: 段①は、最初の課題から切替ごとに働く主張である。GPT では direct が早期に 0.986〜0.996 で揃い、後期に崩れた。早期はこの箱に①の幾何があるかを、後期はそれが続くかを問う。
- **記録（S）**:
  - head 全体を通す押し（g_n = Wᵀ e_n）の、同じ割合 s_full。課題 t + 1 の最初の一歩の、期待の勾配そのものである。
  - 3 項への分け方: loadsign §7 の softmax の恒等式 p − u = H f で、中心化した logit f を、自分の unit・他の unit・残差の 3 項に分ける。定数項（b2 と head の bias b）は残差の項に入れる。
  - κ > 0 の状態の数、cos²、Q、K_n > 0 の割合、生きた unit の数。
  - kappa_cnn5p1 §3 の補題 ⟨W^c, F_t⟩ ≥ N(log K − L_K) − Σ_c (n_c − N/K) b^c_c の破れの数（N = 250、K = 5、L_K は 5 クラスの交差エントロピーの平均、n_c は課題の中のラベル c の枚数）。
- **記録（R0）**: 同じ定義の反実仮想の s_load と s_full。

**J5r 実際に働く一次の押し（R0 の記録。ラベルを出さない）**

- R0 の head は 0 から始まる。全 batch の勾配で一歩 η だけ進めると、W′ = η Σ_m (y_m − u) h_mᵀ になる（W = 0 では p_m = u）。
- その W′ での体への誤差は ∂L/∂h_n = W′ᵀ(p_n − y_n) ≈ −η Σ_m h_m (y_m − u)ᵀ(y_n − u) である。
- 新ラベルが一様で iid なら、E[(y_m − u)ᵀ(y_n − u)] は m = n で 1 − 1/K、m ≠ n で 0 になる。だから E_y[∂L/∂h_n] = −η(1 − 1/K) h_n + O(η²) である。
- J5r は、J5 の式の g_n を −h_n に置き換えた押し S^r_j とする。正の係数 η(1 − 1/K) は符号を変えないので落とす。probe・ȳ・K・生きた unit は J5 と同じにする。
- LN の無いこの箱では h_n = r_n + Σ_i U_i a_ni + b2 なので、S^r_j の自己項は −mean_n K_n φ′(z_nj) a_nj ‖U_j‖² である。ReLU では φ′(z) a = a ≥ 0 なので、K_n > 0 なら自己項は 0 以下で、unit を浮かせる側に働く。
- Adam の形（記録）: head の最初の数歩は、要素ごとに符号に近い一歩になる。そのときの期待の誤差として、g_n = −h_n ⊘ s（s_k は probe の h_nk の 2 乗平均の平方根）も出す。
- 記録: s^r（生きた unit のうち S^r_j > 0 の割合）と、自己・他・残差の 3 項。窓は J5 と同じ。

### 7.5 記録だけ（判定に入れない）

- **幅（草案の J2・J2b）**: n̄(u) を、課題の中の記録（§6.2）の 6 ブロックの up 行のノルムの中央値の平均とする。
  - 課題の中の伸びの割合 ρ2_k = Σ_{t∈後期} [n̄(500) − n̄(100)] / Σ_{t∈後期} [n̄(500) − n̄(0)]。分母が 0 以下の seed は出さない。
  - 当てはめた後の伸びの速さの比 ρ_post,k = [Σ_t (n̄(500) − n̄(T90_t)) / Σ_t (500 − T90_t)] ÷ [Σ_t (n̄(500) − n̄(0)) / (課題の数 × 500)]。使う課題は、課題 2〜60 のうち T90_t ≤ 250 の課題（当てはめの後に 250 更新以上が残る課題）である。
  - 早期と後期を分け、両腕について出す。
- head のノルムの推移（S は 60 課題分を持ち越す）と、損失の行の bias。
- online の早期 − 後期（課題平均と最初の 100 更新）。
- fresh との比較（§7.2 の記録）。
- factorial と同じ読み出しの値（§6.1）と、課題 40 の末の値と N セルの .2764 との対。
- 課題 1 の online と、N セルの課題 1 の値 .481 との差（§8 の S-smoke-b）。
- J5 の記録の量と J5r（§7.4）。

- **S-smoke**（記録。止めない）: R0 の seed 0 を T = 3・U = 500 で回し、online を N セルの .481 / .712 / .806 と比べて差を残す。丸めへの感度の目安として、同じ設定を eager でも回し、compile との差を残す。参照値は別のマシンで出たので（§2.5）、ビットの一致は期待しない。
- **S-speed**（記録。止めない）: S-smoke の compile の走の課題 2〜3 で、1 更新あたりの時間を、学習だけ・記録込み・保存と読み込み込みで測る。§10.4 の表を測った値で換算し直して §12 に書く。

**本走の中の検査**:

- **S-env**（launcher が始める前に毎回）: `pgrep -fa python` で python のプロセスを数えて一覧を残し、`nvidia-smi` と `nvidia-smi --query-compute-apps` で GPU の使用量・利用率・driver・GPU を使うプロセスを残す（`env_<時刻>.json`）。ほかの走は止めない。GPU を使う python が既にあれば、始めずに止まる。
- **S-disk**（各課題の前）: §8 の上の規則。
- **S-smoke-b**（記録。止めない）: 本走の R0 の seed 0 の課題 1 の online を、N セルの .481 と、S-smoke の課題 1 と比べて差を残す。S-smoke とは、同じマシン・同じコードなのでビットで一致するはずである。そのため、最初の更新より前に大域の乱数（dropout が使う CUDA の乱数）を消費しない。

**事後の検査**（S-J5。J5 の本計算の前。学習なし）:

- S と R0 の seed 0 の課題末 1・5・41・60 で、§7.4 の S_j（装填成分と head 全体の両方）を、対応するスカラーの autograd の勾配と照合する（float64、最大の絶対誤差 / 最大の |S| ≤ 1e−10）。head 全体のスカラーは L̄ = mean_n [−(1/5) Σ_c log softmax(W h_n + b)_c] で、S_j = ∂L̄/∂w_j · ȳ + ∂L̄/∂b_j が K_n = r_n · ȳ + 1 の重みと一致する。
- 恒等式: 3 項の和 = 全体、softmax の p − u = H f を、各状態で確かめる。誤差は、その式に出る項の絶対値の最大で割って測り、1e−10 以内とする。結果の値で割ると、打ち消し合いの桁落ちで正しい計算も落ちるからである。
- κ の恒等式 ⟨W^c, F_t⟩ = Σ_n [(ℓ_{n,y_n} − ℓ̄_n) − b^c_{y_n}] が、kappa_cnn5p1_1022 の C2 と同じ許容で成り立つ（ℓ̄_n は 5 クラスの logit の平均）。
- 再現: CPU の float64 の順伝播で出した課題末の暗記率が、`per_task.csv` の値と一致する。許す食い違いは測って決める。同じ状態で GPU の float32 と CPU の float64 の logit の差の最大 δ を測り、1 位と 2 位の logit の差が 2δ 未満の画像（ほぼ同点）の数までを許す。

- J5 が `LOADING_SINKS` なら: 「head を共有した箱では、最終ブロックの FFN の CLS 位置への切替の押しが、早期に X% の unit で沈める側に揃った（5 seed）。」と書く。MLP・CNN・GPT の段①と同じ幾何が ViT にもある、とする。
- J5 が `NOT_SINKING` なら: 「head を共有しても、最終ブロックの FFN への切替の押しは沈める側に揃わなかった。」と書き、段①は ViT では支持されない、とする。
- J5r の自己項の符号は一次の導出で決まる（§7.4）。本文には「head を 0 から学び直す一次の押しの自己項は、LN の無い網では unit を浮かせる側に働く」とだけ書き、測った割合は付録へ置く。
- 機構の文の「課題が切り替わるたびに」の段は、head を課題の間で共有する箱の主張として範囲を書く。

### 11.3 幅（記録）

- J2・J2b は記録なので、本文の文にしない。付録の表に、両腕の ρ2 と ρ_post を置く。

- 文の中の X などの数は、走の記録から入れる。どの文も §9 の範囲の言い方にとどめる。
