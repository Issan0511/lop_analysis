## 0. 一行

原典の Joudaki ViT（ReLU、FFN 1536）に、乱数ラベル 10 値の課題（1 課題 10 クラス × 25 枚 = 250 枚、拡張と dropout なし）を 60 課題 × 500 更新続け、LN の有無と head の扱いの 2×2 を、同じ seed 0〜4 で対にして回す（20 走）。head を課題ごとに 0 へ戻す原典の手順（R0、R0L）では、課題の最初の一歩で体への勾配がちょうど 0 になり、前課題の読み出しが新課題の誤差を体へ運ぶ道（段①の切替の押し）が無い。課題 1 の 10 行を共有する手順（S、SL）はその道を開く。主の判定は LN ありの比較（SL − R0L）で、「LN は切替の押しが無いときだけ盾なのか」を同じ箱で問う。喪失は暗記率が 0.9 に届くまでの更新数 T90 で測り、課題末の重みを残して、走った後で共有の腕の切替の押しの向きを当てる。

## 1. 問い

- **Issa の判断（1024）。**
  - LN なしの箱（factorial の N セル）は喪失を出したが、40 課題 × 500 更新では 10 seed 中 4 seed が崩れ切らなかった。そこで課題数を 60 に延ばし、指標を到達時間 T90 に替え、課題末の重みを残す。腕は LN なしの 2 つに絞った（案 B）。LN ありの腕と実ラベルの腕は回さない（§4.4）。
  - 乱数ラベルは 10 値にする（1 課題 10 クラス × 25 枚）。乱数ラベルの標準の箱と、MLP の箱に揃えるためである。N セル（5 値）との錨は失う（§2.0）。
  - 拡張と dropout は外す（Issa「拡張と dropout はいらん」）。乱数ラベルの標準の箱に合わせる。0919 の手順からは外れる（§2.0）。
  - LN ありの 2 腕を足して、LN の有無 × head の扱いの 2×2 にする（費用の承認つき）。LN ありは原典どおり、norm1・norm2・最終 norm が affine の LayerNorm である。
  - 主の判定を LN ありの比較（SL − R0L）に移す。LN なしの比較と、LN なしの腕の J1・J3・J5 は記録に下げる。white-san の検査で、LN なしの R0 が課題 3 で覚え切る直前に損失が跳ねて崩れたからである（§2.0）。
- **背景（1024 に分かったこと）。**
  - 原典の手順は、課題の始めに head の 200 行を 0 にし、損失を新課題のクラスの行に限る。最初の更新では logit がすべて 0 で、体への誤差 ∂L/∂h = Wᵀ(p − y) はちょうど 0 になる（§4.6）。
  - だから、前課題の読み出しが新しいラベルの誤差を体へ運ぶ道が無い。N セルの喪失は、段①（切替の押し）の相 1 が無いまま起きた喪失である。
  - Dohare et al.（Nature 2024）の Continual ImageNet も、head を課題ごとに 0 へ戻す。Methods はこれを標準の慣行とし、可塑性の研究には理想的でないとも書いている（1024 の Fable の読み）。
  - 共有と戻すを同じ箱で並べた先行例は、1024 の検索では見つからなかった。
- **この走の問い。**
  1. LN のある網で head を共有して段①の道を開くと、後期の課題を学ぶ力は、head を戻す網より落ちるか（J0、主。SL − R0L）。
  2. LN の盾は、切替の押しが無いときだけ保つのか（JLN、主の次）。R0L が喪失せず SL が喪失すれば、押しが盾を破ったと読む。
  3. 60 課題で、LN ありの各腕は到達時間で見て喪失するか（J1）。課題 60 の末に FFN の unit は死んでいるか（J3）。
  4. SL では、最終ブロックの FFN の CLS 位置への切替の押しが、unit を沈める向きに揃うか（J5。走った後に保存状態で計算する）。
  5. 記録: LN なしの 2 腕の同じ量（J0 の S − R0、J1・J3・J5）と、課題の中の跳ね上がりと崩れ（§7.5）。
- **Issa の向き（1024 の発言）。** 「head を戻さないとすぐ壊れるのでは」（LN の有無は言っていない）。LN ありについての発言は無い。
- **記録に下げた問い。** 課題の中で幅が伸びるか（草案の J2・J2b）は、判定にせず記録だけにする（§7.5）。

用語（初出で言葉を添える）:

- **K**: 1 課題のクラスの数で、乱数ラベルの値の数でもある。この走は K = 10。
- **online 正解率**: 各更新の前のミニバッチ正解率を、課題の中で平均した量（battle と同じ）。正解は損失の行（下）の K 個の argmax で数える。拡張と dropout が無いので、更新の前の重みでその batch を評価したのと同じ計算になる。
- **損失の行**: head の 200 行のうち、損失と正解率に使う K 行。R0 は課題 t の K クラス classes_t の行、S は全課題で課題 1 の K クラス classes_1 の行である。乱数ラベル y ∈ {0, …, K − 1} を、その K 行の y 番目へ写す。
- **暗記率**: 課題の訓練画像 250 枚を評価の状態（拡張なし）で通し、損失の行の argmax が乱数のラベルと一致する割合。
- **T90**: 課題の中で暗記率が初めて 0.9 以上になる更新数。25 更新ごと（u = 25, 50, …, U）に測る。250 枚では 225 枚以上が当たることに当たる。U 更新までに届かなければ「未到達」とし、数値は U + 25 として扱う（U = 500 なら 525）。
- **T・U**: 課題数（60）と、課題あたりの更新数（500。較正で決めた。§2.0）。
- **up 行**: FFN の最初の線形層 fc1 の行 w_j。unit j への 384 次元の入力重みである。
- **probe**: seed ごとに固定した検証画像 64 枚。1 枚は 65 token（CLS と 64 patch）なので、4,160 位置になる。
- **死（J3 の量）**: probe の全 4,160 位置で z > 0 になる割合 p が 0.005 未満の channel。4,160 位置のうち 20 位置以下でしか開かない channel である（依頼文では「完全死」と呼んだ）。p = 0 の channel は「厳密な死」として別に記録する。
- **頭と胴**: 課題の最初の 100 更新（頭）と、残りの更新（胴）。
- **CLS 位置**: token 0。head は最終の正規化（この箱では恒等）の後の CLS 位置だけを読む。

### 2.3 T90 の目安（測った値ではない。判定の閾値の読み方にだけ使う）

1 batch の正解率が課題の始めの 0.2 から T90 更新で直線的に 0.9 まで上がり、その後は約 0.95 に留まると仮定する（暗記率と online 正解率を同じ曲線とみなす粗い仮定）。すると online ≈ 0.95 − 0.4 × T90 / U で、U = 500 の smoke から T90 を逆算できる。

| セル | 課題 1 | 課題 2 | 課題 3 |
| --- | --- | --- | --- |
| N（R0 の土台） | 500 を超える（課題 1 は 500 更新で当てはめ切らない） | 約 300 | 約 180 |
| randlabel（LN あり） | 約 330（実測の暗記率 .932 と矛盾しない） | 約 140 | 約 100 |

- この換算は立ち上がりを 1 本の直線と仮定した粗いもので、実測ではない。
- これは 5 値・拡張あり・dropout ありの N セルの目安で、この走の箱（10 値、拡張と dropout なし）には当てはまらない。この走の早期の T90 は較正（§2.0）で測る。
- J1 の「早期の 2 倍」は、未到達が過半の seed では、早期の T90 の中央値が (U + 25)/2 以下（U = 500 なら 262.5 以下）の seed でしか満たせない（§7.2）。

## 4. 腕と箱

### 4.1 箱

本走の設定は `analysis/vit_long_1024/production.json`（4 腕、K = 10、クラスごとに 25 枚、拡張 off、dropout 0、T = 60、U = 500、seed 0〜4、fresh の課題、保存の予定）にあり、launcher がそれを各走へ渡す。

- **模型**: `analysis/joudaki_vit_battle_0919/model.py` の `make_model('R', seed, device, config)` を、factorial の `cell_config(4.0, 'none')`（N セル）の dropout を 0 にした設定で呼ぶ。上流の vit.py を無改変で使い、6 つの FFN の活性化だけを `R`（ReLU。`src/rlcifar_mlp_battle_0918.make_act('R')`）に替える。patch 8、埋め込み 384、6 ブロック、6 head、FFN 1536（mlp_ratio 4）、CLS、qkv の bias。
- **dropout なし（1024、Issa）**: `dropout_p` と `attn_drop_rate` を 0 にする（`--dropout 0`）。上流の FFN の drop1・drop2 は恒等になり、pos_drop・注意の dropout・proj_drop は p = 0 の Dropout になる。dropout の module は乱数を使わずに作られるので、初期値は dropout 0.1 の網と一致する。
- **正規化**: LN なしの腕（R0・S、fresh）は `normalization='none'` で、上流の `get_normalization` が norm1・norm2・最終 norm の 13 か所を `nn.Identity` にする。パラメータは 10,814,024 個。LN ありの腕（R0L・SL、freshL）は randlabel のセルと同じ `cell_config(4.0, 'layer')`（dropout だけ 0）で、13 か所が affine の LayerNorm（γ = 1、β = 0 で始まる）になる。パラメータは 10,824,008 個で、差の 9,984 は 13 個の LN の γ と β である（1024 に数えた）。
- **初期値**: `torch.manual_seed(seed)` の後に上流の `_init_weights`（trunc normal 0.02、bias 0）。LN の初期化は乱数を使わないので、同じ seed の 4 腕は、共有するパラメータの初期値が一致する（§8 の S-model で確かめた）。
- **学習**: Adam（lr 1e−4、β 0.9 / 0.999、ε 1e−8、weight decay なし、fused）。Adam の moment は head も含めて課題をまたいで持ち越す（原典どおり）。battle の `train_forward` で `torch.compile(fullgraph=True)` にし、`fallback_random=True` で ATen の乱数列を保つ。float32、TF32 無効、`torch.use_deterministic_algorithms(True)`、`CUBLAS_WORKSPACE_CONFIG=:4096:8`。batch 128、warmup なし。勾配の clip はせず、非有限の検出だけを行う。
- **compile の形と再開**: 250 枚を batch 128 で回すので、batch の大きさは 128 と 122 が交互に来る。compile は最初の 128 で大きさを固定した graph を、最初の 122 で batch の次元を動かせる graph を作り、以後は 128 の batch も後者を使う。この 2 つの graph の勾配は、丸めの分だけ違う（1024 に測った。最大の差 1.4e−9）。だから途中の課題から再開するプロセスは、学習の前に 128 と 122 の batch で forward と backward を 1 回ずつ通す（乱数の状態は戻し、勾配は捨て、Adam は進めない）。こうして、続けて回したプロセスと同じ graph を持たせる（§8 の S-resume で確かめる）。
- **拡張なし（1024、Issa）**: 学習の入力も、評価と同じ変換（ImageNet の mean と std による標準化だけ）にする（`--augment off`）。batch の順は、拡張の有無によらず同じ stream から作る。
- **乱数の stream**（どれも `stream_seed(...)`、sha256 の先頭 8 byte）: batch の順は `('batch', seed, task)`、loader は `('loader', seed, task)`、乱数ラベルは `('randlabel', seed, task)`。どれも学習の履歴によらず、(seed, task) だけで決まる。拡張の stream `('augment', seed, task, step, idx)` は、拡張なしでは使わない。
- **乱数ラベル**: 各課題で 250 枚に {0, …, 9} の一様な iid のラベルを引き直す（`torch.randint(0, 10)`、乱数の stream は randlabel と同じ `('randlabel', seed, task)`）。250 枚を batch 128 で回すので、1 epoch は 128 枚と 122 枚の 2 batch になり、500 更新は 250 epoch である。
- **既定の経路（検査用）**: 引数を付けないと、コードは N セルの設定（5 値 × 50 枚、拡張あり、dropout 0.1）で動き、課題列は randlabel の `make_task_dataset` とビットで一致する（§8 の S-stream・S-smoke）。

### 4.2 課題列（10 クラスの組、1 巡 20 課題）

- Tiny ImageNet は 200 クラスなので、重複しない 10 クラスの課題は 20 個作れる。
- 課題 t の巡回の番号を c = ⌊(t − 1)/20⌋、巡回の中の位置を i = (t − 1) mod 20 とする。
- **クラスの組**: c = 0 は、battle の `task_classes(seed)` と同じ並べ方（200 クラスを `random.Random(seed)` で混ぜる）を 10 個ずつに切った 20 組を使う。battle の 5 クラスの組を、隣どうし 2 組ずつまとめたものになる。c ≥ 1 は、200 クラスを `random.Random(stream_seed('cycle', seed, c))` で混ぜて 10 個ずつに切った 20 組を使う。
- **画像**: 各クラスの訓練画像（path の順に並べた 500 枚）の 25c + 1 番目から 25c + 25 番目を使う。1 課題は 10 クラス × 25 枚 = 250 枚になる。
- この並べ方では、どの訓練画像も 2 つの課題に出ない。T = 60 は巡回 0〜2（課題 1〜20、21〜40、41〜60）を使い、各クラスの画像の 1〜75 番目を使う。
- 課題 61（巡回 3 の位置 0、各クラスの画像の 76〜100 番目）は学習に使わない。J5 の課題 60 の末の probe にだけ使う（§7.4）。
- 巡回ごとにクラスの組を混ぜ直すのは、20 課題ごとに同じ 10 クラスの画像分布が戻る周期を作らないためである。
- 乱数ラベルでは、クラスの名前はラベルの情報を持たない。クラスが別の巡回で再び出ても、画像とラベルは新しい。
- 5 値の既定の経路では、1 巡 40 課題・各クラス 50 枚になり、巡回 0 は randlabel・N セルの課題列とビットで一致する（§4.1 の最後、§8）。

### 4.3 腕

| 腕 | LN | head を 0 にする時 | 損失と正解率の行 | 役割 |
| --- | --- | --- | --- | --- |
| **R0L**（戻す） | あり | 各課題の始め（課題 1 を含む）に、200 行の重みと bias | classes_t の 10 行 | 原典の手順（主の比較の基準） |
| **SL**（共有） | あり | 課題 1 の始めだけ | 全課題で classes_1 の 10 行 | 段①の道を開く（主の比較） |
| R0（戻す） | なし | 各課題の始め | classes_t の 10 行 | 記録 |
| S（共有） | なし | 課題 1 の始めだけ | 全課題で classes_1 の 10 行 | 記録 |

共通: T = 60、U = 500、seed 0〜4、ReLU、FFN 1536、乱数ラベル 10 値・250 枚（§4.2）、拡張なし、dropout 0、Adam 1e−4（moment は持ち越す）、batch 128、float32・TF32 無効、compile と fused Adam。乱数ラベル y はその腕の損失の行の y 番目へ写す。走の順は seed ごとに R0・S・R0L・SL・fresh（課題 25・50・60）・freshL（同じ）である。

- 同じ seed の 4 腕は、共有するパラメータの初期値・画像・ラベル・batch の順が一致する。拡張と dropout が無いので、学習の結果は乱数の値に依らない（p = 0 の Dropout は恒等である）。
- 同じ LN の条件の 2 腕（R0 と S、R0L と SL）は、課題 1 の計算が同じなので、課題 1 はビットで一致するはずである（§8 の S-arm1）。違いは課題 2 の始めからで、共有の腕では head が課題 1 の末の値のまま残る。
- S の残りの 190 行は勾配を受けないので、0 のまま動かない。R0 では前課題の行が 0 に戻された後も Adam の 1 次 moment で少し動くが、損失の外にあるので学習に入らない（原典と同じ）。
- S では、同じ 10 行が 60 課題の間ずっと学び続ける。乱数ラベルではクラスの名前は情報を持たないので、どの 10 行を使うかは学習に関わらない。
- 10 値・拡張なし・dropout なしなので、課題 1 は N セルの課題 1 と同じ計算ではない。N セルとの比べは、既定の経路の S-smoke（§8）だけで行う。
- **fresh**: 課題 25・50・60 で、初期化したての網にその課題だけを U 更新学ばせる。LN の有無ごとに 1 つ（fresh は LN なし、freshL は LN あり）で、初期値は継続の網と同じ `make_model('R', seed)` の初期値、Adam は新しく作る。画像・ラベル・batch の順は、継続の網のその課題と同じにする。
  - R0 と S で課題のデータは同じで、初期化したての網はどちらの手順でも head が 0 から始まる。だから 2 腕の fresh は、厳密な算術では同じ計算になる。違うのは、損失の行の位置による和の順序の丸めだけである。
  - そこで fresh は LN の有無ごと・seed ごとに 1 回だけ、戻す手順（head を 0、損失の行は classes_t の 10 行）で回し、同じ LN の条件の 2 腕の比較に使う。
  - 課題 1 の fresh は継続の網の課題 1 と同じ計算になるので、回さない（§8 の S-fresh1 で一度だけ確かめる）。

- **腕 C（実ラベル）は回さない（1024 の Issa の決定、時間の短縮）。** だからこの走は、実ラベルについて何も言わない（§9）。
- 草案の腕 B（LN あり）は、初回の登録で回さないことにしたが、この再登録で 2×2 の LN ありの 2 腕（R0L・SL）として回す（1024 の Issa の決定）。

### 4.5 予算

- 1 走（1 腕・1 seed）は 60 課題 × 500 更新 = 30,000 更新である。
- 4 腕 × 5 seed の継続の走が 20 本、fresh が 30 課題（LN の有無 2 × seed 5 × 課題 25・50・60）である。
- 借りた GPU の較正 3 の 67.5 ms/更新で、1 走は約 37 分、20 走と fresh・評価で約 12.7 時間になる（§10.4）。借りた機械は 1 時間 $0.194 で、約 $2.5 である（残高 $3.75、Issa の承認つき）。
- 腕ごとに 5 seed で、J1・J3・J5 の過半は 3/5、J0 は 4/5 とする。

### 4.6 段①がこの箱で働く形

- **R0（原典）**: 課題の始めに head の 200 行がすべて 0 になる。新課題の最初の更新では logit がすべて 0 で、予測は一様になる。体への誤差 ∂L/∂h = Wᵀ(p − y) は厳密に 0 である。前課題の読み出しは、新課題の損失に一度も入らない。切替で実際に働くのは次の 2 つである。
  1. **Adam の慣性**: 体の勾配が 0 でも、持ち越した 1 次 moment m で、体は前課題の最後の向きに動き続ける。m は 1 更新に 0.9 倍ずつ減るので、効くのは約 10 更新である。
  2. **head の学び直し**: 新しい head W′ は、新課題のラベルと特徴の相関の向きに育つ。一次の近似では、新ラベルの一様な期待のもとで、体への誤差は E_y[∂L/∂h_n] ∝ −h_n になる（§7.4 の J5r で導く）。
- **S（共有）**: 課題 t の末の head の 10 行が、課題 t + 1 の最初の更新の読み出しになる。新しいラベルは一様な iid なので、最初の一歩の誤差の期待は E_y[p_n − e_{y_n}] = p_n − 1/K（K = 10）である。体への誤差は Wᵀ(p_n − 1/K) で、0 ではない。前課題の読み出しが新課題の誤差を体へ運ぶので、段①の押しが学習の中で働く。これは MLP・CNN・GPT の箱（読み出しを共有する）と同じ形である。
- J5 は共有の腕（SL が主、S は記録）の課題末の状態で、この押しが沈める向きに揃っているかを測る（§7.4）。戻す腕の同じ量は「head を戻さなかったら」の反実仮想になるので、記録だけにする。
- **LN ありの腕では**、最終の LN と norm2 が押しの形を変える。最終の LN を通る誤差には、分散の微分の項が入る（§7.4 の R_n）。GPT の箱では、この項を含めると早期の沈める側の割合が 0.986〜0.996 から 0.72〜0.80 に下がった（§2.6）。
- 共有の腕の head は戻さないので、60 課題分の学習を持ち越す。戻す腕と共有の腕の違いには、段①の道の有無のほかに、head の大きさの蓄積と、損失の行の Adam moment の続き方も入る（§9）。

## 5. 却下した代案

### (a) 腕 C（実ラベル）も回す

- 1024 の Issa の決定で回さない（時間の短縮、§4.4）。LN ありの腕（草案の B）は、再登録で 2×2 として回す。

### (b) 草案の推奨（100 課題 × 1,500 更新、A と B で 28 GPU 時間）

- 時間を縮めた案 B を採った。U = 500 のままなので、T90 の上限は 500 で、J1 の「早期の 2 倍」は早期の T90 の中央値が 262.5 以下の seed でしか満たせない（§7.2）。

### (c) S でも課題ごとに classes_t の行を使い、前の行は戻さない

- 最初の巡回（K = 10 なら課題 1〜20）では、新課題の行は一度も学ばれていない 0 の行である。最初の一歩の体への勾配は R0 と同じく 0 になり、段①の道は開かない。
- だから S は、全課題で同じ classes_1 の 10 行を使う。

### (d) S の損失を 200 行すべてにかける（mask をやめる）

- 損失の形が R0 と変わり、比べるものが head の扱いだけでなくなる。K 行の mask は両腕で同じにした。

### (e) 40 課題を超えた後、同じ 250 枚を使い回す（40 課題の列を繰り返す）

- 同じ画像が新しい乱数ラベルで戻ってくる。前に覚えた対応が新しい対応とぶつかる課題になり、「新しい課題を覚える」の型から外れる。
- §4.2 の並べ方なら、どの画像も一度しか出ない。

### (f) 1 課題の画像を 2,500 枚にする（乱数ラベル）

- randlabel の較正（§2.2）で、2,500 枚は 500 更新で暗記率 .229 だった。床に張り付いて、喪失ではなく「学べない」を測ってしまう。

### (g) U を延ばす代わりに lr を上げる

- 原典の ViT の lr（1e−4）を外れる。randlabel の較正では、lr 3e−4 は暗記を良くしなかった（2,500 枚で .229 から .220）。lr は後の lever として §9 に残す。

### (h) 1 枚の GPU に 2 本以上を並べる

- 0919 の測定で、総処理量は 2 本で 0.92 倍、4 本で 0.97 倍だった（§2.4）。速くならないので 1 本ずつ回す。

### (i) 10 seed にする

- 時間が 2 倍になる。5 seed で、過半を 3/5（J0 は 4/5）とする。

### (j) dropout を外した腕（原典の Fig. B.5 の「正規化なし・dropout なし」）

- 喪失の大きさを変える別の lever なので、今回は回さない（§9）。

### 6.2 課題の中の記録（`intask.npz`）

- 25 更新ごと（u = 0, 25, …, U。u = 0 は head の扱いを決めた後、最初の更新の前）に、次を取る。
  - 暗記率と暗記の損失（課題の訓練画像 250 枚、評価の状態）。T90 はこの記録から出す。
  - 6 ブロックの up 行のノルムの中央値（全 1536 unit）。
  - 損失の行の 10 行のノルムと bias。
- 更新ごとに、batch の正解数・batch の大きさ・損失を取る。online の元の値である。
- 評価は、網を `eval()` にし、compile していない元の module を `no_grad` で通してから `train()` に戻す（randlabel の `train_accuracy` と同じ）。250 枚を 128 枚と 122 枚の 2 回で通す。評価は大域の乱数を消費しない。この記録が学習の軌道を変えないことは、§8 の S-recorder で確かめる。
- U = 500 なら 1 課題に 21 回の評価が入り、学習の約 3% の時間と見込む（§8 の S-speed で測る）。

### 6.3 単位の統計（`layer_stats.csv` と、保存した重みからの事後の計算）

- **走の中では、初期値と各課題末だけ**に probe の層の要約を取る。1 課題に 64 枚の forward が 1 回なので、学習の 0.5% に満たない。
- **重い量は、保存した重みから後で計算する**。課題末の重みは §6.4 の 36 課題で残す。J5 の窓（課題末 1〜9 と 41〜60）と J3（課題 60）は、すべてその中にある。走を遅くしないために、この分け方にした。後で計算する量は、unit ごとの配列（μ_j・σ_j・p_j・‖w_j‖・b_j）、更新 100 の状態の層の要約、r の分け方（chargpt_l0carrier_1023 §3）、残差への書き込みの比（chargpt_handover_1023 §3.2）、生き返り、J5 である。
- 走の中の値と事後の値は、同じ GPU の float32 の eager の forward で、同じ画像の組なら一致するはずである。事後の解析の最初に、課題 60 の末の死で確かめる。
- **probe**: 検証画像 10,000 枚を file 名の順に並べ、`torch.Generator().manual_seed(stream_seed('probe', seed))` の `randperm` の先頭 64 枚を取る。同じ seed のどの腕・どの課題でも同じ 64 枚を使う。評価の状態・拡張なしで通す。
- **forward の取り方**: 上流の forward と同じ順で、ブロックごとに module を呼んで途中の値を取る（hook を使わない。compile の guard を変えないため）。この forward の logit が `model(x)`（評価の状態）とビットで一致することを、§8 の S-model で確かめる。
- 層の要約（ブロック l = 1〜6 の FFN ごと。全 4,160 位置と、CLS の 64 位置を別々に）:

| 量 | 定義 |
| --- | --- |
| μ・σ・r の中央値 | unit j の前活性 z の平均 μ_j と sd σ_j（ddof 1）、r_j = μ_j / (σ_j + 1e−12) の、unit の中央値 |
| p_j | z > 0 になる位置の割合 |
| 死・厳密な死 | p_j < 0.005 の unit の割合と、p_j = 0 の unit の割合。CLS だけでは 64 標本なので、厳密な死だけを出す |
| 正側の片側化（記録） | p_j ≥ 0.99 の unit の割合 |
| 負側の質量 | すべての（位置、unit）の z のうち、z < 0 の割合（factorial の `negative_mass` と同じ式） |
| up 行のノルム | ‖w_j‖ の中央値。全 unit と、生きた unit（p_j > 0）の別に出す。fc1 の bias の中央値と、負の bias の割合も出す |
| FFN の入力の要約 | FFN の入力 x̃（LN が無いので残差そのもの）の位置の平均 m について、‖m‖、‖m‖/√384、平均の割合 ‖m‖² / mean_n ‖x̃_n‖²。位置の共分散 C（ddof 1）の participation ratio tr(C)² / tr(C²) |

- **ブロック 6 の読み方**: ブロック 6 の FFN は、CLS 以外の位置では損失に効かない（§7.4）。ブロック 6 の死と位置は、CLS の値と並べて読む。

### 6.5 fresh

- 課題 25・50・60 で回す（§4.3）。1 つの fresh の課題が 1 つのプロセスで、Adam・compile・乱数は課題ごとに新しく作る。

## 7. 判定（走る前に固定）

### 7.0 集約の共通規則

- **主の判定は LN ありの J0（SL − R0L）で、次が JLN（§7.6）である。** 判定として扱うのは、ほかに LN ありの腕の J1・J3（R0L・SL）と SL の J5 である。LN なしの腕の J0（S − R0）・J1・J3・J5 は、同じ規則で出すが記録に下げる（1024 の Issa の決定、§2.0）。
- 窓は、早期 = 課題 2〜11、後期 = 課題 41〜60 とする。課題 1 は初期値から始まり、同じ LN の条件の 2 腕で同じ計算なので、窓に入れない。
- seed ごとに 1 つの値を作り、条件を満たす seed を数える。腕ごとの判定（J1・J3・J5）は 5 seed のうち 3 seed 以上、J0 は 4 seed 以上で決める。
- 発散した走は、発散した課題までの記録を残す。判定には、その判定の窓を終えた seed だけを使う。使える seed が 4 未満なら、その判定のラベルは `INSUFFICIENT` とする。使える seed が 4 のときも、閾値の seed の数（3 または 4）は変えない。発散した seed の数は、ラベルと別に書く。
- T90 は打ち切りのある量なので、平均を取らず、中央値と数で扱う。未到達は U + 25 として並べ、表には未到達の数を添える。
- 同じ seed の R0 と S の差は、符号を数えるだけにする。5 対では全勝でも両側の exact 符号検定が p = 0.0625 なので、検定の言い方をしない。

### 7.1 J0 SHARED_VS_RESET（主は LN あり）

- **主**: LN ありの比較。seed k の値は Δ_k = mean_{t=41..60} online_SL(k, t) − mean_{t=41..60} online_R0L(k, t) とする。online は課題平均（U 更新の平均）である。
- **記録**: LN なしの比較。同じ規則を S − R0 に当てる。

| ラベル | 条件 |
| --- | --- |
| `SHARED_WORSE` | Δ_k < 0 の seed が 4 以上 |
| `SHARED_BETTER` | Δ_k > 0 の seed が 4 以上 |
| `MIXED` | それ以外 |
| `INSUFFICIENT` | 両腕が後期の窓を終えた seed が 4 未満 |

- **併記: 喪失の始まりの課題**（共有の腕と戻す腕の対）。m_t を、online の課題 t − 4〜t の 5 課題の平均とする（t = 6〜60。課題 1 は入れない）。始まりは、m_t < 0.5 となる最初の t である。来なければ「なし」と書く。0.5 は依頼の値で、K = 10 でも変えない。
- 併記: seed ごとの Δ_k、早期（課題 2〜11）の同じ差、online の最初の 100 更新で取った同じ差。
- 読み方の注意: 後期に両腕が床（偶然水準 1/K = 0.1 の近く）に張り付いた seed では、Δ_k の符号は雑音で決まる。その seed は始まりの対で読む。

### 7.2 J1 喪失（各腕。判定は R0L・SL、R0・S は記録）

seed k の到達時間 T90_{k,t}（未到達は U + 25。U = 500 なら 525）から、次を出す。

- **E_k と L_k**: 早期（課題 2〜11）の T90 の中央値と、後期（課題 41〜60）の T90 の中央値。
- **N_k**: 後期の 20 課題のうち、未到達の課題の数。
- **seed の条件**: L_k ≥ 2 E_k、かつ N_k ≥ 11（後期の課題の過半で未到達）。
- **学習の成立**: 早期の 10 課題のうち 6 課題以上で到達した seed。

| ラベル | 条件 |
| --- | --- |
| `LOSS` | seed の条件を満たす seed が 3 以上 |
| `NO_LOSS` | 満たす seed が 3 未満で、学習が成立した seed が 3 以上 |
| `NOT_JUDGEABLE` | 学習が成立した seed が 3 未満 |
| `INSUFFICIENT` | 後期の窓を終えた seed が 4 未満 |

- 2 倍と過半（11/20）は依頼の値である。評価の間隔 25 更新は、早期の T90 の目安（100〜300 更新）より十分小さい。
- N_k ≥ 11 なら L_k = U + 25 になる。だから 2 倍の条件は、未到達が過半の seed では E_k ≤ (U + 25)/2 と同じである（U = 500 なら 262.5）。
- 記録: seed ごとの E_k・L_k・N_k・L_k / E_k、10 課題ごとの T90 の中央値と未到達の数、online の早期 − 後期、課題末の暗記率、T50・T75。
- **fresh との比較（記録）**: t = 25・50・60 で、online の差 Δ_fresh(t) = online_fresh(t) − online_継続(t)（課題平均と最初の 100 更新）と、T90 の対（継続、fresh）を、両腕について出す。Δ_fresh > 0 は継続の網が劣ることを指す。

### 7.3 J3 死（各腕。判定は R0L・SL、R0・S は記録）

- D_k = 課題 60 の末の、6 ブロックの死（probe の 4,160 位置で p < 0.005）の割合の平均。

| ラベル | 条件 |
| --- | --- |
| `DEATH` | D_k ≥ 0.2 の seed が 3 以上 |
| `NO_DEATH` | それ以外 |
| `INSUFFICIENT` | 課題 60 を終えた seed が 4 未満 |

- 0.2 は依頼の値である。参考に、N セルの課題 40 は .2764、LN ありは .0005 だった（16 枚の読み出しで z の最大が 0 以下、§2.1）。量の定義が違うので、並べて書くだけにする。
- 記録: 厳密な死、ブロックごとの値、CLS だけの値、factorial と同じ読み出し（課題 40 と 60）、死が初めて 0.2 以上になる課題、負側の質量、課題 40 の末の D の値。

### 7.4 J5 最終ブロックの FFN の CLS 位置への切替の押し（事後、保存状態。判定は SL、S は記録）

J5 は走った後に、保存した課題末の重みだけで計算する。学習も optimizer の更新もしない。計算は CPU の float64 で行う。定義は走る前のここで固定する。

最終ブロックの FFN の出力は、CLS 位置の分しか logit に届かない。その後に注意の層が無いからである。だから最終ブロックの FFN の重みへの勾配は CLS 位置からだけ来て、J5 は CLS 位置で定義する。

記号（ブロック 6、CLS 位置、画像 n、状態は課題 t の末）:

| 記号 | 意味 |
| --- | --- |
| r_n | ブロック 6 の注意の後の残差（norm2 の入力） |
| y_n | FFN の入力。LN ありは norm2(r_n)、LN なしは r_n |
| z_n、a_n | z_n = W1 y_n + b1、a_n = φ(z_n) |
| U_j | fc2 の列 j。unit j が残差へ書く向き（384 次元） |
| t_n | 最終の正規化の前の残差。t_n = r_n + W2 a_n + b2 |
| h_n | head が読む特徴。LN ありは LN_f(t_n) = γ ⊙ q_n + β（q_n は t_n を中心化して σ_n で割った量）、LN なしは t_n |
| W、b | 課題 t の末の損失の行の K 行（K = 10）と bias。共有の腕は classes_1 の行で、課題 t + 1 の損失がそのまま使う。戻す腕は classes_t の行で、課題 t + 1 の始めに 0 へ戻される |

- **装填**（kappa_cnn5p1_1022 §3 の定義を移す）: F_t = Σ_{m∈課題 t} (e_{y_m} − 1/K) ⊗ h_m（K × 384）。y_m は課題 t の乱数ラベルで、画像は課題 t の 250 枚を評価の状態で通す。クラスで中心化した head を W^c = W − mean_c W とし、κ_t = ⟨W^c, F_t⟩ / ‖F_t‖²、cos²、Q = κ_t‖F_t‖ を出す。装填成分は vL = κ_t F_t である。
- **勾配の probe**: 次の課題（t + 1）の訓練画像 250 枚の CLS 位置を、評価の状態で通す。課題 60 の末では、§4.2 の規則で作った課題 61 の画像を使う（学習には使わない）。ȳ は probe の y_n の平均、担い手は K_n = y_n · ȳ + 1 とする（bias の経路を含む V13 の K_n = x̄ · x_n + 1）。loadsign と同じ K⁰_n = y_n · ȳ も記録する。
- **誤差**: e_n = softmax(W h_n + b) − 1/K。共有の腕では、これが課題 t + 1 の最初の一歩の、新ラベルについての期待の誤差そのものである（E_y[p − e_y] = p − 1/K）。戻す腕では「head を戻さなかったら」の反実仮想になる。
- **装填成分を通す逆伝播**: g_n = vLᵀ e_n。LN ありは b_n = γ ⊙ g_n、D_n = (b_n − mean(b_n)) / σ_n、R_n = −q_n mean(q_n ⊙ b_n) / σ_n とする（σ_n² = t_n の中心化した分散 + ε、ε = 1e−5）。LN なしは D_n = g_n、R_n = 0。
- **押し**: S_j = mean_n K_n φ′(z_nj) [(D_n + R_n) · U_j]。S_j > 0 なら、勾配降下は w_j · ȳ + b_j を下げる。これを「沈める側」と呼ぶ。
- **生きた unit**: probe の CLS 位置で、z_nj > 0 の画像が 1 枚以上ある unit。
- **状態ごとの値**: s_load = 生きた unit のうち S_j > 0 の割合（0 は正に数えない）。
- **窓**: 早期 = 課題末 1〜9（probe は課題 2〜10）。後期 = 課題末 41〜60（probe は課題 42〜61）。

| ラベル | 条件 |
| --- | --- |
| `LOADING_SINKS` | 早期の s_load の、seed の中の中央値（9 状態）が 0.75 以上の seed が 3 以上 |
| `NOT_SINKING` | そうでない |
| `INSUFFICIENT` | 課題 10 を終えた seed が 4 未満 |

- 判定は SL に当てる。S にも同じ規則を当て、記録にする。
- 同じ規則を後期の窓（20 状態）に当てたラベル（`LOADING_SINKS_LATE` / `NOT_SINKING_LATE`）も出す。記録である。
- 早期を主にした理由: 段①は、最初の課題から切替ごとに働く主張である。GPT では direct が早期に 0.986〜0.996 で揃い、後期に崩れた。早期はこの箱に①の幾何があるかを、後期はそれが続くかを問う。
- **記録（共有の腕）**:
  - head 全体を通す押し（g_n = Wᵀ e_n）の、同じ割合 s_full。課題 t + 1 の最初の一歩の、期待の勾配そのものである。
  - 直通の項（D だけ）と分散微分の項（R だけ、LN ありのみ）の別の割合。
  - 直通の項の 3 項への分け方: loadsign §7 の softmax の恒等式 p − u = H f で、中心化した logit f を、自分の unit・他の unit・残差の 3 項に分ける。定数項（b2、β、head の bias b）は残差の項に入れる。
  - κ > 0 の状態の数、cos²、Q、K_n > 0 の割合、生きた unit の数。
  - kappa_cnn5p1 §3 の補題 ⟨W^c, F_t⟩ ≥ N(log K − L_K) − Σ_c (n_c − N/K) b^c_c の破れの数（N = 250、K = 10、L_K は K クラスの交差エントロピーの平均、n_c は課題の中のラベル c の枚数）。
- **記録（戻す腕）**: 同じ定義の反実仮想の s_load と s_full。

**J5r 実際に働く一次の押し（戻す腕の記録。ラベルを出さない）**

- 戻す腕の head は 0 から始まる。全 batch の勾配で一歩 η だけ進めると、W′ = η Σ_m (y_m − u) h_mᵀ になる（W = 0 では p_m = u）。
- その W′ での体への誤差は ∂L/∂h_n = W′ᵀ(p_n − y_n) ≈ −η Σ_m h_m (y_m − u)ᵀ(y_n − u) である。
- 新ラベルが一様で iid なら、E[(y_m − u)ᵀ(y_n − u)] は m = n で 1 − 1/K、m ≠ n で 0 になる。だから E_y[∂L/∂h_n] = −η(1 − 1/K) h_n + O(η²) である。
- J5r は、J5 の式の g_n を −h_n に置き換えた押し S^r_j とする。正の係数 η(1 − 1/K) は符号を変えないので落とす。probe・ȳ・K・生きた unit は J5 と同じにする。
- この次数で言える 2 つのこと:
  - LN なし（R0）: h_n = r_n + Σ_i U_i a_ni + b2 なので、S^r_j の自己項は −mean_n K_n φ′(z_nj) a_nj ‖U_j‖² である。ReLU では φ′(z) a = a ≥ 0 なので、K_n > 0 なら自己項は 0 以下で、unit を浮かせる側に働く。
  - LN あり（R0L）: γ = 1・β = 0 なら D_n + R_n = −(ε/σ_n²)(q_n/σ_n) が各画像で成り立つ。押しは直通の項の ε/σ_n² 倍に縮み、LN の ε の分を除いて 0 になる。
- Adam の形（記録）: head の最初の数歩は、要素ごとに符号に近い一歩になる。そのときの期待の誤差として、g_n = −h_n ⊘ s（s_k は probe の h_nk の 2 乗平均の平方根）も出す。
- 記録: s^r（生きた unit のうち S^r_j > 0 の割合）、LN なしの自己・他・残差の 3 項、LN ありの直通と分散微分の 2 項。窓は J5 と同じ。

## 8. 検査（走る前に通す）

落ちたら本走を始めずに報告する。ただし S-smoke・S-smoke-b・S-speed は記録だけで、値が参照と合わなくても止めない。launcher は、データの要らない検査とデータの要る検査の両方の記録が `all_pass` で、記録したソースの hash と本走の設定（production.json）が今のものと一致しないと、本走を始めない（§10.3）。

- **S-speed**（記録。止めない）: S-arm1 の R0 と R0L の課題 2〜3 で、1 更新あたりの時間を、学習だけ・記録込み・保存と読み込み込みで測り、20 本の継続の走と fresh の時間を換算する。借りた GPU でも同じ検査を回し、§12 に書く。
- **S-spikes**（記録。止めない）: 4 腕の seed 0 の課題 1〜3 で、跳ね上がりと崩れ（§7.5。0.9 と 0.8 の両方）、暗記率の山、online の損失の最大を記録する。課題 3 までに LN ありの腕で崩れが出たら、起動の前に親に知らせる。
- **S-smoke**（記録。止めない）: 既定の配置で R0 の seed 0 を T = 3・U = 500 で回し、online を N セルの .481 / .712 / .806 と比べて差を残す。丸めへの感度の目安として、同じ設定を eager でも回し、compile との差を残す。参照値は別のマシンで出たので（§2.5）、ビットの一致は期待しない。

**本走の中の検査**:

- **S-env**（launcher が始める前に毎回）: `pgrep -fa python` で python のプロセスを数えて一覧を残し、`nvidia-smi` と `nvidia-smi --query-compute-apps` で GPU の使用量・利用率・driver・GPU を使うプロセスを残す（`env_<時刻>.json`）。ほかの走は止めない。GPU を使う python が既にあれば、始めずに止まる。
- **S-disk**（各課題の前）: 上の規則。
- **S-smoke-b**（記録。止めない）: 本走の R0 の seed 0 の課題 1 を、S-arm1 の R0 の課題 1 と比べる。同じ機械・同じコード・同じ設定ならビットで一致するはずである。

**事後の検査**（S-J5。J5 の本計算の前。学習なし）:

- 4 腕の seed 0 の課題末 1・5・41・60 で、§7.4 の S_j（装填成分と head 全体の両方）を、対応するスカラーの autograd の勾配と照合する（float64、最大の絶対誤差 / 最大の |S| ≤ 1e−10）。head 全体のスカラーは L̄ = mean_n [−(1/K) Σ_c log softmax(W h_n + b)_c] で、S_j = ∂L̄/∂w_j · ȳ + ∂L̄/∂b_j が K_n = y_n · ȳ + 1 の重みと一致する。
- 恒等式: 3 項の和 = 全体、softmax の p − u = H f を、各状態で確かめる。誤差は、その式に出る項の絶対値の最大で割って測り、1e−10 以内とする。結果の値で割ると、打ち消し合いの桁落ちで正しい計算も落ちるからである。
- J5r の LN の恒等式: γ = 1・β = 0 に置き換えた LN ありの網で、D_n + R_n = −(ε/σ_n²)(q_n/σ_n) が各画像で成り立つ。誤差は直通の項 D_n の最大の絶対値で割って測り、64 × 2.2e−16 以内とする。D_n + R_n は D_n の ε/σ_n² 倍まで打ち消し合った値なので、それ自体で割ると桁落ちが 1e−10 の桁になる。
- κ の恒等式 ⟨W^c, F_t⟩ = Σ_n [(ℓ_{n,y_n} − ℓ̄_n) − b^c_{y_n}] が、kappa_cnn5p1_1022 の C2 と同じ許容で成り立つ（ℓ̄_n は K クラスの logit の平均）。
- 再現: CPU の float64 の順伝播で出した課題末の暗記率が、`per_task.csv` の値と一致する。許す食い違いは測って決める。同じ状態で GPU の float32 と CPU の float64 の logit の差の最大 δ を測り、1 位と 2 位の logit の差が 2δ 未満の画像（ほぼ同点）の数までを許す。

## 9. 言わないこと

- **箱の外へ一般化しない。** 対象は Joudaki の ViT（patch 8、埋め込み 384、6 ブロック、FFN 1536、ReLU、dropout なし、LN あり・なし）、Tiny ImageNet 64 × 64、拡張なし、1 課題 10 クラス × 25 枚の乱数ラベル 10 値、Adam 1e−4、60 課題 × U 更新、seed 0〜4 である。
- **N セルの延長とは呼ばない。** ラベルの値の数（5 → 10）、拡張と dropout の有無、課題列が違う。N セルとの比べは既定の経路の検査（S-stream・S-smoke）だけで、喪失の大きさを N セルと並べない。
- **0919 の手順（拡張と dropout）の効果は言わない。** この走は拡張と dropout を外しただけで、それぞれの効果を分けていない。
- **S・SL は原典の手順ではない。** 共有の腕は課題 1 の 10 行を全課題で使う。乱数ラベルではクラスの名前が情報を持たないので、行の再利用は情報を運ばない。実ラベルの箱で head を共有した場合とは別の箱である。
- **J0 の差を「段①の効果」と言い切らない。** R0 と S の違いには、段①の道の有無のほかに、head の大きさの蓄積、損失の行の Adam moment の続き方、課題の始めの損失の大きさ（S は旧 head の自信のある誤りから始まる）も入る。押しの向きは J5 で、head の大きさは記録で並べる。
- **盾を特定の LN に帰さない。** LN ありと LN なしは、13 個の LN（norm1・norm2・最終 norm）の有無で違う。最終 norm は読み出しの幾何も変える。どの LN が盾なのかは、この走では分けない。
- **LN なしの腕の結果を主張にしない。** LN なしの網は、拡張と dropout を外すと不安定になり（§2.0）、ゆっくりした喪失と別の壊れ方が混ざる。LN なしの判定は記録である。
- **実ラベルについて何も言わない。** 腕 C を回していない。
- **lr の効果は言わない。** lr は 1e−4 のまま変えていない。lr は次の lever として残す。
- **40 課題を超えた課題列は原典に無い。** 課題 41 以降は、同じ 200 クラスの別の画像と、混ぜ直したクラスの組で作った（§4.2）。原典の 40 課題の結果と同じ課題列とは呼ばない。
- **40 × 500 のセルとの差を「課題数の効果」と呼ばない。** 箱が違い（上）、別のマシンで回す。
- **T90 の打ち切りを実際の値として扱わない。** 未到達の課題は「500 更新までに届かなかった」とだけ書き、平均に入れない。
- **fresh gap を 40 × 500 のセルと並べない。** 箱が違い、fresh の値には、特徴を一から作る費用と、Adam の moment が 0 から始まることが入る。
- **J5 は一次の期待の押しである。** 共有の腕では J5 が最初の一歩の期待の勾配の装填の部分に当たるが、Adam の実際の一歩ではない。戻す腕の J5r も一次の期待である。
- **死は probe での量である。** 「どの入力でも開かない」とは言わない。factorial の .2764 は現課題の訓練画像 16 枚で測った値で、この spec の probe（検証画像 64 枚）の値とは別の量である。
- **データは公式の zip と照合していない。** Kaggle の写しで、0919 の N セルと同じ画像かは確かめられない（§10.2）。
- **同じ LN の条件の 2 腕の 5 対の差に検定の言い方をしない**（§7.0）。
