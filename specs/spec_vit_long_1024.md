## 0. 一行

原典の ViT から LN を外すと喪失は出たが（factorial の N セル）、40 課題 × 500 更新では 10 seed 中 4 seed が崩れ切らず、課題平均の online 正解率は天井と床の間で差が縮んだ。この spec は同じ N セル（腕 A: LN なし・ReLU・乱数ラベル 250 枚）を課題数と課題あたりの更新数の両方で延ばし（推奨は 100 課題 × 1,500 更新・seed 0〜4）、喪失を「訓練集合の暗記率が 0.9 を超えるまでの更新数 T90」で測る。LN ありの同じ設定（腕 B）を盾の対照に置き、課題末の重みと Adam を保存して、走った後で段①（装填の押し）の帳簿を当てる。

## 1. 問い

- **Issa の判断（1024）。** LN なしの箱（factorial の N セル）は喪失を出したが、40 課題では 10 seed 中 4 seed が崩れ切らなかった。課題平均の online 正解率（500 更新の平均）は、天井（新品並み）と床（偶然水準 0.2）の間で差が縮む。そこで課題数と課題あたりの更新数を両方増やし、指標を到達時間 T90 に替える。課題末の重みも保存し、走った後で段①の帳簿（装填 κ、切替の押しの分解、沈みの担い手）を当てる。
- **見立ての分かれ目（幅）。**
  - Fable の読み: 乱数ラベルの暗記では、当てはめた後に課題の中の誤差が消える。だから課題あたりの更新を増やしても、幅（up 行のノルム・前活性の sd）は伸びない。根拠は wconv_pca_1003（RL-MNIST の MLP で課題を 64,000 更新まで延ばすと、当てはめ後に Adam の一歩が 1/5〜1/40 になり、ほぼ止まった）。
  - Issa の読み: 幅が伸びるのは長い更新である。
  - 実ラベルでは誤差が残るので、幅は伸び続けると読む。根拠は cifar5p1_cnn_budget_1019（実ラベル 5+1 CNN で、課題あたり 7,800 更新の腕は 780 更新の腕より FC2 の幅が伸びた）。
  - この走で分けるのは、課題の中の伸びと切替をまたぐ伸びの割合（J2）と、当てはめ後の伸びの速さ（J2b）である。
- **追加の問い（Fable）。** 段①（装填の押しが unit を沈める向きに揃う）は Transformer でも成り立つか。J5 で、最終ブロックの FFN の CLS 位置への切替の押しを、chargpt_loadsign_1023 の恒等分解で分ける。
- **先に書いておく制約。** 原典の手順は課題ごとに head をゼロへ戻し、損失を現課題の 5 クラスに限る。このため前課題の読み出しは新課題の損失に入らず、段①はこの箱では学習中に働かない（§4.6）。J5 は「head を課題の間で共有したら」という反実仮想の量になる。実際に働く押しは J5r（記録）で別に出す。

用語（初出で言葉を添える）:

- **online 正解率**: 各更新の前のミニバッチ正解率を、課題の中で平均した量（battle と同じ）。訓練の状態で測るので、拡張と dropout が入る。
- **暗記率**: 課題の訓練画像（A・B は 250 枚）を評価の状態（dropout なし・拡張なし）で通し、5 クラスの argmax が（乱数の）ラベルと一致する割合。実ラベルでは訓練精度。
- **T90**: 課題の中で暗記率が初めて 0.9 を超えた更新番号。250 枚では 226 枚以上が当たることに当たる。25 更新ごとに測る。U 更新までに超えなければ T90 = U とし、「上限張り付き」（打ち切り）と呼ぶ。
- **T・U**: 課題数と、課題あたりの更新数。
- **up 行**: FFN の最初の線形層 fc1 の行 w_j。unit j への 384 次元の入力重みである。
- **幅**: up 行のノルムと、前活性 z の unit ごとの sd。
- **probe**: seed ごとに固定した検証画像 64 枚。1 枚は 65 token（CLS と 64 patch）なので、4,160 位置になる。
- **死**: probe で z > 0 になる位置の割合 p が 0.005 未満の unit。**完全死**は p = 0 の unit。
- **頭と胴**: 課題の最初の 100 更新（頭）と、残りの更新（胴）。
- **CLS 位置**: token 0。head は最終の正規化の後の CLS 位置だけを読む。

## 4. 腕と箱

### 4.1 箱（battle・randlabel・factorial から変えないもの）

- **模型**: `analysis/joudaki_vit_battle_0919/model.py` の `make_model('R', seed, device, config)`。上流の vit.py を無改変で使い、6 つの FFN の活性化だけを `R`（ReLU。`src/rlcifar_mlp_battle_0918.make_act('R')`）に替える。patch 8、埋め込み 384、6 ブロック、6 head、FFN 1536（mlp_ratio 4）、CLS、qkv の bias、dropout と attention dropout 0.1。
- **正規化**: 腕 A・C は `normalization='none'` で、上流の `get_normalization` が norm1・norm2・最終 norm の 13 か所を `nn.Identity` にする（factorial の `cell_config(4.0, 'none')` と同じ）。腕 B は `'layer'`（affine あり）。
- **パラメータ数**（CPU で数えた）: A・C は 10,814,024、B は 10,824,008。差の 9,984 は 13 個の LN の γ と β である。
- **初期値**: `torch.manual_seed(seed)` の後に上流の `_init_weights`（trunc normal 0.02、bias 0）。LN の初期化は乱数を使わないので、同じ seed の A と B は共有するパラメータの初期値が一致する（§8 の S-stream で確かめる）。
- **学習**: Adam（lr 1e−4、β 0.9 / 0.999、ε 1e−8、weight decay なし、fused）。`torch.compile(fullgraph=True)` で、`fallback_random=True` により dropout の ATen 乱数列を保つ。float32、TF32 無効、`torch.use_deterministic_algorithms(True)`、`CUBLAS_WORKSPACE_CONFIG=:4096:8`。batch 128、warmup なし。勾配の clip はせず、非有限の検出だけを行う。
- **head**: 各課題の始め（課題 1 を含む）に、200 行 × 384 の重みと bias を 0 にする。Adam の moment は持ち越す。損失と online 正解率は現課題の 5 クラスの出力に限る（`index_select`）。
- **拡張**: 8 の pad と 64 の crop、反転 0.5、明るさ・コントラスト・彩度の jitter 0.1 をランダムな順で掛ける（Pillow の `transform`）。評価は拡張なし。標準化は ImageNet の mean と std。
- **乱数の stream**（どれも `stream_seed(...)`、sha256 の先頭 8 byte）: batch の順は `('batch', seed, task)`、拡張は `('augment', seed, task, step, idx)`、loader は `('loader', seed, task)`、乱数ラベルは `('randlabel', seed, task)`。どれも学習の履歴によらず、(seed, task) だけで決まる。
- **乱数ラベル**（A・B）: 各課題で 250 枚に {0, …, 4} の一様な iid のラベルを引き直す（randlabel の `random_labels`）。250 枚を batch 128 で回すので、1 epoch は 128 枚と 122 枚の 2 batch になる。

### 4.2 40 課題を超える課題列（新しく決めること）

- Tiny ImageNet は 200 クラスなので、重複しない 5 クラスの課題は 40 個しか作れない。
- 課題 t の巡回の番号を c = ⌊(t − 1)/40⌋、巡回の中の位置を i = (t − 1) mod 40 とする。
- **クラスの組**: c = 0 は `task_classes(seed)`（battle と同じ）。c ≥ 1 は、200 クラスを `random.Random(stream_seed('cycle', seed, c))` で混ぜて 5 個ずつに切った 40 組を使う。
- **画像**: 各クラスの訓練画像（path の順に並べた 500 枚）の 50c + 1 番目から 50c + 50 番目を使う。1 課題は 5 クラス × 50 枚 = 250 枚になる。
- この並べ方では、どの訓練画像も 2 つの課題に出ない。500 枚 / 50 枚 = 10 巡なので、最大 400 課題まで作れる。T = 100 なら巡回 0・1・2 を使い、課題 81〜100 は巡回 2 に入る。
- 巡回 0（課題 1〜40）の画像とラベルは、randlabel・N セルの `make_task_dataset` とビットで一致する（§8 の S-stream）。
- 巡回ごとにクラスの組を混ぜ直すのは、40 課題ごとに同じ 5 クラスの画像分布が戻る周期を作らないためである。
- 乱数ラベルでは、クラスの名前はラベルの情報を持たない。クラスが別の巡回で再び出ても、画像とラベルは新しい。

### 4.3 腕

| 腕 | 正規化 | ラベル | 1 課題の画像 | T | U | seed | 役割 | fresh |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| **A** | なし | 乱数 | 250 枚（§4.2） | 100 | 1,500 | 0〜4 | 主 | 課題 25・50・100 |
| **B** | LN あり | 乱数 | 250 枚（§4.2） | 100 | 1,500 | 0〜4 | 対照: 盾が予算を増やしても保つか | 課題 25・50・100 |
| C | なし | 実 | 2,500 枚（battle と同じ） | 40 | 1,500 | 0〜4 | 記録・任意（Issa が決める） | 課題 25・40 |

- 同じ seed の腕どうしは、初期値・クラスの順・画像・batch の順・拡張が一致する。A と B は乱数ラベルも一致する。
- T・U・seed の数は §4.5 の推奨で、Issa が決める。
- 活性化は ReLU だけで、幅 1536・lr 1e−4 も変えない。lr は後の lever として §9 に残す。
- 課題 1 の最初の 500 更新は、A では N セルの課題 1 と、B では randlabel の課題 1 と、同じ初期値・画像・ラベル・batch の順・拡張を通る。batch の列は U によらず先頭が同じだからである。ビットで一致すれば、seed 0 の課題 1 の最初の 500 更新の online は A で .481、B で .687 になる（§8 の S-smoke-b で記録する）。
- fresh は「初期化したての網に、その課題だけを U 更新学ばせる」対照である。初期値は継続の網と同じ `make_model('R', seed)` で、Adam は新しく作る。課題 1 の fresh は継続の網の課題 1 と同じ計算になるので、新しく回さない（§8 の S-fresh1 で一度だけ確かめる）。

### 4.4 腕 C（実ラベル）の扱い

- 実ラベルでは、40 課題を超えるとクラスが再び出る。同じクラスの意味を学び直す課題になり、問いが変わる。だから C は T = 40 にとどめ、battle と同じ課題列を使う。
- C の T90 は、訓練の 2,500 枚から各クラスの最初の 50 枚を固定した 250 枚（A の同じ課題の画像）で測る。2,500 枚を 25 更新ごとに通すと、評価だけで学習の約 3 割の時間がかかるからである。
- 課題末には、2,500 枚の訓練精度と、250 枚の検証精度も出す。
- 費用は 5 seed で 5.8 GPU 時間、保存は 14.5 GB である（§10.4）。
- C を回すかは Issa が決める。回すなら A・B の後に回す。

### 4.5 予算と推奨セル

計算量の表は §10.4 にある。A と B を合わせた合計（62 ms/更新での換算）から読めることは次のとおり。

- 依頼の格子（T ∈ {40, 100, 200} × U ∈ {500, 2,000, 5,000} × seed ∈ {5, 10}）には、T と U の両方を増やしたまま 20〜30 GPU 時間に入るセルが無い。
- 20〜30 時間に近いのは、T = 40・U = 2,000・10 seed の 30.6 時間（U だけを増やす）と、T = 200・U = 500・5 seed の 19.1 時間（T だけを増やす）である。
- Fable の目安（T = 100・U = 2,000・5 seed）は 37.4 時間で、30 時間を超える。

**推奨は T = 100・U = 1,500・seed 0〜4（A と B）。** 62 ms/更新で 28.2 GPU 時間、67 ms/更新で 30.4 GPU 時間、保存は 50 GB である。理由は次のとおり。

1. T と U の両方が増える（2.5 倍と 3 倍）。1 seed の更新数は 150,000 で、N セル（20,000）の 7.5 倍になる。
2. U = 1,500 は、早期の T90 の目安（100〜300 更新、§2.3）の 5〜15 倍である。J1 の「早期の 2 倍以上」と「上限張り付き」の両方に余地がある。
3. 早期の課題でも当てはめの後に 1,200 更新以上が残る。Fable と Issa の読みは当てはめ後の伸びで分かれるので、この長さが J2b に要る。
4. T = 100 なら後期の窓（課題 81〜100）は、喪失が更新数で進む場合も切替の数で進む場合も、N セルが喪失した長さを大きく越えた所に来る。N セルは 40 課題 × 500 更新で喪失した。
5. 腕ごとに 5 seed で、過半は 3/5 である。A と B は seed 0〜4 で対になる。10 seed にすると 56.4 時間かかる。
6. 62 ms/更新なら 30 時間に入る。67 ms/更新なら 30 時間をわずかに超える。§8 の S-speed で実際の速さを測り、換算が 30 時間を超えたら報告する。

次の候補（Issa が選ぶ）:

| 案 | T | U | seed（A + B） | 合計 GPU 時間 | 得るもの | 失うもの |
| --- | --- | --- | --- | --- | --- | --- |
| 推奨 | 100 | 1,500 | 5 + 5 | 28.2 | — | — |
| (i) Fable の目安 | 100 | 2,000 | 5 + 5 | 37.4 | 当てはめ後の期間が 1/3 長い | 30 時間を 7.4 時間超える |
| (ii) | 100 | 2,000 | 5 + 3 | 29.9 | U を Fable の目安に保つ | B の過半が 2/3 になり、A との対は 3 組 |
| (iii) | 150 | 1,000 | 5 + 5 | 28.1 | 課題が 1.5 倍 | 当てはめ後の期間が短く、J2b が弱い |

### 4.6 段①がこの箱で働く形（J5 の前提）

- 原典の手順では、課題の始めに head の 200 行がすべて 0 になる。損失は現課題の 5 行だけを使う。
- 新課題の 5 行は、課題の始めには必ず 0 である。T ≤ 40 では一度も学ばれていない行で、T > 40 でも課題の始めに 0 へ戻される。
- だから新課題の最初の更新では logit がすべて 0 で、予測は一様になる。体への誤差 ∂L/∂h = Wᵀ(p − y) は厳密に 0 である。
- 前課題の読み出しは、新課題の損失に一度も入らない。MLP・CNN・GPT の段①（前課題の読み出しが、新課題の一様な期待のもとで unit を沈める押し）は、この箱では学習中に働かない。
- 切替で実際に働くのは次の 2 つである。
  1. **Adam の慣性**: 体の勾配が 0 でも、持ち越した 1 次 moment m で体は前課題の最後の向きに動き続ける。m は 1 更新に 0.9 倍ずつ減るので、効くのは約 10 更新である。
  2. **head の学び直し**: 新しい head W′ は、新課題のラベルと特徴の相関 F′ の向きに育つ。一次の近似では、新ラベルの一様な期待のもとで、体への誤差は E_y[∂L/∂h_n] ∝ −h_n になる（§7.6 で導く）。
- このため J5 は「head を課題の間で共有したら（MLP・CNN の箱と同じ形）」の反実仮想として定義する。課題末の体と head に残った装填の幾何が、沈める向きに揃っているかを測る量である。
- 実際に働く一次の押しは J5r として記録する。B では、最終 LN の γ = 1・β = 0 のとき、J5r は LN の ε の分を除いて 0 になる。A では、J5r の自己項は unit を浮かせる側に働く（§7.6）。

## 5. 却下した代案

### (a) 40 課題のまま U だけを延ばす（T = 40、U = 2,000〜5,000）

- Issa の決定は「課題数と課題あたりの更新数を両方増やす」なので採らない。
- N セルでは 4 seed が 40 課題で崩れ切らなかった。課題数を増やさないと、その 4 seed が喪失するかは見えない。

### (b) 40 課題を超えた後、同じ 250 枚を使い回す（40 課題の列を繰り返す）

- 同じ画像が新しい乱数ラベルで戻ってくる。前に覚えた対応が新しい対応とぶつかる課題になり、「新しい課題を覚える」の型から外れる。
- §4.2 の並べ方なら、どの画像も一度しか出ない。

### (c) 1 課題の画像を 2,500 枚にする（乱数ラベル）

- randlabel の較正（§2.2）で、2,500 枚は 500 更新で暗記率 .229、2,000 更新でも .375 だった。床に張り付いて、喪失ではなく「学べない」を測ってしまう。

### (d) U = 500 のまま指標だけを T90 に替える

- N の早期の T90 の目安は約 180〜300 更新で、課題 1 は 500 を超える（§2.3）。上限 500 は早期の T90 の 1.7〜2.8 倍しかなく、J1 の「早期の 2 倍以上」は上限に張り付いた課題でしか満たせない。

### (e) U を延ばす代わりに lr を上げる

- 原典の ViT の lr（1e−4）を外れる。randlabel の較正では、lr 3e−4 は暗記を悪くした（2,500 枚で .220）。
- lr は後の lever として §9 に残す。

### (f) 1 枚の GPU に 2 本以上を並べる

- 0919 の測定で、総処理量は 2 本で 0.92 倍、4 本で 0.97 倍だった（§2.4）。速くならないので 1 本ずつ回す。

### (g) 10 seed にする

- 推奨セルで 56.4 GPU 時間になり、予算の 2 倍になる。5 seed で過半を 3/5 とする。

### (h) C を 100 課題にする

- 実ラベルは 40 課題を超えるとクラスが再び出て、同じクラスの学び直しになる（§4.4）。費用も 14.1 GPU 時間になる。

### (i) dropout を外した腕（原典の Fig. B.5 の「正規化なし・dropout なし」）

- この spec の N セルは dropout 0.1 を残している（factorial §6 の残る差）。dropout は課題の中の雑音の出どころの一つなので、外すと J2b の読みが変わる。
- 喪失の大きさを変える別の lever なので、今回は回さない（§9）。

### (j) 全課題の課題末を保存する

- 保存は 1 seed・1 腕で約 5 GB から約 18 GB に増える。ディスクの空きの半分には収まるが、J5 と後の解析は 5 課題ごとで足りる。

## 6. 測る量

### 6.1 課題ごとの記録（`per_task.csv`）

| 量 | 定義 |
| --- | --- |
| online（課題平均） | 各更新の前の batch 正解率の、課題の U 更新での平均（battle と同じ） |
| online（最初の 500 更新） | 同じ量を更新 1〜500 だけで取る。40 × 500 のセルの課題平均と同じ長さの窓 |
| online（100 更新ごと） | 100 更新ごとの区間の値（battle の `online_chunks`） |
| online の損失 | 同じ batch の交差エントロピーの平均 |
| 課題末の暗記率 | 課題末の網を評価の状態で、課題の訓練画像（A・B は 250 枚、C は 2,500 枚）に通した正解率 |
| T90 と reached | §1 の定義。25 更新ごとの暗記率から出す。reached は U までに 0.9 を超えたかどうか |
| T50・T75（記録） | 暗記率が初めて 0.5・0.75 を超えた更新。T90 に届かない課題の遅れを見る |
| T90_online（記録） | 連続する 2 batch（1 epoch = 250 枚）の online 正解率が、初めて 0.9 を超えた更新。評価の forward を使わない別の数え方 |
| 検証精度（C だけ） | 課題の 5 クラスの検証画像 250 枚の正解率 |
| 200 出力の正解率（C だけ） | battle の `*_global_acc` と同じ |
| 秒数 | 学習・評価・記録・保存を分けて残す |
| 発散 | 非有限の検出の有無と、その課題・更新の番号 |

- C の T90 は、§4.4 の固定の 250 枚で測る。課題末の暗記率（訓練精度）は 2,500 枚で出す。

### 6.2 課題の中の記録（`intask.npz`）

25 更新ごと（u = 25, 50, …, U）と、課題の始め（head を 0 にした直後、u = 0）に取る。

- 暗記率と損失（課題の訓練画像、評価の状態）。
- ブロックごとの up 行のノルムの中央値（全 1536 unit）と、fc1 の bias の中央値。
- ブロックごとの up 行の 25 更新の変位の中央値 median_j ‖w_j(u) − w_j(u − 25)‖。Adam の一歩の大きさが当てはめの後に縮むかを見る。
- fc2 の列のノルムの中央値、head の 5 行のノルム、最終 LN の γ のノルム（B だけ）。
- 100 更新ごと（u = 100, 200, …, U）には、probe の層の要約（§6.3 の表の量）も取る。unit ごとの配列は残さない。

評価は、網を `eval()` にし、compile していない元の module を `no_grad` で通してから `train()` に戻す（randlabel の `train_accuracy` と同じ）。評価は dropout を使わないので、大域の乱数を消費しない。この記録が学習の軌道を変えないことは、§8 の S-recorder で確かめる。

### 6.3 単位の統計（probe。`layer_stats.csv` と `unit_stats/`）

- **probe**: 検証画像 10,000 枚を file 名の順に並べ、`torch.Generator().manual_seed(stream_seed('probe', seed))` の `randperm` の先頭 64 枚を取る。同じ seed のどの腕・どの課題でも同じ 64 枚を使う。評価の状態・拡張なしで通す。
- **いつ**: 初期値（課題 1 の前）と、全課題の更新 100 と課題末。fresh も更新 100 と課題末。層の要約は 100 更新ごとにも取る（§6.2）。
- ブロック l = 1〜6 の FFN ごとに、全 4,160 位置と、CLS の 64 位置を別々に、次の量を出す。

| 量 | 定義 |
| --- | --- |
| μ_j・σ_j | unit j の前活性 z の平均と sd（ddof 1） |
| r の中央値 | r_j = μ_j / (σ_j + 1e−12) の unit の中央値。μ と σ の中央値も出す |
| p_j | z > 0 になる位置の割合 |
| 死 | p_j < 0.005 の unit の割合（dead005）。CLS だけでは 64 標本なので、p = 0 と同じになる |
| 完全死 | p_j = 0 の unit の割合（dead0） |
| 正側の片側化（記録） | p_j ≥ 0.99 の unit の割合 |
| 負側の質量 | すべての（位置、unit）の z のうち、z < 0 の割合（factorial の `negative_mass` と同じ式） |
| up 行のノルム | ‖w_j‖ の中央値。全 unit と、生きた unit（p_j > 0）の別に出す。fc1 の bias の中央値と、負の bias の割合も出す |
| FFN の入力の要約 | FFN の入力 x̃（B は norm2 の出力、A・C は残差そのもの）の位置の平均 m について、‖m‖、‖m‖/√384、平均の割合 ‖m‖² / mean_n ‖x̃_n‖²。位置の共分散 C（ddof 1）の participation ratio tr(C)² / tr(C²) |
| r の分け方（記録） | r_j = ‖m‖ c_j / ŝ_j + b_j / s_j。c_j = cos(w_j, m)、ŝ_j = sd_n(ŵ_j · x̃_n)、s_j = ‖w_j‖ ŝ_j（chargpt_l0carrier_1023 §3 と同じ） |
| 残差への書き込みの比 | 最終の正規化の前の残差を t = e + Σ_l (a_l + f_l) と書く（e は patch 埋め込み・CLS・位置埋め込み、a_l は注意の出力、f_l は FFN の出力）。成分 c ごとに w_c = 位置の平均の ‖c_n‖ / ‖t_n‖ と、射影の分担 π_c = 位置の平均の ⟨c_n, t_n⟩ / ‖t_n‖²（13 成分の和は 1）を出す。‖t_n‖ の平均も出す（chargpt_handover_1023 §3.2 と同じ形） |

- **factorial と同じ読み出し（記録、課題末）**: 現課題の訓練画像のうち `np.linspace(0, 249, 16)` 番目の 16 枚 × 65 token で、z < 0 の質量と、z の最大が 0 以下の channel の割合を出す（`randlabel_control_joudaki_vit_0919.readout` と同じ式、6 層平均）。§2.1 の .2764・.0005 と並べるための量である。
- **生き返り（記録）**: 保存した課題末の状態の間で、完全死から p > 0 に戻った unit の数をブロックごとに数える。LN が死を「防ぐ」のか「戻す」のかを分ける量である。
- 層の要約は `layer_stats.csv`（git に入れる）に置く。unit ごとの μ・σ・p・‖w‖・b（全位置と CLS）は `unit_stats/` の npz（float32）に置き、生データの置き場へ入れる。

### 6.4 保存（checkpoint）

| 状態 | 中身 | 課題 | 1 個の大きさ |
| --- | --- | --- | --- |
| 初期値 | 重み | 課題 0 | 43.3 MB |
| 課題末 | 重み・Adam（exp_avg・exp_avg_sq・step）・RNG（CPU と CUDA） | 1〜10、15、20、…、T | 129.8 MB（A・C）、129.9 MB（B） |
| 更新 100 | 重み | 課題末と同じ課題 | 43.3 MB |
| fresh の課題末 | 重み | fresh の課題 | 43.3 MB |
| 再開用の `checkpoint.pt` | 課題末と同じ中身と、記録の行 | 毎課題で上書きする 1 本 | 約 130 MB |

- 大きさは「パラメータ数 × 4 byte（float32）」で、Adam 込みはその 3 倍（重み・m・v）になる。
- 保存する課題は T = 100 で 28 個ある。1 seed・1 腕で 4.9 GB、fresh を足して 5.0 GB になる。
- 置き場は `~/Projects/obsidian-research-data/vit_long_1024/<腕>/seed<k>/ckpt/`。書き込みは一時ファイルからの原子的な置き換えにする（battle の `atomic_save`）。
- 合計は推奨セル（A と B、5 seed）で 50 GB、C を足して 65 GB である。2026-10-24 の空き 409 GiB の半分（204 GiB）を超えない（§10.4）。

### 6.5 fresh

- 課題 25・50・T（C は 25・40）で回す。初期値は継続の網と同じで、Adam は新しく作る。画像・ラベル・batch の順・拡張は、継続の網のその課題と同じにする。
- 記録は §6.1〜§6.3 と同じ量で、課題末と更新 100 の単位の統計を含む。
- 課題 1 の fresh は継続の網の課題 1 そのものなので回さない（§4.3）。
- fresh と継続の網の違いには、初期の特徴を一から作る費用、Adam の moment が 0 から始まること、dropout の乱数の履歴の 3 つが入る（§9）。

## 7. 判定（走る前に固定）

### 7.0 集約の共通規則

- 量は seed ごとに 1 つの値にし（seed の中で窓の中央値を取る）、seed 間の中央値と範囲を出す。
- 窓は、早期 = 課題 2〜11、後期 = 最後の 20 課題（T = 100 なら課題 81〜100、C は課題 21〜40）とする。課題 1 は初期値から始まるので、早期に入れない。
- 過半は、判定に使える seed の数 n について ⌈(n + 1)/2⌉ 個とする（n = 5 と 4 で 3 個）。
- 発散した走は、発散した課題までの記録を残す。後期の窓を終えた seed だけを判定に使い、その数が 4 未満なら、その腕のラベルは `INSUFFICIENT` とする。発散した seed の数はラベルと別に書く。
- T90 は打ち切りのある量なので、平均を取らず、中央値と数で扱う。
- 同じ seed の A と B の差は記録で、符号を数えるだけにする。5 対では全勝でも両側の exact 符号検定が p = 0.0625 なので、検定の言い方をしない。

### 7.1 J1 喪失（主、A）

seed k・課題 t の T90_{k,t}（上限 U）と reached_{k,t} から、次を出す。

- **学習の成立**: 早期の 10 課題のうち 6 課題以上で reached。
- **E_k と L_k**: 早期の T90 の中央値と、後期の T90 の中央値。打ち切りの課題は U として並べる。
- **上限張り付きの seed**: 後期の 20 課題のうち 11 課題以上で reached でない seed。このとき L_k = U になる。
- **比**: R = median_k L_k / median_k E_k。

| ラベル | 条件 |
| --- | --- |
| `LOSS` | R ≥ 2、かつ上限張り付きの seed が過半 |
| `SLOWDOWN` | R ≥ 2 で、上限張り付きの seed が過半に届かない |
| `MIXED` | R < 2 で、上限張り付きの seed が過半 |
| `NO_LOSS` | R < 2 で、上限張り付きの seed が過半に届かない |
| `NOT_JUDGEABLE` | 学習が成立した seed が過半に届かない、または median_k E_k = U |

- 2 倍と過半は依頼の値である。評価の間隔 25 更新は早期の T90 の目安（100〜300 更新）より十分小さく、比は間隔で決まらない。
- 記録: seed ごとの L_k / E_k、10 課題ごとの T90 の中央値の推移、online（課題平均と最初の 500 更新）の早期 − 後期、課題末の暗記率、T50・T75・T90_online。
- **fresh との比較（記録）**: t = 25・50・T で、online の差 Δ(t) = online_fresh(t) − online_継続(t)（課題平均と最初の 500 更新の両方）と、T90 の比 T90_継続(t) / T90_fresh(t) を出す。Δ > 0 は継続の網が劣ることを指す。

### 7.2 J2 幅は課題の中で伸びるか（A、後期）

- n_l(s) を、状態 s でのブロック l の up 行のノルムの中央値（全 1536 unit）とし、n̄(s) を 6 ブロックの平均とする。
- 課題 t の始め（前課題末）を s_{t,0}、更新 100 を s_{t,100}、課題末を s_{t,U} とする。
- 課題内の伸びは within_t = n̄(s_{t,U}) − n̄(s_{t,100})、1 課題あたりの伸びは per_t = n̄(s_{t,U}) − n̄(s_{t,0}) である。
- seed の値は ρ2_k = Σ_{t∈後期} within_t / Σ_{t∈後期} per_t とする。Σ per_t ≤ 0 の seed は ρ2 を出さない。

| ラベル | 条件 |
| --- | --- |
| `WITHIN_TASK_GROWS` | median_k ρ2_k ≥ 0.5 |
| `SWITCH_GROWS` | median_k ρ2_k < 0.5 |
| `NO_LATE_GROWTH` | Σ per_t ≤ 0 の seed が過半 |

- 0.5 は依頼の値である。参考に、課題の中で一様に伸びれば ρ2 = (U − 100)/U = 0.93、伸びが頭の 100 更新だけなら ρ2 = 0 になる。
- 更新 100 は早期の T90 の目安より前にある。だから当てはめの後半の伸びも「課題内」に数えられる。当てはめの後の伸びは J2b で別に見る。
- 記録: ブロックごとの ρ2、生きた unit の中央値での ρ2、前活性の sd（probe の全位置）での同じ割り方、早期の窓、B と C の同じ量。

### 7.3 J2b 当てはめの後も幅は伸びるか（A、起案者が足した判定）

- **足した理由**: J2 の更新 100 の割り方では、当てはめが更新 100 より長く続くと、当てはめ中の伸びも「課題内」に数えられる。Fable の読み（当てはめ後に止まる）と Issa の読み（長い更新で伸びる）を分けるには、T90 の前後で割る必要がある。採否は登録の前に Fable と Issa が決める。
- **使う課題**: 課題 2〜T のうち、reached で T90_t ≤ U − 500 の課題（当てはめの後に 500 更新以上が残る課題）。
- T90 の時点の n̄ は、25 更新ごとの記録（§6.2）から取る。T90 は評価の点なので、記録の点と重なる。
- seed の値は、当てはめ後の伸びの速さを課題全体の平均の速さで割った比とする。

  ρ_post,k = [Σ_t (n̄(s_{t,U}) − n̄(s_{t,T90})) / Σ_t (U − T90_t)] ÷ [Σ_t (n̄(s_{t,U}) − n̄(s_{t,0})) / (課題の数 × U)]

- 使える課題が 10 未満の seed と、分母の伸びが 0 以下の seed は数えない。

| ラベル | 条件 |
| --- | --- |
| `POSTFIT_GROWS` | median_k ρ_post,k ≥ 0.5 |
| `FIT_GROWS` | median_k ρ_post,k < 0.5 |
| `INSUFFICIENT` | 数えられる seed が 3 未満 |

- 0.5 の出どころ: 「当てはめ後に止まる」なら ρ_post = 0、「課題の中で一様に伸びる」なら ρ_post = 1 なので、その中点を取った。
- 記録: 早期と後期の窓を分けた値、前活性の sd での値、T90 の前後の 25 更新の変位（§6.2）、B と C の同じ量。

### 7.4 J3 死（A、後期）

- D_k = 後期の各課題末での完全死の割合（probe の 4,160 位置で p = 0 の unit、6 ブロックの平均）の、課題の中央値。
- ラベル: median_k D_k ≥ 0.2 で `DEATH`、そうでなければ `NO_DEATH`。
- 0.2 は依頼の値である。参考に、N セルの課題 40 は .2764、LN ありは .0005 だった（16 枚の読み出し、§2.1）。
- 記録: 死（dead005）、ブロックごとの値、CLS だけの値、factorial と同じ読み出し、完全死が初めて 0.2 以上になる課題、生き返りの数、負側の質量、B と C の同じ量。

### 7.5 J4 LN の盾（B）

- J1 の規則を、そのまま B に当てる。

| ラベル | 条件 |
| --- | --- |
| `LN_SHIELDS` | B の J1 が `NO_LOSS` |
| `LN_FAILS` | B の J1 が `LOSS` |
| `LN_PARTIAL` | B の J1 が `SLOWDOWN` か `MIXED` |
| `INSUFFICIENT` | B の J1 が `NOT_JUDGEABLE` か `INSUFFICIENT` |

- A の J1 が `LOSS` でないときは、ラベルに「A にも喪失が無いので、盾の検査になっていない」と添える。
- 記録: B の J2・J2b・J3、同じ seed の A − B の E_k・L_k・D_k の差の符号。

### 7.6 J5 最終ブロックの FFN の CLS 位置への切替の押し（事後、保存状態。主は A）

J5 は走った後に、保存した課題末の状態だけで計算する。学習も optimizer の更新もしない。計算は CPU の float64 で行う。定義は走る前のここで固定する。

記号（ブロック 6、CLS 位置、画像 n、状態は課題 t の末で head を 0 に戻す前）:

| 記号 | 意味 |
| --- | --- |
| r_n | ブロック 6 の注意の後の残差（norm2 の入力） |
| y_n | FFN の入力。B は norm2(r_n)、A は r_n |
| z_n、a_n | z_n = W1 y_n + b1、a_n = φ(z_n) |
| U_j | fc2 の列 j。unit j が残差へ書く向き（384 次元） |
| t_n | 最終の正規化の前の残差。t_n = r_n + W2 a_n + b2 |
| h_n | head が読む特徴。B は LN_f(t_n) = γ ⊙ q_n + β（q_n は t_n を中心化して σ_n で割った量）、A は t_n |
| W、b | 課題 t の 5 クラスの head の行と bias |

- **装填**（kappa_cnn5p1_1022 §3 の定義を移す）: F_t = Σ_{m∈課題 t} (e_{y_m} − 1/5) ⊗ h_m（5 × 384）。y_m は課題 t の乱数ラベル、画像は課題 t の 250 枚を評価の状態で通す。クラスで中心化した head を W^c = W − mean_c W とし、κ_t = ⟨W^c, F_t⟩ / ‖F_t‖²、cos²、Q = κ_t‖F_t‖ を出す。装填成分は vL = κ_t F_t である。
- **勾配の probe**: 次の課題（t + 1）の訓練画像 250 枚の CLS 位置を、評価の状態で通す。ȳ はその y_n の平均、担い手は K_n = y_n · ȳ + 1 とする（bias の経路を含む V13 の K_n = x̄ · x_n + 1）。loadsign と同じ K⁰_n = y_n · ȳ も記録する。
- **反実仮想の誤差**: e_n = softmax(W h_n + b) − 1/5。旧 head を新課題の画像に当て、新ラベルの一様な期待を目標にした誤差である。
- **装填成分を通す逆伝播**: g_n = vLᵀ e_n。B は b_n = γ ⊙ g_n、D_n = (b_n − mean(b_n)) / σ_n、R_n = −q_n mean(q_n ⊙ b_n) / σ_n とする（σ_n² = t_n の中心化した分散 + ε、ε = 1e−5）。A は D_n = g_n、R_n = 0。
- **押し**: S_j = mean_n K_n φ′(z_nj) [(D_n + R_n) · U_j]。S_j > 0 なら、勾配降下は w_j · ȳ + b_j を下げる。これを「沈める側」と呼ぶ。
- **生きた unit**: probe の CLS 位置で、z_nj > 0 の画像が 1 枚以上ある unit。
- **状態ごとの値**: s_load = 生きた unit のうち S_j > 0 の割合（0 は正に数えない）。
- **成分（記録）**: 直通の項（D だけ）と分散微分の項（R だけ、B のみ）。直通の項は、loadsign §7 の softmax の恒等式 p − u = H f で、自分の unit・他の unit・残差の 3 項に分ける。ViT の定数項（b2、β、head の bias b）は残差の項に入れる。
- **窓**: 早期 = 保存した課題末 1〜9、中期 = 45・50、後期 = 85・90・95・100。

| ラベル | 条件 |
| --- | --- |
| `LOADING_SINKS` | 早期の s_load の seed 内の中央値が 0.75 以上の seed が過半 |
| `NOT_SINKING` | そうでない |

- 同じ規則を後期の窓に当てたラベル（`LOADING_SINKS_LATE` / `NOT_SINKING_LATE`）も出す。
- 早期を主にした理由: 段①は最初の課題から切替ごとに働く主張である。GPT では direct が早期に 0.986〜0.996 で揃い、後期に崩れた。早期はこの箱に①の幾何があるかを、後期はそれが続くかを問う。窓の選び方は登録の前に Fable と Issa が変えてよい。
- B と C も同じ量を出して記録にする。B には分散微分の項 R が入る。
- 記録: κ > 0 の状態の数、cos²、Q、kappa_cnn5p1 §3 の補題 A ≥ N(log K − L_K) − B の破れの数、K_n > 0 の割合、生きた unit の数。

**J5r 実際に働く一次の押し（記録。ラベルを出さない）**

- head は 0 から始まる。全 batch の勾配で一歩 η だけ進めると、W′ = η Σ_m (y_m − u) h_mᵀ になる（W = 0 では p_m = u）。
- その W′ での体への誤差は ∂L/∂h_n = W′ᵀ(p_n − y_n) ≈ −η Σ_m h_m (y_m − u)ᵀ(y_n − u) である。
- 新ラベルが一様で iid なら、E[(y_m − u)ᵀ(y_n − u)] は m = n で 1 − 1/K、m ≠ n で 0 になる。だから E_y[∂L/∂h_n] = −η(1 − 1/K) h_n + O(η²) である。
- J5r は、J5 の式の g_n を −h_n に置き換えた押し S^r_j とする。正の係数 η(1 − 1/K) は符号を変えないので落とす。probe・ȳ・K・生きた unit は J5 と同じにする。
- この次数で言える 2 つのこと:
  - A（LN なし）: t_n = r_n + Σ_i U_i a_ni + b2 なので、S^r_j の自己項は −mean_n K_n φ′(z_nj) a_nj ‖U_j‖² である。ReLU では φ′(z) a = a ≥ 0 なので、K_n > 0 なら自己項は 0 以下で、unit を浮かせる側に働く。
  - B（LN あり）: γ = 1・β = 0 なら D_n + R_n = −(ε/σ_n²)(q_n/σ_n) が各画像で成り立つ。押しは直通の項の ε/σ_n² 倍に縮み、LN の ε の分を除いて 0 になる。
- Adam の形（記録）: head の最初の数歩は要素ごとに符号に近い一歩になる。そのときの期待の誤差として、g_n = −h_n ⊘ s（s_k は probe の h_nk の 2 乗平均の平方根）も出す。
- 記録: s^r（生きた unit のうち S^r_j > 0 の割合）、A の自己・他・残差の 3 項、B の直通と分散微分の 2 項。窓は J5 と同じ。
