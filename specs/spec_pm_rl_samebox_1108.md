状態: **登録（予測 §5 を固定、本走の前）** / 2026-11-08 / 起案: Claude（Opus 5.5）。予測 P9〜P12 は親（Fable）が走る前に与えたもの。Issa の go（「走らせてください」）により親が依頼。
親: `specs/spec_pm_ledger_1108.md`・`specs/spec_pm_ledger_add_1108.md`（箱の定義はそこと同じ。ここには差分だけ書く）。事後の集計は追補 C（`results/pm_ledger_add_1108/width_posthoc.md`、main a75be8ea）。

## 1 問い

追補 C は、PM の CHB では第 1 層の幅が 2.72 倍に伸び、RL-CIFAR の CHB ではノルムが 2.39 倍でも幅が 0.82 倍で伸びないことを見た。
ただし箱が違う（MNIST 500 課題 対 CIFAR 200 課題）。
同じ箱で順列と乱数ラベルを並べて、「Permuted MNIST は乱数ラベルと違って第 1 層の実効的な幅（前活性の標準偏差）が増えやすい」を測る。

## 2 設計

### 2.1 箱

`src/pmnist_0905.py` の課題と同じ網と学習則: ReLU 784-100-100-10、Adam 1e−3（β 0.9/0.999、ε 1e−8、bias 補正、状態は課題をまたいで持ち越す）、バッチ 16、625 更新/課題、500 課題、seed 0〜9、CPU。
初期化は `B.init_params(seed)`、乱数列は `B.stream(role, seed)`。
実装は `analysis/pm_ledger_add_1108/run.py` を `analysis/pm_rl_samebox_1108/run.py` に写して拡張する（元は触らない）。

### 2.2 列（sequence）

| 列 | 入力 | ラベル | 画像 |
|---|---|---|---|
| `perm1200` | 課題ごとに画素の順列（`B.stream("perm", seed)`、本走と同じ） | MNIST の本物で固定 | 固定 1,200 枚 |
| `rl1200` | 順列なし（恒等） | 課題ごとに 10 クラス一様乱数で振り直す（`B.stream("labels", seed)` の `randint(0, 10, (1200,))`。課題間で独立） | 固定 1,200 枚（`perm1200` と同じ 1,200 枚） |
| `perm10000` | 本走のまま | 本走のまま | 課題ごとに 10,000 枚 |

- 固定 1,200 枚: 層化抽出（`B.hamilton` の配分を n = 1,200 で、`B.stream("data1200", seed)` から）。全課題で同じ 1,200 枚。腕の間でビット一致。seed ごとに別の 1,200 枚。
- 画像数の理由: 先生の論文の乱数ラベルの定義は「固定した 1,200 枚に 10 クラスの乱数ラベル」（main.tex §3）。幅 100 の網では 10,000 枚の乱数ラベルは 625 更新で覚えられない。順列と乱数ラベルの差だけを見るため、順列にも同じ 1,200 枚の対照（`perm1200`）を置く。
- 更新: 625 更新 × バッチ 16 = 10,000 サンプル。1,200 枚を epoch ごとに新しくシャッフルする（`B.stream("batch", seed)` の `randperm(1200)` を 9 本、連結して先頭 10,000 サンプル）。つまり 8 epoch と 25 更新（400 サンプル）。n = 10,000 のときはこの手順が本走の 1 回の `randperm(10000)` と一致する（S1）。
- `perm10000`（pm_ledger_1108 の none、pm_ledger_add_1108 の CHB）は走り直さず、参照の行として表に載せる。この spec の実行で `perm10000` を使うのは S1 だけ。

### 2.3 腕

none（ReLU・介入なし）と CHB（`pm_ledger_add_1108` の CHB。C: 入力の EMA 0.01、H: 両隠れ層の EMA 0.01、B: 第 1 層の bias を 0、第 2 層の bias に λ = 0.1713）× 列 {perm1200, rl1200} = 4 腕 × seed 0〜9 × 500 課題 = 40 走。

ディレクトリ名は `runs/<列>_<腕>/seed{S}/`（例 `perm1200_CHB`）。

### 2.4 測るもの

- online: 本走と同じ（課題の流れの上で更新前のミニバッチ正答率の平均、10,000 サンプル）。
- 新品: 同じ規則の網（同じ腕の活性化、同じ列・同じ課題のデータと順番、Adam 0）を初期化から学ばせる。課題 100・200・300・400・500（`fresh.csv`）。G = 新品の online − 継続の online（課題 400・500 の平均）。正の G が喪失。
- `per_task.csv` の列は本走のまま全部（`zsd_l1`・`zbar_l1`・`w_norm_l1`・`dead_frac`・`eff_rank`・第 2 層も）。これらは本走と同じくテスト 10,000 枚に課題の順列を当てて測る（`rl1200` は順列なし）。**幅・平均・死の一次の値はこの列を使う**（perm10000 の参照と同じ測り方）。`rl1200` の `acc` は本物のラベルに対する正答率なので意味が無く、偶然の 10% 付近になるはずの値である。
- 追加の列（課題の 1,200 枚そのもので測る、`_tr`）: `acc_tr`（課題末の、その課題のラベルに対する正答率）、`dead_frac_{l1,l2}_tr`、`zbar_{l1,l2}_tr`、`zsd_{l1,l2}_tr`。これは参考の値で、予測の採点には使わない。一次の値と結論が割れたら報告する。
- 保存: `W1.npy`（課題末、(501,100,784)、float32）、`b1.npy`、`perm.npy`（`rl1200` は恒等）、`labels.npy`（`rl1200` のみ、(501,1200)、int8）、`idx.npy`（固定 1,200 枚の添字）、`per_task.csv`、`fresh.csv`、`provenance.json`。

幅 = `zsd_l1`（課題末の第 1 層の前活性の、ユニットごとの標準偏差の中央値）。ノルム = `w_norm_l1`（第 1 層の行ノルムの中央値）。どちらも追補 C と同じ列。
窓: w1 = 課題 6〜50、w2 = 101〜150、w3 = 251〜300、w4 = 451〜500（追補 C と同じ）。
比 = w4 の窓平均 ÷ w1 の窓平均（seed ごと）。

## 6 判定（予測の和で決める）

幅の判定（`verdict_width`）は上から順に当てはめる。

1. `PERM1200_DIFFERS`: perm1200 の CHB の幅の比 ≥ 1.8 の seed が 8/10 未満（1,200 枚の順列で幅が伸びない。perm10000 の幅の伸びの再現に失敗）。
2. `BOTH_GROW`: rl1200 の CHB の幅の比 > 1.25 の seed が 8/10 以上（乱数ラベルでも幅が伸びる）。
3. `WIDTH_CONTRAST`: P9 ○ かつ P10 ○。
4. `MIXED`: それ以外（どの条件が崩れたかを書く）。

喪失の判定（`verdict_loss`）: P11 ○ なら `LOSS_PERM_ONLY`。perm1200 の G ≥ +0.5 が 9/10 以上で rl1200 の G ≥ +0.5 が 8/10 以上なら `LOSS_BOTH`。perm1200 の G < +0.5 が 8/10 以上なら `NO_LOSS_PERM1200`。それ以外は `LOSS_MIXED`。
