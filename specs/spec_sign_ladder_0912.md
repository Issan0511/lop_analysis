# 谷の符号梯子 spec 0912 —— 反転は箱 B の損失の原因か

親: `spec_transport_holes_0910.md` §4.2 / 実装 `src/sign_ladder_0912.py`

## 0. 何が未決か

箱 B で GELU は L_ref 7.68 pt、ReLU 4.78、leaky 4.36、ELU1 4.13。同じ絶対深さで
GELU ユニットは非谷腕の約半分しか動かない（尺度不変 P(0.7·sd 上がる/50 タスク)：
GELU 0.39–0.43、leaky 0.62–0.65、ReLU 0.74–0.75、ELU1 0.83–0.85）。腕またぎでは
可動性の順が損失の順と一致する（Spearman 0.90、n=5）が、腕の中のクランプは逆を言う
（GELU は dclamp のほうが可動性が高いのに ρ 0.27 対 wclamp 0.69、ReLU は wclamp が
可動性を半減させて ρ 0.73）。相関では決まらない。反転そのものを操作する。

## 1. 腕（1 層目・2 層目とも同じ活性化。箱 B: pmnist・784-100-100-10・Adam・batch 16・lr 0.001・400 タスク・seed 0–2）

z_c = −0.7517915239、φ(z_c) = −0.16997120747990369。**3 腕は z ≥ z_c で完全に同一**
（自己検査で maxabs 0.0）。違うのは z < z_c のゲートの符号だけ。

| 腕 | φ′(z), z<z_c | φ(z), z<z_c | 位置づけ |
|---|---|---|---|
| `GELU` | φ′(z) < 0 | φ(z) → 0 | committed 参照（G1 で bit 一致を要求） |
| `GELUF` | 0 | φ(z_c) = −0.16997 | 反転を消す（箱 A の `clamp0` と同型） |
| `GELUA` | \|φ′(z)\| > 0 | 2φ(z_c) − φ(z) → −0.33994 | 反転の符号だけ反転。**\|ゲート\| は全 z で GELU と bit 一致** |

`GELUA` が厳密な腕、`GELUF` が緩い腕。GELUF 単独は「符号が悪い」と「信号が無い」を
交絡し、GELUA 単独は符号と「正のゲートを持つために必要な有界出力」を交絡するので、
両方が要る。

## 2. 進捗ゲート（通らなければ該当ラベルは `NOT_TESTABLE`）

  で再現（比較件数 = 6×400 = 2400 件を同時に記録。件数 0 で 0.0 を報告する罠を塞ぐ）
- **G2（操作チェック a）**: `GELUF`・`GELUA` の `gate_neg_frac` が全タスクで厳密に 0
  （`T.check_gates` の非谷分岐が走中に assert する）
- **G3（操作チェック b）**: 3 腕とも `past_zc_units`(t400) ≥ 20。新腕でユニットが谷を
  越えないなら介入は試されていない
- **G4（操作チェック c・可動性）**: z̄ ∈ [−9,−5) での尺度不変可動性 P(0.7·sd/50 タスク)
  が `GELUA` で GELU + 0.10 以上。これが外れると「可動性が損失を作る」の検定は
  情報を持たない（「反転が損失を作る」の検定は残る）

## 3. 主判定（endpoint）

L = 100 × ( median acc(t16–20) − median acc(t301–400) )、seed ごと。0910 の L_ref と同一。
ΔL = L(GELU) − L(新腕)。3 seed すべてで:

- ΔL ≥ +1.5 pt が **GELUF と GELUA の両方** → **`VALLEY_CAUSAL`**
  （1.5 は GELU の ReLU 超過 2.90 pt の約半分）
- |ΔL| < 0.7 pt が **両方** → **`VALLEY_IRRELEVANT`**（0.7 は GELU の seed 幅 0.36 の約 2 倍）
- GELUA のみ ≥ +1.5 → **`SIGN_ONLY`**（反転を消すだけでは足りず、戻す必要がある）
- GELUF のみ ≥ +1.5 → **`FLOOR_ONLY`**
- それ以外 → **`PARTIAL`**

## 5. 外れたときに第一に疑うもの

1. **`VALLEY_CAUSAL` が出たら**: GELUA は深部で −0.34 に飽和する有界活性化なので、
   ELU（→ −1 に飽和・L_ref 4.13）に近い**別の良い活性化関数**になっただけかもしれない。
   判別: GELUA の L が 4.0–4.3 に着地したら ELU 化を疑い、GELUF（→ −0.17 に飽和・
   ゲート 0）と分離して読む。
2. **`VALLEY_IRRELEVANT` が出たら**: G3 を見る。新腕のユニットが谷を越えていても
   深さ・幅が GELU とずれていれば、介入は反転以外も動かしている。z̄(t400)・sd(t400)・
   cnorm(t400) を 3 腕で並べて報告する（ラベルには使わない）。
3. **G1 が落ちたら**: この計算機（i7-14700K）は lab（i9-13900KF）と同じ Raptor Lake だが、
   torch が違う（2.13.0+cu130 対 2.12.0+cu126）。その場合 G1 を数値一致に落とし、
   **落としたことを判定に明記する**。

## 追補 1（2026-09-12・本走 1 回目の中断と開示。判定量は読む前に固定済み）

### 開示

1 回目の走で **GELU 3 seed・GELUF 3 seed・GELUA seed 0 の `acc`(t400) を見た**
（完了行が印字する）: GELU 0.8551/0.8397/0.8601、GELUF 0.8809/0.8793/0.8699、
GELUA(s0) 0.8799。これは endpoint L（base t16–20 と late t301–400 の中央値の差）
そのものではないが、**方向の情報を含む**。§3 の閾値・ラベル・§4 の記名予測は
**一切変更していない**。変更したのは下の実装バグの修正だけ。

### 中断の理由（float32 の符号跨ぎ・追補 2 blocker と同型で 2 例目）

`GELUA` seed 1 が `T.check_gates` の「非谷腕はゲートが負になってはならない」で落ちた
（`gate_neg_frac` = 1.95e−5、51200 標本中 1 点）。原因は z_c **直上**にある:

- GELU の φ′ は z_c で符号を変える。float32 で評価すると z ≥ z_c なのに φ′ < 0 に
  なる点が存在する（[−1.2,−0.3] の 2e6 点格子で 1 点。float64 では 0 点）。
- 実装が `where(z >= ZC, d, -d)` だったので、その点で d < 0 がそのまま出た。
- `GELUF` の `where(z >= ZC, d, 0)` も同じ穴を持つ。3 seed とも通ったのは、
  プローブ標本がその点に落ちなかっただけ。

### 修正（意図した数学の忠実な float32 実装。関数は変えていない）

- `GELUA.dphi = |φ′_GELU(z)|`（全 z）。z ≥ z_c では φ′ ≥ 0 なので恒等、z < z_c では
  −φ′。float64 の自己検査は従来どおり 0.0 で通る。
- `GELUF.dphi = where(z >= ZC, clamp(φ′, min=0), 0)`。

これで G2 は `GELUA` について構成上真になるので、検査の強さを保つために自己検査に
**float32 の検査とその変異対照**を足す: 生の GELU φ′ が float32 で z_c 近傍に符号跨ぎを
**持つこと**（持たなければガードは空虚）と、2 腕の float32 ゲートの最小値が 0 以上であること。

### 再走

**9 走すべてを新コードで回し直す**（GELU 腕は `VA.GELU` しか使わず軌道は変わらないが、
provenance の code_sha256 を揃えるため）。1 回目の出力は破棄する。

## 追補 2（2026-09-12・SiLU 梯子の事前登録。GELU の結果を見た後に書いている）

GELU は `VALLEY_CAUSAL`（ΔL +2.98・着地 4.70/4.62 で非谷帯の中）。SiLU で同じ梯子を回す。
**SiLU は 3 つの仮説が別々の着地点を予言する腕**なので、ここが本当の検定になる。

### 腕

`SILU`（参照・committed）/ `SILUF`（z<z_c でゲート 0・φ=φ(z_c)=−0.27846）/ `SILUA`
（ゲート \|φ′\|・φ=2φ(z_c)−φ(z) → −0.55693）。z ≥ z_c では 3 腕同一（自己検査 maxabs 0.0）。
SiLU の z_c = −1.2784645428、φ(z_c) = z_c + 1（恒等式）。

### 三つ巴（決定的な読みは **比 ΔL_SiLU / ΔL_GELU**、ΔL_GELU = 2.98）

| 仮説 | 根拠 | 予言する比 | ΔL_SiLU | 着地 L |
|---|---|---|---|---|
| **A 帯規則** | 谷は「非谷帯からの超過分」をちょうど持つ。GELU で 2.90 予言・2.98 実測 | **0.78** | 2.33 | ~4.6 |
| **B 可動性比例** | 可動性の欠損に比例（GELU 0.334・SiLU 0.141 対 非谷 0.74） | **0.42** | 1.26 | ~5.7 |
| **C 差分商（Claude の閉形式）** | 反転の総量は \|φ_min\|。SiLU 0.2785 / GELU 0.1700 | **1.64** | 4.9 | ~2.0 |

C は SiLU が ELU（4.13）より良くなることを意味する。谷底 3 下のゲートは SiLU −0.0440 対
GELU −0.0012 で 36 倍（指数裾 対 ガウス裾）なので、C の言い分には実体がある。

### ラベル

- 主: 3 seed とも両腕が ΔL ≥ +1.5 → **`SILU_VALLEY_CAUSAL`** ／ 両腕とも \|ΔL\| < 0.7 →
  **`SILU_VALLEY_IRRELEVANT`** ／ 他 → `PARTIAL`
- 副（着地・2 腕の平均 L）: 4.0 ≤ L ≤ 5.0 → **`LANDS_IN_BAND`**（A）／ L > 5.0 →
  **`PARTIAL_RECOVERY`**（B）／ L < 4.0 → **`OVERSHOOTS`**（C）
- ゲートは §2 と同形（G1 は `long_horizon_acts_0910/SILU_none_s*`、G4 は SILUA の可動性が

### 記名予測

**Claude: `SILU_VALLEY_CAUSAL` + `LANDS_IN_BAND`（A・60%）**、B 25%・C 15%。
GELU で帯規則が 0.08 pt の精度で当たったことを重く見る。**自分の閉形式 C は支持しない**
（\|φ_min\| は非重み付きゲートの話で、e との相関を含まないため水準を決める根拠が弱い）。
C が出れば差分商が損失水準まで予言したことになり、A が出れば \|φ_min\| は水準に効かない。

### コードの出所

追補 2 で `src/sign_ladder_0912.py` を base 一般化した。**GELU 腕のコード経路は不変**
（smoke が改修前と同一: acc(t8) 0.9364・past_zc_units 68）で、GELU 3 走は改修前の
code_sha256 のまま据え置く。GELU 腕の軌道は G1（lab の committed 参照と maxabs 0.0・
2400 件）で外部から固定されているので、内部のハッシュ一致より強い保証がある。

### float32 ガード

GELU では生の φ′ が float32 で符号を跨ぐ（z_c ±0.45 の 2e6 点格子で 1 点）のでガードは
**実証済み**。SiLU では同じ格子で 0 点なので、SiLU 側のガードは**予防的**（自己検査に
`float32_guard_demonstrated` として記録し、実証済みと書かない）。

## 追補 3（2026-09-12・媒介の分離を事前登録）

GELU/SiLU とも `VALLEY_CAUSAL` で、反転は L を 2.4〜3.1 pt 動かす。だが介入は幅と深さも
動かす（GELU: cnorm 9.13 → 14.25、z̄ −6.89 → −3.67）。**その 3 pt は幅経由か・深さ経由か・
直接か。**

### 設計: 分岐点で活性化も切り替える

`clamp_horizon` の機構をそのまま使い、**t1–20 を GELU で共通に走らせてから** t21 で
(活性化 × クランプ) に分岐する。こうすると 6 枝の**基準状態 `base` とスナップショットが
厳密に同一**になり、クランプ目標も同一になる。

枝 = {`GELU`, `GELUA`} × {`ref`, `wclamp`（‖W̃ᵢ‖ を t20 に固定）, `dclamp`（行平均を固定）}、
seed 0–2、t400 まで。

### 判定

gap(c) = L(GELU, c) − L(GELUA, c)。3 seed の平均で:

- `gap_wclamp ≥ 0.7·gap_ref` かつ `gap_dclamp ≥ 0.7·gap_ref` → **`DIRECT`**（どちらの経路も担っていない）
- `gap_wclamp ≤ 0.3·gap_ref` → **`WIDTH_MEDIATED`**
- `gap_dclamp ≤ 0.3·gap_ref` → **`DEPTH_MEDIATED`**
- 両方 ≤ 0.3 → **`BOTH_MEDIATED`** ／ 他 → `PARTIAL`

### ゲート

- **GM0**: gap_ref ≥ 1.5 pt（媒介すべき効果が存在する）
- **GM1**: (GELU, ref) 枝が committed `long_horizon_acts_0910/GELU_none_s*` を t1–400 で
  maxabs 0.0 再現（件数も記録）
- **GM2（操作チェック・対照つき）**: wclamp 枝の cnorm(late) が base の ±5% 以内、**かつ**
  ref 枝の cnorm(late) が base の 1.5 倍以上（対照が無ければ空虚）
- **GM3**: 2 つの wclamp 枝どうしの cnorm(late) が互いに 5% 以内（媒介変数が両腕で揃って
  いなければ媒介の検定にならない）。dclamp については行平均で同じ検査
- クランプの不変量（`c3_m_absdiff`・`c5_sd_rel`・`c5_cnorm_rel` 等）は CH.TOL の上限で assert

### 記名予測

**Claude: `DIRECT`（55%）。しかも `gap_wclamp > gap_ref` を予測する（30%）。**
理由: 反転を消した腕は cnorm が**大きい**のに損失が**小さい**（14.25 対 9.13 で L 4.62 対 7.68）。
ω 則は「‖W̃‖ が大きいほど損失が大きい」なので、幅の経路は観測された効果と**逆向き**に
効いている。幅を固定すれば逆向きの打ち消しが消えて gap は広がるはず。
深さは `ρ_dclamp` が GELU で +0.27 あるので、gap_dclamp は gap_ref の 7〜9 割と読む。
次点 `PARTIAL` 30%・`DEPTH_MEDIATED` 10%・`WIDTH_MEDIATED` 5%。

### 限界（走る前に明記）

クランプの変異対照の全バッテリ（`_controls`）は再実行しない。クランプのコードは committed
のものをそのまま使い、不変量は走行中に記録して上限で assert する。GM2 の ref 対照が
「クランプが実際に効いている」ことの対照を兼ねる。
