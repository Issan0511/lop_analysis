# 谷の符号梯子 spec 0912 —— 反転は箱 B の損失の原因か

親: `spec_transport_holes_0910.md` §4.2 / 実装 `src/sign_ladder_0912.py`

## 0. 何が未決か

箱 B で GELU は L_ref 7.68 pt、ReLU 4.78、leaky 4.36、ELU1 4.13。同じ絶対深さで
GELU ユニットは非谷腕の約半分しか動かない（尺度不変 P(0.7·sd 上がる/50 タスク)：
GELU 0.39–0.43、leaky 0.62–0.65、ReLU 0.74–0.75、ELU1 0.83–0.85）。腕またぎでは
可動性の順が損失の順と一致する（Spearman 0.90、n=5）が、腕の中のクランプは逆を言う
（GELU は dclamp のほうが可動性が高いのに ρ 0.27 対 wclamp 0.69、ReLU は wclamp が
可動性を半減させて ρ 0.73）。相関では決まらない。反転そのものを操作する。

## 1. 腕（1 層目・2 層目とも同じ活性化。箱 B: pmnist・784-100-100-10・Adam・batch 16・lr 0.001・400 タスク・seed 0–2）

z_c = −0.7517915239、φ(z_c) = −0.16997120747990369。**3 腕は z ≥ z_c で完全に同一**
（自己検査で maxabs 0.0）。違うのは z < z_c のゲートの符号だけ。

| 腕 | φ′(z), z<z_c | φ(z), z<z_c | 位置づけ |
|---|---|---|---|
| `GELU` | φ′(z) < 0 | φ(z) → 0 | committed 参照（G1 で bit 一致を要求） |
| `GELUF` | 0 | φ(z_c) = −0.16997 | 反転を消す（箱 A の `clamp0` と同型） |
| `GELUA` | \|φ′(z)\| > 0 | 2φ(z_c) − φ(z) → −0.33994 | 反転の符号だけ反転。**\|ゲート\| は全 z で GELU と bit 一致** |

`GELUA` が厳密な腕、`GELUF` が緩い腕。GELUF 単独は「符号が悪い」と「信号が無い」を
交絡し、GELUA 単独は符号と「正のゲートを持つために必要な有界出力」を交絡するので、
両方が要る。

## 2. 進捗ゲート（通らなければ該当ラベルは `NOT_TESTABLE`）

- **G0**: GELU の L_ref ≥ 2.0 pt（既知 7.47–7.83 なので通る見込み）
- **G1**: GELU 腕が `long_horizon_acts_0910` の per-unit 6 配列を t1–400 で **maxabs 0.0**
  で再現（比較件数 = 6×400 = 2400 件を同時に記録。件数 0 で 0.0 を報告する罠を塞ぐ）
- **G2（操作チェック a）**: `GELUF`・`GELUA` の `gate_neg_frac` が全タスクで厳密に 0
  （`T.check_gates` の非谷分岐が走中に assert する）
- **G3（操作チェック b）**: 3 腕とも `past_zc_units`(t400) ≥ 20。新腕でユニットが谷を
  越えないなら介入は試されていない
- **G4（操作チェック c・可動性）**: z̄ ∈ [−9,−5) での尺度不変可動性 P(0.7·sd/50 タスク)
  が `GELUA` で GELU + 0.10 以上。これが外れると「可動性が損失を作る」の検定は
  情報を持たない（「反転が損失を作る」の検定は残る）

## 3. 主判定（endpoint）

L = 100 × ( median acc(t16–20) − median acc(t301–400) )、seed ごと。0910 の L_ref と同一。
ΔL = L(GELU) − L(新腕)。3 seed すべてで:

- ΔL ≥ +1.5 pt が **GELUF と GELUA の両方** → **`VALLEY_CAUSAL`**
  （1.5 は GELU の ReLU 超過 2.90 pt の約半分）
- |ΔL| < 0.7 pt が **両方** → **`VALLEY_IRRELEVANT`**（0.7 は GELU の seed 幅 0.36 の約 2 倍）
- GELUA のみ ≥ +1.5 → **`SIGN_ONLY`**（反転を消すだけでは足りず、戻す必要がある）
- GELUF のみ ≥ +1.5 → **`FLOOR_ONLY`**
- それ以外 → **`PARTIAL`**

## 5. 外れたときに第一に疑うもの

1. **`VALLEY_CAUSAL` が出たら**: GELUA は深部で −0.34 に飽和する有界活性化なので、
   ELU（→ −1 に飽和・L_ref 4.13）に近い**別の良い活性化関数**になっただけかもしれない。
   判別: GELUA の L が 4.0–4.3 に着地したら ELU 化を疑い、GELUF（→ −0.17 に飽和・
   ゲート 0）と分離して読む。
2. **`VALLEY_IRRELEVANT` が出たら**: G3 を見る。新腕のユニットが谷を越えていても
   深さ・幅が GELU とずれていれば、介入は反転以外も動かしている。z̄(t400)・sd(t400)・
   cnorm(t400) を 3 腕で並べて報告する（ラベルには使わない）。
3. **G1 が落ちたら**: この計算機（i7-14700K）は lab（i9-13900KF）と同じ Raptor Lake だが、
   torch が違う（2.13.0+cu130 対 2.12.0+cu126）。その場合 G1 を数値一致に落とし、
   **落としたことを判定に明記する**。

## 追補 1（2026-09-12・本走 1 回目の中断と開示。判定量は読む前に固定済み）

### 開示

1 回目の走で **GELU 3 seed・GELUF 3 seed・GELUA seed 0 の `acc`(t400) を見た**
（完了行が印字する）: GELU 0.8551/0.8397/0.8601、GELUF 0.8809/0.8793/0.8699、
GELUA(s0) 0.8799。これは endpoint L（base t16–20 と late t301–400 の中央値の差）
そのものではないが、**方向の情報を含む**。§3 の閾値・ラベル・§4 の記名予測は
**一切変更していない**。変更したのは下の実装バグの修正だけ。

### 中断の理由（float32 の符号跨ぎ・追補 2 blocker と同型で 2 例目）

`GELUA` seed 1 が `T.check_gates` の「非谷腕はゲートが負になってはならない」で落ちた
（`gate_neg_frac` = 1.95e−5、51200 標本中 1 点）。原因は z_c **直上**にある:

- GELU の φ′ は z_c で符号を変える。float32 で評価すると z ≥ z_c なのに φ′ < 0 に
  なる点が存在する（[−1.2,−0.3] の 2e6 点格子で 1 点。float64 では 0 点）。
- 実装が `where(z >= ZC, d, -d)` だったので、その点で d < 0 がそのまま出た。
- `GELUF` の `where(z >= ZC, d, 0)` も同じ穴を持つ。3 seed とも通ったのは、
  プローブ標本がその点に落ちなかっただけ。

### 修正（意図した数学の忠実な float32 実装。関数は変えていない）

- `GELUA.dphi = |φ′_GELU(z)|`（全 z）。z ≥ z_c では φ′ ≥ 0 なので恒等、z < z_c では
  −φ′。float64 の自己検査は従来どおり 0.0 で通る。
- `GELUF.dphi = where(z >= ZC, clamp(φ′, min=0), 0)`。

これで G2 は `GELUA` について構成上真になるので、検査の強さを保つために自己検査に
**float32 の検査とその変異対照**を足す: 生の GELU φ′ が float32 で z_c 近傍に符号跨ぎを
**持つこと**（持たなければガードは空虚）と、2 腕の float32 ゲートの最小値が 0 以上であること。
