## 2. 候補 A の定義

層 l の入力 `a^(l-1)` に対し

```
a_hat  <- (1-alpha) * a_hat + alpha * a^(l-1)      # 勾配を流さない
z_i     = w_i . (a^(l-1) - a_hat) + tau_i
```

`tau_i` は通常の bias として勾配で学習する（初期値 0）。`alpha = center_alpha = 0.01`。

- **第1層に入れた場合は `src/train.py` の `enc=centered` と同じ演算**（`x_in = x_raw - running_mean`、EMA 更新は forward の直後）
- 前向きで `s_i` の µ 項が消え、後ろ向きでも勾配が中心化入力 `a - a_hat` を通るので µ 駆動ドリフト（潮流）も消える
- **乱数を消費しない。** これが §3.2 の対応づけの前提

### 3.2 腕は対応がつく（Phase 0b との最大の違い）

A は乱数を消費しないので、**同じ深さの腕どうしは init・教師・入力列・flip 軌道が bit 一致**する（`ratchet_centered_0822` が `ratchet_log_0819` と対応がついたのと同型）。

- `L2_*` の 4 腕は **seed 単位で対応のある比較**ができ、**paired bootstrap を使う**
- `L1w100_A1` は深さが違うのでペアにならない。**深さをまたぐ paired 比較は禁止**
- **S-pair（§4）でこの前提を検査する。** 落ちたら paired 統計は使わない

### 3.3 実装

Phase 0b の `VecMLPL` と `src/mlp2_phase0b.py` を拡張する。A は層ごとの `centered` フラグとして持たせ、`running_mean` を層ごとに確保する。**勾配は閉形式のまま**（autograd に切り替えない）。

## 5. 集計（事前登録）

### 5.1 窓

早期窓 = タスク 2-11。**末尾窓 = タスク 451-500（50 タスク）**。

改訂理由: Phase 0b で 3 腕とも task 400 付近から平坦（末尾 100 タスクの Spearman 中央値が +0.045 / -0.059 / -0.039）。一方で平坦域の振れが大きく、L2 の seed 中央値は 0.151(300) -> 0.031(350) -> 0.277(400) -> 0.047(490) -> 0.096(500) と隣接ブロックで 5 倍動く。10 タスク窓では平坦域の分散を拾いきれない。

### 5.1b 床は実測して凍結する

Phase 0b は `unfit_floor = 1e-12` を決め打ちにし、**実データを切った**。観測された unfit の最小値は 2.956e-15、1e-12 未満の点が 15000 中 1663 点（11%）あり、残差分散の生値は 7.5e-14〜1.2e-13 と float64 の eval としてまだ意味のある領域だった。これが腕依存の左検閲（0.3% / 10.4% / 22.5%）を作った。

**S6 を「床が精度より上にあることの確認」から「床を精度に合わせて決める」較正へ変える。**

- `L2_none` の 200k 短走から 20 個のチェックポイントを取り、各点で 32 パターン厳密 eval を**2 通りの総和順序**で計算し `|Δunfit|` を出す
- `floor := 10 × (|Δunfit| の 99 パーセンタイル)` を上に丸めて 10 のべき乗にする
- 決めた値を config に書き戻してから本走を回す。本走中は変えない

### 5.2 主 endpoint（co-primary の 2 本）

**P1: 未フィット率の水準。** 各 seed で末尾窓の未フィット率の窓平均 `U_k^arm`。腕 A とベースラインの対応差

```
Delta_k = log10(U_k^A) - log10(U_k^none)
```

の中央値と **paired studentized bootstrap**（B=10000、`rng = np.random.default_rng(20260829)`）。**改善 = CI が 0 を下に外す。**

**P2: eff_rank の水準。** 各 seed で末尾窓の**読み出し直前の層**（`L2_*` では第2層、`L1w100_A1` では第1層）の eff_rank 窓平均。対応差、同じ paired bootstrap。**改善 = CI が 0 を上に外す。**

| P1 | P2 | verdict |
| --- | --- | --- |
| 改善 | 改善 | `A_EFFECTIVE` |
| 改善なし | 改善なし | `A_NULL` |
| 片方だけ | | `INCONCLUSIVE_SPLIT` — **これも結果** |

P1 は結果（LoP そのもの）、P2 は機構（表現の多様性）。**両方が同じ向きを指したときだけ「効いた」と書く。**

### 5.2b 「LoP を防いだ」のか「1 タスクの学習が速くなった」のか【必須の判別】

センタリングは条件数を良くするので、**LoP を一切防がなくてもタスク内収束が速くなるだけで P1 は改善しうる**。P1 単独では分離できない（§8-5 の第一の疑い）。

各腕 × ベースラインの対応差を**早期窓と末尾窓の両方**で取る。

| 署名 | 読み |
| --- | --- |
| `Delta_early ~ 0` かつ `Delta_late < 0` | **LoP を防いだ** |
| 両方 `< 0` で同程度の大きさ | **タスク内学習が速くなっただけ**の可能性（水準シフト） |
| `Delta_early < 0` かつ `Delta_late` の方が大きい | 両方効いている |

補助: 各 seed で `log10(unfit)` のタスク番号に対する Spearman を全区間（2-500）で取り、腕間で対応差を見る。**LoP の防止は傾きを下げるはず**で、水準シフトだけなら傾きは変わらない。

格: 本節は P1/P2 の verdict を上書きしない。**「LoP を防いだ」と書けるのは第 1 行の署名のときだけ。**

### 5.2c 整列（Σ 経路）の追跡【REPORT_ONLY】

§8-5 の第二の疑い（µ を閾値未満に落としても LoP は改善せず、Σ による整列が別経路で LoP を起こす）に対応する登録項目。

層別に時系列で記録（既存 `src/lop_metrics.py` の列）: `wcos_mean` / `eff_rank_W` / `stable_rank_W` / `top1_frac` / `sign_match_mean` / `sign_clone_frac`。

読み方（事前固定）: A 腕でも `wcos_mean` が baseline と同じように上がり `eff_rank_W` が同じように下がるなら、**µ を消しても整列は進んでいる**。逆に整列も止まるなら整列は µ 経路の下流だった。

格: すべて REPORT_ONLY。**本走はこの問いを閉じない。**

### 5.3 床検閲の扱い

`unfit_floor` は §5.1b で実測して凍結した値。各腕について**床にかかった点の割合を verdict.csv に列として持つ**。

- どちらかの腕で **20% を超えたら** その対比を `CENSORED` と立て、paired 統計を**判定に使わない**
- fallback: 対応差の**符号検定**（床は単調変換なので順序は保たれる）
- **Phase 0b の §5.4 回帰は、この規則があれば `CENSORED` になっていた**（L2 22.5%）

### 5.4 副次

層別の `strict_dead` / `alive` / `||w||` / `eff_rank_W` / `dose` の時系列（すべて REPORT_ONLY。`strict_dead` は verdict に使わない）。第2層の dose の減衰（Phase 0b で 12.81 -> 8.16）が A@L1 で止まるかも報告する。

### 5.5 CI の退化検出と fallback

Phase 0b §5.5 を継承（SE < 1e-15 の resample が 1% 超、または CI 幅が点推定の 100 倍超で `CI_DEGENERATE`。studentized は報告のみ、percentile と符号検定を併記）。

### 5.6 壁座標

`D^(l) = -median_i M_i^(l)`、32 パターン厳密計算、退化ガード 1e-8、位相揃え（タスク末尾のみ）を継承。**A を入れた層では µ 項が定義上ゼロになるので M も D も verdict に使わない**（S-taut）。介入していない層の D は REPORT_ONLY として意味がある。

### 5.7 数値発散の実行追補（2026-08-29）

`lop_every = 1000` の各 probe で、ネットワークの重み・bias・readout、または
層ごとの running mean に NaN / ±Inf が 1 個でもあれば、その腕を
**`NUMERIC_DIVERGENCE` = 介入失敗**とする。厳密 eval や SVD より先に検出し、
最初に検出した step・task・seed・tensor を `arm_status/<arm>.json` に保存する。

- 発散した腕はその時点で停止し、seed の除外、再初期化、checkpoint からの救済、
  LR 低下、gradient clipping、float64 学習への変更をしない
- その腕を含む対比は P1 / P2 / CI / 床割合を計算せず、主 verdict を
  `NUMERIC_DIVERGENCE` に固定する。部分時系列も `layer_stats.csv` に混ぜない
- 発散腕を含まない腕と対比は、元の事前登録どおり実行・集計する
- 残りの腕は順次続行する。別の腕も発散した場合は同じ規則を独立に適用する
- S-pair-final は完走した同深さ腕だけで検査し、発散腕は `not_tested` と明記する

この追補は、最初の本走が `L2_A2` の非有限化で停止した後に追加した
**実行・欠測処理規則**であり、元の §8 の予測を変更しない。

## 8. 事前予測（**全項目 記入済み・2026-08-29・実行前**）

1. **`L2_A1`（第1層のみ）= `A_EFFECTIVE`**（Issa）
2. **`L2_A2`（第2層のみ）= `A_NULL`**（Issa）

3. **`L2_Aall` は `L2_A1` より良い**（Issa）
   - 2 と併せると「第2層単独では効かないが、第1層を直した上で足すと効く」を予測することになる。**A2 の効果が A1 の有無に依存する（交互作用がある）**という主張で、腕3 と腕1 の対応差がその検定になる
4. **`L1w100_A1` = `A_EFFECTIVE`**（5M でも持つ）（Issa）
5. **外れたときに疑うもの**（Issa・順序は Issa 指定）
   - (i) **「LoP 防止」と「単一タスクの性能向上」は違う。** 判別は §5.2b に事前登録した
   - (ii) **µ を閾値未満に落としても LoP は改善せず、Σ 等による整列が別経路で LoP を起こす。** 追跡は §5.2c に登録した
   - (iii) 上の 2 つが空振りなら **b（tau）経路の罠**を疑う。A は µ 項を消すが b 項は残る（b 経路は整流ではなく片符号ドリフト＋罠）。作業5 の最低用量 arm（bias share 0.883・strict_dead 0.245）が実測の裏付け
