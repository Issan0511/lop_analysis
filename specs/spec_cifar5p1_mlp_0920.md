# cifar5p1_mlp_0920 — 5+1 CIFAR を MLP に移し、まず「ReLU が落ちるか」だけを先に確かめる

書いた時刻: 2026-09-20 16:0x（**先行走の前・値は未観測**）。Claude（Opus 5）。
経緯: `joudaki_vit_battle_0919` で 13 腕を完走したが、**この箱は可塑性を失わなかった**
（fresh gap −.249・正は 0/130・全 13 腕で早期−後期が負）。
2×2 の因子分解で犯人は **LayerNorm** と判明し、原典 Appendix B も「正規化が LoP を防ぐ」と述べている。
ReLU が落ちない箱では「介入が可塑性を保つ」という売りがそもそも測れないので、Issa「ViT の箱は捨てて構いません。
次の箱は『ReLU が落ちるか』を 3 seed の先行走で確かめてから 13 腕を回す順にします」。
候補を並べたうえで Issa の決定は **5+1 CIFAR を MLP で**。

親: `spec_rlcifar_mlp_battle_0918.md`（13 腕の定義とエンジン）、`pmnist_rlcifar_0907`（MLP 箱の系譜）。

## 0. 一行

Kumar et al. の第 4 問題「5+1 CIFAR」（CIFAR-100・難易度が交代する 30 タスク・780 更新/タスク・
**出力 100 次元・クラスは二度と現れない**）を 3072-100-100-100 の MLP に移植し、
**先行走（`R` 単独・3 seed・4 セル）で ReLU が可塑性を失うことを確認できた場合にのみ** 13 腕の本走に進む。

## 1. なぜこの箱か（数字）

| 箱 | ReLU | WD / L2 で直るか | 我々の手元 |
|---|---|---|---|
| RL-CIFAR × MLP（0918） | t1 で全滅（窓 .113） | — | エンジンあり |
| joudaki ViT（0919） | **落ちない**（窓 .8695・首位） | — | 完走済み |
| **5+1 CIFAR** | **4.76%**（L&C Table 2） | **直らない**（Kumar Fig.2: Baseline .37・L2 .55・L2 Init .67・CBP .52） | CNN 版 `rlcifar_cnn_0908` と MLP のエンジン |

- **ReLU が落ち、かつ L2 では直らない**と著者自身が数えている 3 箱の 1 つ（他の 2 つは RL-MNIST と RL-CIFAR＝我々の背骨と同族）。
- **活性化で結果が割れる**: L&C Table 2 の 5+1 CIFAR 列は ReLU 4.76 に対し Leaky 48.86・ELU 47.64・CeLU 54.23・
  Smooth-Leaky 49.87・Rand. Smooth-Leaky 57.01・SiLU 35.31・GELU 17.60・CReLU 20.56・Tanh 28.59・Sigmoid 1.79。
  **レンジが 55 ポイント**あり、0918 の 13 腕を同じ土俵に並べられる。
- 本物のラベル・公開の CIFAR・Adam・WD なしという条件が今の背骨と揃う。
- PCIFAR（置換）は採らない: 手元の PM-MNIST では ReLU も ELU も生き残り、raw を置換すると μ による「学べない」になり、
  std にすると置換の蹴り $w^\top\Delta\mu$ 自体が消える。期待値が低い。

## 2. 箱（原典の定義）

### 2.1 原典から動かさないもの

Kumar, Marklund & Van Roy (2024) §4.2 と Table 1（Appendix A.1.2）、および Lillo & Cheney (2026) App. E:

- データは **CIFAR-100**。*"every even task is 'hard' while every odd task is 'easy.' ... a hard task is
  characterized by seeing (image, label) data pairs of 5 CIFAR 100 classes, whereas in an easy task, data from
  only a single class arrives."*
- *"Each hard task consists of 2500 data pairs (500 from each class), while each easy task consists of 500 data
  pairs from a single class."* CIFAR-100 の訓練集合はちょうど 1 クラス 500 枚なので、**部分抽出は無い**
  （タスクの画像集合はクラスが決まれば一意）。
- *"Each task has a duration of 780 timesteps which corresponds to 10 epochs through the hard task datasets
  when using a batch size of 32."* → **780 更新 × batch 32**、タスク数 **30（hard 15・easy 15）**。
- *"each individual class does not occur in more than one task"* → 1 seed が使うのは **90 クラス**
  （15×5 + 15×1）。**頭は 100 次元で、真の CIFAR-100 ラベルをそのまま当てる。**
  クラスが再訪しないので、**各タスクの出力ユニットは一度も持ち上げられたことがない** — 他の箱の head リセットに
  当たるものを、原典はリセット無しで実現している。
- 最適化は **Adam・WD なし**。Kumar Table 4 の 5+1 CIFAR・Adam・Baseline は **α = 1e−4**。
  L&C も *"CIFAR 5+1 prefers 10⁻⁴"*。
- 主指標は **average online task accuracy**: *"a_j is the average accuracy on the jth batch of samples"* の
  タスク内平均＝**更新前**の当たり率。**hard タスクだけを採点する**
  （*"we measure agents' performance specifically on the hard tasks since all agents do well on the easy tasks"*）。

### 2.2 移植で変えたもの（1 つだけ）

**網**。Kumar も L&C もこの問題では CNN（5×5×16 conv ×2 + maxpool + FC100 ×2）を使う。
本 spec は **3072-100-100-100 の MLP**（幅は彼らの MLP と同じ 100、出力は 5+1 の 100）で回す。
13 腕とそれを束ねるエンジンが MLP 側にあるためで、**MLP 版で ReLU が落ちるかは原典が答えていない**。
それを §3 の先行走が決める。

- init は PyTorch の `nn.Linear` 既定 U(±1/√fan_in)、`H.init_params(seed, device, DIMS)`（`init` stream）。
- タスク列は seed ごとに `c51_classes` stream で 100 クラスを randperm し先頭 90 を順に消費する。
  **タスク 1 が hard**（原典の 0 番目）。
- バッチ順は `c51_batch` stream。タスクごとに「全体の randperm を並べて先頭 780×32 を切る」。
  hard で 9.98 epoch、easy で 49.9 epoch に当たる（原典の「≈10 epochs」「≈50 epochs」と同じ）。
- 発散は記録して打ち切り、救わない。束ねた中では発散したスロットだけ止める。
- 入力条件は 0918 と同じ 2 つ: `raw` = u8/255、`std` = チャネルごとに (x−mean)/std
  （**CIFAR-100 の定数** mean (0.5071, 0.4865, 0.4409)・std (0.2673, 0.2564, 0.2762)。CIFAR-10 のものではない）。
- エンジンは `src/cifar5p1_mlp_0920.py`。**活性化・積み重ね forward・Adam の 1 step は
  `src/rlcifar_mlp_battle_0918.py` から import する**（腕が別コードに分岐しないため）。宿主 3 本は無改変。
  タスクは「どの大域行番号を静的テンソルに書くか」だけで決まるので、CUDA graph は 1 度の capture で
  30 タスク全部に使える。

## 3. 先行走（`R` 単独・3 seed）— **判定を値の前に固定する**

seed 100–102（登録用の 0–9 とは別）。4 セル: lr ∈ {1e−4, 1e−3} × cond ∈ {raw, std}。
各セル 3 seed を 1 プロセスに束ねる。

### 3.1 指標

hard タスクは t = 1, 3, …, 29 の 15 本。`online_acc` はその 780 バッチの更新前当たり率の平均。

- **早期窓** = hard 1–5（t = 1,3,5,7,9）の平均
- **後期窓** = hard 11–15（t = 21,23,25,27,29）の平均

### 3.2 fresh network 対照（ViT の箱で必須と分かったもの）

最後の hard タスク（t = 29）の**まさにそのバッチ列**を、初期値に戻した網（Adam の moment も α の状態も初期化）で
780 更新だけ学習させ、`fresh_gap = fresh(t29) − continual(t29)`。
**これが正でなければ「劣化」ではなく「課題が難しくなっただけ」である。** ViT の箱はこれで
「転移に隠れている」を棄却できた（gap −.249・正 0/130）。

### 3.3 登録する 3 つの読み（値を見る前に固定）

| # | 読み | 定義 |
|---|---|---|
| **Q1 単調劣化** | 早期窓 − 後期窓 の 3 seed 中央値が **> 0** | 閾値に依らない符号だけの署名 |
| **Q2 fresh gap**（**主判定**） | `fresh_gap` の中央値が **> 0** かつ **3 seed 中 2 以上で正** | 喪失が実在する直接証拠 |
| **Q3 崩壊** | 後期窓の中央値が **< 0.20** | 下記の床 |

**Q3 の 0.20 について。** 5 クラス均等の hard タスクで「常に同じ 1 クラスを出す」退化解の水準が 0.20 である。
ただしこの箱では**クラスが再訪しない**ので、前のタスクのクラスを出し続ける網は 0 を取る。
つまり達成域は 0〜1 で 0.20 は自然な下側の目印であり、原典の ReLU（L&C 4.76%）はこれを大きく下回り、
Leaky（48.86%）は上回る。**閾値は原典の 2 値の間に置いた**。

### 3.4 本走へ進む条件（先行走の通過条件）

**Q2 が真、かつ Q1 が真**であるセルが少なくとも 1 つあること。

セルの選び方は**値を見る前に固定する**:

1. **既定は `std` × lr 1e−4**（両原典がこの箱に与えている設定）。ここが通れば本走はこのセル。
2. 既定が落ち、別のセルが通った場合はそのセルを使い、**「既定では出ず、条件を変えて出した」ことを本走の spec と
   結果ノートに明記する**。
3. 4 セルとも落ちた場合、**本走はやらない**。MLP 版 5+1 CIFAR は「ReLU が落ちない箱」として
   ViT と並べて陰性で記録し、次の候補（CNN 版 5+1 CIFAR）に移る判断を Issa に返す。

## 4. 検査（本走の前に all_pass を commit する。先行走は §4.1 のみで走らせてよい）

### 4.1 先行走の前に通すもの

- **S-data**: 配布物の sha256 を記録し、train が 50,000×3072・1 クラスちょうど 500 枚、
  test が 10,000×3072・1 クラスちょうど 100 枚、ラベルが 0..99。
  変異: 1 枚でも落とすと 500 枚の検査が落ちる。
- **S-plan**: seed ごとに 30 タスクで**クラスが一度も再訪しない**・hard 15 / easy 15・タスク 1 が hard・
  hard の枚数 2500 / easy 500・同じ seed で再現し、別の seed では列が違う。
- **S-batch**: 各タスクの 780×32 の添字が**そのタスクのクラスの画像だけ**を指す・
  先頭 1 epoch 分がそのタスクの集合のちょうど置換になっている・(seed, task) で列が変わる。

### 4.2 本走の前に追加で通すもの

- **S-stack**: R=3 で束ねたエンジンの 1 step の logits と勾配を、スロットを 1 本ずつ回した参照と比べる
  （logits は bit 一致、勾配は相対 ≤ 1e−6）。変異: スロットの params を入れ替えると落ちる。
- **S-graph**: CUDA graph 有無で 2 タスクの行が bit 一致。変異: graph 側の static_idx を 1 バッチずらすと落ちる。
- **S-act**: 13 腕の φ′ が autograd と一致（`rlcifar_mlp_battle_0918_checks` の S-act をそのまま呼ぶ）。
- **S-head**: あるタスクの 5 つの出力ユニットが、そのタスクより前に**正例として一度も現れていない**。
- **S-fresh**: fresh 対照が (i) 本走と**同じバッチ列**を使い、(ii) 初期重み・Adam moment・α 状態が
  初期値に戻っている（bit 一致）。変異: moment を戻し忘れると落ちる。
- **S-diverge**: 1 スロットを人為的に NaN にした束と、そのスロットを除いた束で、残りの重みが bit 一致。

**固定値・固定倍率の閾値は使わない**（過去 9 回、正しく動いている装置を殺している）。
閾値は算術から出すか、変異対照で分離幅を示す。

## 5. 本走（先行走が通った場合のみ・別途 spec 追補で確定する）

- 腕: 0918 の 13 腕（`SNA KKA KKA23 KKT1 R LR LK001 LK03 SL RSL ELU SILU GELU`）。
  **全腕とも既定値のまま、この実験のために調整しない。**
- 追加候補: `CR`（Concat ReLU・Kumar の architectural 手法で L&C 表にもある。5+1 で 20.56 と**落ちる**側）、
  `DF`（Deep Fourier・L&C 付録で 5+1 の最高 72.29）。**実装が要るので先行走の結果を見てから決める。**

- 判定は §3.3 の 3 つに加えて、0918 と同じ**対応符号検定（Holm 補正）**で腕を比べる。

## 8. 実測・結果（2026-09-20・先行走）

### 8.1 検査

`src/cifar5p1_mlp_0920_checks.py --stage main` で **8 件すべて PASS**（`results/cifar5p1_mlp_0920/_checks_main/checks.json`）。
配布物の sha256 は `85cd44d0…77a7`、md5 は公開値 `eb9058c3a382ffc7106e4002c42a8d85` と一致。
測ったチャネル統計 (0.5071, 0.4866, 0.4409) / (0.2673, 0.2564, 0.2762) は宣言した定数と 1e−4 以内。

**S-stack で閾値を 1 度借りて失敗した**（記録）。最初 0918 の登録値 1e−6 をそのまま当てたところ、
実測 1.01e−6（LR）・1.27e−6（SNA）で**落ちた**。0918 の網は頭が 10 ユニット、この箱は 100 ユニットで
積算の本数が違うのだから、**あの箱の数字はこの箱の数字ではない**。
オペランドから導出し直した（1 段目 √n·eps·Σ|xW|、層間は誤差が直交に足されるので重み行の 2-ノルム）。
結果: 1 段目は余裕 54.7 倍・変異との分離 1.4e4 倍、logits は余裕 277–334 倍・分離 4.5e3–6.7e3 倍。
最初に当てた worst-case 版（(n−1)·eps·Σ|xW|）は実測の 1e6 倍という緩さで、**変異が閾値を越えられず
「何でも通る検査」になっていた**ので採らなかった。**空虚な検査を作りかけたのは通算 7 回目。**

### 8.3 既定セルの機構（記述・登録外）

| t | 種 | online | test(末) | 死 l1 | 死 l2 | mob l2 | eff_rank l2 | ‖w‖ l1 |
|---|---|---|---|---|---|---|---|---|
| 1 | hard | .610 | .584 | .000 | .000 | **.740** | 19.3 | .715 |
| 9 | hard | .541 | .630 | .000 | .020 | .137 | 17.8 | .891 |
| 19 | hard | .425 | .576 | .000 | .250 | .009 | 10.0 | .999 |
| 29 | hard | .452 | .606 | .000 | **.370** | **.003** | 8.6 | 1.063 |
| 28 | easy | .834 | 1.000 | .000 | **.640** | .000 | 3.2 | 1.046 |

- **死ぬのは 2 層目だけ**（.000 → .370）。3072 次元を読む 1 層目は 30 タスク通して**死者ゼロ**。
  `transport_holes_0910` の「lever は幅」でも ViT の「幅は無関係」でもなく、**入力次元が桁で違う 2 層の非対称**。
- **ゲートは 250 倍閉じる**（mob_l2 .740 → .003）。eff_rank は 19.3 → 8.6。‖w‖ は 1.5 倍。
- **殺しているのは easy タスク**: t28（easy）で死 .64 → t29（hard）で .37 に戻る。
  1 クラス 500 枚を 50 epoch 当てる「出力を定数に押し込む」区間が応力源で、hard タスクが一部だけ生き返らせる。
  原典が *"a highly synthetic environment designed to stress test methods"* と書いた通りの動き方をしている。
- **重要な但し書き**: 既定セルで落ちているのは**適応の速さ**であって最終到達点ではない。
  t1 → t29 で online は .610 → .452 と落ちるが、タスク末の train は .743 → .698、test は .584 → .606 で**ほぼ横ばい**。
  原典の主指標（average online task accuracy）はまさにこの速さを測る量なので判定は原典どおりだが、
  **「fit できなくなる」型の喪失ではない**ことは結果ノートに明記する。
  なお raw × 1e−3 では t29 に online .000 / train .000 / test .000 の**完全死**が起き、こちらは両方の意味で失っている。

### 8.5 代価の実測

## 11. 追補 1: 腕を 3 本足す（2026-09-20・本走の前・値は未観測）

Issa の指示で 13 腕に 3 本足して **16 腕**にする。3 本とも**この箱の文献が報告している腕**であって、
我々のデータで選んだ値ではない（それは調整になる）。

| 腕 | 定義 | 由来と 5+1 CIFAR での報告値 |
|---|---|---|
| `LK07` | leaky、負側の傾き **0.7** | L&C 付録 E: *"a 'Goldilocks zone' for the negative linear sides ... the best values typically land between 0.6 and 0.9"*。Table 2 の Leaky-ReLU **48.86** はこの帯の傾きであり、0918 の梯子（0.01 / 0.1 / 0.3）は**帯に 1 本も無い** |
| `CR` | Concat ReLU: φ(z) = [relu(z), relu(−z)] | Shang et al. 2016 / Kumar et al. の architectural 手法。L&C v2 Table 2 で **20.56 ± 2.28**（5+1 でだけ崩れる腕。Kumar も *"Concat ReLU does well on all problems except for 5+1 CIFAR"*） |
| `DF` | Deep Fourier: φ(z) = [sin(z), cos(z)] | Lewandowski, Schuurmans & Machado 2024（arXiv:2410.20634）: *"deep Fourier features, which are the concatenation of a sine and cosine in every layer"*。**L&C v2 Table 2 の 5+1 CIFAR 最高値 72.29 ± 2.11**（2 位 RSL 57.01 を 15 点引き離す） |

### 11.1 幅の扱い（決めて登録する）

`CR` と `DF` は前活性 1 本につき 2 本を出すので、次の層の fan-in が 2 倍になる。

- **本走は 3 本とも hidden=100 で回す**（他の 13 腕と同じ網）。これは L&C の設定（*"two hidden layers,
  each of width 100"*）と同じで、外部の参照表と並べられる。
  パラメータは 327,500 → **347,500（+6.1%）**になる。**開示する。**
- Kumar は CReLU について *"compute the smallest fraction of neurons to remove ... such that the total
  number of parameters ... is at least as large"* という規則を置き、彼らの CNN では 0.31 削っている。
  **我々の MLP でこの規則を解くと hidden=94**（347,500 → 325,528 ≤ 327,500。S-init が算出）。
- したがって **`CR` と `DF` は hidden=94 でも回し、対照として登録する**（1 本 1.5 分なので安い）。
  **勝敗の判定は hidden=100 側で行い**、94 側は「6% のパラメータ差で説明できるか」だけに使う。

### 11.2 読み出しの但し書き（構成上の恒真）

`CR` と `DF` は **|∂φ/∂z| が恒等的に 1**（CR は z=0 を除く）なので、`dead_frac` と `mob` は
**構成上一定**で、この 2 腕については何も測っていない。両腕の「死」は `zeroout`（タスクの全画像で
出力が恒等的に 0 のチャネル）・`eff_rank`・`w_norm` で読む。**これを「死なない腕」の証拠に使わない。**

### 11.3 追加した検査

- **S-init**: pointwise 腕・hidden=100 で、この箱の init が宿主 `H.init_params` と **bit 一致**。
  `CR`/`DF` は 2・3 層目の fan-in が 200 になり、境界が PyTorch 既定の 1/√200 に一致する。
  等パラメータ幅 94 もここで算出する。
- **S-act-new**: 3 腕の微分を autograd と照合。`CR`/`DF` は φ: Rⁿ → R²ⁿ でスカラーの φ′ が無いので、
  **学習が実際に使う vjp**（乱数の余接ベクトルとの積）で比べ、`dphi` が Jacobian の列ノルムであることも別に見る。
  実測誤差 0.0（`DF` の列ノルムのみ 5.96e−8）、閾値は 1 回の積和の丸め（4·eps·max|want|）から。
  変異: `CR` の 2 つの半分を入れ替えると落ちる。

検査は **10 件すべて PASS**（`results/cifar5p1_mlp_0920/_checks_main/checks.json`）。

### 17.1 走る 5 本（seed 0–9・std・lr 1e−4・約 15 分）

### 17.2 判定（値を見る前に固定）
