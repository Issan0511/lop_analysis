# mlp_center_x10_1020 — 5+1 CIFAR MLP の 10 倍予算で、中心化の腕を診断つきに回し直す

登録: 2026-10-20、Claude（Opus 5.5、実装担当）。依頼は親（Fable）から。予測は §8 に親の名で写した。

## 0. 一行

5+1 CIFAR の MLP 箱（`cifar5p1_mlp_0920`）を、課題あたり 7,800 更新（原典の 10 倍）で R・CH・CHB0 の 3 腕について回す。後期窓の online を比べ、unit ごとの幅・開く割合・実効階数・bias・重み、課題の中の学習曲線を記録する。

## 1. 経緯

- 乱数ラベル MLP（入力固定）では、経路を塞ぐ腕（中心化 CH、bias も抑える CHB・CHB0）で学び直しが保たれた。
- 文字 GPT（`chargpt_cl_1019`、課題ごとに入力分布が変わる箱、1 課題 10,000 更新）では逆に出た。中心化した腕は沈みも押しも消えたのに、学ぶ力が土台より悪かった。塞ぐ経路が多いほど悪かった（3 seed・7 走）。
- 文字 GPT の事後解析では、中心化した腕で次の 3 つが見えた。開く割合 0.05〜0.3 の「まばらな検出器」が 0% になった。深い層の幅が 5〜7 倍に伸びた。実効階数は潰れなかった。
- 親の読み: 入力が変わる箱では unit の閾値を課題ごとに置き直す必要があり、沈降がそれを供給していた。塞ぐと、半分開いた unit が伸びる幅を流す。害は幅とともに育つので、1 課題が長いほど出る。
- 同じ向きの既知が 5+1 CIFAR MLP にある（0920 spec §17.4、V12 付録 G.2）。CH − R の後期窓は、780 更新で +0.116（10/10）、全課題 7,800 更新で −0.086（0/10）と反転した。
- その 10 倍予算の走には CHB0 が無い。幅・検出器・学習曲線の診断も無い。この実験はそこを埋める。

## 2. 箱

- 0920 の箱のままである。CIFAR-100 で、hard（5 クラス）と easy（1 クラス）が交代する 30 課題を、batch 32 で学ぶ。課題 1 は hard である。
- 予算は hard・easy とも 7,800 更新である（0920 追補 5 の (a) 一様 ×10 と同じ）。
- 網は 3072-100-100-100 の MLP、入力は `std`、最適化は Adam（lr 1e−4、WD なし）、seed は 0〜9 である。
- エンジン・データ・課題列・batch 列・初期値は `src/cifar5p1_mlp_0920.py` の `run` をそのまま呼ぶ。0920・0918・0905 のモジュールは書き換えない。
- 診断は新しいモジュール `src/mlp_center_x10_1020.py` が足す。0920 の `make_act` と `evaluate` をモジュールの名前の上で包み、学習の計算には触れない（§7 の S-diag で確かめる）。
- CPU のスレッド数は 2 に固定する。eff_rank が LAPACK のスレッド数で最終桁を変えるためである（0920 の罠）。
- CIFAR-100 の archive は main のクローン（`proj_004_drift/data/cifar100/`）から読む。worktree に symlink は置かない。sha256 は provenance に残る。

## 3. 既存の走に何が残っているか（調べた結果）

`results/cifar5p1_mlp_0920/` の 10 倍予算の走は 5 本ある。

| ディレクトリ | 腕 | hard × easy | seed |
|---|---|---|---|
| `R_std_x10_7800x7800` | R | 7800 × 7800 | 0〜9 |
| `CH_std_x10_7800x7800` | CH | 7800 × 7800 | 0〜9 |
| `KKT1_std_x10_7800x7800` | KKT1 | 7800 × 7800 | 0〜9 |
| `CH_std_x10_7800x780` | CH | 7800 × 780 | 0〜9 |
| `KKT1_std_x10_7800x780` | KKT1 | 7800 × 780 | 0〜9 |

- 各ディレクトリにあるのは `per_task.csv`・`fresh_control.csv`・`provenance.json` の 3 つだけである。
- `per_task.csv` の列は次のとおり。online・train・test の精度、層ごとの `dead_frac`・`zeroout`・`zbar`・`zsd`・`zbar_min`・`mob`・`eff_rank`、層ごとの `w_norm`。
- unit の統計は課題の訓練画像の上で取り、unit の中央値（`zbar_min` は最小）に縮めてある。全 unit の配列は無い。
- 課題末の重みも checkpoint も無い。課題の中の学習曲線も無い（online は課題全体の平均だけ）。
- fresh 対照はある。課題 29 を初期値から 7,800 更新で学び直す（`fresh_control.csv`）。
- CHB0 の 10 倍予算の走は無い。

したがって事後解析では済まない。3 腕とも診断つきで回し直す。旧走は torch 2.13.0+cu126、git `75419809`、この走は torch 2.13.0+cu130 である。

**旧走の軌道を再現できるのは R だけである**（実装前の試走と S-reuse-early・S-door-repro で確かめた）。

- R は、課題 1・2 の全列が旧走と同じ文字列になった。違うのは `eff_rank` の 2 行だけで、§7 の上界の内側である。
- CH は課題 1 の online から食い違う。原因は扉 C の平均画像である。
- 扉 H 単独（780 更新）は旧 0920 の行と全列一致し、扉 C 単独は一致しない。
- 平均画像は 50,000 枚の float32 の和を GPU で取る。この値は float64 の平均から最大 408 ulp ずれ、GPU と CPU では 3,072 要素のうち 2,060 が違う。足す順が変われば値が変わる量である。足す順は GPU とライブラリの版で変わりうる。旧走と今では torch の CUDA 版（+cu126 → +cu130）も機械も違い、どちらが効いたかは切り分けていない。
- したがってこの走の CH と CHB0 は、旧走と同じ箱・同じ設定の別の実現である。腕の比較はすべてこの走の中の値で行う。旧走の CH − R は、この走の CH − R の再現の記述として並べる。

## 4. 腕

| 腕 | 定義（0920 の `DOORS`、`relu_doors_0919` の移植） |
|---|---|
| R | 素の ReLU |
| CH | 扉 C（入力から CIFAR-100 訓練集合の平均画像を引く、割らない）＋扉 H（φ(z) = relu(z) − m、m は relu(z) の batch 平均の EMA、β = 0.01） |
| CHB0 | CH ＋ b1・b2 を毎更新のあと厳密に 0。b3 には触れない |

- どの腕も 0920 の定義のままで、この実験のために lr も形も調整しない。
- fresh 対照は 0920 のエンジンのものを使う（課題 29、7,800 更新）。新しくは作らない。

## 5. 測るもの

### 5.1 0920 のまま（`per_task.csv`・`fresh_control.csv`）

- 主指標は後期窓で、hard 課題 21・23・25・27・29 の更新前 online 精度の平均である（0920 の登録窓）。
- 課題末の train 精度、test 精度、fresh gap（課題 29 の fresh − 継続）。

### 5.2 新しく足す診断（`diag_units.npz`・`diag_per_task.csv`）

**probe**: seed ごとに固定した 1,200 枚である。CIFAR-100 の test 集合から、100 クラスのそれぞれで 12 枚を選ぶ。選び方は乱数の役 `mcx_probe` で seed ごとに一度だけ決め、全課題・全腕で同じ画像を使う。入力の前処理はその腕が test に施すものと同じである（CH・CHB0 は平均画像を引いた後）。

課題の末ごとに、生きている全 seed について次を記録する。

| 量 | 対象 | 形 |
|---|---|---|
| 前活性の平均 z̄（unit ごと） | probe と課題の訓練画像、第 1・2 層 | (課題, seed, unit) |
| 前活性の幅 σ（unit ごとの標準偏差、0920 の `zsd` と同じ不偏の式） | 同上 | 同上 |
| 開く数（z > 0 の入力の数、unit ごと）と入力の数 | 同上 | 同上 |
| 実効階数（0920 と同じ `eff_rank`、φ の出力の上） | probe、第 1・2 層 | (課題, seed, 層) |
| bias b1・b2・b3、重みの行ノルム W1・W2・W3（unit ごと） | — | (課題, seed, unit) |
| 扉 H の m（unit ごと、CH・CHB0） | — | 同上 |
| online の累積（20 更新ごと）と課題末の合計 | 課題の中 | (課題, seed, 格子) |
| fresh 対照の online の累積 | 課題 29 の fresh | (seed, 格子) |

- 開く割合 p⁺ は「開く数 / 入力の数」である。区分は次の 6 つで、互いに排他で網羅的である。dead（p⁺ = 0）、(0, 0.05)、**まばらな検出器 [0.05, 0.3)**、[0.3, 0.7]、(0.7, 0.95)、[0.95, 1]。境目は整数の比較で判定する（例: p⁺ < 0.05 ⇔ 20 × 開く数 < 入力の数）。
- 課題の中の学習曲線は、最初の 100 更新・最初の 780 更新・課題全体の online を主に読む。累積の格子から任意の窓を引ける。
- 課題の訓練画像の上の統計は、0920 の `per_task.csv` の中央値と同じものを unit ごとに残したものである（S-units で一致を確かめる）。

## 6. 登録する判定（値を見る前に固定）

検定は 0920 と同じ対応符号検定である。厳密な両側検定で、差が 0 の seed は除く。p_holm < 0.05 で中央値の差が正なら `A_WINS`、負なら `B_WINS`、それ以外は `TIE` とする。発散した run を含む比較は、その seed を除く。

### 6.1 主: 族 M（Holm 2 比較）

| 比較 | 量 |
|---|---|
| CH − R | 後期窓 |
| CHB0 − R | 後期窓 |

総合のラベルは次の 4 つで、互いに排他で網羅的である。

| ラベル | 条件 |
|---|---|
| `DOSE` | 2 比較とも `B_WINS`、かつ CH − CHB0 の対応差の中央値 > 0（順 R > CH > CHB0） |
| `BOTH_WORSE` | 2 比較とも `B_WINS`、かつ CH − CHB0 の中央値 ≤ 0 |
| `ONE_WORSE` | ちょうど 1 比較が `B_WINS` |
| `NOT_WORSE` | どちらも `B_WINS` でない |

CH − CHB0 の符号検定は記述として報告し、族には入れない。

### 6.2 副（それぞれ単独、記述の数と符号検定）

| # | 量 | 報告 |
|---|---|---|
| W | 第 2 層の幅: probe の上の σ の unit 中央値、課題 30 の末 | CHB0 ≥ 2 × R の seed 数（同じ seed の対）。CH ≥ 2 × R の seed 数も。3 腕の seed 中央値 |
| D | まばらな検出器の割合: probe の上で p⁺ ∈ [0.05, 0.3) の unit の割合（第 1・2 層の 200 unit をまとめる）、後期窓の課題 21〜29 の末の平均 | R > CHB0 の seed 数と符号検定。層別と課題 30 の末も記述 |
| O | 最初の 780 更新の online の差 CH − R。早期 = hard 課題 1・3・5・7・9 の平均、後期 = hard 課題 21〜29 の平均。Δ = 後期 − 早期（seed ごと） | Δ の符号検定でラベル: p < 0.05 で中央値 < 0 なら `OPENS`、> 0 なら `CLOSES`、それ以外は `FLAT`。早期と後期の差それぞれの符号検定も。CHB0 − R は記述 |
| K | 実効階数: probe の上、第 2 層、課題 29 の末（第 1 層と課題 30 も記述） | CH − R と CHB0 − R の符号検定、3 腕の seed 中央値 |

ほかに記述として出すもの: fresh gap、課題末の train 精度、最初の 100 更新の online、σ と p⁺ の課題ごとの推移、bias と行ノルム。

### 6.3 読みの文（実行前に固定）

- `DOSE` なら「この箱でも、10 倍予算では塞ぐ経路が多いほど学ぶ力が落ちる」と書く。
- `NOT_WORSE` なら「0920 の反転（CH − R = −0.086）はこの走では再現しなかった」と書き、S-reuse の結果を添える。
- W・D・O・K は機構の記述であり、主判定を変えない。

| S-verdict | 判定 script に答えの分かっている合成データを与える | 決めたラベルが出る |

本走の後に判定 script が回す検査:

| 検査 | 内容 |
|---|---|
| S-reuse | 本走の R・CH の `per_task.csv` を旧 10 倍走と比べる。`eff_rank` 以外の全列が同じ文字列で、`fresh_control.csv` がバイトで一致し、`eff_rank` が全行で上界以内なら `PASS`。バイトの一致も記録する。R は `PASS` を見込む。CH は §3 の理由で `FAIL` を見込み、最初に食い違う課題を記録する |

**eff_rank の上界の導き方。** eff_rank は float32 の活性 A（N 行 × 100 列）から float64 の Gram AᵀA を作り、固有値から計算する。A が同じなら、違いは丸めだけである。

- Gram の丸めは足し算の順によらず |ΔG| ≤ γ_N |A|ᵀ|A| で、スペクトルノルムは γ_N ‖A‖²_F 以下である（γ_k = k·u / (1 − k·u)、u = 2⁻⁵³）。
- 固有値の計算は後退安定で、誤差は p(n)·u·‖G‖₂ 以下である。LAPACK の手引きの「n に緩やかに依存する関数」p(n) を n = 100 と置き、γ_n ‖A‖²_F で抑える。
- Weyl の不等式から、1 回の計算の各固有値の誤差は ε = (γ_N + γ_n) ‖A‖²_F 以下である。2 回の計算の差は 2ε 以下である。
- 各固有値を区間 [λ − 2ε, λ + 2ε]（0 で切る）に置き、特異値の比 p_i の区間を作る。エントロピーの各項 −p log p の区間上の変動を足して ΔH の上界とし、|Δ eff_rank| ≤ eff_rank × (exp(ΔH) − 1) とする。
- 照合する値は `%.10g` で印字されているので、両方の印字の丸め（最後の桁の半分ずつ）を足す。
- この上界は「float32 の活性が同じ」を前提にする。前提が崩れた行は上界を超えうる。そのときは軌道の照合（`eff_rank` 以外の列）と分けて報告する。

- 旧走では、課題の訓練画像の上で CH の第 2 層の幅は R より狭く、実効階数は R より低い。P2 の CH > R と P5 は、この値と逆の向きである。この走の P2・P5 は probe（test の 1,200 枚）の上で採点するので、課題の訓練画像の値とは別の量である。ただし同じ向きに出る見込みが高い。
- 参考までに、780 更新の 0920 本走では第 2 層の `zsd` が課題 30 の末で R 4.78・CH 63.73・CHB0 63.60 だった。10 倍予算で R の幅が 5 倍に伸び、CH の幅が 10 分の 1 に縮んだことになる。
- CHB0 の 10 倍予算は、登録した seed 0〜9 ではどの量も未観測である。検査で見たのは seed 100・101 の 3 課題（S-diag）と seed 100 の 3 課題（S-smoke）だけである。
- 実装担当は検査のために R と CH の seed 0〜9 の課題 1・2（7,800 更新）を回した。R は旧走と同じ値である。CH は旧走と違う値が出たが、見たのは課題 1・2 だけで、後期窓（課題 21〜29）は見ていない。
