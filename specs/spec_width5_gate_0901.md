### 2.2 腕（**9/1 裁定: 案 B を採用**。§8-1・§8-2）

| 腕                                    | 幅   | 活性化                      | 役割                                     |
| ------------------------------------ | --- | ------------------------ | -------------------------------------- |
| `R5`                                 | 5   | ReLU                     | 幅 5 の陽性対照                              |
| `LR5`                                | 5   | leaky ($a$=0.1)          | **本命**（図 B.10 では重症）                    |

| `R100` / `LR100` / `E100` / `LIN100` | 100 | 同上                       | 幅対比を**同一 run・同一 seed 数・同一 commit** で取る |

**`LIN` を leaky($a$=1.0) で作る理由**: 新しい活性化分岐を実装せずに config 値だけで恒等が作れる。副産物として **活性化が「負側可動度の床 $a \in \{0,\ 0.1,\ 1.0\}$ の梯子」＋ ELU** という連続的な読みになる（[[現象3指標再定義_P3_0901]] §3.1 の軸2）。`validate_config` が `slope == 0.1` を固定検査しているので、そこだけ緩める必要がある。

**なぜ w100 腕を作り直すのか（案 A との差）**: committed の `gate_dose_0830` は **10 seed**、本走は 20 seed。seed 数が違う腕どうしを対比すると、幅の効果と seed 数の効果が混ざる。同一 run で並べれば「幅の一軸」という [[容量不足レジームの機構_0830]] §5 の局在結果に直接対応する比較になる。**コストは §7 の見積りで +約 45 分。**

### 2.3 ★ 乱数系列（**この節を飛ばさない**）

`src/train.py:22` の `make_gens` は **`base = SEED_BASE[exp] + width + offset`** で、**学習器の幅が乱数の基底に入っている**。したがって:

1. **幅 100 と幅 5 は同じ seed 番号でも教師も入力実現も違う。** → **幅対比は非対応（unpaired）である。** 「同一個体の幅違い」と書かない
2. `offset = 0` のままだと、**幅 5 の基底は既存の w5 走 8 本（`drift_0809` / `aniso_0812` / `aniso_perp_0812` / `fullbatch_0812` / `coupling_ab_0813` / `coupling_fbw_0813` / `methods_sde_0813` / `center_selfcov_0814`、いずれも offset 未指定 = 0）と一致する。** 事故ではないが、**意図せず基底を共有するのは [[9月運用_0901]] §3-1 の 1 項目め（T0b の事故）が禁じている型**である → **新しい `generator_offset` を切る**（値は §5 で確定）
3. **`width + offset` は加算なので衝突しうる。** 幅 5 × offset 95 は 幅 100 × offset 0 と同じ基底になる。**選ぶ offset が既存 offset との差 95 にならないことを確認する**（既用: 0 / 20260830 / 20260831 / 20260905）
4. **seed 数を 10 → 20 に増やすと `R` が変わり、`LTUTarget(R, …)` などの初期ドローの形状が変わる。** よって §3 の S0′（bit 再現）は **必ず R=10 で**走らせる。R=20 の腕は committed 走の bit 再現ではなく統計的追試である

### 2.5 凍結時の実装定義（報告量のみ）

- 可動度重みペア cos は、入力重み行のユニット間 cosine $c_{ij}$ を、各ユニット可動度の積 $m_i m_j$ で重み付けした $\sum_{i<j}m_i m_j c_{ij}/\sum_{i<j}m_i m_j$ とする。符号付き値と絶対値をともに出し、報告上の既定名は絶対値とする
- 床正規化可動度は $\widetilde m_i=(m_i-a)/(1-a)$（ReLU・ELU は $a=0$、leaky は $a=0.1$）とし、生 $m_i$ 版と $\widetilde m_i$ 版を別列で出す
- `LIN` は $a=1$ のため $\widetilde m_i$ が $0/0$ となる。`LIN` の $\widetilde m_i$、$R_c/\sum_i\widetilde m_i$、および $\widetilde m$ 重み cos は未定義（NaN）とする
- 以上は G3 の報告量の実装定義であり、G0 の登録判定には入れない

## 3. 実行前 sanity

- **S0′（bit 再現・失敗時は本走禁止）**: `hidden=[100]`・**R=10**・`generator_offset=0`・活性化 ReLU/ELU/leaky に戻した 30k replay が `gate_dose_0830` の `R_off` / `E_off` / `LR_off` と `p_hat`・`eval_loss_exact`・`unfit`（1k 格子）で一致すること
- **S-lin**: `negative_slope = 1.0` の腕で $\varphi(z) = z$ が 1e-12 以内。かつ **隠れ 1 層なので学習器全体が線形**であることを、$\hat y$ が入力のアフィン関数であることの数値確認で示す
- **S-mob（恒真の確認であって発見ではない）**: ReLU 腕で $m_i = \hat p_i$、leaky 腕で $m_i = a + (1-a)\hat p_i$ が bit 一致すること。**一致することを確認したうえで、この 2 腕の $m$ を判定に使わない**（P-3 §2-2・教訓②）
- **S-rank**: $R_c$ の実装が (a) 定数列を含む行列で raw `eff_rank` より小さくなる、(b) 直交ランダム行列で幅に一致する、(c) 幅 5 では値域 $[1,5]$ に収まる
- **★ S-cap（幅 5 の到達床の較正・本走前に必須）**: **`onset_threshold = 0.05` は w100 で較正された値であり、幅 5 の到達床がこれを上回る可能性がある。** [[容量不足レジームの機構_0830]] §3.1 の静的到達上界（32 パターン厳密列挙・幅 5 で MSE $\le 0.007813$）は `eval_loss` の量であって `unfit` ではないので、**そのままでは流用できない**。preflight で `LIN5` と `R5` の early 窓（task 2–11）の `unfit` を測り、**各腕・各 seed について窓内最小 `unfit` がしきい値未満となること（全 seed の窓内最小値の最大が `0.05` 未満）を確認する。** 確認できない場合は本走を禁止し、G0 を無効とする。**§5.1 の分解能不足により G1 を主判定へ昇格しない**
- **S-dose**: 全腕が用量固定なしなので dose は走行中に動く。**「この腕の用量は X」と書かない**（[[引用禁止]] B）
- **未フィット率の床**: **1 層系 `1e-16` を `gate_dose_0830` から継承**（2 層系の `1e-23` を使わない。継承元を明示する — [[現在地]] 運用メモ）

## 5. 事前登録判定（案・凍結時に確定）

実験単位は seed（n=20）。主窓は末尾 `task 491–500`。paired percentile bootstrap 95% CI（B=10,000）。studentized fallback と退化ガードを併記（教訓⑬）。**総和と率の両方**を出す（教訓⑰）。

**bootstrap seed**: **`202609011921`**（Issa 記入・2026-09-01・チャット `P3_P2_0901`）。既用 = `20260829` / `20260901` / `20260902` / `20260903` / `20260904` / `20260906` / `202609011252` のいずれとも重ならない。
**`generator_offset`**（§2.3）: **`202609011921`**（同上）。既用 = `0` / `20260830` / `20260831` / `20260905`。**衝突検算済み**: (i) 既用のいずれとも一致しない、(ii) 既用との差が 95 にならない、(iii) 幅 5 の基底 `5 + 202609011921` に一致する「幅 100 × offset」は `202609011826` で、これは未使用。
**注（要確認）**: bootstrap seed と `generator_offset` に**同一の値**を充てている。両者は別系統（前者は解析側の再抽出、後者は `train.make_gens` の学習側系列）なので機能上の衝突は無いが、`lr_a1_0901` は `generator_offset=0` / bootstrap `202609011252` と**別の値**を使っていた。分けるなら §8-5 で指定する。

### G0（**単独の主判定**・存在確認）

> **9/1 裁定（Issa）: G0 を単独の主判定とし、G1 は報告へ降格する。** 根拠は §5.1 の分解能較正 —— G1 が測ろうとしている効果（図 B.10 で約 0.08 dex）は n=20 の分解能（約 0.55 dex）の 7 分の 1 で、**Δ_lev をどう置いても G1 は登録判定を返せない**。P-2 の目的はもともと存在確認であり、閾値越えの本数である G0 はこの問題を受けない（0/20 対 15/20 は誤差に埋もれない）。

`n_onset` = 末尾窓で生 `unfit` $\ge$ `onset_threshold` の seed 数（`gate_dose` の定義を継承）。

- `LR5`・`E5` がともに 0/20 → **`PHENOMENON3_NOT_REPRODUCED`**
- 少なくとも一方が $\ge$ 5/20 → **`PHENOMENON3_REPRODUCED`**
- 最大が 1–4/20 → **`PHENOMENON3_MARGINAL`**
- **⚠ 飽和ガード（教訓⑪）**: `LIN5` を含む全腕が 0/20 または全腕が 20/20 → **`BINARY_SATURATED_NO_VERDICT`**。**このとき本走は登録された存在判定を返さない。** G1 へ逃がさない —— §5.1 のとおり G1 には代替できる分解能が無いためである。**S-cap（§3）はこの分岐を事前に潰すための preflight であり、省略できない**

### 5.1 分解能の較正（**事後・未登録**・G1 降格の根拠）

出所: `results/gate_dose_0830/verdict.csv` の `U_5m_seed_values` / `U_1m_seed_values`（**w100・10 seed・末尾窓 task 491–500**）。`summary.md` に無い読み方なので教訓⑫に従い出所と窓を明記する。**w100 の分散を w5 へ外挿したものである。**

| 量                                    | 値                 |
| ------------------------------------ | ----------------- |
| 非 ReLU 腕の $\log_{10}U$ の seed 間 SD   | 0.56–0.94 dex     |
| `LR` − `E` の対応差の SD                  | 0.83–1.31 dex     |
| **中央値差の bootstrap 半値幅（n=20 へ外挿）**    | **0.53–0.64 dex** |
| 図 B.10 の leaky 対 Linear（0.95 / 0.79） | **約 0.08 dex**    |
| 図 B.10 の ELU 対 Linear（0.70 / 0.85）   | 約 −0.09 dex       |
| `gate_dose` P3（ゲートの効果・登録済み）          | 1.8–2.6 dex       |

**★ 同じ幅・同じ offset でもペアリングは分散を減らさない。** `LR_off` と `E_off` の seed 間相関は **0.087** で、対応差の SD（1.129）はどちらの腕の SD よりも大きい。これは `gate_dose` の登録済み `pairing_caveat: activations_diverge_after_step1` そのものであり、**`LR5` 対 `LIN5` でも同じことが起きる**（init・教師・入力実現の共有は step 1 までしか効かない）。

必要 seed 数（半値幅 $h \approx 1.96\,\mathrm{SD}/\sqrt n$、SD ≈ 1.13 dex）: $h$=0.5 → n≈20 ／ $h$=0.3 → n≈54 ／ $h$=0.1 → **n≈490** ／ $h$=0.08 → **n≈766**。**5M を 490 本は非現実的。**

**この較正が効くのは「弱い再現」の場合だけである。** 現象3 が強い形で存在すれば効果は 1–2 dex 級になり（ReLU 対 非 ReLU の実測差がその大きさ）、水準側でも普通に見える。**G1 は強い現象3 には効き、弱い現象3 には構造的に盲目**である、と読む。

### G1（Dohare の判定規則の自前適用・**報告のみ・登録しない**）

末尾窓 $\log_{10}U$ の腕別 20 seed 中央値を **`LIN5` と比較**する。**$\Delta_{\rm lev} = 0.5$ dex**（§5.1 の分解能の下限。科学的な閾値ではなく**読み取り可能な最小幅**として置く）。

- `LR5` が `LIN5` より $+\Delta_{\rm lev}$ 以上高い（悪い）→ `LEAKY_ABOVE_LINEAR`（図 B.10 と整合）
- $-\Delta_{\rm lev}$ 以下 → `LEAKY_BELOW_LINEAR`
- 差の CI が $\pm\Delta_{\rm lev}$ の内側 → `LEAKY_WITHIN_RESOLUTION`
- CI が帯をまたぐ → `INCONCLUSIVE_WIDE`
- `E5` にも同じ規則を独立に適用する
- **★ 引用上の制約**: `LEAKY_WITHIN_RESOLUTION` を「leaky と線形は同じ」と読まない。**意味するのは「図 B.10 の効果は当方の分解能より下」まで**である（帯 0.5 dex は図の効果 0.08 dex の約 6 倍幅）。**いずれのラベルも登録判定ではない**

### G2（幅対比・**記述のみ・登録しない**）

w5 腕 対 w100 腕。**§2.3 のとおり非対応**なので、腕間の paired 統計は取らない。腕ごとの水準と CI を並べるだけ。

### G3（機構・[[現象3指標再定義_P3_0901]] の 3 軸）

- **軸1**: `median_s`（**`median_M + median_B` ではない** —— P-3 §2-4 D-4 で集約順の差を確認済み）、および生の `zbar` 中央値と `denom` 中央値

## 6. 窓・引用の規律

- 数値を書くたびに窓ラベルを添える（教訓⑫）
- **0/20 は「5M までに観測しなかった」の強さ**（片側 95% 上限 $p \le 0.1391$・n=20）。「起きない」と書かない
- **「ELU / leaky は LoP を防ぐ」と一般には書かない**（Q22 反論欄・維持）
- **`LIN` を「線形ネットワーク」と呼ぶときは、これが leaky($a$=1.0) の実装であることを併記する**
- 幅対比を「同一個体の幅違い」と書かない（§2.3-1）
- スコープは condA・$T=10^4$・batch 1・`lr` 0.01・5M。他タスク・他ホライズンへ外挿しない

## 7. コスト見積り（**未実測の外挿**）

`gate_dose_0830` の実測は w100・10 seed・5M・1 腕で **429–468 秒**（`provenance.json` の `arm_elapsed_sec`。ReLU 腕は 0.0 = `--s0prime` からの resume）。seed はベクトル化された `R` 次元なので 20 seed は 2 倍未満。幅 5 は行列が小さいぶん速いが、**律速は 1,000 step ごとの 32 点支持の厳密評価**と見られるので幅の効きは限定的。

| 案         | 腕                 | 見積り        |
| --------- | ----------------- | ---------- |
| **A**（最小） | w5 × 4            | **約 1 時間** |
| **B**（推奨） | w5 × 4 + w100 × 4 | **約 2 時間** |

いずれも [[9月運用_0901]] §3 の「P-2 は 1–3 時間級」の範囲に収まる。**seed のプロセス並列（§3-4）を入れるなら、導入条件である既存走 1 本の bit 一致確認が先。**

## 9. 本 spec が前提にしている未登録の判断

- [[現象3指標再定義_P3_0901]] の 3 軸分割は **Claude の整理であり、先生の承認も登録判定も無い**
- §4-5・§4-6 の「幅は床を変えない」は **設計値からの論証**であって測定ではない
- 図 B.10 の読み（`LR` は Linear より上、`E` は下）は **目視読み**であり、本走はそれを再現するのではなく**置き換える**ためのもの。したがって「図 B.10 と一致した／しなかった」を主判定にしない
