# ViT × ランダムラベル 1 セル — 「易しさ」の出どころを切り分ける

状態: 事前登録（2026-09-20、本走前・値は未観測）。
親: [spec_joudaki_vit_battle_0919.md](spec_joudaki_vit_battle_0919.md)。学習条件はすべて継承する。

## 1. なぜ

13 腕本走（130/130 run 完了）で、この箱は**可塑性を全く失わなかった**:

- online 正解率は t1–5 の .719 から t36–40 の .883 へ**単調に上昇**（全 13 腕で早期−後期が負）
- **fresh network 対照**（事後・登録外、130 run）で **fresh gap 中央値 −.249、gap>0 は 0/130**。
  40 タスク積んだネットは新品より **25 ポイント高い**精度で新規タスクに適合する
- `z<0` 質量は .575 → .840 と**疎化は起きている**のに、**完全死 channel は 1536 中 4 本（.26%）**

一方 `relu_doors_0919`（3072-100-100-10 MLP・正規化なし・**ランダムラベル CIFAR**）では ReLU が窓 .113 まで崩壊した。
2 つの箱は少なくとも 4 つ違い、どれが効いているか未分離である:

| | relu_doors_0919 | joudaki_vit_battle_0919 |
|---|---|---|
| **ラベル** | **ランダム** | **本物のクラス** |
| 構造 | 素の MLP | transformer（attention + LN + 残差） |
| 幅 | 100 | 1536 |
| データ | CIFAR | Tiny ImageNet |

Issa は「**transformer が MLP のタスク自体を易しくしすぎている**」説を推す。
本セルはその説とラベル説を切り分ける。**fresh gap −.249 はタスク間に転移可能な構造がある直接証拠**であり、
ランダムラベルはその構造を原理的に消すので、ラベルだけを入れ替えれば出どころが決まる。

なお「残差があるので FFN は補正を足すだけ」という形の構造説は、事後測定で**弱い反証**が出ている:
‖mlp_out‖/‖x‖ は block 0 で t1 .67 → t40 **1.18**、block 5 で .26 → **.81** と attention より大きく、
タスクを重ねるほど**増える**。FFN は遊んでいない。

## 2. 変えるのはラベルだけ

13 腕本走の設定をすべて据え置き、**ラベルの与え方だけ**を替える。

- 腕は **`R`（素の ReLU）のみ**、seed0–9、40 タスク × 500 更新。
- **タスクごとの 5 クラスは本走と同一**（`task_classes(seed)` をそのまま使う）。
  ただし**各クラス先頭 50 枚＝1 タスク 250 枚**に絞る（理由は §2.1 の較正）。
  提示回数は 250 枚 × 250 epoch = **62500 で本走と同一**。
- ラベルは **iid uniform {0..4}**、**タスクごとに引き直す**（`pmnist_rlcifar_0907` の規約に合わせる。
  同じ画像に毎タスク新しいラベルを振る）。乱数は `stream_seed('randlabel', seed, task)` の専用ストリームで、
  batch 順・拡張・dropout のストリームを一切消費しない。
- バッチ順と拡張は `(seed, task)` だけで決まるので、**本走と同じ画像列・同じ拡張**を見る。
- ViT・Adam 1e−4・WD なし・float32・TF32 無効・compile + fused Adam・dropout .1・
  head リセット・5 クラスへの mask、すべて本走のまま。
- val 正解率はランダムラベルでは意味を持たない（汎化する対象が無い）。**記録するが判定に使わない**。

モデルスナップショットは保存しない（本走の 2.5 GB/run に対し、本セルは判定に不要）。
前活性の読み出しは t1 / t21 / t40 で固定 16 画像から取る。

### 2.1 画像枚数の較正（**判定の登録より前**・seed0 の task1 のみ）

本走の 2500 枚をそのまま使うと **ViT はランダムラベルをほとんど暗記できない**。
seed0 の task1 で実測:

| 枚数 | 更新 | lr | task1 online | task1 暗記率 |
|---|---|---|---|---|
| 2500 | 500 | 1e−4 | .217 | **.229**（偶然水準 .2＝床） |
| 2500 | 500 | 3e−4 | .200 | .220（lr を上げると悪化） |
| 2500 | 2000 | 1e−4 | .262 | .375（4 倍の費用でも不足） |
| 500 | 500 | 1e−4 | .452 | .762 |
| **250** | **500** | **1e−4** | **.687** | **.932** |
| 125 | 500 | 1e−4 | .827 | .944 |

2500 枚のまま回すと **Q1（窓 < .5）が床効果で自明に真**になり、
可塑性の喪失ではなく「そもそも学習していない」を測ってしまう（空虚な検査）。
500 枚でも task1 の online が既に .452 で閾値 .5 を下回るため、同じ理由で使えない。

**250 枚を選ぶ**。task1 の暗記率 .932 は天井に近く**落ちる余地が十分**あり、
task1 の online .687 は崩壊閾値 .5 の**上**なので、後の崩壊は床ではなく本物の劣化を意味する。
効いているのは枚数であって学習率ではないことも上表で確認した。

この較正は **seed0 の task1 だけ**を見ており、**タスクをまたぐ動き（=本 spec が予測する量）は一切見ていない**。
較正の後に §3 の判定と §5 の予測を確定した。

## 3. 判定（値を見る前に固定）

主指標は親 spec のまま: 各タスク 500 更新の**更新前** online 正解数 / 提示画像数、窓 = t21–40 の平均。
偶然水準 .2。崩壊ラベル = 窓 < .5。

**登録する 3 つの読み**:

- **Q1 崩壊**: `R` の窓の 10 seed 中央値が **< .5**
- **Q2 fresh gap**: task40 で `fresh_gap = fresh − continual` の中央値が **> 0**
  （本走と同じ事後対照を、本セルでも同じ手順で取る。**> 0 なら可塑性喪失が実在する**）
- **Q3 単調劣化**: 早期（t1–10 平均）− 後期（t31–40 平均）の中央値が **> 0**
  （閾値に依存しない最もきれいな喪失の署名。本走では全 13 腕で**負**だった）

**Q2 が本セルの主判定**である。Q1 は .5 という操作的閾値に依存し、Q3 は符号だけを見る。

判定の読み替え:

- **Q2 > 0（喪失が出る）** → 易しさの出どころは**ラベル**。transformer は盾ではない。**Issa の説は棄却**
- **Q2 ≤ 0（喪失が出ない）** → ランダムラベルでも ViT は転移する。**transformer が本当に盾**で Issa の説が支持され、
  幅説とも切り分く（幅は 1536 のまま動かしていないため）

fresh gap は Adam の moment と dropout 履歴を統制していない（本走の対照と同じ既知の留保）。
本セルでも同一手順で取るので、**2 つのセルの gap の差**には統制の効かない分が相殺されて残る。

## 4. 代価

`R` 単独 10 seed × 40 task ≈ **1.5 時間**、fresh 対照が追加で 2 分。保存は数十 MB。

## 5. 予測の登録

Claude（本セッション）:

| # | 予測 | 確率 |
|---|---|---|
| Q1 | 窓の中央値 < .5（崩壊） | 45% |
| Q2 | fresh gap 中央値 > 0（**主判定**・可塑性喪失が実在） | 70% |
| Q3 | 早期 − 後期 > 0（単調劣化） | 75% |

根拠: ランダムラベルは転移可能な構造を原理的に持たないので、本走の −.249 という巨大な負の gap は
少なくともゼロ付近まで戻るはず。正に振れるかどうかは、ViT の幅 1536 と残差がどこまで暗記容量を支えるか次第で、
そこは幅説の領域なので確信度を 70% に留める。Q1 の 45% は、崩壊閾値 .5 が
「暗記がどこまで速いか」に強く依存し、偶然水準 .2 からの立ち上がりの速さを事前に見積もれないため。

Issa の予測: **未登録**。
