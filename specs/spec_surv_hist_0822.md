## 0. 一行

`ratchet_log_0819` の保存 npz のみを使い、生存ユニットの p̂ 水準（**T1**）と生存者数の平衡（**T2**）の 2 票で、停止条件の残る 2 候補 **H_earn**（低次成分の稼ぎ説）と **H_marg**（罠幾何説）を判別する。

## 1. 背景 — 何が既に決着し、何が残っているか

`teachw_0820` で **P1 FAIL**（傾き −5.755、予言は正の単調増加）により「生存者数＝タスクを表現するのに必要なユニット数」（役立ち説の複雑度予言）は棄却された。スケール整合層 H∈{4,8,32,100} では傾き −0.0181 [−0.379, +0.309] のタイトな null で、「入力統計が固定なら生存者数は教師複雑度に非感応」が積極的に支持されている（Q9b）。

残る 2 候補は複雑度非感応と両立する:

| | 主張 | T1 の予言 | T2 の予言 |
|---|---|---|---|
| **H_marg**（罠幾何説） | 動く罠の共通部分に落ちなかった者だけが残る。生存者数は入力統計と消灯点で決まる定数 | 生存者は**閾値際に滞留**しているので p̂ は alive 閾値のすぐ上に積み上がる（中央値が低い） | 定数なので**平衡がある**（[700k,1M] で下げ止まる） |
| **H_earn**（低次成分の稼ぎ説） | 生存者は稼いでいるが、稼ぎ先は教師複雑度に依存しない成分（µ 方向・定数項まわり）のみ | 生存者は**実際に発火して稼いで**いるので p̂ は閾値から離れて高い | 稼ぎが続く限り残るので平衡は要求されない（**T2 は H の判別力を持たない**） |

**T2 の役割は二重である。** Q10 の判別（H_marg 側の予言のみを持つ片側テスト）と、Q9b の反論欄を閉じる防衛（平衡の有無そのものが知りたい）。**現論文で使うのは後者だけ**（§8）。

**8/20 の訂正の反映**: 「生存者は 8.5% で止まる」は誤りで、alive は 1M でも下げ止まっていない（`停止条件.md`）。したがって T2 は「平衡が**ある**ことの確認」ではなく「**平衡があるか否かの判定**」である。「停止条件」という枠組み自体が正しいかも未確定で、T2 がこれを兼ねる。

## 2. 入力とデータ構造（確認済み）

- 入力: `results/ratchet_log_0819/logs/seed{0..9}.npz` **のみ**。新規走行・新規アームなし
- 10 seed すべてで step グリッドが byte 一致、`width=100`、`period=10000`、`lr` 一致、`run_id` 一意、`p_hat` に NaN/Inf なし
- 記録点: seed あたり 20,901 点（バルク 1000 step 毎 ＋ 各境界の ±100 step を毎 step）。`step` は 0 から 1,000,000
- `p_hat` は (20901, 100) float32。**1 タスク内のサポートは 32 パターン**なので p̂ は **k/32（k = 0..32）に量子化**される。したがって alive 閾値 0.05 は実質 **p̂ ≥ 2/32 = 0.0625** を意味し、「閾値際」は k ∈ {2, 3} を指す
- 境界は 99 個実現（100 番目の t=1,000,000 では flip が起きない）。step 999,900–999,999 に**境界ではない毎 step 記録が 100 点**あるので、境界窓として扱ってはいけない

## 3. 定義（事前固定）

- **alive / dead**: p̂_i ≥ 0.05 / p̂_i < 0.05（`teachw_0820`・`spec_dead2path_0821` と同規約）
- **alive 集合の評価時点**: 各記録点でその時点の p̂ から判定する（履歴を使わない瞬間値）。`dead2path` の「恒久死」概念は**使わない**（§8 の A/B 独立の規定）
- **T1 統計量**: **1,000,000 step 時点の alive ユニットの p̂ の中央値**。seed ごとに中央値を取り、seed 間の中央値を点推定とする
- **T2 の窓**: `[700000, 1000000]`。この窓に含まれる記録点をすべて使う（毎 step 記録と粗いグリッドが混在するので §4-2 の重み付けに従う）
- **T2 統計量**: 窓内の alive 数の **step に対する傾き**（seed ごとに OLS、単位は「1 ユニット / 10⁵ step」）
- **CI**: seed 単位ペアブートストラップ、`B = 10000`、`np.random.default_rng(20260822)`、`run_id` ソートで seed をペアリング（`9. 計測の信頼性` の規約）

## 4. 識別限界（先に書く）

1. **記録グリッドが不均一**。窓 [700k, 1M] には毎 step 記録（各境界 ±100）と 1000 step 刻みのバルクが混在する。境界近傍が過剰代表されるので、T2 の傾きは**バルクグリッドの記録点のみ**（`step % 1000 == 0` かつ境界窓外）で推定する。境界窓内の点を含めた版を**副次**として併記する。どちらを主判定にするかは §5 で事前に固定する
2. **T1 は 1 点のスナップショット**。p̂ が k/32 に量子化されているので、alive 数が少ない seed では中央値が離散的に飛ぶ。alive 数そのものを併記する
3. **T2 は片側の判別力しか持たない**。平衡が無い（傾きが有意に負）ことは H_marg に不利だが、平衡がある（傾き null）ことは H_earn を排除しない。決定行列（§5）はこれを反映する
4. **単一アーム**。`ratchet_log_0819` は H_T=100・w100・T=1e4・batch=1 の 1 条件のみ。教師複雑度に対する感応は `teachw_0820` で既に測ってあり、本 spec は**それを再測しない**

## 5. 判定基準（事前登録・commit 前に固定）

### T1（生存者の p̂ 水準）

統計量: §3 の T1。**帯は下表で固定する。**

**A 案（構造基準）で確定**（2026-08-22 承認）。p̂ が k/32 に量子化されていることに合わせた帯:

| 帯 | 基準 | 意味 |
|---|---|---|
| **H_marg 側** | CI 上端 < **4/32 = 0.125** | alive が閾値際 k ∈ {2, 3} に収まっている＝閾値際の滞留者 |
| **H_earn 側** | CI 下端 > **16/32 = 0.5** | alive がサポートの半分以上で発火している＝実際に稼いでいる |
| **保留** | それ以外 | 正規の結末として扱い、**FAIL とは書かない** |

（不採用: B 案「等分基準」= H_marg 上端 0.25 / H_earn 下端 0.50。採否の理由は p̂ の量子化構造に合わせたことのみで、既知の探索値とは無関係 → §9）

### T2（平衡の有無）

| ID | 予測 | 統計量 | 基準 |
|---|---|---|---|
| **T2** | 窓 [700k,1M] で alive 数は平衡に達している | バルクグリッド限定の傾き（seed 中央値、ペアブートストラップ CI） | **CI がゼロを含む → 平衡あり（EQ）**。CI 上端 < 0 → **平衡なし（DECL）**。CI 下端 > 0 → **増加（INC、想定外）** |
| **T2-win**（副次） | 同上 | 境界窓内の点も含めた傾き | 判定に使わない。主判定との符号一致のみ報告 |

### 決定行列（2 票）

|  | **T2 = EQ（平衡あり）** | **T2 = DECL（平衡なし）** |
|---|---|---|
| **T1 = H_marg 帯** | **H_marg 支持**（両票一致） | **判別不能**。T1 は H_marg、T2 は H_marg に不利 → 台帳へ差し戻し |
| **T1 = 保留** | **T2 のみ記録**（Q9b の反論欄は閉じる。Q10 は未決） | **T2 のみ記録**（同上。Q10 は未決） |
| **T1 = H_earn 帯** | **H_earn 支持**（T2 は H_earn を排除しない） | **H_earn 支持**（両票整合） |

**T2 = INC は処置表に無い結末**とし、その場合は判定を「想定外」と記録するに留めて処置を決めない（`cell4_0821` 追補と同じ扱い）。

### E2 について

台帳（`命題リスト.md` L56、`blindspot_0820.md` L72）は「T1/T2/**E2**」と 3 つ挙げているが、**E2 の定義は vault・specs・README・全 commit のどこにも無い**。本 spec は **E2 を含めない**。定義が人間側から出てきたら別 spec の補遺として起票する。

## 9. 留保 — 盲検性が既に一部毀損していること（承認前に読むこと）

**本 spec は厳密な意味での盲検事前登録ではない。** T1・T2 に対応する探索値が、起草時点で既に vault に記録されている:

- **T1 相当**: `teachw_0820` の P3（探索的・判定なし）に「alive の p̂ 中央値 0.219–0.578」があり、`ratchet_log_0819` と厳密一致するアーム（H_T=100）の値は **0.2969**（`results/teachw_0820/summary.md`）
- **T2 相当**: `停止条件.md` に「700k→1M の中央値変化: H8/H32/H100 は −1〜−2 でほぼ横ばい」

したがって:

1. **§5 の T1 の帯を選ぶ行為は、答えを見た上での選択になる。** 採用した A 案（上端 4/32 = 0.125）でも、既知の探索値 0.2969 は **H_marg 帯に入らず「保留」に落ちる可能性が高い**。帯を 0.2969 が入るように広げれば、それは結果に合わせた閾値設定になる。**A 案はその調整を**しない**ように置いてある**（採否の理由は p̂ の量子化構造に合わせたことのみ）
2. この毀損は `summary.md` の逸脱節に必ず記載する
3. teachw の P3 は「判定に使わない」と明記されている探索値なので、**本 spec の判定として改めて測る意味はある**（母集団・アーム・CI の作り方が違う）。ただし「独立な検証」とは呼べない

**この留保を受け入れられない場合は、T1 を判定から外して T2 のみを実施する**という選択肢がある。その場合 Q9b の反論欄は閉じるが Q10 は未決のまま残る。承認時に指示すること。
