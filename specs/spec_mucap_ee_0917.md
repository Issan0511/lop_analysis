## 0. 一行と問い

RL の ELU→ELU（EE）は第2層が task 10 前後で死に、網は床（online 約 10%）に落ちる（`layer_chimera_rl_0914`）。**第1層の平均画像方向の成分 $q$ と直交成分 $v$ の成長をそれぞれ task 2 から止めると、第2層の崩壊は防げるか、早まるか。** 第2層には一切触らない。

- **Q1（主）**: 直交成分を止める（cap_perp）と、第2層は床に落ちず、応答（平均 $\varphi'$）が ref より残るか。
- **Q2**: 平行成分を止める（cap_par）と、崩壊は防げるか、早まるか。
- **Q3**: 両方（cap_both）。
- **Q4（機構・報告のみ）**: 第2層の入力平均 $\|\mu_2\|$ を作るのは第1層のどのユニットか。腕の順位は $\|\mu_2\|$ の順位と一致するか。

## 1. なぜ（既存データとパイロット・REPORT_ONLY・登録判定ではない）

### 1.1 EL 箱（mucap_el_0916）の事後の読み

同じ 4 腕を ELU→leaky で回した結果（10 seed、task 51–150 の平均）:

| | ref | cap_par | cap_perp | cap_both |
|---|---|---|---|---|
| online 精度 | 30.5% | 71.1% | 81.1% | 88.5% |
| $\sigma_1$（第1層の前活性の広がり） | 22.1 | 12.4 | 1.74 | 1.49 |
| $\|\mu_2\|$（第1層出力の平均のノルム） | 13.4 | 26.6 | 7.8 | 6.3 |
| $\bar z_2$（第2層の平均前活性） | −14.6 | −40.2 | −3.9 | −4.9 |

事後の読み（未登録）は「第1層の直交成分のノルム成長 → 第1層出力の尺度 → $\|\mu_2\|$ → 第2層が $\mu_2$ 方向に沈む（`l2_wall_0916` の壁）」。EL では第2層が leaky なので沈んでも死なない。**ELU なら死ぬはず**、というのが本 spec の出発点。

**0916 の記録の訂正（本 spec の commit で修正）**: 0916 の runner の `memo_acc`（タスク終端の 1200 枚での正解率）は `RL.evaluate_rl(params, x, y, act1)` で計算しており、宿主の forward が act1（ELU）を**両隠れ層**に使うため、学習した ELU→leaky の網ではなく「第2層を ELU に差し替えた網」の正解率だった（seed 0・task 1 で記録 0.433、正しい網では 0.501）。0916 の `online_acc`・登録判定・ユニット量は正しい forward で計算されており影響はない。本 spec の commit で runner を学習した網そのものの forward に直し、S0 で「0916 の記録値は ELU→ELU の複製の正解率だった」ことと「直した値は学習した網の正解率である」ことを検査した。

**このパイロットが予測を動かす**: EE の ref で上流の尺度を作っているのは、EL の事後の読み（直交成分の広がり）ではなく、**平行成分 $q$ が正に育った常時点灯ユニット**に見える。cap_par はその経路を塞ぎ、広がりの経路（$v$）は開けておく。cap_perp はその逆だが、EL では $v$ を止めると $q$ も育たなかった。どちらが効くかは §7 に分けて書く。

### 1.3 速度と flush_denormal

パイロットの 1 タスクの所要時間は 3.3 秒 → t40 で 12.9 秒と伸びた（第2層の前活性が float32 の非正規化数の域を通るため）。`torch.set_flush_denormal(True)` で同じ ref seed 0 を 40 タスク回すと、**per_task.csv の全列（online・中央値）が flush なしと 1 bit も変わらず**、所要時間は 265 秒 → 155 秒（t38 で 5.5 秒/タスク）。本走は flush を有効にする（§2.1）。それでも時間は伸び続ける（exp のアンダーフロー処理）ので、地平線を 100 タスクにし、第1層の帳簿（ledger）は切る。

## 3. 測る量（すべて float64 で保存）

0916 spec §3 と同じ診断点（task 1 の開始・終了、task 2–10 は更新 0/75/375/1500/3000/6000、以降は開始・終了）と同じ `units.npz` の量（両隠れ層の $\bar z,\sigma,U,p^+,d,K$、平均・RMS $\varphi'$、低ゲート割合、両基底の成分、bias、第1層の Adam 量）。MNIST test は task 1・10・50・100 の終了点。本 spec で追加したもの:

- `mu2_proj_sd`: $\mathrm{sd}_x(e_2^\top a_1(x))$。壁の定数 $c_2=\|\mu_2\|/\mathrm{sd}$ を出す。
- `a1mean_l1`: 第1層ユニットごとの出力平均（$\mu_2$ そのもの）。
- `per_task.csv` の `major_frac`: そのタスクのラベルでの最良定数予測器の正解率 $\max_c n_c/1200$（床の算術）。
- `memo_acc` は学習した網そのものの正解率（§1.1 の修正後）。
- **ledger は off**（§1.3）。

## 4. endpoint（すべて seed ごとに作ってから seed 間で要約）

### 4.1 主 endpoint と床

**主窓 $W$ = task 51–100**（50 タスク）。形成窓 task 2–10・11–50 は副報告。

- **E1（機能）**: online 精度の窓内タスク平均。$\Delta E1=E1_W-\text{online}(1)$。
- **E2（第2層の応答）**: 第2層の平均 $\varphi'$ を「画像平均 → 全 100 ユニットの算術平均 → 窓内タスク終端の算術平均」。$\Delta E2=E2_W-E2_{t1}$。

腕の効果は seed 内の対応差 $\delta=\Delta_{\mathrm{arm}}-\Delta_{\mathrm{ref}}$（task 1 は全腕で bit 一致なので、窓の水準差と同じ）。正なら「ref より網が学べる／第2層の応答が残る」。

**床（親 `layer_chimera_rl_0914` の規則を主窓に適用）**: run ごとに、主窓の 50 タスクの `major_frac` の平均 $F$ と標本 SD $s$（ddof=1）から閾値 $F+3s/\sqrt{50}$。主窓の online 平均がこれ以下なら AT_FLOOR。腕の状態は、有効 seed すべてで AT_FLOOR なら **FLOORED**、すべてで上なら **ALIVE**、割れたら **SPLIT**。

### 4.2 副 endpoint（登録・判定の代用にしない。ただし 1 は §5.3 の時間ラベルに使う）

1. **崩壊の時刻 $T_{1/2}$**: 適合率 $F(t)=(A(t)-0.1)/(A(1)-0.1)$（$A$ は online、0.1 は偶然水準）が task 2 以降で初めて 1/2 を下回るタスク。100 までに下回らなければ右打切りで、101 などに置き換えない。
2. **第2層の吸収**: $U_2<0$ が 5 タスク連続するユニットの割合と初回タスク。第1層も同じ。
3. **第2層の幾何**: $\bar z_2,\sigma_2,d_2$、$c_2=\|\mu_2\|/\mathrm{sd}(e_2^\top a_1)$、$\|W_2\|$、$b_2$、$S_2$。
4. **$\|\mu_2\|$ の担い手**: 第1層で $q>0$ のユニットの割合、全画像で点灯している（$p^+_1=1$）ユニットの割合、それぞれが $\|\mu_2\|^2$（`a1mean_l1` の二乗和）に占める割合。
5. **第1層**: 平均 $\varphi'$、$d_1$、$\sigma_1$、$\|v\|$、$q$。**FLOORED の腕では第1層は下流の停止で凍るので、腕間の機構比較に使わない。**
6. **性能**: online・`memo_acc` の窓平均。
7. test 集合での同じ幾何量（t1/10/50/100）。

## 5. 判定

### 5.1 帯の算術

主 2 endpoint それぞれで、有効 seed の $\delta$ の平均・SD・**97.5% 対応差 t 区間**（df = n−1、2 量の Bonferroni）。95% 区間も併記。SD = 0 なら区間を作らず実測の同一差を示す。符号: 区間の下端 > 0 なら +、上端 < 0 なら −、それ以外 0。t 分位点は 0916 の `verdict.py` の実装（公表表と 1e−6 で照合済み）をそのまま使う。

### 5.2 適用条件

- **(A) 完全性**: 全 seed で 4 腕の task 1 終端 sha256・ラベル・標本順が一致、全 run が 100 タスク完走、非有限値なし（online・両層の平均 $\varphi'$）。有効 seed が 8 未満なら全ラベル INAPPLICABLE。
- **(B) ref が崩壊する**: ref が有効 seed の 8 割以上（切り上げ）で主窓 AT_FLOOR、かつ ref 単独の $\Delta E2$ の 95% t 区間の上端 < 0。満たさなければ全ラベル **NOT_REPRODUCED**。
- **(C) 上限がかかった**: 各 cap 腕・各有効 seed で、**task 2–10 の全タスク**について、その腕が上限する成分の射影行数 > 0。満たさない腕は INAPPLICABLE。（0916 は主窓で要求したが、EE では崩壊した腕の第1層が凍って射影が止まるので、崩壊が起きる窓で要求する。）

**読みのフラグ（判定を変えない）**: IMPAIRED — cap 腕の task 2–5 の平均 $F$ が「ref の task 2–5 の平均 $F$ − (1 − それ)」を下回る seed が過半数（0916 と同じ規則）。

### 5.3 ラベル

**主 = cap_perp − ref（97.5%）**。cap_par − ref と cap_both − ref は 95%。cap_perp − ref の 95% も参考に出す。

| 腕の床の状態 | $s_{E1}$ | $s_{E2}$ | ラベル |
|---|---|---|---|
| FLOORED | — | — | **COLLAPSED** |
| SPLIT | — | — | **SPLIT** |
| ALIVE | + | + | **RESCUED** |
| ALIVE | + | 0 / − | RESCUED_FUNCTION_ONLY |
| ALIVE | 0 / − | — | ALIVE_UNRESOLVED |

適用条件の順: (A) か (C) を満たさなければ INAPPLICABLE、(B) を満たさなければ NOT_REPRODUCED。

**時間（各 cap 腕・判定と並べて出す）**: seed ごとに腕の $T_{1/2}$ を ref と比べ、早い／遅い／同じ（打切りは観測されたどの時刻よりも遅い、両方打切りは同じ）。同じ seed を除いた数で両側の正確な符号検定を行い、p < 0.05 なら多い側で **EARLIER** / **LATER**、それ以外は NO_TIMING_DIFF。（同じを除いた数が 5 以下なら全一致でも p ≥ 0.0625 で立たない。）

### 5.4 読み方（登録）

- cap_perp が RESCUED → **第1層の直交成分の成長を止めると、第2層（ELU）は 100 タスクまで床に落ちない**。§4.2-4 で $\|\mu_2\|$ の担い手を併記する。
- cap_perp が COLLAPSED → 第1層の直交成分の成長は EE の崩壊に必要ではない。
- cap_par が RESCUED → **常時点灯ユニット（$q>0$）の成長が崩壊を運ぶ**という §1.2 の読みと整合。EL の事後の読み（「$q$ を止めると尺度が上に流れて死ぬ」）はこの箱では成り立たない。
- cap_par が COLLAPSED かつ EARLIER → EL の事後の読みと整合。
- 両方 RESCUED → どちらの成分を止めても $\|\mu_2\|$ の爆発は止まる（EL の「$v$ を止めると $q$ も育たない」と同型の結合を疑う）。§4.2-4 で区別する。
- RESCUED は「この箱で 100 タスク床に落ちなかった」であり、無限時間の非崩壊ではない。主窓で第2層の応答が下がり続けていれば、そう書く。
- IMPAIRED の腕では「可塑性を守った」と書かない。
- 機構（§4.2-3・4）は報告のみ。腕の順位の一致は因果の証明ではない。
- すべて「この ELU→ELU・乱数ラベル・6000 更新・task 2 開始・第1層だけの上限・100 タスク」に限る。

## 8. 費用と実行

- S-cost は 6 プロセス同時・2 タスクで 1 更新あたりの時間を測り、パイロット（flush あり）の時間の伸び（task 2–10 に対する task 1–100 の平均の比、task 41–100 は task 14–40 の直線で外挿: 1.69 倍）を掛けて 100 タスクへ投影する。**実測（登録前）: 0.74 ms/更新 → 1 run 12.5 分、6 並列で 1.4 時間**、1 プロセスの peak RSS 1.33 GiB、空きメモリから 12 スロット。0916 では投影の 1.75 倍かかったので、2.5 時間程度までは想定内とする。
- 並列数は min(6, S-cost のスロット, 起動時の空きメモリで収まる数)。4 未満なら起動しない。コア数では決めない。
- キューは seed 順（seed 0 の 4 腕 → seed 1 …）。`provenance.json` のある shard は飛ばす。
- 起動は本 spec の登録 commit を runner に書き込み、全検査を再実行して all_pass になってから。
