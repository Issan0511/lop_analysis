## 0. 一行と問い

resp_ee_0917 は、崩壊していく自然軌道の分岐点で第2層の「応答の場」を固定して移植し、再学習が両方向に動くことを示した。ただし固定した場は、自然な劣化の半分弱しか運ばなかった（$\rho_2=0.47$）。**本 spec は場を固定せず、移植元の網の自然な継続に追随させる。** 残り半分が「応答を失った状態」の外にあるのか、「失い続けること（継続する輸送）」にあるのかを決める。

- **Q1（主）**: 健康な t2 の網（Adam 初期化）に、崩壊していく t10 の網の第2層の場を、その網の継続（N10）に追随させて与える（**S2dyn_10r**）。固定した場の腕（S2_10r・0.46）より学べなくなるか。学べなくなるなら、応答の操作で届く床（S2u30r・0.21）まで届くか。
- **Q2（副）**: 崩壊した t10 の網（Adam 継続）に、t2 の網の継続（N2）に追随する場を与える（**R2dyn_10**）。resp_ee の復元の超過（R2_10 0.90 > N2 0.78）は、場が止まっていたためか。
- **Q3（副）**: 機能的な応答を「課題中に訓練の微分を運んだ実効画像数の平均 $\bar n_{\rm eff}$」と定義すると、resp_ee の 25 腕で当てはめた直線が、新しい腕の E を予測区間に収めるか。
- **Q4（併走）**: 第2層の訓練の微分が厳密に 0 にならない網（float64 と `F.elu`）でも、同じ箱は崩壊し、学べなくなるか。
- **Q5（報告のみ）**: 構造のない一様な沈み（ランプ）、崩壊の段階（t5・t20 の場）、固定補正なしの復元（R2_10_noanchor）。

## 1. なぜ

### 1.1 resp_ee_0917 に残ったこと（公開済みの値・10 seed 平均）

| 腕 | E（継続 1 タスク目の online 正解率） | 実効引数 $z_2+d$ の平均（開始 → 課題 1 終了） |
|---|---|---|
| N2r（t2・Adam 初期化・自然） | 0.724 | −0.11 → −0.91 |
| S2_10r（t2・Adam 初期化・t10 の固定した場） | 0.464 | −50.87 → −45.92（網が自分で +4.95 登る） |
| S2u30r（t2・Adam 初期化・一様 −30＝全画像で訓練の微分 0） | 0.212 | −30.11 → −30.11 |
| N10r（t10・Adam 初期化・自然） | 0.169 | −50.87 → −54.27 |
| N10（t10・Adam 継続・自然） | 0.137 | −50.87 → −59.78（−8.9） |

- 固定した場の媒介率 $\rho_2=(0.724-0.464)/(0.724-0.169)=0.47$。
- **移植した腕のユニットは登って逃げる（+4.95）。自然な網は沈み続ける（−8.9）。** 設計案の読み: LoP = 応答の喪失（状態）＋ 逃げられないこと（継続する輸送）。固定した場は前者だけを渡した。
- 応答が尽きた腕の群（分岐点で 93% 以上の微分が 0 の 10 腕）の中では、課題中に戻れた量が E を並べる（事後・vault resp_ee 結果ノート §4.2-8）。観察側は揃っている。本 spec は押しへの介入。

### 1.2 応答の操作で届く床

S2u30r は第2層の訓練の微分がすべての画像で 0 なので、第1層も第2層も 1 歩も動かず、固定した t2 の特徴の上で読み出しだけが学ぶ（0.212）。**t2 の網に第2層の応答の操作をする腕は、特徴を前向きに残す限り（固定補正）この床より下へは原理的にほとんど行けない。** N10r（0.169）との差 0.043 は、前向きの値（崩壊した網の特徴が定数に近いこと）の分で、応答では運べない（設計案 §1 の 1 行目）。したがって、自然な差 $0.724-0.169=0.555$ のうち応答の操作で届くのは最大 $0.724-0.212=0.512$（92%）。

### 1.3 設計案からの変更（実装時・新しい腕の値を見る前に決めた）

1. **主ラベルの参照を N10r から応答の床 S2u30r へ変えた。** 設計案の規則（S2dyn_10r − N10r の 95% 区間が 0 を含めば FULL）では、動く場が応答を完全に消しても E は床の 0.21 付近に止まり、N10r（0.17）との差 0.04 は resp_ee の seed のばらつき（N10r の SD 0.022・S2u30r 0.007）では区間から外れるので、**FULL は構造的にほぼ出ない**。設計案自身の予測（E = 0.22 で FULL 55%）もこの規則では PARTIAL になる。本 spec は「動きの寄与 M」と「床からの残り R」で判定し（§4.3）、設計案の字義どおりの規則のラベルも並べて報告する。
2. **ランプは 2 タスク通しで Δ = 10 → 30**（課題 1 で 10 → 20、課題 2 で 20 → 30）。沈む速さ 10/タスクは自然な N10 の −8.9/タスクに近い。課題 1 のランプを固定した段（Δ = 10・15・20）と比べられる。
3. **併走は f64_felu を 10 seed で登録**し、f32_felu と f64_host を 3 seed ずつ報告に付けた。1 run が約 2 分と軽いので seed を増やした（設計案は 3 seed）。
4. **機能的応答の登録は「課題中の軌跡の平均」の手続きにした。** 開始時の $n_{\rm eff}$ で resp_ee の 25 腕を直線で当てはめると（公開値から計算）R² 0.67・残差 SD 0.168 で、S2dyn_10r（開始状態は S2_10r と同じ）の予測は 0.447 [0.090, 0.803] と、どの結果も収まる広さになり、予測の試験にならない（同じ開始状態の N10・N10r・S2_10r・S2_10 が 0.14〜0.46 に散る）。そこで課題中の $n_{\rm eff}$ を測る（§2.5）。新しい腕の説明変数は走った後にしか分からないので、登録するのは数値ではなく手続き（当てはめる腕・変数・区間の式）で、新しい腕の E は当てはめに使わない。
5. **resp_ee の 26 腕は再走する**（再利用ではなく再現）。軌跡の $n_{\rm eff}$ が要るため。各腕の状態 sha256 が resp_ee の記録と一致するかを走行中に記録する（報告。S0 で seed 0・1 の 7 腕を登録前に確認済み）。

## 2. 設計

### 2.1 箱（resp_ee_0917 と同一）

Random Label MNIST（seed ごとに 1200 枚固定・画素/255・毎タスク独立一様な 10 クラスラベル）、784–100–100–10、両隠れ層 ELU(α=1)（`elu_growth_0909.ELU`・expm1 実装）、出力線形、宿主の初期化。Adam lr 1e−3・β (0.9, 0.999)・ε 1e−8、正則化なし。batch 16、80 epoch × 75 更新 = 6000 更新/タスク、各 epoch で標本順を引き直す。seed 0–9。CPU・1 スレッド・`torch.set_flush_denormal(True)`。

### 2.2 接頭部と分岐点（resp_ee_0917 のまま）

1 プロセス 1 seed。`RE.run_prefix` で task 22 まで回し、task 2・5・7・10・15・20 の終端の状態（パラメータ・Adam の m, v, t・ラベルと標本順の乱数生成器・1200 枚の $z_1,z_2$）を保存する。各腕は一つの分岐点から、接頭部と同じ乱数の続きで新しい 2 タスクを学ぶ。

### 2.3 動く場

resp_ee の固定補正つきの前向き

$$
a_i(x)=\phi\big(z^0_i(x)\big)+\Big[\phi\big(z_i(x)+d_i(x,s)\big)-\phi\big(z^0_i(x)+d_i(x,s)\big)\Big]
$$

の $d$ を、更新 $s$ ごとに書き換える（前向きの式は `RE.make_forward` のまま。場のテンソルを各更新の直前にその場で上書きする）。

- **dyn**: $d_i(x,s)=\mathrm{fl}_{32}\big(z_{2,i}^{(\rm shadow)}(x,s)-z_{2,i}^{(\rm br)}(x)\big)$（引き算は float64）。影（shadow）は移植元の分岐状態の**自然な継続 N⟨src⟩ そのもの**（パラメータ・Adam の moment・ラベルと標本順の乱数を移植元から複製）で、腕の更新 1 回ごとに 1 回更新する。$z^{(\rm shadow)}(x,s)$ は影が $s$ 回更新された後の 1200 枚の前活性で、分岐点の場を保存したのと同じ演算で計算する。
  - $s=0$ で影は移植元の状態そのものなので、$d(0)$ は resp_ee の固定した場と bit 一致する（走行中に `field0_equal_fixed` を記録・検査 S-t0）。
  - 影の状態は各継続タスクの終端で接頭部の task src+k と sha256 が一致する（走行中に `shadow_hash_match_prefix` を記録・検査 S2）。
  - 影を止めると、dyn の腕は固定した場の腕と bit 一致する（検査 S-t0）。
  - 課題の境目では、影も自分の次のラベルを引く（N⟨src⟩ の task src+2）。
- **ramp**: 全ユニット・全画像で $d=-\Delta(g)$、$\Delta(g)=10+20\,g/12000$、$g$ は継続 2 タスク通しの更新番号。$d(0)$ は S2u10r の場と bit 一致。
- **noanchor**: 固定補正なし $a_2=\phi(z_2+d)$、$d$ は resp_ee の固定した場（t2 − t10）。分岐点で前向きの値も t2 の特徴になるので、logit の一致は要求しない。

### 2.5 軌跡の測定

全腕の各継続タスクで、更新 $s=0,750,\dots,6000$ の 9 点（$s<6000$ はその更新の前、6000 は終端）に、1200 枚で腕自身の前向きを回し、第2層について:

- $n_{\rm eff}$: ユニットごとに $(\sum_x g)^2/(N\sum_x g^2)$、$g=\phi'_{\rm train}(z_2+d)$（float32 の expm1+1、全画像で 0 のユニットは 0）、ユニット平均（resp_ee の `neffT_l2` と同じ定義）。
- 0 の割合、訓練の微分の平均、網自身の $z_2$ の平均、場 $d$ の平均、実効引数 $z_2+d$ の平均。

**$\bar n_{\rm eff}$** = 課題 1 の 9 点の $n_{\rm eff}$ の平均。`traj.csv` に全点を書く。

| 変種 | dtype | 活性化 | 第2層の訓練の微分が厳密に 0 になる範囲 | seed | 役割 |
|---|---|---|---|---|---|
| **f64_felu** | float64 | `F.elu`（逆伝播は入力からの exp） | $z<-708$（flush 境界） | 0–9 | **登録** |
| f32_felu | float32 | `F.elu` | $z<-87.3$ | 0–2 | 報告 |

float32 と宿主の ELU の組は接頭部そのもので、bit 一致する（検査 S8）。精度を変えた走は別の軌道なので bit の比較はしない。基準は同じ seed の resp_ee の接頭部（float32・記録済み）。

## 4. 判定

### 4.1 帯の算術

有効 seed の差の平均・SD・**95% 対応差 t 区間**（df = n−1、設計案どおり 95%）。符号: 下端 > 0 なら +、上端 < 0 なら −、他は 0。SD = 0 なら区間を作らず同一差。t 分位点は resp_ee の実装（公表表と 1e−6 で照合・S6）。E は継続 1 タスク目の online 正解率（resp_ee と同じ）。

### 4.2 適用条件

- **(A) 完全性**: seed が有効 ⇔ 登録 commit が一致・flush 有効・80 epoch、接頭部 22 タスクが有限、32 腕 × 2 タスクが揃って有限、R2_10_noanchor 以外の全腕で分岐点の logit が自然な網と一致（1200 枚と最初のミニバッチ）、自然腕 6 本が接頭部と状態 sha256 で一致、dyn の 4 腕で影が両タスクとも接頭部と一致、dyn と ramp の 5 腕で `field0_equal_fixed`。**有効 seed が 8 未満なら INAPPLICABLE。** resp_ee の記録との一致は条件にしない（報告。同じプロセスの中の比較で判定するため）。
- **(B) 前提が再現する**: 次の 3 つの 95% 区間の下端がすべて > 0: 自然な差 N2 − N10、固定した場の沈降 N2r − S2_10r、床が固定場より下 S2_10r − S2u30r。満たさなければ **NOT_REPRODUCED**。
- **(C) 場が動いた**: 全有効 seed で、S2dyn_10r の場の平均が課題 1 の終端で開始より低い（影が沈んだ）。満たさなければ **FIELD_STATIC**。

### 4.3 主ラベル

- **M**（動きの寄与）= E(S2_10r) − E(S2dyn_10r)
- **R**（応答の床からの残り）= E(S2dyn_10r) − E(S2u30r)

| M | R | ラベル |
|---|---|---|
| − | 任意 | **MOVEMENT_HELPS** |
| 0 | + | **STATIC_ONLY** |
| 0 | 0 か − | UNRESOLVED |
| + | + | **PARTIAL** |
| + | 0 か − | **FULL_MEDIATION** |

**設計案の字義の規則（報告）**: A = E(S2dyn_10r) − E(N10r) で、M が + のとき A が 0 → FULL_MEDIATION、+ → PARTIAL、− → BEYOND_NATURAL（M が 0・− のときは上の表と同じ）。

媒介率（報告）: $\rho_{\rm dyn}=\overline{(N2r-S2dyn\_10r)}/\overline{(N2r-N10r)}$、固定場の $\rho_2$、応答の床に対する $\rho^*=\overline{(N2r-S2dyn\_10r)}/\overline{(N2r-S2u30r)}$。

### 4.4 副判定（復元の超過）

超過 R2_10 − N2 の区間の下端 ≤ 0 なら **NO_EXCESS**。超過があるとき X = E(R2dyn_10) − E(N2) の符号で、0 → **EXCESS_IS_STATIC**、+ → **EXCESS_REMAINS**、− → **EXCESS_REVERSED**。

### 4.5 機能的応答の予測（手続きの登録）

- 当てはめ: resp_ee の 26 腕から S1u20r（第1層の操作。第2層の $n_{\rm eff}$ はそれを記述しない）を除いた 25 腕の seed 平均。$y$ = E、$x=\log_{10}\max(\bar n_{\rm eff},1/1200)$（下限は 1 画像ぶん＝定義の分解能）。最小二乗の直線。
- 予測区間: $\hat y(x_0)\pm t_{0.975,\,n-2}\,s\sqrt{1+1/n+(x_0-\bar x)^2/S_{xx}}$。
- **登録ラベル**: S2dyn_10r の seed 平均 E がその $\bar n_{\rm eff}$ での区間に入れば **NEFF_PREDICTS**、入らなければ **NEFF_MISSES**。
- 報告: 他の新腕 5 本の当否、当てはめの R²、25 腕の 1 つ抜きの被覆率、開始時の $n_{\rm eff}$ で同じことをした結果。

### 4.6 併走のラベル（f64_felu・登録）

seed ごとに、同じ seed の float32 接頭部 $E^{32}_t$ から中点を作る: $m=(E^{32}_3+E^{32}_{11})/2$（N2 と N10 の E の中点）、$m_{\rm late}=(E^{32}_3+\overline{E^{32}_{18..22}})/2$。

- $D_E=E^{64}_{11}-m$、$D_{\rm late}=\overline{E^{64}_{18..22}}-m_{\rm late}$。95% 対応 t 区間。
- $D_E$ と $D_{\rm late}$ の上端がともに < 0 → **REPRODUCED**。$D_{\rm late}$ だけ < 0 → **DELAYED**。$D_{\rm late}$ の下端 > 0 → **NOT_REPRODUCED**。他は UNRESOLVED。有効 seed（dtype が float64・22 タスク・有限・flush・登録 commit）が 8 未満なら INAPPLICABLE。
- 報告: 半減の時刻（$E_t<m$ となる最初の $t\ge3$）、$\bar z_2$、0 の割合、$2^{-24}$ 未満の割合、正の微分の log10 中央値、W2 の ε 域。f32_felu・f64_host は同じ量を報告のみ。

### 4.7 読み方（登録）

- **FULL_MEDIATION** → この箱で、応答の低下（失った状態 ＋ 失い続けること）が、応答の操作で届く分の学習能力の喪失をすべて運ぶ。残りの 0.04 は前向きの値（崩壊した特徴）の分。V10 §1.4 に「応答低下 → LoP（輸送が続く限り）」を 1 箱で書ける。
- **PARTIAL** → 継続する輸送が残りの一部を運ぶ。残りは第2層の場の外（W₁・W₂・W₃・特徴）か、影が再現しない押しの形。
- **STATIC_ONLY** → 場を動かしても固定した場と同じ。残り半分は第2層の場の外にあり、V10 §1.4 は「半分」で確定。
- **MOVEMENT_HELPS** → 動く場が学習を助ける。読みの前提（継続する輸送が害）が逆。
- 副判定: EXCESS_IS_STATIC なら resp_ee の復元の超過は場が止まっていたため。EXCESS_REMAINS なら場の静止では説明されず、固定補正（前向きの値が定数から始まること）が候補に残る（R2_10_noanchor を報告で並べる）。
- NEFF_PREDICTS なら「機能的な応答 = 課題中に訓練の微分を運んだ実効画像数」がこの箱で 1 回予測に耐えた。NEFF_MISSES なら $\bar n_{\rm eff}$ は動く場の効果を運ばない。
- 併走 REPRODUCED なら、この箱の ELU の崩壊と学べなさは float32 の厳密な 0 の産物ではない（小さいが 0 でない微分でも学べない）。NOT_REPRODUCED なら、この箱の ELU 崩壊の解釈（resp_ee 以前を含む）を見直す。
- どれも「この ELU→ELU・乱数ラベル・6000 更新・固定 1200 枚・固定補正を持つ人工的な関数変更」に限る。影が運ぶのは自然な網の第2層の前活性の動きで、上流（W の成長）への介入ではない。

## 7. 費用と実行

- 1 seed = 接頭部 132,000 更新 ＋ 32 腕 × 12,000 更新（dyn の 4 腕は影の更新と 1200 枚の前向きが毎更新に加わり約 4 倍）。短いタスクの煙試験で dyn の腕は 4.1 ms/更新。見積もり 1 seed 10–15 分（S-cost で記録）。併走は 1 run 約 2 分（float64・健康な区間の実測 4.2 s/タスク）。
- **ローカル（white-san）で走らせる。GCP は使わない。** S0 の bit 一致は resp_ee を作ったこのマシンでしか成り立たない。走が小さい。
- `launch.sh`: 本走 10 本と併走 16 本を 1 列に並べ、起動のたびに flock で直列化し、空きメモリ（デスクトップに 6 GiB 残す、1 本 1.2 × S-cost の peak RSS）で 1 本ずつ起動を判定して 25 秒待つ。並列の上限 4（共有機。別セッションの GPU ジョブが 5 本走っている）。`provenance.json` のあるジョブは飛ばす。`STOP` ファイルがあれば新しい起動をしない。
- 起動は、本 spec の登録 commit を両 runner の `PREREG_COMMIT` に書き込み、全検査を再実行して all_pass になってから。
