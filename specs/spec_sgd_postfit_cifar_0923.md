## 0. 問い

LR_iid（leaky 0.1、std、Adam 1e−3、seed 0–9、R=10、50 課題 × 30,000 更新）で分かっていること:

- ‖W1‖² は 50 課題で 76k。局面別の帳簿では、正味の伸びは全部が収束後に出る（t26–50 の 1 課題あたり: 衝撃 −1,104、当てはめ −98、hit999→+500 は +89、残りは +2,502）。
- 覚える速さ（hit999 の t41–50 平均の seed 中央値）は 4,015 更新。t1–5 では 2,050 だった。
- 停止チェーン LR_iid_stop（各課題を hit999+500 で打ち切る、seed 0–4、R=1 eager）: N(50) は 21k、hit999 の t41–50 は 2,100 で、遅れはない。

停止チェーンには交絡が 2 つある。
1. 収束後の更新を丸ごと削っているので、「収束後に何をしても害になる」のか「Adam の収束後の動きが害になる」のかを分けられない。
2. 次の課題に持ち込む Adam の状態 (m, v) も違う（停止: hit999+500 時点、全長: 収束後に減衰した v）。

**問い**:
- 収束後の区間だけ plain SGD に替えたら、W の伸びと学習の遅れは消えるか（方策の比較）。
- 消えるなら、それは SGD が CE をあまり下げないからか、それとも同じだけ CE を下げても Adam だけが害を生むのか（CE の減りを揃えた Adam の腕で見る）。
- Adam の害は、持ち越す最適化状態と漂流した重みのどちらで運ばれるか（課題末に状態を戻す腕 AR と、1 課題の 2×2 交差 fork で見る）。

## 1. 設計

エンジンは親の `run()` に既定 off の `postfit` を足しただけ。
- 設定は altlabels の LR_iid と同じ: LR、std、seed 0–9、R=10、iid ラベル（課題ごとに `rlc_labels` から draw）、50 課題 × 30,000 更新（400 epoch × 75）、batch 16、Adam lr 1e−3（β 0.9/0.999、ε 1e−8）、CUDA graph、100 更新ごとの trace、keep_ckpts、課題末スナップショット。
- `postfit` を付けた走は trace に列 **ce_st** を 1 つ足す。ce_st = 画像平均の log1p(Σ_{k≠y} exp(z_k − z_y))。float32 の logits から float64 で計算するので打ち消しがなく、float32 の CE が厳密に 0 になる床でも 0 にならない。
  - quiet_drift で見たとおり、float32 の CE は 1 − p_y < 6e−8 で 0 になり、深い収束後では訓練勾配も真の勾配から外れる。この走の e-fold は全部 ce_st で数える。

**切替点**: スロットごとに hit999（更新 100 以降の trace eval で最初に 1,200 枚中 1,199 枚以上が正解になった更新）を取り、s_sw = hit999 + 500 とする。s_sw > 30,000 ならその課題では切り替えない。更新 1..s_sw はどの腕でも Adam。更新 s_sw+1..30,000 を「収束後の区間」と呼ぶ。

| 腕 | 収束後の区間の更新 | 区間中の Adam の m, v | 次の課題に持ち込む m, v |
|---|---|---|---|
| **A** | Adam（変更なし） | 更新する | 減衰した状態（= LR_iid） |
| **AR** | Adam（変更なし） | 更新する | **課題末に s_sw 直後の値へ戻す** |
| **F** | なし（重みを凍結） | 凍結 | s_sw 直後の値 |
| **S_lo, S_hi** | plain SGD: p ← p − η g（同じミニバッチ勾配、6 テンソル全部、モーメンタムなし、WD なし） | 凍結 | s_sw 直後の値 |
| **A_ce**（第 2 段） | Adam。ce_st が ce_st(s_sw)·e^{−X} 以下になった最初の eval から凍結（F と同じ扱い）。届かなければ課題末まで Adam | 凍結点まで更新 | 凍結点の値 |

- A_ce の X は S_hi の本走から決める。S_hi の seed ごとの t26–50 の e-fold 中央値を取り、さらに seed で中央値にしたもの。S_hi の本走が終わってから回す（第 2 段）。
- バイアス補正の時計 tc は run ごとに 1 つのスカラー（lockstep）で、どの腕でも全更新で数える。AR は「m, v は巻き戻すが時計は巻き戻さない」介入になる。
  - float32 では 1/(1−0.999^tc) が tc ≥ 16,628 で、1−0.999^tc が tc ≥ 17,321 でちょうど 1 になる。課題 2 の開始時には tc > 30,000 なので、課題 2 以降の補正は 1。
- 全腕が 30,000 更新を回すので、ラベルとミニバッチ順は全課題で全腕同じになる。seed は腕をまたいで対になる。
- **F は停止チェーンと同一ではない**。F は乱数を 30,000 更新分消費し、R=10・graph で計算する。停止チェーンは R=1・eager。F と停止チェーンの比較（Q6）は、過去の参照との記述的な差にとどめる。

**読み方（長い連鎖では方策の総効果）**: 課題 2 以降は、どの腕も当てはめの軌道・hit999・切替時の重みと状態まで変わる。したがって A − AR は「状態を戻す方策の総効果」、AR − F と S − F は「その収束後の更新方策の総効果」であって、状態と重みの純粋な媒介分解ではない。媒介は §2b の交差 fork で見る。

## 2. η の決め方（試走、登録の前）

- 格子は η ∈ {0.001, 0.003, 0.01, 0.03, 0.1, 0.3, 1}。上端の 1 は、試運転で 10 seed とも切替の約 9 更新後に NaN になった（`_checks/_v1_engine/C_sgd1`）。
- 試走は各 η で S 連鎖の課題 1–2 を回す（R=10、seed 0–9、本走の最初の 2 課題と同じ計算）。
- **安定(η)**: 2 課題とも全スロットで次の 6 条件を満たすこと。
  1. 損失が全部有限。
  2. 切替が起きた。
  3. s_sw より後の全 eval で正解数 ≥ 1,188。
  4. s_sw より後の全 eval で ce_st ≤ 2·ce_st(s_sw)。
  5. 更新 30,000 の正解数 ≥ 1,199。
  6. ce_st(30,000) < ce_st(s_sw)。
- **η_hi = 自分とそれ以下の格子点が全部安定な、最大の格子点**（課題 1–2 だけで判定）。
- **η_lo = 課題 1–2 に加えて課題 49 の脚でも（自分とそれ以下が全部）安定な、最大の格子点。それが η_hi 以上なら η_lo = η_hi / 10。**（v2.1、試走の結果を見る前に変更。理由: F や停止チェーンでも ‖W1‖² は 50 課題で約 700 → 21k に伸び、曲率も上がる。課題 1–2 で選んだ η は後半の課題で発散しうる。η_hi は「強い SGD」、η_lo は「Adam で膨らんだ網でも安定な SGD」として両方回す。）
- 分岐:
  - 安定な η が 1 つも無い: S 腕は回さず、A・AR・F と交差 fork だけにする。
  - 最上端 1 まで安定: 「検査範囲の最大」と書く（試運転の結果から、起きない見込み）。
- 課題 49 の脚: LR_iid の `ckpts/t48.pt` から課題 49 を各 η で 1 回（Adam で膨らんだ網、‖W1‖² ≈ 76k での安定性）。η_lo の選定にだけ使う（v2.1）。
- 試走が見るのは課題 1–2 だけで、エンドポイントは t41–50 と t50。ただし η は同じ seed 系列で選ぶので、S 腕は独立な確認実験ではない。この点は結果に明記する。

**試走の結果と v2.2 の追加**（`results/sgd_postfit_cifar_0923/pilot.json`）:
- 規則どおり **η_hi = 0.03**（課題 1–2 で安定。0.1 は課題 2 で 2 seed が発散）、**η_lo = 0.001**（課題 49 の脚で安定なのは 0.001 だけ。0.003 は正解数 470–690 まで落ち、0.01 以上は発散）。
- 収束後の CE の減り（ce_st の e-fold、課題 1 の中央値）: 0.001 で 0.6、0.003 で 1.2、0.01 で 2.2、0.03 で 3.3、0.1 で 4.6。Adam（LR_iid）は区間内の最小まで 12.9（課題末は暴発で戻って 3.3）。
- 収束後の Δ‖W1‖²（課題 1 の中央値）: SGD は全 η で +0.8〜+7.5、Adam は +635（課題 49 では +2,928）。
- 安定の上限は重みの大きさとともに下がる（課題 1–2 では 0.03、‖W1‖² ≈ 76k の課題 49 では 0.001）。F でも ‖W1‖² は 50 課題で約 30 倍に伸びるので、**S_hi は連鎖の途中で発散する見込みが高い**。S_lo は安定だが弱い（課題 1 で 0.6 e-fold）。
- **追加腕 S_mid = 0.003**（格子上で η_lo と η_hi の間）。課題 1–2 で安定（1.2 e-fold）で、課題 49 の脚では落ち込むが発散しない。連鎖の網は課題 49 の脚ほど膨らまないので、強くて安定な SGD の候補。判定は Q2b（Q1 と同じ規則）。
- **Q7 の参照腕**: X は S_hi から取る。ただし S_hi が 50 課題を生き残った seed が 8 本未満なら、S_mid から取る（S_mid も 8 本未満なら S_lo）。Q7 は A_ce をその参照腕と比べる。
- **発散の読み**: Q1 は登録どおり失敗込みで判定する。S_hi が発散で NO_RESCUE になった場合、それは「SGD が発散した」ことであって「収束後の CE の最小化が学習を遅くした」ことではない。結果ではそう書き分け、生存者だけの値（副）と Q2・Q2b を並べる。

## 2b. 交差 fork（機序用、副）

LR_iid の課題 t ∈ {10, 20, 30, 40, 48} ごとに次を行う。
1. `ckpts/t<t−1>.pt` から課題 t を freeze モードでもう一度回す。この終わりの checkpoint が、LR_iid 自身の s_sw 直後の (W, m, v) になる（s_sw までは LR_iid と bit 一致: C3）。乱数の流れと tc は LR_iid の `ckpts/t<t>.pt` と同じになる（assert する）。
2. 重み {s_sw, 課題末} × (m, v) {s_sw, 課題末} の 4 つの checkpoint を作る。それ以外は全部 `ckpts/t<t>.pt` から取る。
3. 各 checkpoint から課題 t+1 を Adam のまま（フックなし）、R=10、停止則 0.999,500 で回し、hit999 を取る。

(課題末, 課題末) のセルは LR_iid の課題 t+1 そのものになる（C9）。単位は (t, seed) の 50 組。
- **状態の効果**: hit(W, 課題末の状態) − hit(W, s_sw の状態)。W を s_sw と課題末のそれぞれに固定して取る。
- **重みの効果**: hit(課題末の W, S) − hit(s_sw の W, S)。状態 S を s_sw と課題末のそれぞれに固定して取る。

1 課題ぶんの収束後の漂流は、連鎖の累積した害の約 1/48 しか運ばないかもしれない。したがって重みの効果の検出力は低く、状態の効果（切替の衝撃は毎課題の即時効果）のほうが見えやすい。

## 3. 測るもの

- 各 (腕, seed, 課題) の hit999。**上限付き到達時間 min(hit999, 30,000)**（−1 → 30,000）を推定対象とし、未到達の数を併記する。
- 感度分析として hit99 と hit_full（1,200/1,200 に最初に届いた eval）も取る。
- 各課題の更新 0・200・hit999・s_sw・30,000 での n1, n2, n3。ここから局面別の帳簿を作る。
  - 衝撃 0–200、当てはめ 200–hit999、保持 hit999–s_sw、収束後 s_sw–30,000。
  - hit999 < 200 のときは、衝撃を 0–hit999 とし、当てはめを空にする。
- 切替時の正解数と ce_st、収束後の ce_st の e-fold 数、実際の収束後更新数 30,000 − s_sw、切替未実施の数。
- 収束後の変位 ‖W_l(30,000) − W_l(s_sw)‖²（per_task の行）。
- 暴発: s_sw より後の trace eval（100 更新ごと）で観測した最小正解数。既存の `min_correct_after_hit` は hit999 以後の窓なので使わない。
- W と次の課題の速さの対応: n1 の課題開始時の値 N_{t−1} と hit_t を、全腕を重ねて図にする（記述）。
- 副・記述: 課題末スナップショットの W1 から帯別帳簿（top/mid1/mid2/low、altlabels の band_ledger と同じ基底）。

## 4. エンドポイントと判定

**E1 学習の遅れ**
- H = seed ごとの t41–50 の上限付き hit999 の平均。腕の値 Ĥ は seed の中央値。
- 除去率 ρ_X = (Ĥ_A − Ĥ_X) / (Ĥ_A − Ĥ_F)。
  - 主統計量は中央値の比。副に、seed 別比 ρ_s = (H_A,s − H_X,s) / (H_A,s − H_F,s) の中央値と、各区間に入る seed の本数を出す。
  - ρ は切り詰めない（< 0 も > 1 も報告する）。
- 副: seed ごとの H − H_early（H_early は t1–5 の平均）。

**E2 W の伸び**
- G = 課題 50 の更新 30,000 での n1。ρ^W は E1 と同じ形。

**失敗の扱い（主）**: 発散した slot は、以後の課題を全部 hit 30,000、G = +∞ として中央値に入れる（失敗込み）。生存者だけの値は副として出す。発散した seed 数は主結果に含める。

**参照差**: D = Ĥ_A − Ĥ_F < 600 なら REF_GAP_SMALL。W 側は Ĝ_A − Ĝ_F < 10,000 なら REF_GAP_SMALL。

**区間推定**: seed を単位に、全腕を一緒に（対のまま）10,000 回再標本化して中央値と比を計算し直し、90% 区間を併記する。分母が 0 近くになる再標本は比が不定なので、その割合も出す。

**判定**（0.25 と 0.75 は実用上の分類の境界として登録する）

| 問い | 対象 | ρ ≥ 0.75 | 中間 | ρ ≤ 0.25 |
|---|---|---|---|---|
| Q1（主） | S_hi（E1） | SGD_RESCUE | PARTIAL | NO_RESCUE |
| Q2 | S_lo（E1） | SGD_RESCUE | PARTIAL | NO_RESCUE |
| Q2b | S_mid（E1、v2.2） | SGD_RESCUE | PARTIAL | NO_RESCUE |
| Q3 | S_hi（E2） | SGD_RESCUE_W | PARTIAL_W | NO_RESCUE_W |
| Q4 | AR（E1、状態を戻す方策の総効果） | RESET_RESCUE | PARTIAL | NO_RESCUE |
| Q5 | AR（E2） | RESET_RESCUE_W | PARTIAL_W | NO_RESCUE_W |

- **Q6（記述）**: seed 0–4 の Ĥ_F と停止チェーンの 2,100 の差。
- **Q7（機序）**: CE の減りを揃えたとき（A_ce 対 S_hi）。(ρ_S_hi, ρ_Ace) の組で判定する。

  | 条件 | 判定 | 読み |
  |---|---|---|
  | 両方 ≥ 0.75 | MATCHED_CE_HARMLESS | SGD が届く程度の CE の減りなら Adam も無害。害は SGD が届かない深い収束後にある |
  | 両方 ≤ 0.25 | MATCHED_CE_HARMFUL | その大きさの CE の減りは、どちらの最適化法でも害 |
  | ρ_S_hi − ρ_Ace ≥ 0.5 | ADAM_WORSE_AT_MATCHED_CE | 同じ CE の減りでも Adam のほうが害 |
  | ρ_Ace − ρ_S_hi ≥ 0.5 | SGD_WORSE_AT_MATCHED_CE | 同じ CE の減りでも SGD のほうが害 |
  | それ以外 | MIXED | |

  - 揃い具合を併記する: A_ce の達成 e-fold の中央値、凍結点に届いた課題の割合。届かない課題が 2 割を超えたら「揃えは不十分」と明記する。
- **Q8（副、交差 fork）**: 状態の効果と重みの効果（§2b）の平均と中央値、(t, seed) で対をとった seed 再標本化の 90% 区間を出す。区間が 0 を含まなければ「あり」とする。

**閾値の算術**:
- LR_iid の seed 間の H の SD は約 350。10 seed の中央値の SE は約 1.25 · 350 / √10 ≈ 140。独立なら 2 腕の差の SE は約 196 で、600 は約 3 SE。
- ρ の SE は共通の A と、ばらつく分母を含むので一律には置けない。区間は再標本化で出す。
- Codex の算術では、H で ρ ≥ 0.75 は H_X ≤ 2,579、ρ ≤ 0.25 は H_X ≥ 3,536 に当たる（A 4,015・F 2,100 を仮定した場合）。

## 5. 検査（判定を読む前に）

| 検査 | 内容 |
|---|---|
| C1 | フックなし（postfit=None）の経路は、LR_iid の課題 1–2 の trace 行（7 列）とスナップショットに bit 一致する |
| C2 | A（mode adam）は LR_iid に 50 課題全部で bit 一致する（trace 行と per_task の共通列） |
| C3 | F・S・A_ce の課題 1 は、slot ごとに固定点（s_sw、A_ce は凍結点）以下の行が LR_iid と一致し、それより後は一致しない（変異対照）。AR は課題 1 全体が一致する |
| C4 | 課題 × slot ごとの旗。F と A_ce は重み・m・v が凍結点の写しと完全一致し、n1..n3 が凍結点から一定で、凍結点の前に n1 が動く（課題頭で mask が解除された証拠）。S は m, v が写しと一致し、重みは動く。AR は戻した後の m, v が写しと一致し、戻す前は違う。A は重みも m, v も写しと違う（変異対照） |
| C5 | 試走の課題 1–2（η_hi, η_lo）は本走 S 腕の課題 1–2 と一致する |
| C6 | 課題末 checkpoint から再開した課題 2 は、連続実行の課題 2 と一致する（freeze・sgd・adam_restore） |
