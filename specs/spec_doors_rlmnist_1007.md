## 0. 一行と問い

この箱の崩壊は、第 2 層の平均前活性 $\bar z_2=q_2\|\mu_2\|+b_2$ が訓練の微分の零点 $\ln 2^{-24}=-16.64$ の下へ運ばれることで起きる。運び手は $\|\mu_2\|$（第 2 層が受け取る入力の、1200 枚の上の平均）の伸びである（l2_wall_0916 の帳簿で 7 割が上流、mucap_ee_0917、l2cap_ee_0917）。中心化はこの運び手を構造として消す。

- **扉 H（主）**: 両隠れ層の出力から、ユニットごとの走行平均 $m_l$ を引く（$a_l=\varphi(z_l)-m_l$）。第 2 層の入力の平均は ≈ 0 になり、$\bar z_2\approx b_2$ ＋ EMA の遅れの分しか残らない。
- **扉 C**: 入力から seed の 1200 枚の平均画像を引く（割らない）。第 1 層は $\bar z_1=b_1$ になる（$\mu_1$ の経路が閉じる）。しかし ELU は非対称なので、$\varphi(z_1)$ の平均（$=\mu_2$）は第 1 層の幅とともに伸びうる。
- **CH**: 両方。

問い:

- **Q1（主）**: 扉 H は ELU→ELU の崩壊を防ぐか（H − ref、97.5%）。
- **Q2**: 扉 C だけではどうか。両方（CH）ではどうか（各 95%）。
- **Q3（梯子 N）**: C → H → CH の順で、最初に `RESCUED` になる腕はどれか。
- **Q4（機構・報告のみ）**: 扉の下で $\bar z_2$ はどの項で動いたか（$b_2$ が残りの経路になるか）。$\|\mu_2\|$・$\|w_2\|$・$\cos(w_2,e_2)$・$m_l$ の推移。

### 1.2 扉が塞ぐもの（算術）

- **扉 H**: 第 2 層の入力は $a_1-m_1$ なので、1200 枚の上で $\bar z_2=W_2(\mu_2^{\rm raw}-m_1)+b_2$ になる（$\mu_2^{\rm raw}$ は中心化前の $\varphi(z_1)$ の平均）。$m_1$ は $\varphi(z_1)$ のバッチ平均の EMA（β = 0.01、時定数 100 更新）なので、課題の中で重みが落ち着けば $\mu_2^{\rm raw}-m_1$ は EMA の雑音と遅れだけになる。**ref で $\bar z_2$ を運んだ $q_2\|\mu_2\|$ の項は、自己の $W_2$ の揃いも上流の $\|\mu_2\|$ の伸びも、両方ほぼ消える。残る経路は $b_2$ と遅れである。** Adam が $b_2$ を動かせるのは 1 更新あたりおよそ lr = $10^{-3}$ までなので、符号が揃い続けても 1 課題で最大 6。cap12 の下での主窓の $\Delta b_2$ は、ref との差で −0.98 にとどまった（l2cap_ee_0917 の輸送）。
- **扉 C**: 入力の平均が 0 なので $\bar z_1=b_1$（重みの項が消える）。しかし $\varphi(z_1)$ の平均は $z_1$ の広がりで正に偏る。$z\sim N(0,\sigma^2)$ なら $E[\mathrm{ELU}(z)]=\sigma/\sqrt{2\pi}+e^{\sigma^2/2}\Phi(-\sigma)-1/2\approx0.40\sigma-0.5$（$\sigma\gg1$）。$\sigma_1$ が ref と同じく 5–8 まで伸びれば、ユニットあたり 1.5–2.7、$\|\mu_2\|$ は 20 前後になる。これは ref の t5 の水準で、そこで $\bar z_2$ はすでに −8.3 だった。mucap_ee_0917 の cap_par（第 1 層の平均画像方向の成分に上限）は $\|\mu_2\|$ を t100 で 58.9 に抑えたが、崩れた。
- **CH**: 両方の経路を塞ぐ。扉 H が $\mu_2$ を消すので、扉 C の下で $b_1$ が作る常時点灯のユニット（mucap_ee_0917 の cap_both で $b_1$ が +4〜+6 に育った経路）も第 2 層には届かない。

### 2.1 箱（l2cap_ee_0917 の ref と同一）

- 最適化: Adam lr 1e−3・β (0.9, 0.999)・ε 1e−8、moment は課題をまたいで保持。batch 16、6000 更新/課題（80 epoch × 75）。
- 規模と実行環境: **100 課題**、seed 0–9、CPU 1 スレッド、`torch.set_flush_denormal(True)`、第 1 層の帳簿 off。
- 乱数: init・subset・ラベル・標本順は宿主の流れ（`pmnist_0905.stream`）。

宿主の `src/mucap_el_run_0916.py` の `run_one(arm="ref", act2_name="ELU1", w2cap=False, bias_fix=False, ledger=False)` の更新ループを、新しいファイル `src/doors_rlmnist_1007.py` に書き出して扉を足す。`resp_ee_0917` と同じやり方である。既存の `src/*.py` は改変しない。**扉を両方とも切った経路（ref 腕）は、l2cap の記録 shard と bit 一致しなければならない**（S0）。

### 2.2 扉（relu_doors_0919 と cifar5p1_mlp_0920 の ReLUDoors を ELU に移す）

| 扉 | 定義 |
|---|---|
| **C** | $x\leftarrow x-\bar x$。$\bar x$ はその seed の固定 1200 枚の float32 平均で、式は `x - x.mean(0)`（relu_doors の `slot_inputs(center=True)` と同じ）。**割らない**。走る前に一度だけ計算し、学習の全バッチ・memo・診断（units.npz）に同じ $x$ を使う。test 画像（TEST_TASKS の診断）には**同じ $\bar x$** を引く。 |
| **H** | 両隠れ層で $a_l=\varphi(z_l)-m_l$。$m_l\in\mathbb R^{100}$ はユニットごとの EMA。初期値は 0（task 1 の最初の順伝播の前）で、課題の境界でリセットしない。各 Adam 更新の直後に $m_l\leftarrow(1-\beta)m_l+\beta\,\mathrm{mean}_{\rm batch}\varphi(z_l)$、**β = 0.01**。$z_l$ はその更新の勾配を出した順伝播の前活性（更新前の重み、$z_2$ は中心化した $a_1$ から）。**EMA は中心化前の $\varphi(z_l)$ を追う**（中心化後を追うと退化する）。$m$ は定数で、勾配を通さず、Adam の対象でもない。online・memo・診断は、すべてその時点の $m$ を使う（訓練と評価で同じ値）。ゲート（訓練の微分 $\varphi'(z_l)$）は変えない。$m$ は定数のずれなので $\partial a_l/\partial z_l=\varphi'(z_l)$ で、ELU の訓練の微分は float32 で $z<-16.64$ のとき厳密に 0 のまま。演算は `m.mul_(1-β).add_(φ(z).mean(0), alpha=β)` で、順序は cifar5p1 の `update(z1, z2)` と同じ（Adam の後）。 |

- **扉は task 1 の最初の更新から（網の構造として）入れる。**l2cap の上限のように task 2 から入れることはしない。理由は 2 つある。C を途中で入れると、切替の時点で入力の分布が跳ぶ（$\Delta z_1=-W_1\bar x$）。その衝撃が中心化と交絡する。また、同じ柱の登録 2 つ（relu_doors・cifar5p1）も扉を最初から入れている。**依頼文の検査 S5「4 腕の task 1 が bit 一致」は、この設計では成り立たない。**扉 C の腕は最初の順伝播から、扉 H の腕は 2 回目の順伝播から ref と違う。S5 は §2.4 のとおり置き換えた（§11 の逸脱 1）。
- 診断の平均画像方向 $e_1$（`q_l1` などの第 1 層の成分）は、全腕で**生の**画像の平均方向を使う（宿主と同じ値）。扉 C の腕では入力の平均が 0 なので、$\bar z_1=b_1$ が成り立つ。そこでの `q_l1` は「生の平均画像方向の成分」を記述するだけである。
- 第 2 層の $\mu_2$（`mu2_norm`・`a1mean_l1`）は、**第 2 層が実際に受け取る入力**の平均とする。扉 H の腕では $a_1-m_1$ の平均である。中心化前の $\|\mathrm{mean}\,\varphi(z_1)\|$ は、扉の腕で `mu2_raw_norm` として別に記録する。

## 3. 測る量

l2cap と同じ `per_task.csv`・`units.npz` を出す。診断点は task 2–10 では 0/75/375/1500/3000/6000、それ以外の課題では 0 と終端。test の診断は TEST_TASKS (1, 10, 50, 100) の終端。**ref 腕の列と配列の集合は、l2cap の ref と同じにする（何も足さない）。**扉の腕だけ、次を足す。

- per_task（扉 C の腕）: `c_in_absmax`（その課題の 6000 更新で実際に入力したバッチの float64 平均の、画素ごとの絶対値の最大）、`c_in_ratio`（画素ごとの |平均| / $B_j$ の最大。$B_j>0$ の画素で取る）、`c_ok`（全画素で |平均| ≤ $B_j$ なら 1）。
- per_task（扉 H の腕）: `h_upd_l1`・`h_upd_l2`（その課題の更新のうち、$m_l$ を bit で変え、かつ更新後の $m_l$ が非零だったものの数）、`m_l1_mean`・`m_l2_mean`・`m_l1_norm`・`m_l2_norm`（課題終端）。
- units.npz（扉の腕）: 各診断点の `mu2_raw_norm`（中心化前の $\|\mathrm{mean}\,\varphi(z_1)\|$）と `a2mean_l2`（読み出しが受け取る入力の平均、100 次元）。扉 H の腕は、さらに `m_l1`・`m_l2`（100 次元）。

**丸めの上界 $B_j$（扉 C、画素 j ごと）の導出。** $n=1200$、$u=2^{-24}$、$\gamma^{(32)}_k=ku/(1-ku)$、$\gamma^{(64)}_k$ は $u=2^{-53}$ での同じ量とする。誤差は次の 3 段で入る。

1. float32 の平均 $\hat m_j$: 和の順序によらず、和と 1/n の扱いで最大 2 回の丸めが加わっても $|\hat m_j-m_j|\le\gamma^{(32)}_{n+2}\,\overline{|x_{\cdot j}|}$。
2. 引き算: $x^c_{ij}=\mathrm{fl}(x_{ij}-\hat m_j)$ の丸めは $u\,|x_{ij}-\hat m_j|\le \frac{u}{1-u}|x^c_{ij}|$。
3. 評価: 入力したバッチの float64 平均。各課題で各画像はちょうど 80 回入るので、真値は 1200 枚の平均である。$N=96{,}000$ 個の和の誤差は $\gamma^{(64)}_{N+1}\,\overline{|x^c_{\cdot j}|}$ 以下。

以上から

$$B_j=\gamma^{(32)}_{n+2}\,\overline{|x_{\cdot j}|}+\Big(\tfrac{u}{1-u}+\gamma^{(64)}_{N+1}\Big)\overline{|x^c_{\cdot j}|}$$

で、$B_j$ 自体の float64 の丸めを覆うため $(1+8\varepsilon_{64})$ 倍する。常に 0 の画素では $B_j=0$ で、そこの平均は厳密に 0 でなければならない。上界は最悪の場合の値（$\overline{|x|}\le1$ で $\lesssim7.2\times10^{-5}$）である。別の seed の平均を引いた場合の差（中央の画素で $\sim10^{-2}$）とは 2 桁以上離れる。

## 4. endpoint

### 4.1 主 endpoint と床（l2cap_ee_0917 §4.1 と同じ）

**主窓 $W$ = task 51–100**。形成窓 task 2–10・11–50 は副報告とする。

- **E1（機能）**: online 精度の窓内タスク平均 − **その腕自身の** task 1 の online。
- **E2（第 2 層の応答）**: 第 2 層の訓練の微分 `dtrain_mean_l2` を、画像平均 → 全 100 ユニットの算術平均 → 窓内タスク終端の算術平均の順に集約する。その腕自身の task 1 からの変化。
- 腕の効果は seed 内の対応差 $\delta=\Delta_{\rm arm}-\Delta_{\rm ref}$。扉は task 1 から入るので、task 1 の水準は腕ごとに違いうる。δ は「自分の出発点からの低下」の差であり、窓の水準の差ではない。
- **床**: run ごとに、主窓の `major_frac` の平均 $F$ と標本 SD $s$ から $F+3s/\sqrt{50}$ を作る。主窓の online 平均がこれ以下なら AT_FLOOR とする。腕は、全有効 seed で AT_FLOOR なら FLOORED、全 seed で上なら ALIVE、割れたら SPLIT。

### 4.2 副 endpoint（REPORT_ONLY。判定の代用にしない）

1. **崩壊の時刻 $T_{1/2}$**: 適合率 $(A(t)-0.1)/(A(1)-0.1)$ が task 2 以降で初めて 1/2 を下回るタスク（右打切り。$A(1)$ はその腕自身の値）。扉の腕ごとに seed 内で ref と比べる。同じを除いた数で両側の正確な符号検定を行い、p < 0.05 なら EARLIER / LATER、それ以外は NO_TIMING_DIFF とする（報告のみ）。
2. **輸送**: 主窓の第 2 層 $\Delta\bar z_2$ と $\Delta b_2$（task 1 からの変化）の、ref との対応差（95%）。
3. **第 2 層の幾何**: 主窓と形成窓の $\|\mu_2\|$（第 2 層が受け取る入力の平均）、中心化前の $\|\mathrm{mean}\,\varphi(z_1)\|$（扉の腕）、$\|w_2\|$（行ノルムのユニット平均）、$\cos(w_2,e_2)$（`q_l2`/`row_norm_l2` のユニット平均）、`dtrain_zero_l2`、$\bar z_2$、$b_2$。
4. **零点を越える時刻**: 第 2 層のユニット平均 $\bar z_2$ が初めて −16.64 を下回るタスク。
5. **性能**: online・`memo_acc` の窓平均（3 窓）。
6. **扉 H の腕の $m_l$ の推移**: 課題終端の `m_l1_mean`・`m_l2_mean`・`m_l1_norm`・`m_l2_norm` の窓平均と、t1/2/5/10/20/50/100 の値。
7. **交互作用** $\delta_{\rm CH}-\delta_{\rm C}-\delta_{\rm H}$（E1・E2、95%）。
8. **ref の全 100 課題の bit 一致**: 全 10 seed の per_task の全列・units の全配列・最終状態の sha256 を、l2cap の ref と照合する。

## 5. 判定

### 5.1 帯の算術

主 2 endpoint のそれぞれで、有効 seed の δ の平均・SD・対応差の t 区間を出す。水準は主腕 H が 97.5%（2 量の Bonferroni）、C と CH が 95%。H の 95% も参考に出す。SD = 0 なら実測の同一差を使う。符号は、区間の下端 > 0 で +、上端 < 0 で −、それ以外は 0 とする（0 は「示せない」であり、同等の意味ではない）。t 分位点は 0916 の実装（`analysis/mucap_el_0916/verdict.py`）を無改変で import する。

### 5.2 適用条件

- **(A)** 全 seed で 4 腕の init・subset・ラベル・標本順の sha256 が一致し、100 タスクを完走し、online と両層の微分診断が有限であること。有効 seed が 8 未満なら全ラベル INAPPLICABLE。
- **(B)** ref が有効 seed の 8 割以上で主窓 AT_FLOOR、かつ ref の $\Delta E2$ の 95% 区間の上端 < 0。満たさなければ全ラベル NOT_REPRODUCED。
- **(C)** 各扉の腕・各有効 seed の task 1–100 の**全課題**で、扉が働いた記録がある。扉 C は `c_ok` = 1（その課題に入力したバッチの平均が、全画素で丸めの上界 $B_j$ 以内で 0）。扉 H は `h_upd_l1` > 0 かつ `h_upd_l2` > 0。CH は両方。満たさない腕は INAPPLICABLE。

**IMPAIRED**（読みのフラグで、判定を変えない）: 扉の腕の task 2–5 の平均適合率が「ref の値 − (1 − ref の値)」を下回る seed が過半数。l2cap と同じ定義。

### 5.3 ラベル

**主 = H − ref（97.5%）**。C − ref・CH − ref は 95%。H − ref の 95% も参考に出す。

| 腕の床の状態 | $s_{E1}$ | $s_{E2}$ | ラベル |
|---|---|---|---|
| FLOORED | — | — | **COLLAPSED** |
| SPLIT | — | — | **SPLIT** |
| ALIVE | + | + | **RESCUED** |
| ALIVE | + | 0 / − | RESCUED_FUNCTION_ONLY |
| ALIVE | 0 / − | — | ALIVE_UNRESOLVED |

(A)/(C) を満たさなければ INAPPLICABLE、(B) を満たさなければ NOT_REPRODUCED。

### 5.4 梯子 N（relu_doors と同じ型。順序は C → H → CH で固定）

各腕の登録ラベル（C 95%・H 97.5%・CH 95%）について、C が `RESCUED` なら **NEED_C**、そうでなく H が `RESCUED` なら **NEED_H**、そうでなく CH が `RESCUED` なら **NEED_CH**、どれでもなければ **NONE_RESCUED** とする。`RESCUED_FUNCTION_ONLY` は数えない。(A)/(B) が満たされないときは、N もその理由のラベル（INAPPLICABLE / NOT_REPRODUCED）にする。

### 5.5 読み方（登録）

- **H が RESCUED** → 表 5 のセルを「登録」にする。第 2 層の入力の平均を unit ごとに消すだけで、この箱の崩壊は 100 課題起きなかった、と書く。§4.2-2 の輸送（$\Delta\bar z_2$ と $\Delta b_2$）と、IMPAIRED でないことを併記する。E1 の大きさが CH より小さければ、第 1 層の沈み（ELU→leaky の箱で online 0.30 に止まる経路）が残った、と §4.2-3・5 で読む。
- **H が COLLAPSED か SPLIT で、CH が RESCUED** → 第 2 層の中心化だけでは足りず、第 1 層の入力の中心化も要る（N = NEED_CH）。扉 H の下で $\bar z_2$ が何で動いたか（$b_2$ か、EMA の遅れか）を §4.2-2・3 で書く。
- **C が RESCUED** → 入力の中心化だけで足りる（N = NEED_C）。§1.2 の算術（ELU の非対称で $\mu_2$ が伸びる）が外れたことを書く。
- **全部 COLLAPSED** → 中心化はこの箱の崩壊を止めない。$\bar z_2$ の運び手が $\mu_2$ でなかったか、$b_2$ が引き継いだかを §4.2-2 で書く。
- 交互作用は報告のみ。単独の腕が未決（0）であることを「両方必要」とは書かない。
- IMPAIRED の腕では「可塑性を守った」と書かない。
- RESCUED は「この箱の 100 課題で床に落ちなかった」という意味であり、無限時間の非崩壊を意味しない。
- すべて「この ELU→ELU・乱数ラベル MNIST・6000 更新/課題・扉は task 1 から・β = 0.01・100 課題」に限る。
