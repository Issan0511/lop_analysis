## 0. 答え

**崩壊した ELU の層を止めたのは、optimizer に渡った微分が厳密に 0 になったこと（float32 の expm1 の床）で、Adam の ε ではない。** これは autograd の expm1 で微分を作る系統（L1・L3）について言える。手書きの exp で微分を作る系統（L2、L3 の SMINH）には 50 タスクで届く床が無く、ε が効く範囲に入っても凍結しない。

## 1. 系統（`lineage.csv`）と床（`kernels.json`）

| 系統 | 走 | 訓練の微分 | 厳密に 0 |
|---|---|---|---|

- K2: CUDA の autograd の境界は −16.982107（CPU と別の丸め）。
- K4: 勾配 0 のとき、flush なしの float32 の m は 834 更新で **4·2⁻¹⁴⁹** に止まり、0 にならない。v は 500·2⁻¹⁴⁹ に止まる。flush ありなら m は 698 更新、v は 59,677 更新で厳密に 0。

- ELU1 の分類は**登録前に見ていた記述**（spec §1.4）。凍結は、第2層の最後の (ユニット, 画像) が床の下に入った次のタスクに始まる。凍結中の m は K4 の丸め残りそのもの（`adam_ratio`×ε = 4·2⁻¹⁴⁹）で、一歩は約 5.6e−40。v も 0 でない止まった残り（K4 では 500·2⁻¹⁴⁹、最小でも 2⁻¹⁴⁹）なので、ε を外しても一歩は 1e−25 以下で、重みの分解能に届かない（算術）。
- **SMINH（exp で微分を作る双子・同じ VM・同じ Adam・同じ ε）は 3 seed とも t50 まで凍結しない。** 第2層のゲートのユニット中央値は t12–18 から ε を下回り、行ごとの √v̂ < 10ε の割合の中央値が 1.0 になっても止まらない。t50 に $\ln\bar g>-70$ のユニットは 25–28 個。凍結した ELU1 網にも同じ意味で 28–56 個あり、そちらは訓練の微分が厳密に 0 なので動かない。

## 4. D — L2（`l2_variant.csv`）

- **D1 `L2_NO_FLOOR`**: t50 に全画像で exp ゲートが 0（$U_2<-103.97$）のユニットは、none・ε=1e−6 の 12 モデルで 0、ε=1e−30 の ELU→ELU 3 モデルで 1/100、leaky→ELU の ε=1e−30 では 0。L2 の ε 介入は 0 でない勾配に働いていた。どのモデルも t50 で $\bar z_2$ が動いている。

## 5. 報告のみ

- **深さの時系列**（`depth_report.csv`・ユニット平均 $\bar z_2$）: L1 ref（10 seed）は t10/20/30/40/50/100 で −50.9/−107.9/−134.0/−146.1/−151.7/−152.9、L2 none EE（3 seed）は t10〜50 で −43.3/−103.4/−126.4/−145.9/−154.1。t41–50 の 1 タスクあたりの変位は L1 −0.56（凍結済みの seed は 0）、L2 −0.83。**t50 までの平均の深さは両系統でほぼ同じで、違うのは L1 が t32–63 に凍り、L2 が止まらないこと。**
- **ε=1e−30 で 1 タスク通す**（`c2_eps30full.csv`・t10/15/20 × 10 seed）: online の差は −0.004〜+0.009 で、どの状態も床のまま。30 状態のうち 12 状態で 1e−2 を超える一歩（Adam では出ない大きさ）が出た。flush ありの float32 で v が 0 に落ち m が残った座標に、m/1e−30 の一歩が出たものと読む。第2層の全滅ユニットが大きく減った 8 状態（44–89 → 0–23）は、すべてこの 12 状態に含まれる。**人工物として読み、「ε を外すと戻る」とは書かない。**
