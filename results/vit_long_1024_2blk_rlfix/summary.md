# 追補 D の結果：同じ 2,500 枚にラベルを引き直す箱（2026-10-26、seed 10252010）

箱は 2 ブロック ViT（FFN 3072・ReLU）です。全課題で同じ 2,500 枚（seed 10252010 の課題 101 の 10 クラス × 各クラスの 251〜500 番目）を使い、課題ごとに乱数ラベル 10 値を引き直します。1 課題 5,000 更新、100 課題、Adam 1e−4、拡張なし、dropout 0 です。設計は spec の追補 D（D.6 で seed を変更、D.7 で機械の分け方を記録）にあります。生データは `~/Projects/obsidian-research-data/vit_long_1024_2blk_rlfix/` です。1 seed なので判定は登録していません（記述）。

SL と R0L は Vast.ai の 2 台、S・R0・新品は white-san で回しました。借りた 2 台どうしは同じ通し走でビットが一致し、white-san とは 33 更新目から丸めの差が出ます。SL と R0L は互いに同じ計算の環境、S と R0 も互いに同じ環境です。

## 2. 分かったこと

1. **LN ありでも、head を共有すると喪失が出ます。** SL は課題 50 まで新品より速く覚え、そこから遅くなって、課題 100 では新品の 1.8 倍かかりました。0.9 には毎課題届いています。
2. **head を戻すと、LN ありの網は速くなり続けます。** R0L は課題 81〜100 で 75 更新、新品の 7 分の 1 です。head を戻す手順（Joudaki の手順）は喪失を隠します。
3. **SL の遅れは、死からも head に入る特徴の大きさからも来ていません。**
   - SL の死は、どの層も全課題でほぼ 0 です。
   - head に入る CLS の特徴は、最後の LN で抑えられて、lr × Σ|h_i| が 0.03〜0.04 で平らです（R0L は 0.03 → 0.17 と伸びても速くなる）。
   - 一緒に動いているのは、課題の始めの損失（10.7 → 18.1、切替の押しの大きさ）と、2 層目の前活性の幅（0.8 → 6.5。R0L は 0.6 → 2.0）です。因果はまだ測っていません。
4. **LN なしの 2 腕は崩れます。** R0 は課題 28 ごろから、S は課題 44 ごろから 0.9 に届かない課題が増えます。崩れた後の 2 層目の死は 0.8〜0.9、2 層目の幅は R0 で約 1,500、S で約 200 まで伸びました。head に入る特徴の lr × Σ|h_i| は、R0 で 0.34 → 4.2、S で 0.34 → 1.4 になりました。R0 は崩れ始め（課題 30）の時点ですでに 1.3 ありましたが、S は崩れ始めの課題 50 で 0.14 しかなく、S の崩れはこの大きさだけでは説明できません。
5. **共有の S の課題の始めの損失は、崩れた後に下がります**（26 → 31 → 5）。網が何も自信を持って当てられなくなったためです。
