# R0 後期（課題 60→61）の持続崩れの主因

依頼 4（`analysis/vit_long_1024/posthoc_2blk/fable_r0_1028_brief.md`）の B。Fable エージェント B、2026-10-29。箱は vit_long_1024 追補 D（2 ブロック ViT、rlfix、seed 10252010、LN なし・head を課題ごとに 0 に戻す腕 R0）。依頼 3 の答え（`posthoc_r0_collapse_codex.md`）で未同定だった「後期 R0 は head の lr を 1/100 にしても暗記が持続しない主因」を、届いた時点から分岐する回し直しで決める。

## 答え

主因は (ii) head と体の結合した更新の不安定さである。
(i) 体の表現の制約ではない。届いた時点の体を凍結して head を 0 から学び直すと 50 更新で暗記率 1.0 に届く。
届いた時点で体を全部凍結すると暗記は持つ（最後 1,000 更新の平均 0.95）。体が動き続けると崩れる。
崩れは急落で起きる。急落の更新では Adam の一歩が平常の 3〜20 倍に跳ね、体の一歩の logit 変化が余裕と同じ桁になる。
体の一歩の logit 変化は head の約 100 倍で、特徴の尺度 ‖h‖ にほぼ比例して t30 の 2.7 倍である。
体の一歩は大きいが向きが毎回入れ替わる乱歩で、head の一歩は小さいが向きがそろう。持続するかは、そろった更新による余裕の増加が乱歩と跳ねの消耗を上回るかで決まる。
凍結の効き方は課題で異なる。最終 FFN を止めるとどちらの課題も崩れ、ブロック 0 を止めるとどちらも持つ。注意 1 と head は t30 で止めると崩れ、t60 では持つか部分的に持つ。
Adam の一歩の一次の上界 3.16 η‖∂m/∂θ‖₁ は導出できるが、t30 でも余裕を超えるので上界だけでは課題を分けない。実現した一歩の |Δ余裕|/余裕 が分ける（t60 0.09、t30 0.04）。
頭から head と体の両方を 1/100 にすると 5,000 更新では届かない。

| 問 | 結論 | 根拠の種類 |
|---|---|---|
| B-1 形 | 急落（≥ 0.1/25 更新）が 7 回。急落は Adam の一歩の跳ねと一致 | 毎更新の記録（測った事実） |
| B-2 凍結 | 体を全部止めると持つ。最終 FFN を止めると崩れ、ブロック 0 を止めると持つ | 届いた時点からの分岐（測った事実） |
| B-3 両方 1/100 | 届かない。届いた後に体だけ 1/10 なら持つ | 回し直し（測った事実） |
| B-4 表現 | 届いた時点の体は線形に表せる（新 head 50 更新で 1.0） | 凍結体の head 学習（測った事実） |

| B-7 判定 | (ii) 結合した更新の不安定さ。決め手は B-2(a) と B-4 | — |

## 方法

- 保存状態 model_t60 + adam_t60（および t30）から、本走と同じ決定的な batch 列で 1 課題 5,000 更新を eager で回す（`fable_r0late_replay.py`）。R0 なので head は 0 に戻し、head の Adam 状態は本走どおり残す。head の lr は 1e-6（1/100）、体は 1e-4。
- 分岐の元の走は依頼 3 の `codex_replay_R0_t60_lr001_full` と T90（2,675）・末の暗記率（0.8148）・最後 1,000 更新の平均（0.6497）が桁まで一致した。t30 も同じ（T90 2,350、末 0.9992）。eager の回し直しは決定的である。
- 「届いた時点」は暗記率（訓練 2,500 枚）が初めて 0.9 に達した評価点（t60: 2,675、暗記率 0.9228。t30: 2,350、0.9208）。そこで model と Adam を保存し、分岐はすべてこの状態から batch 列を同じ位置で続ける。介入なしの分岐（`fable_r0late_track.py`）は分岐の元と末の暗記率まで一致した。
- 凍結は群の requires_grad を切り lr を 0 にする。群は ブロック 0（埋め込み・cls・位置・ブロック 0 の全部）、注意 1、最終 FFN、head。
- 一歩の logit 変化は固定の訓練画像 512 枚で Δℓ = (ΔW)h + W(Δh) + ΔWΔh と分け、画像ごとの平均を引いた rms で測る（softmax は平行移動に不変）。体の項は、その群だけ新しい値で順伝播して分ける（和の誤差 ≤ 1e-4）。分岐の元では届いた時点の前後の窓（届く前は暗記率 0.8 以上の区間、届いた後 400 更新）で毎更新、その外は 5 更新ごと。介入なしの分岐では届いた後の全更新で毎更新。
- 余裕 m = ℓ_y − max_{c≠y} ℓ_c。予測の入替は一歩で argmax が変わった画像の割合。
- 一貫性 C = ‖Σ_t 項_t‖ / Σ_t ‖項_t‖。毎歩同じ向きなら 1、乱歩なら 1/√n。
- 上界（B-6）: Adam の座標ごとの一歩は |Δθ_i| = η|m̂_i|/(√v̂_i + ε)。β1 = 0.9、β2 = 0.999 では |m̂_i|/√v̂_i ≤ (1−β1)/√(1−β2) = 3.16（Kingma & Ba 2015 §2.1、(1−β1) > √(1−β2) の場合）。一次近似で |Δm| ≤ Σ_i |∂m/∂θ_i| |Δθ_i| ≤ 3.16 η_g ‖∂m/∂θ_g‖₁（群 g ごと）。画像 256 枚で画像ごとの勾配から出す。表には係数 3.16 を掛ける前の η_g‖∂m/∂θ_g‖₁ を載せる。Adam の状態から出す「いまの歩幅」での和 Σ_i |∂m/∂θ_i| η|m̂_i|/(√v̂_i+ε) も併記する。
- 本走は compile、回し直しは eager で、軌跡の一致は保証しない（依頼 3 と同じ但し書き）。batch の分け方だけで T90 が 75 動く。1 seed。

## B-7 判定

(ii) 結合した更新の不安定さが主因である。
決め手は B-4（届いた時点の体は線形に表せる）と B-2(a)（体を止めれば持つ）の組で、(i) 表現の制約は棄却される。
機構は次の 3 つの測定で押さえる。体の一歩の logit 変化が head の 100 倍で尺度に比例すること（B-5）、急落が Adam の歩幅の跳ねと一致し、跳ねは batch の誤りが多いときに起きること（B-1）、届いてから体を遅くすれば持つこと（B-3）。
跳ねの連鎖は次の読みで、測定はそろっているが式にはしていない。数枚の入替で batch の誤りが増える → その batch の勾配が大きく向きがそろう → 直前まで静かだった Adam の二次モーメントに対して歩幅が跳ねる（上界 3.16 η）→ 体の項が余裕と同じ桁で logit を動かし、さらに入れ替わる。
t30 では余裕が 2.1 から 6.6 へ伸びて batch の誤りが 0 になり、引き金が消えて持つ。t60 では余裕が 3 のまま、batch の 2 割が誤りのままで、跳ねが繰り返す。
どの群を止めれば持つかは状態に依り、最終 FFN は両課題で止めると崩れ、ブロック 0 は両課題で止めても持つ、注意 1 と head は t30 で止めると崩れ t60 では持つ。この依存は 1 seed の測定で、必要十分の形にはしない。

### 鎖への位置づけ

R0 の後期の崩れは ⑤ 応答の喪失（死）ではない。死の割合が 0.8 の体でも、届いた時点では線形に表せる。
崩れは ③ の共通入力の成長が作った尺度（‖h‖ ≈ 8,000）の下で、Adam の一歩が logit を余裕と同じ桁で動かすことから来る。
V13 では、R0 の T90 と持続の崩れを「尺度と結合した更新の不安定さ」の経路に置き、死（⑤）と分けて書く。LN ありの腕が尺度を固定してこの経路を閉じることは依頼 1 の結果と整合する。

## 検証と残る問い

| 検証 | 値 |
|---|---|
| 分岐の元と依頼 3 の同条件の走の一致 | T90・末・最後 1,000 更新の平均が桁まで一致（t60・t30） |
| 介入なしの分岐と分岐の元の一致 | 末の暗記率が一致（0.8148、0.9992） |
| 一歩の分解の和の誤差 | ≤ 1e-4 |
| 既存入力の SHA256 の照合 | 11 件すべて変更なし |
| RSS の最大 | 1.85 GB |
| GPU の予約の最大 | 2.38 GB（fraction 0.30、同時 1 本、nice 10） |
| 回し直しの条件数 | 24（≤ 5,000 更新）＋ 上界 2 ＋ 介入なしの分岐 2 |

- 本走（compile）との軌跡の一致は保証しない。
- 1 seed、1 課題対（60→61 と 30→31）。凍結の効き方の課題依存は必要十分の形にしていない。
- 最終 FFN を止めると崩れる理由は未同定である。一歩の中の打ち消しではない（cos +0.21）。
- 跳ねの連鎖（batch の誤り → 勾配がそろう → Adam の歩幅が跳ねる → 入替）は測定で支持されるが、式にはしていない。余裕の増加（そろった更新）と消耗（乱歩と跳ね）の競争も同じ。
- 一貫性の cum_margin（track の JSON にある）は次点の選び直しによる最大値の選択バイアスを含むので使わない。
