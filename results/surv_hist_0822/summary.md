## 3. T1 — 生存者の p̂ 水準

統計量: 1,000,000 step 時点の alive ユニットの p̂ の中央値 (seed ごとに中央値 → seed 間中央値、seed 単位ペアブートストラップ B=10000, `np.random.default_rng(20260822)`)。

点推定 0.296875  95%CI [0.187500, 0.562500]

帯 (spec §5 A案): H_marg 側 = CI 上端 < 4/32 = 0.1250 / H_earn 側 = CI 下端 > 16/32 = 0.5000 / それ以外 = 保留 (正規の結末、FAIL ではない)。

**判定: 保留**

## 4. T2 — 平衡の有無

統計量: 窓 [700000, 1000000] での alive 数の step に対する傾き (seed ごとに OLS、単位「1 ユニット / 10⁵ step」)。**主判定はバルクグリッド 限定** (`step % 1000 == 0` かつ実現した境界の ±100 窓外、spec §4 識別限界 1 項)。

主判定 点推定 -0.091482  95%CI [-1.267392, 0.977085]

基準: CI がゼロを含む → 平衡あり (EQ)。CI 上端 < 0 → 平衡なし (DECL)。CI 下端 > 0 → 増加 (INC、処置表に無い結末＝想定外)。

**判定: EQ（平衡あり）**

T2-win (副次、境界窓内の点を含む。判定には使わない): 点推定 -0.113396  95%CI [-1.307417, 1.068656]。主判定との符号一致: 一致。

## 6. 逸脱節

1. **盲検性の毀損 (spec §9)**: 本 spec は厳密な意味での盲検事前登録ではない。T1・T2 に対応する探索値が起草時点で既に vault に記録されていた: `teachw_0820` の P3 (探索的・判定なし) で alive p̂ 中央値 0.2969 (H_T=100 アーム、`results/teachw_0820/summary.md`)。`停止条件.md` に 「700k→1M の中央値変化: H8/H32/H100 は −1〜−2 でほぼ横ばい」。spec §5 の T1 帯 (A 案、上端 4/32=0.125) は既知の探索値 0.2969 が入るように調整したものではなく、p̂ の量子化構造 (k/32) のみを根拠に固定してある。本走の T1 点推定はこの探索値と近い値になったが、それは事後に判明したことであり、帯の選定基準ではない。
2. **E2 は実装していない**: 台帳 (`命題リスト.md` L56, `blindspot_0820.md` L72) は「T1/T2/E2」の 3 統計量を挙げているが、E2 の定義は vault・specs・README・全 commit のどこにも存在しない (spec §5)。本 spec は E2 を含めない。定義が人間側から出てきたら別 spec の補遺として起票する。
3. **T2 の seed 間集計統計量**: spec §3 は T1 について「seed ごとに中央値 → seed 間の中央値」と明記するが、T2 の seed 間集計方法 (点推定に何を使うか) は spec 本文に明記が無い。house の標準 (`src.figures_ratchet_log.boot_ci` の seed 平均・ペアブートストラップ) をそのまま用いた。判定基準自体は CI の上端・下端のみで決まるため、この選択は判定結果に影響しない。
4. **T1 の先を追跡しない** (spec §8): 決定行列のセルを書く以上の追加解析・spec 提案・実装は行っていない (8/21 の線引き)。
5. **camp = sign(v_i) によるブレークダウンは行っていない** (Q17 穴A の禁止)。
6. **【事後・判定は動かさない】T2 の検出力が不足している。** 事前登録の基準（CI がゼロを含む → EQ）に**字義どおり従えば EQ** であり、判定は EQ のままとする。ただし CI の半幅は約 **1.12**（単位「1 ユニット / 10⁵ step」）で、`停止条件.md` が記録する H100 の減少（700k→1M で中央値 −1〜−2 ユニット ＝ **−0.33〜−0.67 / 10⁵ step**）を**丸ごと含む**。つまり本判定は「平衡がある」と「台帳が記録している減少が続いている」を**区別できない**。1M 時点の alive が 10 seed 合計 53 ユニット（seed あたり約 5.3）しかないことが直接の原因である。

   したがって **Q9b の反論欄「1M 時点のスナップショットで平衡未確認」は、本結果では閉じない。** §5 決定行列のセル「T2のみ記録（Q9bの反論欄は閉じる。Q10は未決）」は事前登録の文言をそのまま転記したものだが、**その前半は本 run の CI では支持されない**。これは判定基準の書き換えではなく検出力の記述であり、判定（EQ）も決定行列のセルも変更していない。

   （`ratchet_log_0819` は H_T=100 の 1 アームのみなので、この検出力不足を本データ内で解消する方法はない。対処が要るなら別 spec の事項であり、8/21 の線引きにより本 spec からは起票しない。）
