# 優先実行した16×16画像の中間比較

RGB32の本走完了分と、別途優先実行したavg16を比較した結果。各条件はAdam/SGD×seed300–304の5系列、50課題・各課題30000更新。これは**登録済みの全50系列による最終解析とは別**の20系列比較である。

## task41–50の対応seed比較

各seedで10課題の中央値を求め、avg16/RGB32の比を取ってから5seedの中央値を示す。`R`と`D`は各条件の固定1200画像bankの共分散を使った第一層の実効幅・実効変位。

| optimizer | R比 | D比 | raw ‖W1‖F比 | raw RMS比 | 訓練精度の対応差 | P2頭打ち基準 |
|---|---:|---:|---:|---:|---:|---|
| Adam | 0.334 | 0.315 | 0.504 | 1.008 | −0.083 | avg16 1/5、RGB32 0/5 |
| SGD | 0.658 | 0.510 | 0.817 | 1.635 | −0.265 | avg16 4/5、RGB32 4/5 |

raw RMSは `‖W1‖F / √(100d)`。avg16の入力次元は768、RGB32は3072で、`√(768/3072)=0.5`。Adamのraw Frobenius比0.504をそのまま「重みの成長が半分」と解釈できない。RMS補正後は1.008でほぼ同じ。一方、SGDはRMS比1.635である。訓練精度のlate窓seed中央値はAdamでavg16 0.898・RGB32 0.996、SGDでavg16 0.474・RGB32 0.737。

P1の近似バランス基準は4条件すべて5/5。P2は**50課題末の有限窓での頭打ち基準**であり、通過しても漸近収束や固定点の高さを確定しない。P3の独立heldout予測はavg16の両optimizerとRGB32 Adamで不通過、RGB32 SGDは4/5で情報不足。`Rstar_local = D/(2|c|)`は各課題で`c<0`のときだけ定義した局所診断で、収束先の推定値とは扱わない。

## 実測した初期幅からの成長倍率（ユーザー指定の事後比較）

ユーザーの「初期の幅から何倍になったか」という指定に従い、各系列の実測初期実効幅 RΣ(0) で割った。重みノルムではなく、同じ定義の機能的な実効幅を比較する。

| optimizer | RGB32の RΣ(50)/RΣ(0) | avg16の RΣ(50)/RΣ(0) | 成長倍率の対応seed比 avg16/RGB32 |
| --- | ---: | ---: | ---: |
| Adam | **129.13倍** | **45.23倍** | **0.350** |
| SGD | **28.93倍** | **19.87倍** | **0.688** |

各系列で倍率を計算してから5seedの中央値を取った。最後の列は同じseedの倍率どうしの比を取ってから中央値を求めたため、前の2列を割った値とは必ずしも一致しない。task50は50課題目**終了後**のsnapshot。対応比の5seed範囲はAdam0.338–0.364、SGD0.663–0.708。

初期幅の5seed中央値はRGB32 **1.45399**、avg16 **1.37419**で、両optimizer共通。task50終了時の幅中央値はAdamでRGB32 **186.874**／avg16 **62.344**、SGDでRGB32 **41.547**／avg16 **27.159**。初期の実測幅は近く、初めから幅が小さかった分だけでは学習後の差を説明できない。

単一時点の変動を確かめるため、課題41–50の各**終了後**の RΣ(t)/RΣ(0) をseed内で中央値にしてから対応比を計算しても、Adam **0.353**、SGD **0.696**。初期幅基準では両optimizerともavg16の成長倍率が小さい。これは先の固定座標振幅を想定した√d基準とは別の比較であり、どの基準を使うかを区別する。

上の登録指標Rは更新前の幅を使う一方、この事後比較は明示的に課題終了後を使っている。どちらの集計も保存し、既存の登録判定は変更しない。初期幅での正規化も、初期関数・スペクトル・学習軌道・到達精度まで揃える操作ではなく、漸近的な収束先を確定しない。

数値と監査は補助データの `initial_growth_posthoc/` に保存した。初期値とtask50は既存snapshot集計と一致し、隣接課題の終了幅と次課題開始幅もすべて一致した。

## 実効幅そのものの次元・入力分散による正規化（質問への事後追補）

**上のR比0.334／0.658は正規化前の機能的な実効幅であり、次元による縮小を除いた値ではない。先の説明で補正していたのは重みRMSだけだった。** 入力次元3072→768の平方根比0.5を基準にすると、以下になる。登録判定は変えず、ユーザーの質問に応じた記述的な事後集計として追加した。

| avg16 / RGB32、task41–50 | Adam | SGD |
| --- | ---: | ---: |
| 実効幅R | 0.334 | 0.658 |
| R / √d | **0.668** | **1.316** |
| R / √trΣ | **0.692** | **1.362** |
| 重みRMS(W) | 1.008 | 1.635 |
| 共分散との整列係数A | 0.692 | 0.836 |

各課題で正規化した値→seed内10課題中央値→対応seedのavg16/RGB32比→5seed中央値。R/√dの対応比のseed範囲はAdam0.663–0.675、SGD1.302–1.348。R/√trΣではAdam0.687–0.700、SGD1.349–1.395。

**√d基準ではAdamは約33%小さいが、SGDは約32%大きい。入力総分散で正規化しても向きは同じ。** したがって正規化後まで含めて「両方で幅が縮んだ」とは言えない。

ただし√dは各座標の重み振幅・平均入力分散・整列が同程度という比較基準であり、画像相関を含む普遍則でも次元だけの因果補正でもない。今回のnative fan-in初期化は E[Wᵢⱼ²]=1/(3d) なので、初期状態では E[R²]=h trΣ/(3d)。対応する初期実効幅の理論的な比 sqrt(E[Ravg²]/E[Rrgb²]) は約0.966で、0.5ではない。これは期待二乗幅から計算した基準で、実測幅の期待値比とは区別する。

各snapshotで厳密に R² = RMS(W)² × h trΣ × A²、A = R / (RMS(W) √(h trΣ)) と分解できる（h=100）。Aは等方的な重み配置を基準にしたWと入力共分散との整列を表す。Adamでは重みRMSがほぼ等しくAが低い。SGDではAは低い一方、学習後の重みRMSが大きい。別々の中央値の積は、積の中央値に必ずしも一致しない。

この比較は終盤10課題の記述であり、固定点の高さや漸近収束の証明ではない。平均化でスペクトル・初期関数・学習軌道・到達精度も変わるので、画像情報の損失だけの効果とも呼ばない。

数値は `width_normalization_posthoc.csv` と `width_normalization_posthoc_groups.csv`、定義は `width_normalization_posthoc_definitions.json`。再計算スクリプトと `width_normalization_posthoc_audit.json` に元CSVのSHAと再現確認を保存した。

## 入力幾何と解釈の範囲

画像bankの共分散trace中央値はavg16 44.532、RGB32 191.247（異なる座標系でのtrace比0.233）。これを「画像分散の77%を失った」とは解釈しない。avg16を元のRGB32座標へ各画素2×2再複製した直交射影では、分散保持率はseed対応中央値で`4 × trΣavg/trΣrgb = 0.9324`、除かれた局所差成分は`0.0676`。seed別値は`projection_variance.csv`に保存した。数値rankは768対1199、participation ratioは7.956対9.106。avg16は2×2ブロック平均で空間情報を失うが、R比0.334をその情報損失だけの効果とは呼ばない。native fan-in初期化により初期関数はRGB32と一致せず、同じ学習率でもoptimizerが作用する座標が異なり、訓練精度も変わる。
